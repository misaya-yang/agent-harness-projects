TURN ENGINE · CONTEXT ECONOMICS · DELEGATION

Hermes Agent 的回合控制，记忆与委派机制。

长耗时工具在后台写入文件或执行迁移时，用户突然关闭终端或遭遇断网，系统如何确保执行不中断、状态不撕裂？Hermes 通过跨进程的持久化回合租约（Durable Turn Lease）确立执行独占权，使客户端断线后可平滑接续。针对经验沉淀，系统由 Review Worker 线程在后台异步自审，并通过三层提示架构在安全的会话重组边界注入记忆，既保证前台交互零阻塞，又杜绝已发送上下文缓存被随意击穿。

  • 画出「序章—循环—尾声」三段式状态流，精准裁决 steer、redirect、interrupt 或 queue 四种干预通道
  • 阐明 stable 前缀、API sidecar 与规范转录（Canonical Transcript）的职责边界，避免污染因果历史
  • 设计具备防震荡熔断与原子回滚的 compaction 事务，确保长上下文压缩不丢关键锚点

CHAPTER 01 · ONE TURN

用户只补充一句话，不该因此杀掉正在写文件的工具。

在通用回合模型中，一次完整用户交互是一个通用回合（Turn），而模型推理与工具执行是内部的多次循环迭代（Iteration）。系统在序章取得跨进程租约，在迭代循环中驱动推理与工具调度，最后在尾声统一持久化与收尾。当用户在途中改变意图时，协调器先判断当前停留在流式请求还是工具执行，再决定分流至哪一条干预通道。

INCIDENT → EXECUTION CONTRACT

三段式回合把一次性工作和重复工作分开。

序章原子争抢跨进程回合租约（Durable Turn Lease）、恢复冻结的提示词快照与规范历史、执行上下文压缩预检门控；循环以状态机反复驱动“请求模型推理 ↔ 工具冲突调度 ↔ 合成配对结果回填”；尾声持久化提交最终转录、释放租约、记录消耗指标，并根据触发条件调度后台复盘。遇到空输出、截断或局部工具异常时，在迭代预算内发起安全重试。

短 trace：lease → build → model → tools → model → finalize

STEER安全排队

当前运行中的工具继续执行，新指令作为一条合成用户消息缓存在调度队列中，待当前工具批次完全收敛落盘后，作为下一轮迭代的上下文注入通用循环。适合“另外也检查测试”。

REDIRECT在途改向

若当前正处于模型流式生成阶段，立即中止请求流并把新目标替换为当前提示；若工具正在执行，若工具支持主动让出则请求其退让，否则平滑降级为 steer，确保外部文件与状态不被破坏。

INTERRUPT立即硬停

向当前活动租约与正在执行的异步任务分支广播取消信号，立即截断回合流并持久化中断标记。遗留的未闭合调用必须按副作用规则安全清尾。

QUEUE下回合再说

当前回合保持完整语义闭环，直至尾声完成持久化落盘，新消息作为下一个全新回合排入会话收件箱。

CHAPTER 02 · MODEL & FAILURE

同一个 429，不一定该做同一件事；先分类，再恢复。

通用循环通过 Transport 适配 OpenAI 兼容规范、Anthropic Messages、Codex Responses 与 AWS Bedrock Converse，再由错误分类器与重试阶段协同裁决恢复动作。显式启用 codex_app_server 时，Hermes 执行子进程委托模式——将整个回合托付给外部 Codex 进程，并把流式事件多路复用投影回本机会话；若子进程遭遇不可恢复异常，再切回原生通用循环。而在标准 API 模式下，只有未被中断的瞬态限流（429）、上游过载（503）或计费故障，且配置了有效备用路由时，才由通用循环接管重试。

01 / INCIDENT

双重重试风暴

供应商 SDK 往往内建指数退避重试，若外层循环也盲目重试，将导致请求量乘积级膨胀而触发严厉封禁。Hermes 剥离 SDK 重试，统一由通用循环协调器遵守 Retry-After 与请求配额。

02 / TRACE

集中分类

建立 error → reason → action bits → one retry owner 归一映射。当遇到供应商特定格式报错时，参数修复仅在本次 API 内存副本中做写时复制（Copy-on-Write），严禁污染规范转录。

03 / EXIT

错误分流终态

请求形状偏差可在适配层透明重写，工具执行异常作为标准结果交还模型纠偏；而配额耗尽、鉴权彻底失败或策略安全阻断则直接作为明确终态呈现，坚决避免无谓重试。

凭据冷却
依照具体失败语义计算冷却时长，而不单纯依据 HTTP 状态码；歧义错误被独立标为“未确认”并限制并发。
备用链
依照实际服务端点身份做拓扑去重，彻底避免“别名不同、底层实为同一坏端点”的假回退陷阱。
成本守卫
长上下文场景出现确定性空响应时，主动熔断昂贵的重复重试，杜绝每次沉默都全额消耗整段输入 Token。
CHAPTER CHECK

你能做什么：为新接入的 Provider 错误在分类器中注册标准映射与恢复动作，而不是在调用入口堆砌零散的字符串匹配；同时向团队解释为什么历史修复必须采用 Copy-on-Write 机制隔离。

CHAPTER 03 · TOOL EXECUTION

模型一次发来六个正确调用和一个空工具名，不该整批作废。

当模型在单次响应中并发吐出多个工具调用时，即使混入空工具名或畸变参数，也不能直接整批抛弃。工具执行器在进入派发前先执行清洗去重与参数宽容纠偏，为非法项即时合成错误响应（Synthetic Error Result），确保保留的合法调用与回填结果严格维持 1:1 配对。随后再依据资源竞争规则将调用批切分为并发段与屏障段，批次落盘失败等整轮退出条件则统一拦截。

  1. 目录发现与延迟求值：所有工具依照注册元数据汇入统一注册表；发现结果支持哈希缓存，动态参数 Schema 仅在向模型组装请求体时才实时求值。
  2. 渐进披露（Tool Search）：当工具集庞大或接入外部 Connections 时启用渐进式桥接。默认 5% 预算仅限制检索目录本身的体积（硬上限 4,000 token）；模型检索到具体工具后，其后续调用仍严格走会话工具面授权与参数校验。
  3. 路径冲突调度与屏障隔离：文件读写工具依据目标规范路径判定竞争。不相交的写入操作与多个只读操作可并发执行；一旦某操作与既有路径重叠且包含写入，立即切分段落设立调度屏障（Barrier），确保数据因果一致。
  4. 结果治理与安全边界：超大输出截取高信息量预览并自动持久化溢出至磁盘，重复的大体积结果置换为哈希引用桩；未信任的外部网页与抓取数据强行包裹语义防护边界，防范间接注入。

CHAPTER 04 · EXECUTION BOUNDARY

本地能执行命令，不等于本地有操作系统沙箱。

工程实践中最危险的假象，莫过于把“宿主支持命令执行”等同于“执行受沙箱保护”。Hermes 的 terminal 工具层抽象了六大内置执行后端：Local、Docker、SSH、Modal、Daytona 与 Vercel，高性能计算后端的 Singularity / Apptainer 则由官方插件提供。在系统选型与安全架构设计中，必须严格区分命令在何处运行、文件可见路径、环境变量流向以及断线后工作现场如何跨会话延续。

SECRET先剥离凭据

执行前强制剔除宿主敏感环境变量与供应商凭据；Docker 配置出口代理（Egress Proxy）后向容器仅注入受控的替代 Token，在外部代理端完成真实凭据换发，从物理上杜绝子环境窃取凭证。

DAMAGE再限制破坏

命令在进入执行前依照生效的审批策略裁决。匹配高危指令模式（如根目录清理、磁盘格式化、环境自毁）或用户拒绝规则时直接触发硬阻断（Hard Rejection）；文件系统工具另行校验目标路径是否越界。

POLICY最后保护规则

Profile 作用域决定使用哪个配置集合、提示词模板与认证凭据。容器挂载、网络出口与进程内插件各有独立隔离面，Profile 作用域归属本身不会提供操作系统级进程隔离。

CHAPTER 05 · TRANSCRIPT & RECOVERY

调用已记录，结果来不及写入。重启后怎样判断工具有没有执行？

当工具调用意图刚写入日志，而外部进程执行到一半被强制杀死，重启后的 Agent 应当如何面对悬挂的调用？规范转录（Canonical Transcript）记录严谨的事实因果链，API Sidecar 则在消息元数据中保存面向模型协议回放的内容副本。Profile 的底层持久化由装配器按需绑定，内置存储使用 SQLite state.db 并提供全文检索。持久会话在调度可能产生副作用的工具前，必须预先持久化调用块；一旦写入失败，立即中止整批执行。

01 / CANONICAL

规范转录事实链

严格保证 User、Assistant、Tool Result 的三元因果时序。临时记忆召回、实验性探针与干预脚手架一律隔离，确保历史在不同模型架构间具备高确定性重放能力。

02 / SIDECAR

精准协议投影

在数据库中随消息持久化存储特定供应商的序列化视图，既完整保留已发送的上下文缓存前缀，又在历史发生上下文压缩或内容改写时自动触发精准失效。

03 / RECOVERY

副作用分级清尾

重启或恢复时，纯只读的未闭合调用直接从模型重放视图中安全剔除；而具有外部副作用的调用不仅必须保留，还强行注入 UNKNOWN 合成结果，强制恢复后的首个回合发起主动状态探测。

CHAPTER 06 · MEMORY LOOP

“记住这条经验”不能阻塞用户当前的回答。

经验提炼与反思绝不能阻塞用户前台的实时交互。Hermes 将认知存储严格区分为三层：会话内冻结的系统提示快照、磁盘上的持久化活状态、以及外部记忆 Provider。系统采用双计数器驱动演进：记忆沉淀按有效用户回合数（Turn Count）累计，技能更新按内部循环迭代数（Iteration Count）累计，默认触发阈值均为 10。只有在回合交付完成、未被中途中断且满足后台权限门禁的前提下，才向后台自审工作线程派发复盘任务。

FROZEN会话内冻结快照

会话初始化时从持久化介质拉取记忆，并在系统提示中固化为冻结快照。即使外部文件在磁盘上已被修改，当前会话也绝不动态重写，必须等待显式重置、会话切换或上下文压缩边界才重新组装，守护缓存稳定。

PREFETCH回合级外源召回

从外部 Provider 召回的相关经验以参考资料形式注入 User 消息的 API Sidecar 视图中，并打上明确的防御性语义栅栏，防止模型将其误认作强制执行的系统指令。

REVIEW后台自审工作线程

后台复盘运行在独立的守护线程中，仅持有当前回合的只读快照与受限分析工具。当前台用户发起新的交互回合时，系统拥有最高优先级，可随时废弃排队或中断执行中的复盘，绝不抢占前台算力。

DRIFT并发写入防漂移

持久化层严禁将文件读取失败误判为“文件为空”从而清空历史；在回写新提炼的经验时，必须校验基线版本哈希，若发现外部已被修改且无法合并，立即拒绝覆盖并保留冲突备份。

CHAPTER 07 · EXTENSION SYSTEM

能观察发生了什么，不等于有权改变将要发生什么。

扩展体系的核心在于严守最小权限边界。Hermes 将扩展形态划分为三个权限层级：Skill 是纯文本按需加载的领域知识包；Observer Hook 负责向外广播生命周期事件，其异常被完全隔离且无权阻断主流程；Middleware 拥有双向改写请求、环绕包裹执行甚至短路返回的最高特权。进程内扩展直接持有宿主权限，平台对声明式能力实行严格的哈希授权契约；Profile 目录下的事件 Hook 则以操作者物理放置文件的特权作为信任边界。

Skill
初始化时仅向系统提示注入技能名与单行摘要，正文仅在模型显式检索调用时才动态读入；适合封装复用型领域规约，不浪费常驻上下文。
Observer
单向接收生命周期通知并记录遥测数据。即使观察者脚本抛出异常或超时，也不会波及错误分类与主循环，多个观察者依次链式运行。
Middleware
拥有拦截、重写与包裹执行权的核心管道组件，仅对受信任扩展开放；所有流入中间件的数据先执行深度复制，杜绝全局共享状态被篡改。
Capability Gate
扩展声明的每一项能力必须对应底层有切实拦截力的强制门控；扩展升级若引入新增权限声明，必须由用户重新授权确认。

CHAPTER 08 · CACHE & COMPACTION

压缩后消息变少，不代表这次压缩有效。

压缩后消息总数减少，绝不等于这次压缩具备正向工程收益。Hermes 的系统提示词遵循 Stable、Context、Volatile 三层严谨组装，回合级动态变化全部通过 API Sidecar 承载。内置压缩起点设定为窗口容量的 50%；当模型上下文小于 512,000 token 时，触发比例提升至 75%，并在扣除输出预留后核算绝对安全裕度。预检门控结合本地启发式粗估与上一轮上游回传的真实 usage；若服务商明确报错溢出，则触发独立的紧急降级恢复。

CACHE保护已发送前缀

Stable 前缀是命中 Provider Prompt Cache 的核心资产；时间戳、动态记忆与插件清单绝不能随心所欲插入头部破坏前缀哈希。

MEASURE粗估结合真实回执

发送前的分词估算用于预检拦截，而响应回传的真实 Token 用量是唯一的事实依据。只有下一次真实请求的输入回执才能验证压缩收益；无用量返回时退守保守估算。

GATES三道防震荡闸门

摘要模型服务异常立即进入冷却期（Cooldown）；历史全为不可裁减的关键数据时主动暂缓；连续两次经真实回执验证无实质收益时立即触发防抖熔断（Anti-thrash），防止陷入反复无效压缩的死循环。

TXN事务化原子提交

遵循严格的事务模型：建立恢复检查点 → 保留头部原始指令与尾部最近轮次 → 摘要中间历史 → 校验体积是否切实收敛 → 满足收益原子替换规范视图并软归档，否则无损回滚。

SHORT TRACE

一次安全压缩的最短心智模型

pressure? → checkpoint → keep head/tail → summarize middle → validate size → commit or rollback

摘要失败分级处理：网络中断、鉴权拒绝、空内容或截断时坚决保全原文历史；仅允许常规错误走确定性规则兜底。压缩产物中务必完整保留用户原话指令、关键文件名与检索提示，使被截断的历史转化为可延迟检索的索引。

CHAPTER CHECK

你能做什么：向团队说明为何每回合都执行的“微压缩”默认处于关闭状态。虽然它能逐步缩短历史行数，但会反复改写 Provider 已经缓存的前缀字节，大幅削弱 Prompt Cache 收益。在具体路由下对比全额输入计费与缓存命中计费，精准计算净收益。

CHAPTER 09 · MULTI-HOST

CLI、桌面、消息网关可以长得不同，但不能各自拥有一套回合语义。

Classic CLI、交互式 Ink TUI 与桌面客户端可以有不同的前端交互形态，但绝不能各自拥有一套冲突的回合语义。Hermes 由共享核心服务提供统一会话仲裁（SessionAuthority），负责管理输入准入、多路事件订阅与活动执行独占权；侧边客户端在连接中断后可随时无损重连。IM 消息适配器依照平台会话键（Platform Session Key）隔离路由，多 Profile 活动绑定独立的工作主目录、安全凭据与执行沙箱。

场景 · 多客户端接续

关掉 TUI 后，用 Desktop 接手待审批回合。

在 TUI 中提交的高危命令正在等待人工审批，此时开发者关闭终端，打开 Desktop 应用接手。prompt.submit 仅确认输入已被网关持久化准入；主动断开（Detach）仅注销该客户端的订阅信道，后台执行并不受损。当新客户端重连时，必须同时携带当前执行世代编号（Generation ID）与特定审批 ID（Approval ID）进行校验，防止错误批准已被过期的历史残留审批。

CHAPTER 10 · ASYNC DELIVERY

后台任务完成时，父代理还在说话：结果不能直接写入当前消息序列。

长耗时异步任务完成时，父 Agent 往往正处于流式生成或工具执行中：新结果绝不能强行插队写入当前消息序列。Hermes 将异步委派完成事件推入持久化完成队列（Completion Queue），待父会话完整收尾并处于静息边界时，再以合成用户消息发起全新回合。Cron 调度器同样具备独立的到期检测、竞争申领租约（Claim Lease）、沙箱执行与多渠道交付流水线。一次性任务支持显式重置触发（rearm），投递通道的连通性与执行终态分别核验。

场景 · 可选投递镜像

发送成功的通知，是否要进入目标聊天历史？

Webhook 调度支持按路由启用的会话转录镜像（Transcript Mirroring）：当通知成功投递至外部聊天群组后，可将已发送内容追加同步写入目标会话的转录中，确保后续用户直接引用回复时 Agent 能感知前文。该选项默认保持关闭，且受目标 Profile 作用域与写入租约的严格约束。

面试追问：为什么外部 Webhook HTTP 200 发送成功，与目标会话本地历史已成功持久化，必须作为两个独立的阶段分别确认？

DISPATCH立即返回句柄

后台委派不阻塞当前前台回合，立即返回任务句柄；若底层检测到目标通道不具备持久消费能力，自动降级为同步阻塞，绝不散发无法跟踪的孤儿句柄。

CLAIM先申领再投递

持久账本分别独立记录「已派发」、「已完成」与「已投递」。多个工作节点通过申领租约（Claim Lease）互斥竞争交付权，防止重复投递并发撞车。

REPLAY有界幂等重放

完成事件具备严格的生命周期防腐治理（最多重试 8 次、启动重放窗口 48 小时）；若在途子任务因宿主崩溃丢失执行所有者，结果统一标记为 UNKNOWN 待核实。

CHAPTER 11 · DELEGATION

多代理最难的不是“并发跑”，而是只把值得保留的内容带回来。

多 Agent 协同体系中最致命的误区，是无节制地把子代理的所有冗长交互全量拼回父会话。Hermes 在执行委派时，由宿主分叉独立的 AIAgent 实例并在子线程中运行，赋予其隔离的规范转录、独立的终端执行后端与专属迭代预算。子代理工具面依照委派策略进行最小化裁剪；当选择继续已有子任务时则无缝延续历史。父回合仅接收任务句柄与高浓度结构化摘要，子代理的完整转录单独落盘归档。同步委派直接作为工具结果返回，异步委派则经由完成队列异步回流。

BUDGET摘要聚合与上下文配额

LIVENESS分级活性与超时裁决

实施场景化无进展超时（模型推理阶段 450 秒、耗时工具执行阶段 1,200 秒）。看门狗触发超时后切断等待并标记超时状态，但底层执行线程与外部副作用必须核查。

PROOF自我报告不是证据

子代理在回答中声称“已修复并部署上线”仅是其主观陈述；父代理必须要求可核验的外部事实句柄（Commit SHA、Status URL、测试退出码），并在尾声亲自探针核验。

CHAPTER 12 · OPERATING JUDGMENT

排查 Agent，不要先猜模块；先判断哪一层还有能力修复。

排查 Agent 线上故障，切忌在没有证据时盲目猜测底层模块；必须自顶向下判断哪一层仍具备修复能力。终章将架构体系提炼为五步诊断法：当前停留在通用回合的哪个阶段？中途输入该分流至哪条干预管道？异常属于机器可自愈、需模型纠偏还是向用户上报？数据状态是否已持久化落盘？新产生的结果能否在不破坏前缀缓存的前提下平滑接入？

五步场景诊断

  1. 精确定位故障层级：精准区分是单次 LLM 推理卡顿、工具执行死锁、回合协调器租约等待、还是多宿主网关路由断开，坚决避免将所有超时笼统归咎为网络问题。
  2. 严密甄别退出原因：区分迭代预算耗尽、用户主动 Interrupt、安全护栏拦截、存储层持久化失败、Provider 鉴权拒绝与真正的业务完成。
  3. 核验持久化事实链：检查不可逆工具副作用发生前，调用块是否已在 state.db 提交落盘；后台完成事件是否已进入持久完成账本。
  4. 守卫缓存前缀边界：排查是否有动态时间戳或易变上下文错误污染 Stable 前缀，导致服务商 Prompt Cache 命中率剧烈下跌。
  5. 闭环验证恢复契约：确认重试是否遵循单宿主仲裁；上下文压缩后是否通过真实用量验证收益并设置熔断；多子代理完成交付是否附带由父代理亲自探查验证的外部事实句柄。

FIRST EVIDENCE

PROBLEM SET 01 · 干预选择

模型正在生成长文本解释，用户改了最终输出格式；模型正在执行不可逆文件删除命令，用户说目标目录选错了。两次分别选哪条通道？

展开判断

前者选择 REDIRECT：立即中止在途流式请求并保留已经完成的前置思考与工具上下文，直接换用新格式要求重试。后者坚决选择 INTERRUPT：高危副作用目标错误，继续执行代价不可逆，必须强行阻断整个回合，并对遗留未决调用注入 UNKNOWN 清尾。若工具正在做安全的只读检索且用户只是补充查询范围，则选择 STEER 安全排队。

PROBLEM SET 02 · 压缩设计

执行历史摘要后消息总条数减少了一半，但下一次真实推理请求的输入 Token 仍然超过触发阈值。这次压缩算成功吗？下一步该怎么做？

展开判断

不算真正成功。一次真实采样的用量依然超标，表明输入上下文压力根本未解除。首先区分是摘要产实体积过大、新回合用户输入增量剧烈、还是系统提示与常驻工具声明等固定成本超标；连续两次经真实回执验证无收益时立即触发 anti-thrash 熔断，停止无效压缩，转为通过 Tool Search 或精简固定提示词进行结构治理。

PROBLEM SET 03 · 委派信任

三个并发子代理的返回文本均包含“全部 Bug 均已修复并部署完成”，父代理可以直接向最终用户宣布任务成功吗？

展开判断

绝对不能。子代理文本中的完成陈述仅属于“自我报告”，不具备工程证明效力。父代理必须要求子代理回传客观的外部校验句柄（例如 Commit SHA、CI/CD 运行 ID、健康检查 URL、测试报告退出码），并在尾声由父代理亲自调用探针工具验证；一旦校验探针无法访问或返回非零状态，结果必须客观判定为 UNKNOWN，绝不能向用户谎报成功。

通用回合
从一条用户输入进入，经多次模型推理与工具迭代，至尾声发布状态并落盘的完整原子业务单位。
API Sidecar
在数据库中随规范消息持久化的供应商特定协议序列化视图，不污染规范因果历史。
检查点 Checkpoint
在执行不可逆副作用或长历史压缩前，确认外部状态与数据具备完整回滚能力的恢复锚点。
完成队列
异步后台任务或子代理完成事件等待父会话进入空闲边界并开启新回合的持久化交付队列。
FailoverReason
