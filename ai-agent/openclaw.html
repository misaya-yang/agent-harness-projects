ONE GATEWAY · THREE LOOPS · DURABLE EVIDENCE

OpenClaw 的长期任务如何保持状态与有界运行。

当用户从另一个聊天入口发来补充指令时，常驻网关（Gateway）必须跨通道精准定位原会话，将输入安全交付给当前执行者。OpenClaw 的核心架构将长期存在的会话实体与单次受严格预算约束的运行过程彻底解耦；而在服务重启时，系统严格核对关停标记、崩溃时间窗与权限范围，只有在证据完备时任务才被安全接续。

COURSE MAP · ONE SYSTEM, FOUR QUESTIONS

四个需要回答的运行问题。

状态归属常驻 Gateway

连接、会话、审批与事件投影由一个常驻控制进程承接；模型与工具只是被它调度的工作面。

续跑条件三层循环

内层处理模型与工具，中层决定逻辑任务是否续跑，外层为失败 attempt 选择重试、轮换或终止。

上下文连续性事件树与检索记忆

转录记录会话事件，压缩用摘要与近期消息重建模型视图。长期事实按需检索。

资源约束预算与证据

时间、尝试、深度、宽度、字符量各有主人；存在副作用且结果不确定时，默认不盲目重放。

阅读前置：先区分 Gateway（入口与控制）、session（持久会话）、turn（一次模型与工具循环）、attempt（一次 Provider 与模型组合的运行尝试）。

CHAPTER 01 · THREE OWNERS OF CONTINUE

场景：模型已经停了，任务却又跑了一轮。哪一层触发了续跑？

沿内置 openclaw 运行时追踪三层控制权：内层判定模型是否需要读取工具结果，中层裁决会话是否需要继续推进本轮逻辑请求，而最外层则决定在失败时是否更换候选凭据或模型再做一次尝试。

LEARNING ROUTE · SAY IT WITHOUT CODE

三层循环的继续权

  1. 内层 turn 循环：模型要不要发起工具调用，执行完毕的工具结果要不要再回填给模型开启下一轮推理。
  2. 中层 logical prompt 循环：在整条请求范围内检查排队插话、处理会话级重试与上下文压缩，决定当前会话是否继续推进或收束结算。
  3. 外层 attempt 循环：当 Provider 网络中断、凭证失效或模型报废时，评估是否轮换候选 profile、切换备用模型或发起新的执行尝试。
attempt → logical prompt → turn → tool results → turn end → settle / continue

判断法：排查异常续跑时，若看到生成了新的 tool_call，应直接聚焦内层 Turn；若观察到上下文压缩触发或消费了排队插话，应聚焦中层 Logical Prompt；若发现凭据轮换、模型切换或重试计数扣减，则责任在外层 Attempt。

学习检验：任选一次“多跑了一轮”的故障，给每层各写一个可能原因，并指出真正拥有终止权的是哪一层。

CHAPTER 02 · INTERRUPT WITHOUT BREAKING HISTORY

场景：用户中途改主意，旧工具没启动，却让下一轮请求因“缺少结果”报废。

在顺序工具批次中发生用户插话时，尚未启动的调用会被安全跳过。宿主必须为被跳过的调用合成写回原因，确保下一次模型请求的上下文中工具调用与结果依然严格成对。

三种消息的进入时机

steering（纠偏插话）代表「立即修正方向」，在当前工具批次结束后、发起下一次模型请求前的安全检查点被消费；follow-up（后续任务）代表「做完当前全部工作后再推进」，必须等待当前任务所有回合自然收口后才被检出；如果需要开启全新独立任务，必须等待当前会话锁完全释放。而若要强行扼杀正在运行的旧回合，则必须使用带有强制终止语义的 interrupt 控制信号。

queue → checkpoint → 已启动的收尾 → 顺序批剩余调用记为 skipped → next turn

关键不变量：插话可以改变未来的执行轨迹，但绝不能抹除已经发生的历史事实。已经启动并产生副作用的工具必须等待其输出返回；而对于在顺序批次中被中途跳过的未启动调用，必须写入包含跳过原因的合成错误结果，保证会话转录中每一次 tool call 都有确定性的结果配对。

SETTLE CHECK

内核发出 agent_end 仅表明单次模型回合完结；会话协调器随后会按严格顺序依次进行六项收束裁决：检查是否需要外部移交（handoff）、是否收到用户中止信号（abort）、当前错误是否可恢复、重试预算是否耗尽、上下文是否需要压缩、以及队列中是否仍有排队插话。只有通过全部裁决，会话才正式发出 agent_settled 进入休眠。

  4. 恢复是否耗尽
  5. 是否需要压缩
  6. 是否还有排队消息

CHAPTER 03 · THE PROCESS DIED, THE TASK DIDN'T

场景：Gateway 重启后，内存计数全没了。助理凭什么知道做到哪一步？

常驻 Gateway 在重启后会扫描已落盘的持久会话账本，精准寻回未完结的执行线索；只有满足关停标记与崩溃时间窗条件的根会话，才被允许调度恢复输入，且系统必须先核对中断前在途工具的实际外部影响。

  1. 转录是仅追加事件树：会话转录采用仅追加（append-only）的事件树结构；消息、状态跃迁与分支切换均作为新事件顺序写入，当前 leaf 节点唯一决定了面向模型的活跃上下文路径。
  2. 压缩仅变更视图而非物理删除：内置压缩通过追加一条包含结构化摘要与截断边界（firstKeptEntryId）的特殊条目来收缩模型视图；底层的原始历史事件依然完好保留在存储库中，受全局归档策略治理。
  3. 重启恢复的准入三要素：正常关停时系统会持久化标记运行中的根会话及其未处理输入；若遭遇意外崩溃，仅当非终态 Run 落在记录的有效崩溃时间窗内、确认无残留并发执行者、且符合当前白名单范围时，才允许自动接续。
  4. 未决副作用按 UNKNOWN 处置：在中途意外中断的工具调用绝不能单方面假设成功，也不允许盲目重跑；缺少执行回执的操作必须置为结果未知并引导核验。
关停标记或崩溃时间窗内的孤立运行 → 核验范围与权限 → 投递恢复输入 → 核对未决副作用

CHAPTER 04 · FOUR THINGS CALLED MEMORY

场景：团队把 cache、compaction、replay 和 memory 当成一回事，结果越优化越贵。

Cache、Compaction、Replay 与 Memory 分别解决重复请求计费、上下文窗口爆满、进程重启恢复以及跨会话长期事实检索四大不同维度的工程问题。混淆这四者的职责边界，必然导致越优化成本越高。

机制它真正保存或改变什么判断问题
Cache支持前缀缓存的提供方可复用稳定请求前缀。易变状态放在后部，有利于保住命中。前缀变了吗？
Compaction用摘要边界替代旧历史的模型视图，同时保留最近尾巴和原始事件。窗口要满了吗？
Replay从已提交的事件重建选中的会话分支，再核对外部动作结果。能安全重建吗？
Memory长期事实进入检索语料，按需 search/get；耐久内容再经来源与预算门晋升。需要哪条旧事实？
stable prefix | CACHE BOUNDARY | dynamic context → budget → retrieve / compact → provider

系统设计上应将工具规格清单、静态行为准则与工作区全局说明保持字节级一致以固化缓存前缀；而将当前时间戳、权限审批状态与任务进度等动态易变内容严格置于请求尾部。排查缓存未命中时，应优先比对请求前缀哈希，再结合 Provider 返回的 cache_read 指标定位。长期记忆统一借助 memory_search 与 memory_get 进行按需语义或关键字检索；底层支持 SQLite 或 PostgreSQL 检索后端；内置的 Dreaming 整理机制默认在每日凌晨 3 点对记忆进行提炼合并，在多代理架构下需明确配置其归属的宿主环境。

CHAPTER 06 · RETRY IS A SAFETY DECISION

场景：一次 429 被多层重试放大；更糟的是，消息已经发出却又被重复发送。

面对错误时，必须先对异常进行分类判定，继而严查当前回合是否已造成外部副作用，最后仅消耗当前责任层专属的预算。在发起任何重试前，必须确认副作用处于安全可控状态且当前层配额充足。

  1. 错误性质精准分流：底层的 Provider 网络通信或鉴权失败路由至外层 Attempt 的故障转移机制；而工具在宿主执行中抛出的异常，必须包装为格式化的错误结果回填给模型参与自愈推理。
  2. 多层预算独立分账：单次 HTTP 往返超时、单次 Run 内的 Attempt 尝试配额、跨 Run 的健康检查频次以及故障 profile 的冷却惩罚，均由各自的责任层独立记账，严禁跨层透支。
  3. 墙钟约束与退避抖动：瞬态网络抖动的重试必须采用带有随机抖动（jitter）的指数退避；若服务端响应中包含 Retry-After 头，等待间隔不得低于该值，且重试整体必须严格受制于总计 48 小时的全局墙钟预算。
  4. 外部副作用严格封闸：若当前回合已实际向外发送了通信消息、创建了调度计划、派生了子任务、或操作结果可能已被外部消费，在无法证明幂等安全的前提下坚决禁止盲目重放。
raw error → classify → side-effect evidence → budget owner → retry / rotate / fallback / surface

外层尝试预算是 clamp(24 + 8 × max(1, 候选凭证数), 32, 160)。这个上限在本次运行开始时选定。开始 attempt 时增加计数，progress_continuation 可退回一次，已完成的模型响应将连续计数收回到 1。仅部分输出或工具推进不能重置计数。默认 agent 墙钟为 48 小时，首个有效输出前的连续空闲超时上限为 5 次。

CHAPTER 07 · COMPACT WITHOUT LYING

场景：摘要说压缩成功，窗口却没释放；下一轮又压一次，成本进入死循环。

内置压缩算法通过生成结构化摘要边界并拼接保留的近期上下文尾部来重建模型视图，同时提取文件修改等结构化事实旁路；不同的运行时环境与外部上下文引擎可按需实现自己的压缩管道。

TRIGGER三种入口

请求前可预检。会话归属的 overflow 恢复最多三次，成功后可续跑。回合后的阈值维护为后续请求腾空间。

CUT原子切点

切点不能落在 tool result；工具调用与对应结果必须一起保留或摘要。

SUMMARY分块再合并

大历史先规划原子块，分别摘要，再合并成固定结构的交接文本。

SIDECAR机械事实旁路

文件读取和修改有可提取的结构化记录。交接摘要写清未完成的工作，外部动作是否生效要回到原始回执核对。

choose cut → group atomic tool batches → summarize chunks → merge → append boundary → sanitize replay state
SNAPSHOT, NOT DELETION原始转录仍在，模型视图变小。新视图由边界摘要、近期尾部与新消息构成。先确认压缩所有者。内置或 context engine 的宿主路径，与 Codex app-server 的原生压缩各有入口。

CHAPTER 08 · COMMIT WHEN EXECUTION REALLY STARTS

场景：五个工具并行提交，第三个被拒绝，后两个却已产生副作用。

工具派发阶段严格依序检查权限并记录执行事实。已经启动的工具调用保有其合法的执行结果，而由于前置失败或插话未及启动的调用，则按批次一致性规则合成写回结果。

工具派发的四条硬规则

  1. 批次默认支持并发派发；若工具显式声明了排他依赖，则按模型调用顺序严格串行化派发。
  2. 任何工具启动执行前，内核必须先将该项调用事实持久化提交至转录，执行完工后以原始调用 ID 精确绑定回填结果。
  3. 接入文件操作队列的内置读写工具按物理文件的绝对路径排队，操作互不相交文件的调用可安全并行。
  4. 工具执行抛出未捕获异常时，调度器统一将其塑形为带 is_error: true 的结构化错误结果，协助模型自纠。
提交模型的调用记录 → 检查与启动工具 → 按调用 ID 提交结果
LARGE TOOL SET

海量工具目录支持按需惰性解析。稳定的工具定义能最大化复用请求前缀缓存，而动态权限则在工具执行入口处实时鉴权。符合条件的异步工具允许在模型流的 toolcall_end 后提前预热启动，但执行前必须先持久化提交对应的转录片段。

TOOL REPEAT GUARD重复工具守卫默认开启。同名同规范化参数连续第 3 次执行并提示，第 20 次在执行前拦截，回合以 tool_repeat_limit 结束。声明可重复的轮询调用有豁免。

学习检验：为“同一文件两次写、另一文件一次读”的 batch 排出并行与串行次序，并标出 steering 能阻止哪些动作。

CHAPTER 09 · THE GATEWAY STAYS, CLIENTS COME AND GO

CHAPTER 10 · FOUR INDEPENDENT DEFENSES

场景：命令通过 allowlist，却借解释器内联代码做了完全不同的事。

单次高危操作在执行前需连续穿透容器环境约束、文件路径解析、宿主审批裁决以及受管网络访问四道独立防线。排查拦截异常时，必须先明确调用走的具体执行通道，再逐层核验该通道生效的防御规则。

SANDBOX容器与配置守卫

在环境拉起前静态拦截危险的文件系统挂载、host 网络直通以及特权降级配置，坚决杜绝容器逃逸。

PATH词法规范化 + realpath

目标路径先进行词法规范化，随后沿现有文件祖先逐级解析物理 realpath，彻底防范符号链接欺骗与目录穿越。

APPROVAL多层级动态审批流

宿主 exec 支持 deny、allowlist、ask、auto、full 五档执行策略；对使用 python -c 或 bash -c 等解释器执行的内联代码施加严格的 AST 语法审查。

NETWORK受管 DNS Pinning

启用 DNS 固定机制的受管 Fetch，先校验域名解析 IP 再建立物理套接字连接；发生跨域重定向时强制清洗敏感 Authorization 头部。

  4. 审批转发进通道

TRUST BOUNDARY

工具钩子可以在调用前阻断，宿主 exec 还有独立的人审与执行前复核。交互审批可按配置送达控制界面或支持的通道。Gateway 宿主的自动化审批只发给在线且具备审批能力的客户端。普通询问无响应时由宿主的 askFallback 决定，默认拒绝。

CHAPTER 11 · ACCEPTED IS NOT THE RESULT

场景：父代理收到 accepted 就宣布完成；孩子稍后失败，结果再也没人接。

子代理拥有完全持久化的独立会话生命周期。调用 spawn 仅代表在底层创建了子任务并获得句柄，真正执行结果必须由异步的 Announce 状态机安全回送。

源码更新 · 取消权限

看得到任务，不等于有权取消它。

当前子任务取消要求调用方拥有现时控制权；历史读取权和完成通知接收权不会自动授予取消权。对于已变更父关系的任务，还要核对实际执行实例与当前控制者。

面试追问：子代理迁移到另一父节点后，谁能取消它，为什么？

announce 的最短 trace

spawn accepted → durable child → terminal lifecycle → claim → bounded capture → announce / outbox → parent admission → transcript commit → consumed

子任务达成终态后，完成结果进入待交付出站队列；若父会话正处于活跃回合中，就绪后可作为 steering 插话注入，若处于空闲状态则触发新一轮会话唤醒。父会话转录一旦落盘提交即登记 consumed；而在系统重启后，未被确认的完成通知支持可靠重投，已提交的输入绝对不重复追加。

CAPABILITY FLOWS DOWN

系统默认限制最大派生深度为 5，单个父会话最多允许 5 个活跃子代理，普通子任务并发度默认限制为 8。在异步创建前先占用并发配额，叶子节点自动剥离派生工具，取消任务必须严格核验现时控制权。

PLUGIN提供能力

SOUL塑造声音

人格影响表达，不改变持久化准入、控制域或工具权限。

COST BOUNDARY并发上限不等于 token 预算。深度约束派生层数，每父会话的孩子数约束挂起规模，执行并发约束同时运行的数量。重试和递归仍会累积成本，需按用量记录估算。

综合场景：助理不回复、费用上涨、子任务完成却没有结果。先查哪一层？

CAPSTONE · FIVE-PASS TRIAGE

一张表完成第一次故障分诊

展开诊断模板

1. 准确定层：明确故障到底出在 Gateway 连接层、外层 Attempt 凭证层、中层 Logical Prompt 调度层、内层 Turn 工具层，还是底层数据库持久化层？

2. 寻访事件：核对最后一条被权威持久化的事件（Turn 结束、Steer 交付、压缩提交或 Announce 回填），锁定事件断流的精确边界。

3. 对账预算：排查是单次 Step 步数触顶、外层 Attempt 耗尽、48 小时全局墙钟超时，还是并发子任务达到上限？

4. 审查副作用：严格检查外部通信是否已送达、本地文件修改是否已落盘、后台任务是否已创建；对于结果不明的调用坚决拒绝盲目重放。

5. 验证恢复闭环：通过构造最小可复现操作，检验系统是在继续推进、切换路由、显形报错，还是安全降级至休眠终态。

EXERCISE · ASYNC DELIVERY

孩子显示 complete，但父会话没有结果，怎么查？

展开判断骨架

区分 execution terminal 与 delivery complete；再查终态是否被认领、捕获是否有可见结果、投递属于 delivered / queued / retryable / ambiguous / permanent failure 哪类；最后核对父回合正在运行、已 yield 还是需要新唤醒。

EXERCISE · CONTEXT COST

每一轮都在重算大段 prompt，怎么查？

展开判断骨架

比较稳定前缀是否变化；再看运行时载体是否位于边界后和请求尾部；检查工具目录指纹；最后区分缓存失效、消息预算不足，还是确实需要 compaction。

turn
一次模型响应及其工具结果；只知道当前请求与工具批。
logical prompt
围绕一条请求的续跑区间，可因恢复、压缩或排队消息包含多个 turn。
attempt
外层针对 provider、凭证与模型组合的一次运行尝试。
cache
复用未变化的请求前缀；不等于保存全部对话。
compaction
将较早上下文压缩成摘要，让下一次请求携带摘要和近期尾部。
replay safety
重建或重试前确认副作用是否已提交、是否可能重复。
announce
子代理结束后向父会话推送状态与有界证据的异步流程。
Gateway
负责连接、控制、会话与事件的常驻进程；不是模型。
