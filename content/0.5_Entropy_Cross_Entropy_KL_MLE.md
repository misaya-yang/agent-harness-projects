# 0.5 信息论：熵、交叉熵、KL 与极大似然

> **一句话核心直觉**：交叉熵 $H(p, q) = H(p) + \mathrm{KL}(p \,\|\, q)$。训练语言模型就是在最小化它：数据的熵 $H(p)$ 是改不掉的底线，你能压下去的只有 KL。极大似然等价于最小化前向 $\mathrm{KL}(\text{数据} \,\|\, \text{模型})$，它逼模型"处处都要覆盖"；反过来最小化 $\mathrm{KL}(\text{模型} \,\|\, \text{目标})$，模型会"挑一个峰钻进去"。这一个不对称，解释了 SFT 与 RLHF 行为上的很多差异。
> **唤醒标签**：$H = -\sum p\log p$ · 交叉熵 = 熵 + KL · MLE ⇔ 最小化前向 KL · 覆盖模式 vs 寻找模式 · 困惑度 $e^{H}$ · 温度改熵 · $p - y$ · bits per byte

---

## 1. 痛点与钩子：如果没有它，世界会怎样？

几个每天都会遇到的问题：

- 预训练 loss 卡在 1.8 不动了，是模型不行，还是已经接近数据本身的极限？
- 两个模型的困惑度一个 6.1、一个 7.3，能直接说前者更好吗？它们的 tokenizer 不一样。
- SFT 之后模型什么都会说一点、偶尔胡说；RLHF 之后模型更"稳"，但多样性明显下降。为什么？
- 调高温度，模型更有"创造力"；调低温度，回答更保守。温度到底改了什么？

这些问题共用一套语言：熵、交叉熵和 KL 散度。

---

## 2. 第一性原理：看透它的几何 / 物理直觉

### 2.1 熵：平均的意外程度

一个结果出现的概率是 $p$，它带来的"意外"是 $-\log p$：越罕见越意外，必然发生的事没有任何意外。熵是意外的期望：

$$
H(p) = -\sum_x p(x) \log p(x)
$$

用以 2 为底的对数，单位是比特，也是给这个分布的样本编码时每个符号平均至少要用的比特数。$K$ 个结果均匀分布时熵最大，为 $\log K$；完全确定时熵为 0。

### 2.2 交叉熵与 KL：用错的分布要多花多少比特

真实分布是 $p$，你却按模型 $q$ 去编码（或去预测），平均意外是交叉熵：

$$
H(p, q) = -\sum_x p(x) \log q(x) = H(p) + \underbrace{\sum_x p(x) \log \frac{p(x)}{q(x)}}_{\mathrm{KL}(p \,\|\, q)\ \ge\ 0}
$$

多出来的那部分就是 KL 散度：**因为用了错的分布而多付的代价**。KL 永远非负，只在 $q = p$ 时为 0。所以交叉熵的下界是数据的熵，不是 0：自然语言本身有不确定性，"今天天气很"后面接"好"还是"热"，没有标准答案。

### 2.3 极大似然就是最小化前向 KL

训练语言模型时，我们最大化训练数据的平均对数似然。数据量足够大时，样本平均趋向期望：

$$
\frac{1}{N}\sum_{i} \log q_\theta(x^{(i)}) \;\to\; \mathbb{E}_{x \sim p}[\log q_\theta(x)] = -H(p, q_\theta) = -H(p) - \mathrm{KL}(p \,\|\, q_\theta)
$$

$H(p)$ 与 $\theta$ 无关。所以**最大化似然 ⇔ 最小化交叉熵 ⇔ 最小化 $\mathrm{KL}(p \,\|\, q_\theta)$**。三种说法是同一件事。

### 2.4 KL 的方向

KL 不对称：$\mathrm{KL}(p \,\|\, q) \ne \mathrm{KL}(q \,\|\, p)$。当模型 $q$ 的表达能力不够，没法完全拟合 $p$ 时，两个方向会给出截然不同的近似。

```academy-lab
0.5
```

把两峰拉开：

- **前向 KL** $\mathrm{KL}(p \,\|\, q)$ 在 $p$ 有质量的地方计分。只要 $q$ 在某个峰上接近 0，$\log(p/q)$ 就爆炸。所以 $q$ 宁可摊开、把质量放进两峰之间的低谷，也要盖住每一个峰。这叫**覆盖模式**（mode-covering）。
- **反向 KL** $\mathrm{KL}(q \,\|\, p)$ 在 $q$ 有质量的地方计分。$q$ 只要不把质量放到 $p$ 很小的地方就行，于是它缩进一个峰里。这叫**寻找模式**（mode-seeking）。

SFT 和预训练最小化前向 KL：模型要覆盖示范数据里的所有模式，连少见的、低质量的说法也学一点。RLHF 的 KL 正则项是 $\mathrm{KL}(\pi_\theta \,\|\, \pi_{\text{ref}})$，再加上奖励把策略推向高分区，整体行为更接近寻找模式：回答更稳，多样性下降（→ 2.1、2.2）。

### 2.5 温度、熵与困惑度

语言模型输出 logits $z$，概率是 $\mathrm{softmax}(z / T)$。温度 $T$ 不改变排序，只改变分布的"尖锐程度"，也就是熵。困惑度 $e^{H}$ 可以读成**等效候选数**：困惑度 4.6，相当于模型在 4.6 个词里均匀地猜。

```academy-lab
0.5-temperature
```

注意两个极端：$T \to 0$ 时分布退化成 argmax，熵趋向 0；可一旦真实的词不是最高分那个，交叉熵会随 $1/T$ 增长。$T$ 很大时分布趋向均匀，困惑度趋向候选词的数量。

## 3. 承重墙推导：重新捡起核心数学

### Step 1　交叉熵分解与 KL 非负

分解只是把 $\log q = \log p - \log(p/q)$ 代入：

$$
H(p, q) = -\sum p\log p + \sum p \log\frac{p}{q} = H(p) + \mathrm{KL}(p \,\|\, q)
$$

KL 非负来自 Jensen 不等式（$\log$ 是凹函数）：

$$
-\mathrm{KL}(p \,\|\, q) = \sum p \log\frac{q}{p} \le \log \sum p \cdot \frac{q}{p} = \log \sum q = 0
$$

等号当且仅当 $q/p$ 处处为常数，即 $q = p$。

### Step 2　softmax 交叉熵的梯度

logits $z$，$q = \mathrm{softmax}(z)$，真实分布 $p$（one-hot 时就是标签）：

$$
L = -\sum_i p_i \log q_i = -\sum_i p_i z_i + \log\sum_j e^{z_j}
\quad\Rightarrow\quad
\frac{\partial L}{\partial z_k} = -p_k + q_k
$$

梯度是"模型分布减真实分布"（→ 0.2 §3）。知识蒸馏时把 $p$ 换成老师的软分布，公式不变。

### Step 3　为什么前向与反向 KL 行为不同

前向：$\mathrm{KL}(p \,\|\, q) = \mathbb{E}_p[\log p - \log q]$。在 $p > 0$、$q \to 0$ 的地方，$-\log q \to \infty$：**漏掉任何一个模式都会被重罚**。

反向：$\mathrm{KL}(q \,\|\, p) = \mathbb{E}_q[\log q - \log p]$。在 $q > 0$、$p \to 0$ 的地方，$-\log p \to \infty$：**把质量放到 $p$ 没有的地方会被重罚**；而 $q$ 漏掉 $p$ 的一个峰，几乎不受惩罚。

另外，在高斯族里最小化前向 KL 的解就是矩匹配：$q$ 的均值、方差等于 $p$ 的均值、方差。

### Step 4　KL 正则下的最优策略

后训练的核心目标（→ 2.3）：

$$
\max_\pi\; \mathbb{E}_{y \sim \pi}[r(y)] - \beta\, \mathrm{KL}(\pi \,\|\, \pi_{\text{ref}})
$$

把目标改写成 $-\beta\,\mathrm{KL}\big(\pi \,\|\, \pi_{\text{ref}} e^{r/\beta} / Z\big) + \beta\log Z$，其中 $Z = \sum_y \pi_{\text{ref}}(y) e^{r(y)/\beta}$。由 Step 1 的 KL 非负，最优解是

$$
\pi^*(y) = \frac{1}{Z}\, \pi_{\text{ref}}(y)\, e^{r(y)/\beta}
$$

参考分布被奖励按指数重新加权，$\beta$ 起的作用和温度一样。DPO 就是把这个闭式解反过来，用策略的对数比表示奖励（→ 2.4）。

### Step 5　困惑度与跨 tokenizer 比较

困惑度 = $\exp(\text{每 token 平均交叉熵})$。同一段文本，词表不同的 tokenizer 切出的 token 数不同，每 token 的 loss 不可比。可比的是**每字节比特数**：

$$
\text{bits per byte} = \frac{\text{总 loss（nats）}}{\text{总字节数} \times \ln 2}
$$

它衡量的是"压缩这段文本平均每字节要几比特"，与怎么切分无关。

## 4. 极简代码锚点（PyTorch）

```python
import torch, torch.nn.functional as F

def entropy(logits):
    logp = F.log_softmax(logits, -1)
    return -(logp.exp() * logp).sum(-1)

# 1. 交叉熵 = 熵 + KL
p = torch.tensor([0.5, 0.3, 0.2])                     # "数据分布"
z = torch.tensor([1.0, 0.2, -0.5], requires_grad=True)
logq = F.log_softmax(z, -1)
H_p = -(p * p.log()).sum()
CE = -(p * logq).sum()
KL = (p * (p.log() - logq)).sum()
assert torch.allclose(CE, H_p + KL)

# 2. softmax 交叉熵的梯度就是 q − p
CE.backward()
assert torch.allclose(z.grad, logq.exp() - p)

# 3. 用策略自己的样本估计 KL(π ‖ π_ref)：k1 无偏但可能为负，k3 无偏且非负
def kl_estimators(logp_pi, logp_ref):
    log_ratio = logp_ref - logp_pi                     # log(π_ref / π)，在 y ~ π 上计算
    k1 = -log_ratio
    k3 = log_ratio.exp() - 1 - log_ratio               # GRPO 使用的形式
    return k1.mean(), k3.mean()

# 4. 温度只缩放 logits：排序不变，熵变
logits = torch.tensor([3.2, 2.6, 2.1, 1.7, 1.2, 0.4, -0.5, -1.8])
for T in (0.3, 1.0, 3.0):
    H = entropy(logits / T)
    print(T, H.item(), H.exp().item())                 # 熵与困惑度（等效候选数）

# 5. 每字节比特数：跨 tokenizer 可比
def bits_per_byte(total_loss_nats, text):
    return total_loss_nats / (len(text.encode("utf-8")) * torch.log(torch.tensor(2.0)))
```

## 5. 实战直觉、避坑与面试深挖

**2026 前沿现状**
- **RL 训练里的 KL 都是采样估计的**。完整计算 $\mathrm{KL}(\pi \,\|\, \pi_{\text{ref}})$ 要对所有可能的回答求和，做不到。实际做法是在策略自己采出的 token 上估计。GRPO（DeepSeekMath）用 $\frac{\pi_{\text{ref}}}{\pi} - \log\frac{\pi_{\text{ref}}}{\pi} - 1$ 这个无偏、非负的估计量，把它直接加进损失，而不是像 PPO 那样塞进奖励里（→ 2.5）。
- **蒸馏开始讲究 KL 的方向**。传统知识蒸馏最小化前向 KL（学生覆盖老师的全部分布）；MiniLLM 等工作发现，对生成任务改用反向 KL、并在学生自己采出的序列上计算（on-policy 蒸馏），学生不会把概率浪费在老师分布的长尾上，生成更稳（→ 2.1）。
- **跨模型比较压缩能力用每字节比特数**。不同模型的 tokenizer、词表大小差别很大，每 token 困惑度已经不能直接比较。比较基座模型的"语言建模能力"时，越来越多地报告 bits per byte。

**与工程 / 应用的连接**
- **loss 降不下去时先估数据熵**。用更大的模型或更长的训练在同一份数据上跑，loss 下降趋缓的位置大致就是数据熵加上模型容量带来的残余 KL。Scaling Law 里那个不可约的常数项，就是数据熵（→ 6.1）。
- **logprob 能当置信度，但要校准**。预训练模型的 token 概率通常校准得不错；RLHF 之后分布被推向寻找模式，模型往往过度自信，用 logprob 判断"它确定吗"之前要先在验证集上校准（→ 9.3）。
- **温度、top-p 都在改熵**。温度对整个分布做缩放；top-p 截掉长尾再重新归一化。两者都会降低熵、减少胡言乱语，代价是多样性下降（→ 7.1）。

**常见误区 / 反直觉点**
1. **"训练 loss 应该能降到 0"** ✗：交叉熵的下界是数据熵。loss 接近 0 通常意味着模型背下了训练集。
2. **"KL 是一种距离"** ✗：它不对称，也不满足三角不等式。方向选错，模型行为会完全不同。
3. **"困惑度低的模型一定更好"** ✗：要在同一个 tokenizer、同一份测试集上比较；跨 tokenizer 时用 bits per byte。
4. **"温度越高越有创造力"** ✗：温度只是把分布压平，低质量的候选也被抬高。高温带来的多样性里，很大一部分是噪声。

**高频深挖题**
- **Q1：为什么说极大似然训练等价于最小化 KL 散度？是哪个方向的 KL？这带来什么行为？**
  思路：平均对数似然 → 期望 → $-H(p) - \mathrm{KL}(p \,\|\, q_\theta)$ → 前向 KL → 漏掉数据的任何模式都会被重罚 → 覆盖模式：模型会把概率分给数据里所有出现过的说法，包括低质量的 → 这就是 SFT 之后模型"什么都学一点"、需要偏好对齐去收窄的原因。
- **Q2：RLHF 里 KL 正则的作用是什么？如果 β 设成 0 会怎样？**
  思路：最优解 $\pi^* \propto \pi_{\text{ref}} e^{r/\beta}$ → β 控制离参考模型多远 → β → 0 时策略把全部概率压到奖励模型给分最高的回答上，奖励模型的漏洞被放大，出现 reward hacking 与语言退化（→ 2.2）→ β 太大则学不到东西。
- **Q3：同一份测试集上，模型 A 困惑度 6.1、B 困惑度 7.3，但 B 的词表是 A 的两倍。哪个模型语言建模能力更强？**
  思路：困惑度按 token 计，词表更大的 tokenizer 每个 token 覆盖更多字节，每 token 的预测更难 → 不能直接比 → 换算成 bits per byte：总 loss（nats）÷（字节数 × ln 2）→ 比较这个数。
