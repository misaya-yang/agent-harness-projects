# 1.5 FlashAttention 与 IO 感知：算得更多，反而更快

> **一句话核心直觉**：标准注意力慢，不是因为 L² 次乘加，而是因为夹在两次矩阵乘中间的 softmax 逼着你把 L×L 矩阵在显存里写一遍、读一遍。FlashAttention 用分块 + online softmax 让这个矩阵只在片上短暂存在，宁可反向时重算也不搬运，结果是**精确的**。
> **唤醒标签**：HBM vs SRAM · tiling · online softmax（running max / sum）· 反向重算与 logsumexp · FA2 / FA3 / FA4

前置：5.1 §2（屋脊线）、§3 Step 2（激活显存的平方项）。

---

## 1. 痛点与钩子：如果没有它，世界会怎样？

5.1 算过：7B 模型、序列 8K，不重算时注意力的 L×L 矩阵要吃 **344 GB** 激活显存，是其余全部激活的 9 倍多。显存只是表象，更要命的是速度。标准实现的数据流：

1. 计算 $S = QK^\top$，把 $L \times L$ 的分数矩阵写入 HBM。
2. 从 HBM 读出 $S$，按行做 softmax，把同样大小的概率矩阵 $P$ 写回 HBM。
3. 从 HBM 读出 $P$，计算 $O = PV$。

仅一张 BF16 分数矩阵，每个头在 4,096、8,192、16,384 token 下就分别占 32、128、512 MiB。

d=128、L=8K 时，每个头算 $4L^2d$ FLOPs，却要搬约 $8L^2$ 字节（S、P 各写一次读一次，BF16），**算术强度 ≈ d/2 = 64**，远在 H100 的屋脊（295）左边。注意力明明是两个大矩阵乘，却被中间那一步 softmax 拖成了带宽受限的算子。

**反直觉现象**：FlashAttention 反向时把 S 和 P 重新算一遍，总 FLOPs 更多，却快 2–4 倍。

## 2. 第一性原理：看透它的几何 / 物理直觉

### 2.1 仓库与工作台

| 存储位置 | 典型容量 | 数据访问 |
|---|---|---|
| HBM（仓库） | 80–288 GB | 约 3.35–22 TB/s，取决于 GPU |
| 片上 SRAM（工作台） | 每 SM 约 200 KB 量级 | 带宽比 HBM 高一个数量级 |
| 寄存器 | 分给每个线程的空间更小 | 最快 |

只要中间结果能留在工作台上，就不用来回跑仓库。常规矩阵乘的输出按块生成，逐行 softmax 却需要跨块知道最大值和指数和。拆成独立算子时，前一个算子先把分数写回 HBM，下一个算子再读入整行。

### 2.2 online softmax：边看边改账

把一行切成块，每次只看一块。维护两个数：到目前为止的最大值 m、以 m 为参照的指数和 l，外加一个以 m 为参照的部分输出 O。来了新块：如果出现了更大的值，就把之前的 l 和 O 整体**换算到新的参照**上，再加上新块的贡献。

> 类比：用一种不断升值的货币记账。每次换"计价单位"，就把旧账本一次性乘上汇率 $e^{m_{\text{old}}-m_{\text{new}}}$。账本永远只有一页，最后除以总额即可。

对固定的 Q 块，扫描各 K/V 块。每次在 SRAM 临时计算分数和指数权重，更新 $(m, l, O)$ 后丢弃临时矩阵。扫完才把 $O_i / l_i$ 写回一次。

### 2.3 反向：存一个数，换一整个矩阵

前向只存 O 和每行的 logsumexp（L 个数），不存 P（L² 个数）。反向时用 Q、K 分块重算 S，再用 logsumexp 直接还原 P。**用 FLOPs 换字节**：在屋脊左边，这笔交易永远划算。

### 2.4 四代 FlashAttention：一直在追"新瓶颈"

| 代 | 硬件 | 追的瓶颈 | 关键手段 |
|---|---|---|---|
| FA1（2022） | A100 | HBM 读写 | 分块 + online softmax + 反向重算 |
| FA2（2023） | A100 | 非矩阵乘运算、并行度 | 沿序列维并行、减少 rescale 等标量运算、warp 分工 |
| FA3（2024） | H100 | 异步硬件没被吃满 | TMA / WGMMA 异步、warp 专精化、softmax 与矩阵乘 ping-pong 重叠、FP8 |
| FA4（2026） | B200 | **exp 单元与共享内存** | 软件模拟 exp、条件重标定、2-CTA MMA / tensor memory、确定性模式 |

主线和 5.1 的屋脊表是同一个故事：**硬件各单元不等比例扩张，瓶颈就不断换位置**。

## 3. 承重墙推导：重新捡起核心数学

### Step 1　为什么 FlashAttention 把注意力搬到了屋脊右边

| | FLOPs（每头） | HBM 字节 | 算术强度 | d=128、L=8K |
|---|---|---|---|---|
| 标准实现 | $4L^2d$ | $\approx 8L^2$（S、P 各写读一次） | $d/2$ | 64，带宽受限 |
| FlashAttention | $4L^2d$ | $\approx 8Ld$（读 Q、K、V，写 O） | $L/2$ | 4096，算力受限 |

**物理含义**：FLOPs 没变，搬运量从 $O(L^2)$ 降到 $O(Ld)$。严格的 IO 复杂度是 $\Theta(L^2d^2/M)$（M 为 SRAM 大小），但量级直觉看这张表就够了。

### Step 2　online softmax 的递推（四行）

对第 j 个 K/V 块，分数 $S_j = QK_j^\top/\sqrt d$：

$$
\begin{aligned}
m^{\text{new}} &= \max\!\big(m,\ \text{rowmax}(S_j)\big) \\
\tilde P_j &= \exp\!\big(S_j - m^{\text{new}}\big) \\
l^{\text{new}} &= e^{\,m - m^{\text{new}}}\, l + \text{rowsum}(\tilde P_j) \\
O^{\text{new}} &= e^{\,m - m^{\text{new}}}\, O + \tilde P_j V_j
\end{aligned}
\qquad\Rightarrow\qquad \text{输出 } O / l
$$

**为什么精确**：softmax 对参照值不变，$\text{softmax}(x)_i = e^{x_i-c}/\sum_k e^{x_k-c}$ 对任意 c 成立。$e^{m-m^{\text{new}}}$ 只是把旧账从参照 m 换算到 $m^{\text{new}}$，没有丢任何信息。

### Step 3　FA4 的条件重标定：max 只为数值安全而存在

由 Step 2 的不变性：**最终结果与用哪个参照值无关，只要指数不溢出**。所以没必要每次出现更大值就换参照。FA4 只在新最大值超过当前参照足够多、真会威胁数值稳定时才重标定，其余时候继续用旧参照，最后统一除以 l。

- **核心 Trick**：把"正确性"和"数值安全"拆开。正确性由不变性保证，max 只负责防溢出，于是它可以"懒"。
- 本篇代码里阈值取 τ=8（指数最大放大 $e^8 \approx 3000$，FP32 绰绰有余）：随机数据上，去掉首块初始化后，重标定次数从约 1.9 万次降到 232 次，输出与标准注意力一致。

### Step 4　反向不存 P：$D_i$ 这一项是关键

softmax 的反向：

$$
dS_{ij} = P_{ij}\Big(dP_{ij} - \sum_k P_{ik}\, dP_{ik}\Big),\qquad dP_{ij} = dO_i \cdot V_j
$$

括号里的求和看似需要整行 P，但：

$$
\sum_k P_{ik}\, dP_{ik} = \sum_k P_{ik}\,(dO_i \cdot V_k) = dO_i \cdot \underbrace{\sum_k P_{ik} V_k}_{O_i} = \text{rowsum}(dO_i \circ O_i) =: D_i
$$

- **核心 Trick**：一个需要整行 P 的量，被结合律改写成只需要 $O_i$ 和 $dO_i$ 的点积。反向因此也能逐块进行：先算每行的 $D_i$，再分块重算 $P_{ij} = \exp(S_{ij} - \text{LSE}_i)$。
- **去掉它会怎样**：要么存 P（回到 $O(L^2)$ 显存），要么反向时扫两遍。

### Step 5　为什么 Blackwell 上瓶颈变成了 exp

每个分数元素要做 1 次 exp，对应 $4d$ 次矩阵乘 FLOPs（QKᵀ 与 PV 各 2d）。d=128 时，1 次 exp 配 512 FLOPs。B200 的张量核吞吐比 H100 翻倍，exp 单元和共享内存带宽却没跟上。FA4 的屋脊分析显示，典型注意力负载里**共享内存流量和 exp 的耗时比矩阵乘本身多 25–60%**。对策：

- **软件模拟 exp**：在 FMA 单元上做多项式近似（指数拆成整数部分 + 小数部分，整数部分直接改浮点指数位），把一部分 exp 从专用单元分流出去。
- **条件重标定**（Step 3）：直接砍掉大部分非矩阵乘运算。
- **2-CTA MMA + tensor memory**：减少反向的共享内存流量和 atomic add。

## 4. 极简代码锚点（PyTorch）

教学版前向：省略了 Q 分块和因果掩码，只保留 K/V 流式扫描与两种重标定策略。已对拍标准 softmax 注意力。

```python
import torch

def flash_attn_fwd(q, k, v, Bc=64, lazy_tau=None):
    """q, k, v: (B, H, L, d)。lazy_tau=None → FA1–3 式每块重标定；
       lazy_tau=8.0 → FA4 式条件重标定。返回 O 与 logsumexp（反向要用）。"""
    B, H, L, d = q.shape
    O = torch.zeros_like(q)                                   # (B, H, L, d) 以 m 为参照的部分输出
    m = torch.full((B, H, L, 1), float("-inf"), dtype=q.dtype)  # 当前参照值
    l = torch.zeros(B, H, L, 1, dtype=q.dtype)                # 以 m 为参照的指数和
    for j in range(0, L, Bc):                                 # 流式扫 K/V 块（真实 kernel 中在 SRAM）
        kj, vj = k[:, :, j:j+Bc], v[:, :, j:j+Bc]             # (B, H, Bc, d)
        s = (q @ kj.transpose(-1, -2)) * d ** -0.5            # (B, H, L, Bc) 只在片上存在
        m_blk = s.amax(-1, keepdim=True)                      # (B, H, L, 1)
        if lazy_tau is None:
            m_new = torch.maximum(m, m_blk)                   # 每次出现更大值都换参照
        else:                                                 # 只在超出 tau 时换：正确性不依赖 m
            m_new = torch.where(m_blk > m + lazy_tau, m_blk, m)
        alpha = torch.exp(m - m_new)                          # 旧账换算到新参照的"汇率"
        p = torch.exp(s - m_new)                              # (B, H, L, Bc)
        l = alpha * l + p.sum(-1, keepdim=True)
        O = alpha * O + p @ vj                                # (B, H, L, d)
        m = m_new
    return O / l, m + torch.log(l)                            # 输出 + 每行 logsumexp (B, H, L, 1)
```

**对照看维度**：循环里出现的最大张量是 `(B, H, L, Bc)`，从来没有 `(B, H, L, L)`。这就是"L×L 矩阵只在片上短暂存在"在张量上的样子。

## 5. 实战直觉、避坑与面试深挖

**2026 前沿现状**
- **FA4（2026 年 3 月，MLSys 2026）**：在 B200 BF16 上最高约 1605 TFLOPs/s（71% 利用率），比 cuDNN 快至多 1.3 倍、比 Triton 快 2.4 倍；全部用 Python 内嵌的 CuTe-DSL 实现。它还提供了**开销很小的确定性执行模式**，明确是为了强化学习训练的可复现性（→ 2.7 训推不一致）。
- **4-bit 注意力**：NVFP4 已经覆盖权重、激活、KV cache 和注意力本身；KV cache 与注意力被 NVIDIA 列为 FP4 最难啃的两处。DeepSeek-V4 的 lightning indexer 直接用 FP4 算注意力分数。精度越低，exp 和 rescale 这些"非矩阵乘"部分的相对占比就越高，FA4 的问题只会更突出。
- **kernel 跟着架构走**：MLA 吸收后是头维 576 的 MQA（→ 1.3），CSA/DSA 需要 top-k gather 后的稀疏注意力（→ 1.6）。2026 年"写注意力 kernel"已经不是一个算子，而是一族。

**与工程 / 应用的连接**
- **TTFT（首 token 延迟）就是 prefill 注意力**。142k 前缀的 Agent 轮次，冷启动 prefill 是纯算力活，FA 的利用率直接决定首 token 要等多久；prefix cache 命中则跳过这部分。
- **"精确"不等于"逐位相同"**。分块顺序、split-KV、反向的 atomic add 都会改变浮点累加顺序，同一个 prompt 在不同 batch 大小、不同 kernel 下可能得到略有差异的 logits，temperature=0 也会分叉。对应用侧这是"偶发不可复现"；对 RL 训练这是训练端与推理端 logprob 对不上的来源之一。这就是 FA4 专门做确定性模式的原因。
- **decode 阶段的注意力是另一种问题**。decode 时只有 1×L 的分数行，不存在 L×L 矩阵要躲；它的瓶颈是读 KV（→ 1.3），FA 式 kernel 在这里的收益主要来自沿 KV 长度切分并行（split-KV / Flash-Decoding），而不是 IO 节省。

**常见误区 / 反直觉点**
1. **"FlashAttention 是一种近似注意力"** ✗：数学上精确，差异只来自浮点累加顺序。近似的是稀疏或线性注意力。
2. **"FlashAttention 降低了注意力的复杂度"** ✗：FLOPs 仍是 $O(L^2d)$，反向因重算还更多。它降的是 HBM 访问量（$O(L^2) \to O(Ld)$）和显存（$O(L^2) \to O(L)$）。长上下文下省 FLOPs 只能靠改架构（→ 1.6）。
3. **"online softmax 每次都必须更新 max"** ✗：max 只为防溢出而存在，正确性由平移不变性保证。FA4 正是利用这一点砍掉了大部分重标定。

**高频深挖题**
- **Q1：online softmax 为什么是精确的？FA4 为什么可以跳过大部分重标定？**
  思路：写出平移不变性 → 说明 $e^{m-m^{\text{new}}}$ 是换参照、不丢信息 → 推出参照值可以是任意不溢出的数 → 所以只在超出阈值时才换。加分项：说出 Blackwell 上 exp 单元成为瓶颈，这是"为什么现在才这么做"的硬件原因。
- **Q2：FlashAttention 反向为什么不用存 P？$D_i$ 这一项怎么来的？**
  思路：前向只存 logsumexp，反向分块重算 $P_{ij} = \exp(S_{ij} - \text{LSE}_i)$ → softmax 反向需要 $\sum_k P_{ik} dP_{ik}$ → 用 $dP_{ik} = dO_i \cdot V_k$ 和结合律把它化成 $dO_i \cdot O_i$ → 一个 O(d) 的点积替代了整行 P。最后补一句：这是"用 FLOPs 换字节"，在屋脊左边永远划算。
