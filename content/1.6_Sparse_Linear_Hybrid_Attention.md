# 1.6 稀疏 / 线性 / 混合注意力：选择还是压缩

> **一句话核心直觉**：降低长上下文成本只有两条路。**选择**：只看一部分 token，保留精确检索，但全量 KV 照样要存。**压缩**：把历史压成一个固定大小的状态，存储降为常数，但精确检索会受损。2026 年没有赢家通吃：Qwen3.5 用 3:1 的线性混合，Kimi K3 用 KDA + MLA，DeepSeek-V4 用压缩 + 稀疏选择，MiniMax M2 坚持全注意力。
> **唤醒标签**：线性注意力 = RNN · delta rule · Gated DeltaNet / KDA · 混合比例 3:1 · DSA 的 lightning indexer · indexer 自身的成本

前置：1.3（KV cache 三轴）、5.1 §3 Step 3（长上下文下注意力占算力的大头）。

---

## 1. 痛点与钩子：如果没有它，世界会怎样？

5.1 算过：7B 模型在 128K 上下文训练时，注意力占总 FLOPs 的 71%；1.3 算过：KV cache 在长上下文下比权重还大。百万 token 的 Agent 时代，全注意力的平方成本绕不过去。

可"高效注意力"的落地远比论文里难。MiniMax 在 M2 发布后专门写了一篇文章解释为什么**退回全注意力**：在真实的工业级系统里，高效注意力离确定性地打败全注意力还有一段距离；真正的瓶颈不在架构设计，而在评测的局限，以及线性和稀疏注意力远不如全注意力成熟的基础设施。

与此同时，Qwen3.5、Kimi Linear / K3 都在用线性注意力混合架构，Kimi Linear 甚至声称在公平对比下首次全面超过了全注意力。**同一个问题，一线团队给出了相反的答案。** 本篇要讲清楚的，是这个分歧背后的取舍。

## 2. 第一性原理：看透它的几何 / 物理直觉

### 2.1 两条路

| 方法 | 存储 | 每步主注意力读取 | 查询能访问什么 |
|---|---|---|---|
| 全注意力 | $O(L)$ 的 KV | $O(L)$ | 全部历史 token 的独立条目 |
| 稀疏选择 | $O(L)$ 的 KV | $O(k)$，$k \ll L$ | 轻量打分器选中的条目 |
| 序列压缩 | $O(L/m)$ | $O(L/m)$ 或 $O(k)$ | 每组 token 的压缩条目 |
| 线性注意力 | $O(1)$ 的状态，大小为 $d \times d$ | $O(1)$ | 从共享状态中读出键值关联，存在容量上限 |

### 2.2 线性注意力就是一个 RNN

去掉 softmax 之后，注意力可以用结合律重排：

$$
o_t = \sum_{i\le t}(q_t^\top k_i)v_i
    = \left(\sum_{i\le t}k_i v_i^\top\right)^\top q_t
    = S_t^\top q_t
$$

每来一个 token，往 $d \times d$ 的状态矩阵 $S_t$ 加一个外积 $k_t v_t^\top$。

- 所有历史被压进一个固定大小的矩阵 S。decode 时每步代价是常数，不再随上下文增长。
- 代价同样来自"固定大小"：**d×d 的状态最多可靠地存下约 d 组键值关联**，再多就开始互相干扰。

### 2.3 delta rule：只写"还不知道的部分"

朴素线性注意力粗暴累加外积特征 $k_t v_t^\top$。若同一个 key 连续写入两次，读取时取出的将是两次写入 value 的绝对和，发生记忆串扰与数值漂移。delta rule 将隐藏状态 $S$ 视为在线线性回归器，先用当前记忆预测新键的取值，**只把未被解释的预测残差误差写进状态**。即使两个键向量存在几何夹角，也能有效限制相互污染。

在下方互动实验中，你可以配置【两键的内积】（例如 0.6）、【新键写入次数】并切换【读取哪个键】（先写的键或新键）：
- 观察折线图中两种记忆写入规则的输出轨迹：在朴素累加规则下，随着新键反复写入，与其非正交的旧键读数发生线性发散漂移，初始存储的原值 1 被严重覆盖扭曲；
- 对比【delta rule】：由于每一步仅针对预测误差做单步梯度修正，其在新键写入方向上迅速平滑收敛至目标值 −1，同时最大程度保护了正交投影方向上的旧键记忆。

容量上限两者都逃不掉：同一个模拟里，存 8 组时两者的取回质量都在 0.95 左右，存 512 组（状态维度的 8 倍）时都跌到 0.33 以下。门控（Gated DeltaNet、KDA）再加一个遗忘因子，让模型主动清理不再需要的记忆。

### 2.4 为什么是混合，为什么是 3:1

线性层负责便宜地处理局部和流式信息，少数全注意力层负责精确检索。Qwen3-Next 的 48 层是 12 组"3 个 Gated DeltaNet + 1 个门控注意力"；Kimi Linear 是 3 个 KDA 层配 1 个 MLA 层，而且 MLA 层不用位置编码（→ 1.2）。2026 年一份 RL 后训练的实践总结里写道：3:1 是多个团队独立得到的消融甜点，1:1 浪费 KV cache，7:1 损失召回。

### 2.5 稀疏选择：先用便宜的打分器挑，再精算

DeepSeek-V3.2 的 DSA 用一个很轻的 lightning indexer 给所有历史 token 打分，选出 top-k（通常 k=2048），只对这些 token 做真正的注意力。读取和计算从 O(L) 降到 O(k)，但存储不变（→ 1.3 误区 3）。

**它还有一个"稠密的尾巴"**：indexer 自己要给全部历史打分。NVIDIA 的研究指出，即使在 DeepSeek-V4 的 CSA 层里已经做了 4 倍的序列压缩，在 512K 到 1M token 时，indexer 仍然是 decode 延迟的主要来源之一。

### 能不能把遗忘和键冲突拆开测？

只存两个正交键。第一个 token 用键 $(1,0)$ 写入数值 1；此后不断用 $(0,1)$ 写入 0，每一步都用第一个键查询。后续写入对第一个键的投影为零，因此这次实验排除了跨键的特征干涉与空间串扰。经 $n$ 次更新，初始信号的读出值精确衰减为 $\alpha^n$。若真实模型发生长程记忆失真，将干扰键替换为正交键能提供明确的归因线索：若误差依然存在，即可断定根源在于乘性遗忘门的过度衰减或 FP16/BF16 的下溢截断。

在下方互动实验中，拖动【相隔的更新步数】滑块（0 到 40 步）：
- 观察两条几何衰减曲线：蓝色实线代表遗忘门 $\alpha=0.9$（每步保留 90%），在第 7 步处读出值便跌破一半（0.478）；绿色实线代表 $\alpha=0.99$（每步保留 99%），即便相隔 20 步仍能保留 81.8% 的记忆强度；

## 3. 承重墙推导：重新捡起核心数学

### Step 1　线性注意力的结合律

$$
\underbrace{\big(\phi(Q)\phi(K)^\top\big)V}_{O(L^2 d)}
= \underbrace{\phi(Q)\big(\phi(K)^\top V\big)}_{O(L d^2)},
\qquad
S_t = S_{t-1} + \phi(k_t)v_t^\top,\quad o_t = S_t^\top\phi(q_t)
$$

softmax 阻止了这种重排：$e^{q\cdot k}$ 不能分解成 q 的函数与 k 的函数之积。去掉 softmax（或用特征映射近似），注意力就变成了一个可以并行训练、常数代价推理的 RNN。

### Step 2　delta rule 是在线回归

把状态 S 看作一个线性记忆，目标是让 $S^\top k_t \approx v_t$。对 $\tfrac12\|S^\top k_t - v_t\|^2$ 做一步学习率为 $\beta_t$ 的梯度下降：

$$
S_t = S_{t-1} + \beta_t\,k_t\big(v_t - S_{t-1}^\top k_t\big)^\top
$$

再加遗忘门 $\alpha_t$（Gated DeltaNet）：

$$
\tilde S_{t-1} = \alpha_t S_{t-1},\quad e_t = v_t - \tilde S_{t-1}^\top k_t,\quad S_t = \tilde S_{t-1} + \beta_t\,k_t e_t^\top,\quad y_t = S_t^\top q_t
$$

**物理含义**：每来一个 token，记忆先整体衰减一点（遗忘），再只把"预测错了多少"写进去（纠错）。KDA 把 $\alpha_t$ 做成更细粒度的门控，更有效地利用有限的 RNN 状态。

### Step 3　容量上限

d×d 的状态最多只能精确存下 d 组正交的键值关联；key 不正交或数量超过 d，取回时必然互相干扰。这是信息量的硬约束，不是训练不够。**所以纯线性模型在"大海捞针"式的精确检索上天然吃亏**，混合架构用少数全注意力层补上这块。

### Step 4　DSA 的打分与成本

$$
I_{t,s} = \sum_{j=1}^{H^I} w_{t,j}^I\cdot\mathrm{ReLU}\big(q_{t,j}^I\cdot k_s^I\big)
$$

- indexer 的头数少、维度低、用 ReLU 而非 softmax，可以跑在 FP8 甚至 FP4 上（V4 的 indexer 就用 FP4 计算）。单 token 代价 = O(L) 的轻量打分 + O(k) 的主注意力。
- L 足够大时，前一项仍然线性增长，这就是"稀疏注意力的稠密问题"。

### Step 5　混合架构的 KV 账

只有全注意力层有随长度增长的 KV。3:1 混合时，在每层缓存规格相同的前提下，KV 只剩全注意力模型的 1/4。Kimi Linear 报告 KV 用量最多减少 75%，在 1M 上下文下 decode 吞吐最高提升 6 倍。[Kimi Linear 技术报告](https://arxiv.org/abs/2510.26692)

## 4. 极简代码锚点（PyTorch）

朴素线性注意力、Gated DeltaNet 的递推形式（逐 token 循环，便于读懂；生产实现用分块并行 kernel），以及 DSA 式的 top-k 选择。已跑通，§2.3 的模拟用的就是前两个函数。

```python
import torch, torch.nn.functional as F

def linear_attn(q, k, v):                                    # q, k, v: (L, d)  单头
    S = k.new_zeros((k.shape[1], v.shape[1])); out = []
    for t in range(len(q)):
        S = S + torch.outer(k[t], v[t])                      # 盲目累加：同一个 key 写两次就混在一起
        out.append(S.T @ q[t])
    return torch.stack(out)                                  # (L, d)

def gated_delta(q, k, v, alpha, beta):                       # alpha, beta: (L,) 遗忘门与写入强度
    k = F.normalize(k, dim=-1)
    S = k.new_zeros((k.shape[1], v.shape[1])); out = []
    for t in range(len(q)):
        S = alpha[t] * S                                     # 先整体遗忘一点
        e = v[t] - S.T @ k[t]                                # 预测误差：只写"还不知道的部分"
        S = S + beta[t] * torch.outer(k[t], e)
        out.append(S.T @ q[t])
    return torch.stack(out)                                  # 状态始终是 (d, d)，与长度无关

def dsa_select(q_idx, k_idx, w, topk=2048):
    """q_idx: (H_I, d_I) 当前 token 的 indexer query；k_idx: (L, d_I) 历史 indexer key；w: (H_I,)"""
    scores = (w[:, None] * F.relu(q_idx @ k_idx.T)).sum(0)  # (L,) 轻量打分，但仍要扫全部历史
    return scores.topk(min(topk, len(scores))).indices       # 只对这些位置做真正的注意力
```

### 数值复算 · 能不能把遗忘和键冲突拆开测？

在同一个 Python 会话中先运行本节上方的实现，再运行以下算例。

```python
import torch
for gap in [0, 7, 20]:
    k = torch.tensor([[1., 0.]] + [[0., 1.]] * gap)
    q = torch.tensor([[1., 0.]]).repeat(len(k), 1)
    v = torch.zeros(len(k), 1)
    v[0] = 1
    values = []
    for alpha in [0.9, 0.99]:
        out = gated_delta(q, k, v, torch.full((len(k),), alpha), torch.ones(len(k)))
        assert abs(out[-1].item() - alpha**gap) < 1e-6
        values.append(out[-1].item())
    print(f"间隔={gap:2d}  {values[0]:.3f}  {values[1]:.3f}")
```

## 5. 实战直觉、避坑与面试深挖

**2026 前沿现状**
- **Qwen 主线全面转向线性混合**：Qwen3.5（2026 年 2 月发布，旗舰 397B-A17B）延续了 Qwen3-Next 的 3:1 Gated DeltaNet 混合骨架。一篇关于 Qwen3.8-Next 架构设计的论文报告，相比全注意力基线，GDN 混合模型在 9 个选定基准中的 8 个上更好，并在全注意力层中保留了 RoPE。
- **三家各走一条路**：Kimi K3 用 KDA 与 Gated MLA 混合；DeepSeek-V4 用 CSA / HCA 压缩加稀疏选择（→ 1.3）；MiniMax M2 坚持全注意力，并把线性注意力的开放问题列得很具体：低精度状态存储、前缀缓存、配合线性骨干的投机解码等。
- **新瓶颈：indexer 本身**：稀疏注意力把主注意力的读取降到了 O(k)，但打分器仍要扫全部历史。NVIDIA 2026 年的工作正尝试利用 indexer 自身的历史选择模式来减少打分。

**与工程 / 应用的连接**
- **线性层让 decode 成本与上下文长度脱钩**：Agent 的长会话里，线性层每步代价恒定，只有少数全注意力层的成本随长度增长。这改变了"长上下文到底多贵"的估算方式。
- **前缀缓存要重新设计**：全注意力的前缀缓存缓存的是 KV 块，可以按块复用；线性注意力缓存的是某个位置上的**状态快照**，只能在保存过快照的位置上复用，粒度和策略都不同。MiniMax 的文章也把缓存列为线性注意力尚未解决的问题之一。对依赖前缀缓存命中率的 Agent 应用来说，这是选模型时容易忽略的一点。
- **评测要覆盖精确检索**：线性混合模型在常规基准上可能和全注意力打平，却在多跳检索、长程精确引用上掉点。MiniMax 指出评测本身就是这条路线的最大瓶颈。

**常见误区 / 反直觉点**
1. **"线性注意力只是 softmax 注意力的近似"** ✗：它是一种不同的记忆模型（固定大小的 RNN 状态），有硬性的容量上限，不能简单地理解成"精度差一点的注意力"。
2. **"稀疏注意力省显存"** ✗：纯 top-k 选择只省读和算，KV 全量照存，还多了 indexer 的 key。省存储要靠压缩序列或换成线性层（→ 1.3）。
3. **"混合比例越偏向线性越好"** ✗：7:1 会损失召回，1:1 又浪费 KV。3:1 是多个团队独立得到的平衡点，但它依赖具体任务分布，不是普适常数。

**高频深挖题**
- **Q1：为什么现在主流是混合架构而不是纯线性注意力？3:1 这个比例怎么理解？**
  思路：线性注意力 = RNN，d×d 状态有容量上限，精确检索天然吃亏；delta rule 和门控提升了状态利用率，但突破不了上限 → 少数全注意力层负责精确检索，KV 只按这些层计 → 3:1 是"KV 成本"和"召回能力"之间的经验平衡点，太稀浪费、太密掉召回 → 补一句反例：MiniMax M2 退回全注意力，理由是评测和基础设施还不够成熟。
- **Q2：如果你的 Agent 产品依赖前缀缓存，换成线性混合模型要注意什么？**
  思路：全注意力缓存的是可分块复用的 KV，线性层缓存的是固定位置的状态快照 → 命中粒度变粗，需要在常见的分叉点（system prompt 末尾、工具定义之后）主动保存快照 → 线性层的 decode 成本与长度无关，长会话更便宜，但少数全注意力层仍需要 KV → 评测要专门覆盖长程精确检索。
