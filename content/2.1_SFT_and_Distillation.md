# 2.1 SFT 与蒸馏的本质：哪个方向的 KL

> **一句话核心直觉**：SFT 是在最小化"示范分布 → 模型"的**前向 KL**：哪里有示范，模型就必须在哪里放概率（mode-covering）。所以它学得快，也什么都学，包括格式、口癖，以及示范者知道而模型并不知道的东西。蒸馏是 SFT 的推广：从"学一个答案"到"学老师的整个分布"。**on-policy 蒸馏**再进一步：在学生自己会走的路上让老师逐 token 纠正，把 RL 的"自己采样"和 SFT 的"稠密信号"合在了一起。
> **唤醒标签**：前向 vs 反向 KL · loss mask 与聊天模板 · 曝光偏差 · 遗忘 · off-policy / on-policy 蒸馏 · 多教师合并

前置：2.3 §3 Step 5（KL 正则目标的三种关系）。本篇是 M2 的收尾：SFT 在流水线里最早，但在坐标系里最后才能看清。

## 1. 痛点与钩子：如果没有它，世界会怎样？

SFT 是一切后训练的起点：RLHF 和 DPO 的参考模型都是 SFT 模型。可它有三个经典的失败模式：

1. **教会模型"自信地编"**：拿更强模型的回答做 SFT，学生学到的是"用肯定语气陈述这些事实"。示范里有学生根本不知道的知识，SFT 也逼它照着说，这是幻觉的一个重要来源。
2. **曝光偏差**：训练时每一步都以"老师写的前缀"为条件，推理时却以"自己写的前缀"为条件。一旦偏离示范轨迹，模型就进入了从没训练过的状态，错误逐步累积。
3. **记忆而非泛化**：系统对比文本和视觉任务后，有研究把结论概括为"SFT 记忆、RL 泛化"。

把学生的表达能力限制为一个高斯分布。面对同一位双峰教师，两个方向的 KL 会给出怎样的拟合？

## 2. 第一性原理：看透它的几何 / 物理直觉

### 2.1 两个方向的 KL，两种性格

用 $p$ 表示教师分布，$q$ 表示学生分布。

| 方向 | 谁提供样本？ | 哪种情况代价最大？ | 学生表达受限时的倾向 |
|---|---|---|---|
| 前向 KL | 教师 $p$ | $p>0$ 处学生令 $q \to 0$，代价趋于无穷 | 尽量覆盖教师的多个高密度区域（mode-covering） |
| 反向 KL | 学生 $q$ | $q>0$ 处教师令 $p \to 0$，代价趋于无穷 | 尽量待在教师的高密度区域（mode-seeking） |

SFT 是前向 KL；RL 的 KL 正则目标、on-policy 蒸馏是反向 KL（→ 2.3）。**用哪个方向，决定了模型在"不确定"时的性格。**

### 2.2 loss mask：只对模型该说的话求梯度

| 聊天顺序 | 内容片段 | loss mask |
|---|---|---:|
| system | 系统提示 | 0 |
| user | 帮我写个函数 | 0 |
| assistant | `def f(): ...` | 1 |
| tool | 工具执行结果 | 0 |
| assistant | 后续答复 | 1 |

- 只对 assistant token 求梯度：system、user、工具返回都是条件（和 2.6 的观测 mask 同理）。
- 多条样本拼接（packing）时要配合文档级注意力掩码，否则样本之间会互相"看见"。
- **训练时的聊天模板必须和推理时逐字一致**。差一个换行符，模型在推理时就处在一个没训练过的条件下，这和 2.6 的 TITO 是同一类问题。

### 2.3 SFT 是一种带"病态奖励"的策略梯度

SFT 的梯度可以改写成策略梯度的形式（§3 Step 3），其隐含奖励是 $1/\pi(y^*)$：**模型赋予示范 token 的概率越小，该 token 对应的隐含奖励越大**。DFT（ICLR 2026）抵消这个权重。论文报告这种修改在受测数学推理、代码生成和多模态任务上改善了泛化。[《On the Generalization of SFT》](https://arxiv.org/abs/2508.05629)

### 2.4 蒸馏的光谱

| 方法 | 谁来采样 | 监督信号 | 对应的 KL | 主要问题 |
|---|---|---|---|---|
| 序列级蒸馏（SeqKD） | 老师生成文本，学生做 SFT | 每 token 一个硬标签 | 前向 | 曝光偏差；学到老师的"自信" |
| 软标签蒸馏 | 在老师 / 数据的序列上 | 老师的完整 logits 分布 | 前向（逐 token） | 仍是 off-policy |
| **on-policy 蒸馏（OPD）** | **学生自己采样** | 老师在学生轨迹上逐 token 打分 | **反向** | 需要老师的 logits；多样性下降 |
| RL | 学生自己采样 | 整条序列一个标量 | 反向（相对参考模型） | 信号稀疏 |

**OPD 的位置**：采样方式像 RL（在学生自己的分布上，没有曝光偏差），信号密度像 SFT（每个 token 都有老师的分布作为目标）。所以它比 RL 的样本效率高得多，又比 SFT 泛化得好。

### 同一个 KL 数值，为什么会给出错误的更新方向？

把词表缩成 A、B。教师给 A 的概率为 $q=0.8$，学生用一个 logit 差 $z$ 表示 $p=\sigma(z)$。在一个固定前缀上，反向 KL 是 $p\log(p/q)+(1-p)\log((1-p)/(1-q))$。先对 $p$ 求导，两个常数项抵消，再乘 $dp/dz=p(1-p)$，便得到 $p(1-p)\log\frac{p(1-q)}{q(1-p)}$。当学生给 A 的权重太低，这个量为负，梯度下降会增加 A 的权重。

只采一个词也能估算 KL 的**值**。但固定已经采出的词，直接反传其 log 概率比，期望梯度会变成 $p(1-p)+(1-p)(-p)=0$。丢掉的是学生变化时采样概率也会变化的贡献。可在同一前缀上显式求和，或把停止梯度的 log 比作为系数乘上采样动作的 log 概率。后者给出正确的期望局部梯度，单条样本仍有噪声。

```academy-lab
2.1-gradient
```

**迁移练习。** 学生已经学到 $p=q$，这时单个词的 log 比为零。全词表梯度和带正确权重的采样梯度都是零；直接对采样词的 log 概率求导却可能非零。只用一个样本验收梯度，会把采样噪声误判为学习信号。

## 3. 承重墙推导：重新捡起核心数学

### Step 1　SFT = 前向 KL

$$
\mathbb{E}_x\,\mathrm{KL}\big(p_{\text{data}}(\cdot|x)\,\|\,\pi_\theta(\cdot|x)\big) = \underbrace{-H(p_{\text{data}})}_{\text{与 }\theta\text{ 无关}} + \mathbb{E}_{(x,y)\sim\text{data}}\big[-\log\pi_\theta(y|x)\big]
$$

最小化交叉熵和最小化前向 KL 的梯度完全相同。SFT 从来不是"一个没有目标的模仿"，它就是在做一个特定方向的分布匹配。

### Step 2　为什么前向覆盖、反向挑峰

- 前向 KL 的被积项 $p\log(p/q)$：在 p>0 的地方 q→0 会让它趋于无穷，所以 q 必须在所有 p 有质量的地方都有质量；p≈0 的地方 q 放多少都几乎不被罚。
- 反向 KL 的被积项 $q\log(q/p)$：在 p≈0 的地方 q>0 会让它趋于无穷，所以 q 必须躲开所有 p 没有质量的地方。
- **反向 KL 的目标可以是非凸的**。当两个等权峰相隔很远，从正中开始拟合可能停在一个同时覆盖两峰的驻点。讲义曾记录均值 18、标准差 1.5 的初始化得到约 3.77 的反向 KL。互动图可以把初始化精确放到两峰正中，再和从左峰出发的结果比较。贴住一个等权成分时，反向 KL 约为 $\log 2 \approx 0.69$。

### Step 3　SFT 梯度的隐含奖励（DFT）

$$
\nabla_\theta\,\mathcal{L}_{\text{SFT}} = -\nabla\log\pi_\theta(y^*)
= -\mathbb{E}_{y\sim\pi_\theta}\Big[\frac{\mathbb{1}[y=y^*]}{\pi_\theta(y)}\,\nabla\log\pi_\theta(y)\Big]
$$

- 对照 2.3 的策略梯度 $\mathbb{E}_{y\sim\pi}[R(y)\nabla\log\pi(y)]$，SFT 等价于一个奖励为 $\mathbb{1}[y=y^*]/\pi(y^*)$ 的策略梯度。
- **病态之处**：示范 token 在模型看来越不可能，"奖励"越大，方差无界。
- **DFT 的一行修正**：$\mathcal{L}_{\text{DFT}} = -\mathrm{sg}\big(\pi_\theta(y^*)\big)\log\pi_\theta(y^*)$，sg 表示截断梯度。隐含奖励变成均匀的 $\mathbb{1}[y=y^*]$，更新从"偏向不可能的 token"变成了"各 token 均匀加权"。

### Step 4　on-policy 蒸馏的目标

学生采样轨迹 $y\sim\pi_\theta$，在每个位置 $c_t$ 上与老师 $\pi_T$ 做反向 KL：

$$
\mathcal{L}_{\text{OPD}} = \mathbb{E}_{y\sim\pi_\theta}\Big[\sum_t \mathrm{KL}\big(\pi_\theta(\cdot|c_t)\,\|\,\pi_T(\cdot|c_t)\big)\Big]
$$

两种实现，和 2.3 的 KL 估计量问题完全同构：
- **采样 token 版**：只用 $\log\pi_\theta(y_t) - \log\pi_T(y_t)$ 这个单点估计。可把它作为停止梯度的成本，再对学生的采样动作做策略梯度。仅将采出的 log 比直接反传，在固定前缀处漏掉了采样概率对参数的依赖。
- **全词表版**：在每个位置对整个词表求 KL。DeepSeek-V4 技术报告（preview 版）明确选择全词表 logits 蒸馏，理由是保留完整的 logit 分布能让反向 KL 的梯度估计更稳定。

多教师合并就是在上式里按领域加权：$\sum_i w_i\,\mathrm{KL}(\pi_\theta\|\pi_{E_i})$，学生在每个领域的样本上由对应的专家纠正。

### Step 5　OPD 的边界

- **多样性**：反向 KL 挑峰，在老师熵高（本来就有多种合理续写）的位置会压缩多样性、信号也不稳定。熵感知 OPD 在老师熵高的 token 上加回前向 KL，在 Qwen3 的 0.6B / 1.7B / 4B 学生上，Pass@8 分别比基线 OPD 高 1.37 / 2.39 / 5.05。
- **可学性**：老师强不等于学生学得会。2026 年的一项系统研究发现，要让学生出现新的思考模式、拿到更高分，老师必须提供学生训练中**没见过的**真正新能力。
- **局部纠正修不了全局**：OPD 的信号是逐 token 的，它在高 loss 的 token 上做局部修正，但修好一个 token 不一定能把后面整条轨迹拉回正轨。

## 4. 极简代码锚点（PyTorch）

SFT（含 DFT 开关）、按角色构建 loss mask、on-policy 蒸馏的两种实现。已跑通。

```python
import torch, torch.nn.functional as F

ASSISTANT = 2                                               # 角色 id：0 system, 1 user, 2 assistant, 3 tool

def build_loss_mask(role_ids):                              # role_ids: (B, T) 每个 token 属于哪个角色
    return (role_ids == ASSISTANT).float()                  # 只对模型该说的话求梯度

def sft_loss(logits, labels, mask, dft=False):
    """logits: (B, T, V) 已对齐到预测下一个 token；labels: (B, T)；mask: (B, T)"""
    logp = F.log_softmax(logits, -1).gather(-1, labels[..., None]).squeeze(-1)   # (B, T)
    w = logp.detach().exp() if dft else 1.0                 # DFT：乘上 sg(π(y*))，抵消 1/π 的病态奖励
    return -(w * logp * mask).sum() / mask.sum()

def opd_loss(student_logits, teacher_logits, mask, sampled=None, full_vocab=True):
    """在学生自己采样的轨迹上，逐 token 做反向 KL(π_s ‖ π_t)。
       student/teacher_logits: (B, T, V)；sampled: (B, T) 学生实际采样的 token"""
    ls = F.log_softmax(student_logits, -1)
    lt = F.log_softmax(teacher_logits.detach(), -1)         # 老师冻结
    if full_vocab:                                          # 全词表：Σ_v π_s (log π_s − log π_t)，梯度更稳
        kl = (ls.exp() * (ls - lt)).sum(-1)                 # (B, T)
    else:                                                   # 采样 token 的单点估计（k1）
        chosen = ls.gather(-1, sampled[..., None]).squeeze(-1)
        cost = (ls - lt).gather(-1, sampled[..., None]).squeeze(-1).detach()
        # 前向读出单样本 log 比；反向用 cost × ∇logπ，老师与采样 id 均冻结。
        kl = cost + cost * (chosen - chosen.detach())
    return (kl * mask).sum() / mask.sum()
```

**注意**：采样 token 版如果直接当 loss 反传，梯度并不等于反向 KL 的梯度（采样本身不求导，k1 的期望梯度为 0，→ 2.3 §3 Step 5）。它要么作为奖励走策略梯度，要么换成全词表版。

### 数值复算 · 同一个 KL 数值，为什么会给出错误的更新方向？

在同一个 Python 会话中先运行本节上方的实现，再运行以下算例。

```python
import torch
teacher = torch.tensor([0.8, 0.2], dtype=torch.float64).log().view(1, 1, 2)
mask = torch.ones(1, 1)
for p in [0.2, 0.5, 0.8]:
    z = torch.logit(torch.tensor(p, dtype=torch.float64)).requires_grad_()
    student = torch.stack([z, z * 0]).view(1, 1, 2)
    exact = torch.autograd.grad(opd_loss(student, teacher, mask), z, retain_graph=True)[0]
    # 枚举学生的两种采样结果，按其概率合成采样估计的期望梯度。
    sampled_gradient = 0.
    for token, weight in enumerate([p, 1-p]):
        loss = opd_loss(student, teacher, mask, torch.tensor([[token]]), full_vocab=False)
        sampled_gradient += weight * torch.autograd.grad(loss, z, retain_graph=True)[0]
    assert torch.allclose(sampled_gradient, exact, atol=1e-12)
    print(f"p={p:.1f}  精确={exact.item():+.3f}  采样期望={sampled_gradient.item():+.3f}")

# 两个等重高斯成分的前向 KL 最优解由矩匹配得到；逆向解用左峰作局部近似。
import math
left, right, width = 12., 28., 1.5
forward_std = math.sqrt(width**2 + (right-left)**2/4)
valley = (left + (right-left)/3, right - (right-left)/3)
for mu, sd in [(20., forward_std), (left, width)]:
    lo, hi = [(edge-mu)/(sd*math.sqrt(2)) for edge in valley]
    mass = (math.erf(hi)-math.erf(lo))/2
    print(f"均值={mu:.1f}  标准差={sd:.3f}  空谷概率={mass:.5f}")
```

## 5. 实战直觉、避坑与面试深挖

**2026 前沿现状**
- **OPD 成为后训练的核心环节**。Qwen3、MiMo、DeepSeek-V4 等工业界工作都验证了 on-policy 蒸馏的效果。它在前沿流水线里的典型位置是"RL 专家 → 蒸馏合并"：DeepSeek-V4 技术报告（preview 版）把十多个领域教师用 OPD 合成一个学生；Kimi K3 按领域 × 推理档位分别做 RL，再用多教师 OPD 合并。（DeepSeek-V4 正式版的后训练流程与 preview 不同，以正式版说明为准。）
- **为什么用 OPD 合并，而不是权重平均**：权重平均假设不同专家的参数改动可以线性叠加，领域差异大时会互相干扰。OPD 让学生在自己的样本上分别接受各领域专家的纠正，冲突在**输出空间**里解决，而不是在参数空间里硬凑。
- **SFT 本身也在被重新理解**：DFT 把 SFT 放进 RL 的框架里分析，指出标准 SFT 的梯度隐含着一个会严重限制泛化的奖励结构，一行修改即可改善。2026 年围绕 OPD 的研究也很密集：熵感知、可学性、跨 token 的轨迹修复、截断到老师 top-K 支撑集的反向 KL。

**与工程 / 应用的连接**
- **"用强模型 API 的输出微调自己的模型"就是 SeqKD**：它继承了曝光偏差和"学会自信"的问题。缓解办法：只保留学生大概率能掌握的样本（按学生自身的困惑度或通过率筛选）；后面接一段 on-policy 训练。另外，**只有 API 输出、拿不到 logits 的老师做不了 OPD**，这是闭源老师的结构性限制。
- **遗忘是分布漂移**：在窄领域数据上 SFT，会把整个分布往那个领域拉。常用手段是混入通用数据回放；LoRA 通常"学得更少、也忘得更少"。
- **聊天模板是隐形的契约**：训练和推理模板不一致，是"微调后效果莫名变差"最常见的原因之一，排查时先逐 token 对比两边的输入。

**常见误区 / 反直觉点**
1. **"SFT 只是在教格式"** ✗：它在做前向 KL 分布匹配，会把示范里的所有东西一起学走，包括对学生来说根本不成立的事实陈述。
2. **"蒸馏就是用老师的输出做 SFT"** ✗：那只是光谱的一端（off-policy、硬标签、前向 KL）。软标签和 on-policy 蒸馏在"谁采样、用哪个方向的 KL"上有本质区别。
3. **"反向 KL 总比前向 KL 好，因为输出更'干净'"** ✗：反向 KL 挑峰会压缩多样性、降低 pass@k，目标非凸、对初始化敏感。2026 年的熵感知 OPD 正是在高熵位置把前向 KL 加回来。

**高频深挖题**
- **Q1：SFT 和 RL 分别对应哪个方向的 KL？这如何解释"SFT 记忆、RL 泛化"？**
  思路：SFT = 前向 KL(p_data ‖ π)，mode-covering，在不确定处对冲、在不会的地方也照着说；RL = 反向 KL 到 π\*，按回报调整采样动作的概率 → 再从梯度角度补一层：SFT 的隐含奖励是 1/π(y\*)，低概率标签对应较大的等价重要性权重，但对 logit 的交叉熵梯度仍然有界→ 收尾：RL 在自己的分布上学习，没有曝光偏差。
- **Q2：为什么 on-policy 蒸馏通常比直接用老师生成的数据做 SFT 效果好？它和 RL 有什么区别？成本在哪？**
  思路：消除曝光偏差（学生在自己的前缀上被纠正）+ 信号稠密（每 token 一个分布，而不是每序列一个标量）→ 与 RL 的区别：目标是老师的分布而不是奖励，样本效率高得多，但上限受老师限制 → 成本：每条学生样本都要过一遍老师的前向；需要老师的 logits；老师必须能提供学生没有的能力，否则学不到新东西。
