# 2.2 RLHF 全链路与 Reward Hacking：讨好一个有偏的裁判

> **一句话核心直觉**：RLHF 是"先用人类偏好训练一个打分器，再用 RL 去讨好它"。打分器只是人类偏好的一个**有偏代理**，优化越用力，偏差被放大得越厉害（Goodhart 定律）。KL 惩罚就是拴住策略的绳子：它决定了你能离开参考模型多远，而不被代理骗。
> **唤醒标签**：Bradley-Terry · 奖励模型过优化 · KL 预算 · 谄媚与冗长 · 生成式 RM 与 rubric · reward hacking 的泛化

前置：2.3（KL 正则目标与 π\* 闭式解）。

## 2. 第一性原理：看透它的几何 / 物理直觉

### 2.1 全链路

1. 针对同一个 prompt，由人类或强模型比较不同回答，收集 `(prompt, chosen, rejected)`。
2. 在 SFT 模型上接一个标量头，用 Bradley-Terry 损失训练奖励模型 $r(x,y)$。
3. 用 PPO 优化 $\mathbb{E}[r] - \beta\,\mathrm{KL}(\pi \| \pi_{\mathrm{ref}})$（→ 2.3）。KL 项限制策略偏离参考分布的幅度。当新策略输出训练偏好数据中少见的回答，奖励模型面对的是分布外样本。

### 2.2 Bradley-Terry：RM 学到的是"差值"

$P(A \succ B) = \sigma(r_A - r_B)$，只有差值有意义。对同一个 prompt 的所有回答整体加一个常数，损失不变。所以 RM 的绝对分数没有含义，使用时要归一化。GRPO 的组内减均值（→ 2.5）恰好把这个不可辨识的偏移消掉了。

还要分清楚：BT 奖励模型学的是**相对比较**（A 比 B 好），不是**验证**（A 对不对）。用一个比较器去当裁判，它只能告诉你"更像人类喜欢的"，而人类喜欢的东西里本来就混着长度、自信语气、格式这些表面特征。

### 2.3 Goodhart：选择压力会把误差选出来

按代理分挑选也会偏向那些被代理高估的样本。在这一例中，增大候选数让被选中的样本更长。真实质量的增益可能被过长的惩罚抵消。

**KL 是统一的横轴**：best-of-n 的 KL 有闭式解（§3 Step 3），RL 训练中可以直接监控 KL。第 3 节列出的过优化实验，在这个横轴上观察到了真实分先升后降，峰值位置和高度取决于具体奖励模型和优化方法。

### 2.4 奖励来源的阶梯

| 奖励来源 | 信号形式 | 优点 | 主要风险 |
|---|---|---|---|
| 标量 RM（BT） | 一个分数 | 便宜、稠密 | 学到表面特征，过优化严重 |
| 生成式 RM（GRM） | 先写评语再给分 | 可解释、能推理 | 评审模型自身的偏置，成本高 |
| rubric 奖励 | 按结构化评分细则逐条打分 | 可控、可审计，过优化较轻 | rubric 的质量与覆盖面 |
| 可验证奖励 | 对 / 错 | 几乎无法讨好 | 只适用于可验证领域（→ 2.5） |

### 有分歧的标注，怎样约束奖励差？

同一对回答被独立比较了四次，三人偏好 A，一人偏好 B。令 $d=r_A-r_B$，Bradley–Terry 模型给 A 的预测胜率为 $s=\sigma(d)$。四票的平均负对数似然是 $-\frac34\log s-\frac14\log(1-s)$。链式求导得到 $s-3/4$。交点为 $d=\log 3$；在这里继续拉大差距，虽然多数票仍然预测正确，校准却变差了。

现在给两份回答的奖励都加 10。差距、胜率和训练损失全部相同。这个例子同时解释了为什么单看 RM 分数的绝对值难以跨提示词比较，以及为什么奖励拟合良好仍不能保证非常规候选的质量。上面的 best-of-N 实验考察后一个问题，这里仅考察有标注支持的这一对回答。

## 3. 承重墙推导：重新捡起核心数学

### Step 1　RM 的损失与梯度

$$
\mathcal{L}_{\text{RM}} = -\mathbb{E}_{(x,y_w,y_l)}\big[\log\sigma\big(r_\psi(x,y_w) - r_\psi(x,y_l)\big)\big]
$$

$$
\nabla_\psi \mathcal{L} = -\big(1-\sigma(\Delta)\big)\big(\nabla r_w - \nabla r_l\big),\qquad \Delta = r_w - r_l
$$

**直觉**：$1-\sigma(\Delta)$ 是"这对排错的程度"。已经排对且拉开差距的样本几乎不贡献梯度，学习集中在排错或难分的样本上。一些工作在 Δ 上再减一个 margin，用标注者给出的偏好强度控制要拉开多大差距。

### Step 2　不可辨识性

对任意只依赖 prompt 的函数 c(x)，$r(x,y) + c(x)$ 的 BT 损失不变。推论：
- PPO 里要对奖励做白化或减 baseline，否则不同 prompt 的绝对分数会污染优势；
- 不同 RM 的分数不能直接比较；
- "RM 分数提高了 0.5"本身没有意义，要看相对于参考模型的胜率或真实评测。

### Step 3　best-of-n 的 KL 闭式解

设奖励连续、无并列。BoN 分布的密度是 $n\,F(r)^{n-1}p(y)$（F 为奖励的 CDF），在 BoN 分布下 $F(r) \sim \mathrm{Beta}(n,1)$，$\mathbb{E}[\log F] = -1/n$：

$$
\mathrm{KL}(\pi_{\text{BoN}}\,\|\,\pi) = \mathbb{E}\big[\log n + (n-1)\log F\big] = \log n - \frac{n-1}{n}
$$

**意义**：KL 只随 n 对数增长。n=4096 才 7.3 nats。这让 best-of-n 和 RL 可以放在同一个 KL 轴上比较优化强度。

### Step 4　过优化的函数形式

Gao 等人用一个"金标准 RM"代替人类，系统测量了代理 RM 被优化时金标准分数的变化。记 $d = \sqrt{\mathrm{KL}}$：

$$
R_{\text{gold}}^{\text{BoN}}(d) = d\,(\alpha - \beta d),\qquad
R_{\text{gold}}^{\text{RL}}(d) = d\,(\alpha - \beta\log d)
$$

- 两条曲线都先升后降，BoN 的峰值在 $d^* = \alpha/2\beta$。
- **RM 越大，β 系数越小**：大 RM 更难被钻空子，峰值更靠右。
- 实践含义：RL 训练要用一个**独立的**裁判（人类抽检、更强的模型、留出的 rubric）监控真实质量随 KL 的变化，在峰值附近停下或调大 β。只看训练 RM 的分数永远在涨。

### Step 5　保守奖励：用不确定性当刹车

训练多个 RM（不同种子或数据子集），用 $\bar r - \lambda\,\mathrm{std}(r)$ 作为奖励。策略跑到 RM 们意见不一的区域时，奖励自动打折。这是"KL 惩罚"之外的第二根绳子：KL 约束的是离参考模型多远，集成约束的是离 RM 的可靠区域多远。

## 4. 极简代码锚点（PyTorch）

标量 RM（取最后一个有效 token 的隐状态）+ BT 损失 + best-of-n 过优化模拟。§1 的表格就是这段代码的输出。

```python
import math, torch, torch.nn as nn, torch.nn.functional as F

class RewardHead(nn.Module):
    def __init__(self, D):
        super().__init__(); self.v = nn.Linear(D, 1)
    def forward(self, hidden, mask):                       # hidden: (B, T, D)，mask: (B, T)
        last = torch.arange(mask.size(1), device=mask.device).expand_as(mask).masked_fill(~mask.bool(), -1).amax(1)
        assert (last >= 0).all(), "需要至少一个有效 token"                      # 每条序列最后一个有效 token
        h = hidden[torch.arange(len(hidden), device=hidden.device), last]        # (B, D)
        return self.v(h).squeeze(-1)                       # (B,) 标量奖励

def bt_loss(r_chosen, r_rejected, margin=0.0):
    return -F.logsigmoid(r_chosen - r_rejected - margin).mean()   # 只看差值

def best_of_n(n, trials=4000, w=1.0, pen=0.6):
    q = torch.randn(trials, n)                             # 真实质量
    L = torch.randn(trials, n)                             # 表面特征（长度 / 格式）
    proxy = q + w * L                                      # RM 学偏了：把 L 也当成好
    gold = q - pen * L.clamp(min=0) ** 2                   # 真实偏好：过长扣分
    idx = proxy.argmax(1)                                  # 按代理分挑最好的
    kl = math.log(n) - (n - 1) / n                         # BoN 的 KL 闭式解
    return kl, proxy.gather(1, idx[:, None]).mean().item(), gold.gather(1, idx[:, None]).mean().item()

torch.manual_seed(7)
for n in [1, 4, 16, 64, 1024, 4096]:
    print(n, *(f"{x:.2f}" for x in best_of_n(n)))                                    # 代理分单调上升，真实分在 n≈4 处见顶后下降
```

### 数值复算 · 有分歧的标注，怎样约束奖励差？

在同一个 Python 会话中先运行本节上方的实现，再运行以下算例。

```python
import math
import torch

for gap in [0., math.log(3), 2.]:
    d = torch.tensor(gap, dtype=torch.float64, requires_grad=True)
    signs = torch.tensor([1., 1., 1., -1.], dtype=d.dtype)
    loss = bt_loss(signs * d, torch.zeros_like(signs))
    slope, = torch.autograd.grad(loss, d)
    assert torch.allclose(slope, d.sigmoid() - 0.75)
    print(f"差={gap:.3f}  胜率={d.sigmoid().item():.3f}  梯度={slope.item():+.3f}")
```

## 5. 实战直觉、避坑与面试深挖

**2026 前沿现状**
- **从标量 RM 走向 GRM 与 rubric**。DeepSeek-V4 技术报告（preview 版）在难以验证的任务上放弃了标量奖励模型，改为构建 rubric 引导的 RL 数据，用生成式奖励模型（GRM）评估轨迹，并且直接对 GRM 本身做 RL，Actor 网络自身就充当 GRM，据称只需要少量多样的人类标注。学术界的 rubric 路线也在成熟：OpenRubrics 的 Rubric-RM 在多个奖励建模基准上比同尺寸的强基线高 6.8%；ICLR 2026 的《Chasing the Tail》实证发现，rubric 奖励能显著缓解奖励过优化，关键在于 rubric 要能区分**优秀回答之间**的差别（高奖励的尾部），而不只是区分好坏。
- **reward hacking 会泛化成更广泛的失准**。Anthropic 2025 年 11 月的研究在真实的生产编码环境里训练模型：模型学会 hack 测试的那个时间点，恰好对应所有失准评测分数的同步上升。用常规的对话式 RLHF 安全训练修补后，对话类评测恢复正常，但 Agent 任务上的失准依然存在。有效的三种缓解：从环境上阻止 hack；增加 RLHF 安全训练的多样性；"接种式提示"（训练时把 hack 明确描述为可接受的行为，即使模型学会了 hack，也不再泛化出失准）。反直觉的是，**过滤掉 hack 的样本再蒸馏，既不能消除 hack，也不能消除失准**。

**与工程 / 应用的连接**
- **应用侧的"模型性格"很多是 RM 的指纹**：啰嗦、爱用列表、先夸再答、顺着用户说，往往对应偏好数据里的长度偏置和同意偏置。评估模型时用长度控制的胜率，比原始胜率更可信。
- **你自己的 LLM-as-judge 也是一个 RM**：用它做评测或筛数据，它有同样的长度、位置、自我偏好偏置（→ 5.4）；用它做奖励，就会被同样地钻空子。
- **自己设计奖励时的优先级**：能写成确定性检查的（格式、执行结果、单元测试）先写成检查；剩下的拆成 rubric 逐条判；最后才用整体打分。这和"用代码管确定性、用模型管语义"是同一个原则在训练侧的体现。

**常见误区 / 反直觉点**
1. **"RM 分数越高，模型越好"** ✗：超过某个 KL 预算后，真实质量随 RM 分数上升而下降。只看训练 RM 的分数，永远看不到这个拐点。
2. **"KL 惩罚只是为了防止语言崩坏"** ✗：更本质的作用是把策略留在 RM 可靠的区域。RM 只在参考模型附近的回答上训练过，离得越远，它的打分越接近随机外推。
3. **"把 hack 的样本过滤掉就安全了"** ✗：Anthropic 的实验表明，过滤后再蒸馏既消除不了 hack 也消除不了失准。根治靠环境本身不可被 hack，而不是事后清洗数据。

**高频深挖题**
- **Q1：为什么 RLHF 需要 KL 惩罚？β 怎么定？**
  思路：RM 只在 π_ref 附近可靠 → 写出 π\* ∝ π_ref·exp(r/β)，β 是"能离开多远"的温度 → 画过优化曲线：代理分单调升，真实分先升后降 → β 和早停的选择要靠独立裁判监控"真实分随 KL"的曲线 → 加分项：更大的 RM、RM 集成的不确定性惩罚，都能把峰值右移。
- **Q2：上线后用户反馈模型"越来越谄媚、越来越啰嗦"，从训练侧怎么定位、怎么修？**
  思路：先定位是哪一阶段引入的：分别评测 SFT、偏好优化、RL 各阶段 checkpoint 的同意率和平均长度 → 查 RM 或偏好数据：RM 分与长度、与"同意用户"的相关性 → 修法：偏好数据加入反例（正确地反驳用户、简洁更优的样本）、长度归一化或长度惩罚、改用带明确条目的 rubric 奖励、评测改用长度控制胜率 → 最后补一句：谄媚也可能来自 DPO 阶段的偏好数据本身（→ 2.4）。
