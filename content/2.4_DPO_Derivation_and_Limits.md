# 2.4 DPO：推导与局限

> **一句话核心直觉**：KL 正则 RL 的最优解有闭式（2.3 的 π\*），所以"奖励"可以反过来用策略自己表示：$r = \beta\log\frac{\pi}{\pi_{\text{ref}}} + \text{常数}$。把它代进 Bradley-Terry，常数相消，RLHF 的"训 RM + 跑 RL"就塌缩成了一个分类损失。代价是：它只约束 chosen 与 rejected 的**差**，从不保证 chosen 本身变得更可能。
> **唤醒标签**：隐式奖励 · 配分函数相消 · 离线 / off-policy · 似然位移 · 长度偏置 · IPO / SimPO / KTO

前置：2.3 §3 Step 5（π\* 闭式解）、2.2（Bradley-Terry）。

---

## 1. 痛点与钩子：如果没有它，世界会怎样？

2.2 的 RLHF 要同时养 4 个模型（→ 2.3），还要在线采样、调 KL、防 RM 被钻空子。对大多数团队来说，这套设施太重。DPO 的承诺是：**不要 RM，不要 RL，不要采样，只要偏好对和一个冻结的参考模型**，像 SFT 一样训练。2023 年之后，开源后训练几乎都转向了它。到 2026 年，OLMo 3、Tülu 3 这样完全公开的后训练流水线仍然是 SFT → DPO → RLVR 三段式。

下面是 §4 四词模型的实际训练结果。No 与 Never 共享一个使两者 logits 同向变化的特征，No 另有一个较弱的独立特征。两次训练从同一参考分布出发，β=1，学习率 0.1，各做 100 步；第二次增加系数为 1 的首选词 NLL。

| 阶段 | No（chosen） | Never（rejected） | Yes | 其他 |
|---|---:|---:|---:|---:|
| 训练前 | 0.386 | 0.472 | 0.095 | 0.047 |
| DPO 训练后 | 0.018 | 0.002 | 0.914 | 0.065 |
| DPO + NLL 锚 | 0.751 | 0.145 | 0.075 | 0.029 |

DPO 成功地把 No 和 Never 的**差**拉开了，可 chosen 的概率从 0.386 掉到了约 0.018，被挤出去的概率质量流向了意思相反的 "Yes"。这就是**似然位移**（likelihood displacement），也是 DPO 最值得在面试里讲透的一点（§3 Step 4）。

## 2. 第一性原理：看透它的几何 / 物理直觉

### 2.1 一条推导链

1. 写出 KL 正则化 RL 的最优策略，它按 $\exp(r/\beta)$ 重加权参考策略，再用 $Z(x)$ 归一化。
2. 反解奖励。每条回答的奖励由其相对参考策略的 log 概率比和公共项 $\beta\log Z(x)$ 给出。
3. 对同一 prompt 的首选和拒选奖励取差。公共项抵消，Bradley–Terry 的二分类损失可直接用策略和参考策略计算。

**画面**：每个策略都隐含着一个奖励模型（相对参考模型的 log 概率比）。DPO 不再先训 RM 再找它的最优策略，而是直接在"策略空间"里拟合偏好。

### 2.2 DPO 在推什么

梯度试图拉大首选与拒选之间的 log 概率差。隐式奖励已明显偏向首选时，样本权重会自动缩小（见 §3 Step 3）。两条回答的概率可以一起下降，只要它们的比值仍在上升，DPO 损失就会下降。


设 $m$ 是偏好对的总概率，$s$ 是其中首选的份额。把 $ms$ 和 $m(1-s)$ 代入它们的概率比，$m$ 会约掉。用实验分开改变 $m$ 和 $s$，可以检查偏好损失究竟约束了哪个量。

### 2.3 DPO 与在线 RL 的根本差别

| | PPO / GRPO（在线） | DPO（离线） |
|---|---|---|
| 样本从哪来 | 当前策略自己采样 | 固定的偏好数据集（通常来自别的模型） |
| 优化的是 | 自己会生成的回答 | 数据集里出现过的回答 |
| 不在数据里的回答 | 有机会被采到并打分 | 缺少针对该回答的直接训练信号，参数更新仍可改变其概率 |
| 成本 | 采样 + 多模型 | 和 SFT 差不多 |

似然位移、长度偏置、分布外泛化差，根源都在第三行。这也是"偏好与风格用 DPO、推理能力靠在线 RL"的分工原因。

### β 如何同时改变学习力度和饱和速度？

把一对回答的对数概率比相对参考模型的变化记为 $h$。DPO 对这一对回答的损失可以写成 $\log(1+e^{-\beta h})$。直接对 $h$ 求导得到 $-\beta/(1+e^{\beta h})$。负号说明这对样本仍在推高 chosen 的相对赔率；分母则决定它还有多大力气。

在训练起点 $h=0$，所有样本都贡献 $\beta/2$ 的标量梯度大小。当 $h$ 已经很大，较大的 $\beta$ 会更快进入平坦区。于是“增大 β 就会让每条样本更新更大”只在某些位置成立。这里画的是损失对一个标量的导数；真实参数的梯度还要乘 chosen 与 rejected 两条序列的 log 概率梯度之差。

## 3. 承重墙推导：重新捡起核心数学

### Step 1　从 π\* 反解奖励

2.3 已证 $\pi^*(y|x) = \frac{1}{Z(x)}\pi_{\text{ref}}(y|x)\,e^{r(x,y)/\beta}$。两边取对数整理：

$$
r(x,y) = \beta\log\frac{\pi^*(y|x)}{\pi_{\text{ref}}(y|x)} + \beta\log Z(x)
$$

**设计巧妙之处**：$Z(x) = \sum_y \pi_{\text{ref}}(y|x)e^{r/\beta}$ 要对所有可能的回答求和，根本算不出来。但它只依赖 x。

### Step 2　代入 Bradley-Terry，配分函数相消

$$
P(y_w \succ y_l \mid x) = \sigma\big(r(x,y_w) - r(x,y_l)\big)
= \sigma\Big(\beta\log\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta\log\frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\Big)
$$

$\beta\log Z(x)$ 在相减中消失（这正是 2.2 §3 Step 2 的不可辨识性：BT 只看差值）。最大化偏好数据的似然：

$$
\mathcal{L}_{\text{DPO}} = -\mathbb{E}\Big[\log\sigma\big(\beta\,\hat h_\theta\big)\Big],\qquad
\hat h_\theta = \log\frac{\pi_\theta(y_w)}{\pi_{\text{ref}}(y_w)} - \log\frac{\pi_\theta(y_l)}{\pi_{\text{ref}}(y_l)}
$$

### Step 3　梯度

$$
\nabla_\theta\mathcal{L}_{\text{DPO}} = -\beta\,\mathbb{E}\Big[\sigma\big(-\beta\hat h_\theta\big)\big(\nabla\log\pi_\theta(y_w) - \nabla\log\pi_\theta(y_l)\big)\Big]
$$

- $\sigma(-\beta\hat h)$：隐式奖励排错时权重大，排对后自动减弱，起到了"不过度优化"的作用。这是 DPO 比"直接 chosen 做 SFT、rejected 做反向 SFT"稳定的原因。
- β 的含义和 RLHF 一样：越小越允许偏离参考模型。

### Step 4　似然位移：chosen 为什么会变少

把 $\log\pi(y_w)$ 沿一步梯度更新的变化做一阶展开（学习率为 η，权重记作 w>0）：

$$
\Delta\log\pi(y_w) \approx \eta\, w\big(\|\nabla\log\pi(y_w)\|^2 - \langle\nabla\log\pi(y_w),\ \nabla\log\pi(y_l)\rangle\big)
$$

**当 $\langle\nabla\log\pi(y_w), \nabla\log\pi(y_l)\rangle > \|\nabla\log\pi(y_w)\|^2$ 时，chosen 的概率反而下降**。也就是 chosen 与 rejected 的梯度方向高度一致、且 rejected 的梯度更大时，"压低 rejected"的动作会顺带把 chosen 一起压下去。

- **谁会更像**。只差几个词的回答可能有非常相似的表示。[Razin 等人对似然位移的研究](https://arxiv.org/abs/2410.08847)展示了一个例子。训练模型偏好 No 胜过 Never 时，概率质量可能流向意思相反的 Yes。
- **概率去了哪**：chosen 和 rejected 都在降，总概率守恒，质量必然流向**数据集之外**的回答。如果流向的回答和 chosen 同义，问题不大；如果流向反义，就是灾难。
- **修法**：给 chosen 加一个 NLL 锚（本篇代码里的 `rpo_alpha`，§1 表格最后一行）；过滤掉表示过于相似的偏好对；确保参考模型本身给 chosen 足够的概率（先在 chosen 上做 SFT）。

### Step 5　变体各修了哪一处

| 变体 | 改动 | 针对的问题 |
|---|---|---|
| **IPO** | 把 $-\log\sigma(\beta \hat h)$ 换成平方损失 $(\hat h - \tfrac{1}{2\beta})^2$ | 偏好接近确定时，DPO 会把 $\hat h$ 推向无穷，过拟合噪声标注 |
| **SimPO** | 去掉参考模型，用**长度归一化**的平均 log 概率作隐式奖励，并加目标间隔 γ | 长度偏置；省掉参考模型的显存 |
| **KTO** | 不需要成对数据，只要"好 / 坏"的单条标注，用前景理论式的价值函数 | 成对偏好数据难获取 |
| **NLL 锚（RPO 等）** | 额外加 chosen 的 SFT 损失 | 似然位移 |
| **在线 / 迭代 DPO** | 每轮用当前策略采样新回答、重新标注偏好 | 离线数据的分布偏移 |

**长度偏置的来源**：$\log\pi(y)$ 是逐 token 求和，回答越长绝对值越大，隐式奖励的方差也越大。如果偏好数据里 chosen 平均更长（人类和 LLM 裁判都有这个倾向），DPO 会学到"越长越好"。

## 4. 极简代码锚点（PyTorch）

输入是每条回答的**序列 log 概率之和**（只对回答 token 求和），形状 `(B,)`。一个函数覆盖 DPO / IPO / SimPO 和 NLL 锚。§1 的玩具实验用的就是 `mode="dpo"` 加不加 `rpo_alpha` 的对比。

```python
import torch, torch.nn.functional as F

def preference_loss(pc, pr, rc=None, rr=None, beta=0.1, mode="dpo",
                    len_c=None, len_r=None, gamma=0.5, rpo_alpha=0.0):
    """pc / pr：策略对 chosen / rejected 的序列 log 概率 (B,)
       rc / rr：参考模型的对应值（SimPO 不需要）；len_*：回答 token 数 (B,)"""
    if mode == "simpo":                                         # 无参考模型 + 长度归一化 + 目标间隔
        logits = beta * (pc / len_c - pr / len_r) - gamma
        loss = -F.logsigmoid(logits)
    else:
        h = (pc - rc) - (pr - rr)                               # 隐式奖励之差 / β
        if mode == "ipo":                                       # 平方损失：不把 h 推向无穷
            loss = (h - 1.0 / (2 * beta)) ** 2
        else:                                                   # 标准 DPO
            loss = -F.logsigmoid(beta * h)
    if rpo_alpha > 0:                                           # NLL 锚：直接托住 chosen 的绝对概率
        loss = loss + rpo_alpha * (-pc / len_c)
    return loss.mean()

def implicit_reward(p, r, beta=0.1):                            # 监控用：每条回答的隐式奖励
    return beta * (p - r)
```

**训练时必看的三条曲线**：chosen 隐式奖励、rejected 隐式奖励、chosen 的绝对 log 概率。前两者之差在涨、第三条在跌，就是似然位移正在发生。

### 数值复算 · β 如何同时改变学习力度和饱和速度？

在同一个 Python 会话中先运行本节上方的实现，再运行以下算例。

```python
import torch
for h in [-2., 0., 2., 6.]:
    slopes = []
    for beta in [1., 0.25]:
        # 两种回答组成完整词表，参考等概率；当前 log 赔率恰为 h。
        z = torch.tensor(h, dtype=torch.float64, requires_grad=True)
        logs = torch.stack([z, z*0]).log_softmax(0)
        ref = torch.tensor(0.5, dtype=z.dtype).log()
        loss = preference_loss(logs[0], logs[1], ref, ref, beta=beta)
        slope, = torch.autograd.grad(loss, z)
        slopes.append(-slope.item())
    print(f"h={h:+.0f}  {slopes[0]:.3f}  {slopes[1]:.3f}")

# 两个共享特征决定四个 logits。每种目标都从同一参考分布重新训练。
base = torch.tensor([0.386, 0.472, 0.095, 0.047], dtype=torch.float64).log()
features = base.new_tensor([[-2., 0.5], [-3., 0.], [1., 0.], [0., 0.]])
for anchor in [0., 1.]:
    weights = torch.zeros(2, dtype=base.dtype, requires_grad=True)
    for step in range(100):
        logs = (base + features @ weights).log_softmax(0)
        loss = preference_loss(logs[0], logs[1], base[0], base[1], beta=1.,
                               len_c=1, rpo_alpha=anchor)
        gradient, = torch.autograd.grad(loss, weights)
        with torch.no_grad():
            weights.sub_(0.1 * gradient)
    probs = (base + features @ weights).softmax(0)
    print(f"锚={anchor:.0f}  " + "  ".join(f"{p:.3f}" for p in probs.tolist()))
```

## 5. 实战直觉、避坑与面试深挖

**2026 前沿现状**
- **DPO 仍是公开流水线里的中间一段**。OLMo 3 和 Tülu 3 的后训练都由 SFT、DPO、RLVR 三段组成。OLMo 3 的 DPO 阶段包含 12.5 万条"增量学习"偏好对：chosen 由 Qwen3-32B 生成，rejected 由 Qwen3-0.6B 生成。背后的"增量学习假说"认为，偏好对之间的**相对差距**比 chosen 的绝对质量更重要，所以用强弱两个模型的输出直接构造偏好对，就能得到有效信号。
- **数据比算法更重要**。ICLR 2026 的一项研究系统分析了五个常用的开源 DPO 数据集，经过筛选的混合数据比其中表现最好的单个数据集更小，效果却更好。另一项覆盖 51 种后训练算法的对照研究，题目就叫"后训练算法真的有差别吗？"，并发现算法排名会随模型规模发生反转。面试里讨论 DPO 变体时，先说"数据和规模的影响往往比变体之间的差别大"。
- **谄媚可以从偏好数据里来**。2026 年一项针对 OLMo 3 和 Tülu 3 各阶段的分析，专门追踪了谄媚式附和在 SFT、DPO、RLVR 各阶段的变化。偏好数据里隐含的"附和用户更好"会被 DPO 直接学进去（→ 2.2 Q2）。

**与工程 / 应用的连接**
- **团队微调的首选**：手里有成对偏好数据（A/B 测试、用户点赞点踩、标注员比较），DPO 的成本和 SFT 相当，是改风格、改语气、减少某类错误的性价比之选；只有单条好坏标注，用 KTO。
- **它改不了能力上限**：离线方法只能在数据集覆盖的回答之间调整偏好。想让模型学会新的推理或工具使用，要么提供新示范（SFT），要么在线 RL。
- **偏好对的构造决定一切**：chosen 和 rejected 太像，容易引发似然位移；差距太大（比如一个明显乱码），信号太弱、学不到细节。强弱模型对比、同模型不同温度采样再打分，是常用的构造方式。

**常见误区 / 反直觉点**
1. **"DPO 会让 chosen 回答更可能出现"** ✗：它只保证 chosen 相对 rejected 更可能。两者一起下降很常见，被挤走的概率去了数据集之外的回答。
2. **"DPO 和 RLHF 数学上等价，所以效果一样"** ✗：等价的是**最优解**，前提是偏好数据覆盖了策略会生成的所有回答。实际数据是离线的、有限的，分布外的回答完全不受约束，这正是在线 RL 依然有优势的原因。
3. **"DPO 没有奖励模型，所以不会 reward hacking"** ✗：隐式奖励同样会被钻空子，最典型的就是长度偏置：偏好数据里 chosen 更长，模型就学会写得更长。

**高频深挖题**
- **Q1：从 RLHF 目标推导 DPO，并说明 Z(x) 是怎么消掉的。**
  思路：写 KL 正则目标 → 闭式解 π\* ∝ π_ref·exp(r/β) → 反解 r = β log(π\*/π_ref) + β log Z(x) → 代入 BT，只用到奖励之差，Z(x) 只依赖 x，相减消失 → 得到损失。收尾：等价性只在最优解成立，离线数据有限时，分布外的回答没有约束。
- **Q2：DPO 训练中 chosen 的 log 概率一直在降，这正常吗？会有什么后果？怎么处理？**
  思路：说出似然位移的名字 → 一阶展开给出条件：chosen 与 rejected 的梯度内积大于 chosen 梯度的模长平方 → 后果取决于概率流向：流向同义回答问题不大，流向反义（如拒答变成有害回答）是灾难 → 修法：NLL 锚、过滤相似对、先在 chosen 上 SFT、换在线或迭代 DPO。
