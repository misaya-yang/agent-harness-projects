# 3.2 VLM 架构与模态对齐：把图片翻译成"外语单词"

> **一句话核心直觉**：主流 VLM 是"翻译官"结构：视觉编码器把图切成 patch 特征，连接器把它们翻译成 LLM 能读的 token，LLM 把它们当成一种外语单词，和文字一起读。真正的工程难题集中在三处：**分辨率与 token 数的平方关系、视觉位置怎么编码、各训练阶段解冻什么**。
> **唤醒标签**：ViT patch · MLP 连接器 vs Q-Former · 两阶段对齐 · 动态 / 原生分辨率 · M-RoPE 与交错 M-RoPE · DeepStack · 视觉幻觉

前置：1.2（RoPE 频率谱，本篇的位置编码部分直接用到）、1.3（token 数决定 KV 成本）。

---

## 1. 痛点与钩子：如果没有它，世界会怎样？

一张截图到底吃多少 token？按 Qwen2.5-VL 的 14 像素 patch、2×2 合并设置估算，一个视觉 token 对应 28×28 像素。下面按每边的完整分组向下取整。

| 分辨率 | 视觉 token 数 |
|---|---:|
| 448 × 448 | 256 |
| 1,344 × 896 | 1,536 |
| 1,920 × 1,080 | 2,584 |
| 2,560 × 1,440 | 4,641 |

一个 computer-use Agent 每步截一张 2K 屏，跑 50 步就是二十多万个视觉 token。token 数随分辨率**平方**增长，而降低分辨率又会让小字和按钮看不清。

另一个经典问题是**视觉幻觉**：问"图里有几只狗"，模型回答"两只"，可图里只有一只猫。很多时候不是视觉编码器看错了，而是语言先验压过了视觉证据：问题里出现了"狗"，模型就顺着语言统计往下说。

## 2. 第一性原理：看透它的几何 / 物理直觉

### 2.1 数据流

图片先切成 patch，由 ViT 计算 patch 特征。连接器把这些特征映射到 LLM 的嵌入维度，得到视觉 token。视觉 token 和输入文字的 token 一同进入 LLM，模型继续预测文本输出。

| 连接器 | 做法 | 取舍 |
|---|---|---|
| **MLP 投影** | 相邻 patch 拼接（如 2×2 合并）后过两层 MLP | 简单、保留空间结构；token 数由分辨率决定 |
| **Q-Former / 重采样器** | 一组可学习的 query 通过交叉注意力"读"图像特征 | token 数固定、可压缩；容易丢细节，训练更难 |

2024 年以后，主流开源 VLM 基本都选了 MLP 投影 + 合并，把压缩交给分辨率策略和 token 压缩模块。

### 2.2 训练阶段：每一步解冻什么

| 阶段 | 训练范围和数据 |
|---|---|
| 对齐 | 冻结 ViT 和 LLM，用图文描述数据训练连接器 |
| 联合训练 | 解冻 LLM，可同时解冻 ViT，用多任务、多分辨率数据训练 |
| 指令与偏好 | 用指令微调、偏好优化或 RL 调整输出行为 |

更新的趋势是**原生多模态**：从预训练阶段起就把图文混在一起训练，而不是在纯文本 LLM 上后接视觉。Kimi K3 就是原生多模态模型，在同一个模型里理解文本、图像和视频。

### 2.3 分辨率：三种策略

| 策略 | 怎么处理图像 | 代价 |
|---|---|---|
| 固定尺寸 | 缩到预设尺寸，例如 448×448 | 缩小会丢文字细节，拉伸会改变长宽比 |
| 切块（tiling） | 大图切成多块，通常加全局缩略图 | 单块内保留细节，跨块关系要靠后续整合 |
| 原生分辨率 | 按保留长宽比的可变分辨率编码 | token 数可变，需要支持可变网格的 ViT |

原生分辨率成为主流：SigLIP 2 提供了 NaFlex 变体，一个 checkpoint 支持多种分辨率并保持原始长宽比。但"切块 vs 全局编码"的争论还在继续：LLaVA-UHD v4 发现，即使用专为原生分辨率设计的 MoonViT，切块编码的平均分仍高于全局编码。原因是切块迫使编码器先在局部邻域里提取文字、图表这类细粒度结构。

### 2.4 视觉位置编码：频谱怎么分给三个轴（接 1.2）

文本只有一个位置维度，图像有高、宽，视频还有时间。M-RoPE 把 RoPE 的维度分成三组，分别编码 (t, h, w)；纯文本 token 在三个轴上用同一个位置号，就退化成普通的 1D RoPE。

按维度分组时，每个轴只拿到连续的一段频谱。用 1.2 的钟表画面理解，高频钟在短距离内转得明显，长距离时则多次绕回。低频钟在长距离上更容易区分位置，短距离内转得很少。[Qwen3-VL 技术报告](https://arxiv.org/abs/2511.21631)介绍了**交错 M-RoPE**，把 t、h、w 的频率分配交错排列，让每个轴都覆盖更宽的频率范围。

### 2.5 DeepStack：不只用最后一层

传统做法只取 ViT 最后一层的特征。DeepStack 从 ViT 的多个中间层提取特征，分别注入 LLM 的对应层：浅层特征保留边缘、纹理这类低层信息，深层特征提供语义。

### 图像压缩四倍，整段输入并不会总是缩短四倍

固定图像为 448×448、patch 边长为 14，视觉编码器得到 32×32 个位置。把每个 2×2 邻域送进 merger 后，语言模型接到 16×16 个视觉 token。若同时还有 $T$ 个文本 token，语言模型的输入长度由 $T+1024$ 变为 $T+256$。对全矩形注意力，配对数之比就是这个长度比的平方。

当文本短时，合并图像对 prefill 的影响很大。把文本加长到两千个 token，同样的图像压缩只能改变输入的一部分。实际端到端还要加视觉编码时间；对于实时 OCR，更要核对压缩后能否读出小字。下图只算语言模型接收的序列。

## 3. 承重墙推导：重新捡起核心数学

### Step 1　token 数与成本

$$
N_{\text{vis}} = \Big\lfloor\frac{H}{p\,m}\Big\rfloor\cdot\Big\lfloor\frac{W}{p\,m}\Big\rfloor
$$

$p$ 为 patch 边长，$m$ 为合并边长。宽高各翻倍且忽略边界取整时，视觉 token 数约为四倍。全局注意力的配对数随 ViT patch 数平方增长，LLM 侧的 KV cache 随视觉 token 数线性增长（→ 1.3）。

```academy-lab
3.2
```

调大合并边长时，ViT 使用同一批 patch，连接器才把相邻特征拼起来。把宽高同时缩小会减少 ViT 的输入 patch，也会减少送进 LLM 的视觉 token。这两种改动影响的计算阶段不同。

### Step 2　2×2 合并（像素反洗牌）

$$
\underbrace{(H/p)\times(W/p)\times C}_{\text{patch 网格}} \;\longrightarrow\; \underbrace{(H/2p)\times(W/2p)\times 4C}_{\text{拼接相邻 4 个}} \;\xrightarrow{\text{MLP}}\; (H/2p)\times(W/2p)\times d_{\text{LLM}}
$$

token 数降为 1/4，信息没有丢（只是重新排列到通道维），压缩由后面的 MLP 学习完成。

### Step 3　M-RoPE 的位置号

图像块内第 (i, j) 个 token 的位置号为 $(t_0,\ t_0 + i,\ t_0 + j)$；块之后的文本从 $t_0 + \max(H', W')$ 继续编号。每个轴各自用分到的那组维度做旋转：

$$
\text{score} = \sum_{a\in\{t,h,w\}}\ \big\langle R^{(a)}_{p_a}\,q^{(a)},\ R^{(a)}_{p'_a}\,k^{(a)}\big\rangle
= \sum_a q^{(a)\top} R^{(a)}_{p'_a - p_a}\,k^{(a)}
$$

每个轴只感知自己方向上的**相对**位移。分组分配与交错分配的差别，就在于每个 $R^{(a)}$ 里包含哪些频率。

### Step 4　训练目标：只对文本算损失

$$
\mathcal{L} = -\sum_{t\in\text{文本回答}}\log p_\theta(y_t\mid \text{视觉 token},\ y_{<t})
$$

视觉 token 只作为条件，不预测它们（预测像素是 3.3 统一生成模型的事）。

### Step 5　幻觉的一个最小模型

把回答的分布粗略拆成"语言先验"和"视觉证据"两部分：

$$
\log p(y\mid v, x) \approx \log p(y\mid x) + \lambda(v)\cdot\text{视觉证据}
$$

视觉信号弱（分辨率不够、目标太小、对齐不足）时 λ 很小，回答几乎由 $p(y\mid x)$ 决定，问题里提到什么就回答什么。对比解码类方法据此用"有图"和"无图（或扰动图）"两次 logits 之差来放大视觉证据。

## 4. 极简代码锚点（PyTorch）

视觉 token 计数、2×2 合并的 MLP 连接器、图像块的 M-RoPE 位置号。已跑通，§1 的表格来自 `n_visual_tokens`。

```python
import torch, torch.nn as nn

def n_visual_tokens(H, W, patch=14, merge=2):
    return (H // patch // merge) * (W // patch // merge)       # 1920×1080 → 2584

class Merger(nn.Module):
    """把相邻 m×m 个 patch 拼到通道维，再用 MLP 投影到 LLM 宽度"""
    def __init__(self, d_vit, d_llm, m=2):
        super().__init__(); self.m = m
        self.mlp = nn.Sequential(nn.LayerNorm(d_vit * m * m), nn.Linear(d_vit * m * m, d_llm),
                                 nn.GELU(), nn.Linear(d_llm, d_llm))
    def forward(self, x, gh, gw):                               # x: (B, gh·gw, C) 行优先的 patch 网格
        B, N, C = x.shape; m = self.m
        x = x.view(B, gh // m, m, gw // m, m, C).permute(0, 1, 3, 2, 4, 5)
        x = x.reshape(B, (gh // m) * (gw // m), m * m * C)      # token 数降为 1/m²，信息只是挪到通道维
        return self.mlp(x)                                      # (B, N/m², d_llm)

def mrope_ids(start, gh, gw, t=0):
    """图像块的 (t, h, w) 三轴位置号；文本 token 三轴取同一个值即退化为 1D RoPE"""
    tt = torch.full((gh * gw,), t)
    hh = torch.arange(gh).repeat_interleave(gw)
    ww = torch.arange(gw).repeat(gh)
    return torch.stack([tt, hh, ww]) + start                    # (3, gh·gw)
```

### 数值复算 · 图像压缩四倍，整段输入并不会总是缩短四倍

在同一个 Python 会话中先运行本节上方的实现，再运行以下算例。

```python
import torch
grid = torch.ones(1, 32*32, 2)
with torch.no_grad():
    count = Merger(2, 4, m=2)(grid, 32, 32).shape[1]
assert count == n_visual_tokens(448, 448) == 256
for text in [0, 256, 1024]:
    ratio = (text + count) / (text + grid.shape[1])
    print(f"文本={text:4d}  点积比例={ratio**2:.3f}  投影比例={ratio:.3f}")
```

**运行结果**

```text
文本=   0  点积比例=0.062  投影比例=0.250
文本= 256  点积比例=0.160  投影比例=0.400
文本=1024  点积比例=0.391  投影比例=0.625
```

## 5. 实战直觉、避坑与面试深挖

**2026 前沿现状**
- **Qwen3-VL 的三处架构升级**：交错 M-RoPE（每个时空轴覆盖完整频谱）、DeepStack（多层 ViT 特征注入 LLM 对应层）、用文本时间戳 token 做视频的时间对齐；原生支持 256K token 的图文交错上下文。旗舰 Qwen3-VL-235B-A22B 是 MoE，总参数 235B、每 token 激活 22B。
- **原生多模态成为前沿模型的标配**：Kimi K3 是原生多模态模型，视觉编码器 MoonViT-V2 约 4 亿参数，输入支持文本和图像。
- **编码器：方法比规模重要**：一份 2026 年的视觉编码器综述指出，训练方法上的改进胜过参数规模，400M 参数的 SigLIP 2 在多数 VLM 任务上超过 5.9B 的 InternViT-6B。token 压缩也在快速进步：LLaVA-UHD v3 的渐进式压缩在 SigLIP2 上把视觉 token 从 1024 降到 256，平均分反而从 61.94 升到 64.71。

**与工程 / 应用的连接**
- **截图 Agent 的成本控制**：先确认模型的 patch 和合并设置，再决定截图分辨率；只把需要细看的区域高分辨率送入，其余用缩略图。§1 的公式能直接估算每步的 token 预算。
- **"点错按钮"不一定是理解问题**：computer-use Agent 的坐标定位依赖位置编码和分辨率，缩放截图会让模型输出的坐标与真实屏幕错位。排查时先核对坐标系和缩放比例。
- **OCR 密集任务要分辨率**：文档、表格、代码截图对分辨率极敏感，压分辨率省下的 token 往往会以识别错误的形式还回来。

**常见误区 / 反直觉点**
1. **"视觉 token 越多越好"** ✗：好的压缩可以用 1/4 的 token 达到同等甚至更好的效果。关键是保留哪些信息，而不是保留多少 token。
2. **"冻结视觉编码器一定更稳"** ✗：对齐阶段冻结是为了不破坏预训练表示，但到了联合训练阶段，解冻 ViT 通常能显著提升细粒度任务（文字、定位）的表现。
3. **"VLM 的幻觉是视觉编码器看错了"** ✗：很多幻觉来自语言先验压过视觉证据。把同一问题在有图和无图时的回答对比一下，往往就能看出来。

**高频深挖题**
- **Q1：要让 VLM 读清一张 4K 文档截图，又要控制总 token 数，你会在哪里保留分辨率、在哪里压缩？**
  思路：先算账：4K 截图按 28×28 像素一个 token 是一万多个 → 原生分辨率编码保住小字，切块编码加强局部结构 → MLP 合并 + 渐进式压缩把 token 降到几分之一 → DeepStack 让浅层细节直达 LLM → 位置编码用交错 M-RoPE 保证二维定位 → 评测重点看 OCR 类和定位类基准。
- **Q2：M-RoPE 为什么要"交错"？**
  思路：把 1.2 的钟表画面搬过来：RoPE 的不同维度对是转速不同的钟 → 分组分配时，每个轴只拿到一段频谱，只有高频的轴分不清远距离，只有低频的轴分不清近距离 → 交错让每个轴都覆盖完整频谱 → 收尾：这本质上是一个"频率预算怎么在多个轴之间分配"的问题。
