# 3.3 原生多模态与统一理解生成：语义与像素的矛盾

> **一句话核心直觉**：理解需要的是**抽象语义**（丢掉像素细节，留下"这是一只坐着的猫"），生成需要的是**可还原的像素细节**（保留每一根胡须的纹理）。这对矛盾决定了统一模型的架构分歧：用离散 token 一路自回归（Emu3.5 路线）、自回归文本加扩散图像共享一个 Transformer（Transfusion / BAGEL 路线）、还是理解和生成各用一套视觉编码器（Janus 路线）。
> **唤醒标签**：早融合 · 离散 vs 连续视觉 token · 混合注意力掩码 · 混合 Transformer（MoT）· 解耦编码器 · 多模态世界模型

前置：3.1（视觉表征）、3.2（VLM）、4.2（Flow Matching）。

---

## 1. 痛点与钩子：如果没有它，世界会怎样？

理解和生成长期是两条独立演化的路线：多模态理解几乎都是自回归架构，而图像生成的基石是扩散模型。于是出现了一个常见现象：**同一个产品里，"看图"和"画图"是两个模型**，彼此并不共享对世界的理解。让模型根据一段复杂的多轮对话去编辑一张图，或者在推理过程中画出示意图辅助思考，都需要两者真正打通。

统一的难点不在"能不能拼起来"，而在训练目标的冲突：理解想让视觉表示越抽象越好，生成想让它越完整越好。同一个视觉编码器同时承担两者时，来自两个方向的梯度会互相拉扯。

## 2. 第一性原理：看透它的几何 / 物理直觉

### 2.1 矛盾的根源

| | 理解（VLM） | 生成（文生图） |
|---|---|---|
| 表示要保留什么 | 物体类别、位置、关系 | 纹理、颜色和精确形状 |
| 常用视觉编码 | CLIP / SigLIP 等语义特征 | VAE / VQ 等支持图像重建的表示 |
| 训练目标 | 基于图像预测文本（→ 3.2） | 预测视觉 token 或在图像 latent 上学习去噪 |

### 2.2 三种架构范式

| 范式 | 视觉表示 | 生成方式 | 代表 | 取舍 |
|---|---|---|---|---|
| **纯自回归** | 离散视觉 token（VQ 词表） | 和文本一样逐 token 预测 | Chameleon、Emu3 / Emu3.5 | 架构最统一；离散化有重建上限，逐 token 生成慢 |
| **自回归 + 扩散混合** | 连续的图像 latent | 文本用下一个 token 预测，图像用扩散 / flow 目标 | Transfusion、BAGEL | 图像质量好；一个序列里两种损失、两种注意力 |
| **解耦编码器** | 理解用语义编码器，生成用重建编码器 | 视具体模型而定 | Janus / Janus-Pro | 消除了编码器层面的冲突；两套表示之间的一致性要另外保证 |

### 2.3 混合注意力掩码

在 [Transfusion](https://arxiv.org/abs/2408.11039) 这类自回归与扩散混合模型里，一个序列同时含有文本和图像。先为整条序列构造因果掩码，再为每张图打开该块内部的双向注意力。

```academy-lab
3.3
```

同一张图的 patch 可以交换信息，以便扩散或 flow 联合去噪。文本维持因果约束，未来的文本与图像不会泄露给更早的文本 token。图像块中最后一个 patch 原本已能读同一张图里的所有位置，所以切换掩码只会增加块中更早的行的可见位置。

### 2.4 混合 Transformer：同一个注意力，两套参数

BAGEL 走的是一种并行结构：为理解和生成复制两套参数，但在注意力计算时把不同任务的 token 拼在一起。两种任务各用各的 FFN 和投影层，避免参数层面的互相干扰，同时又通过共享的注意力交换信息。

### 2.5 原生多模态 ≠ 能生成图像

"原生多模态"指的是从预训练起就把多种模态混在一起训练，而不是在纯文本模型上后接视觉模块。Kimi K3 是原生多模态模型，能在同一个模型里理解文本、图像和视频，但它的**输出仍然是文本**。统一理解和生成，是在此基础上更进一步。

## 3. 承重墙推导：重新捡起核心数学

### Step 1　混合模型的联合损失

$$
\mathcal{L} = \underbrace{-\sum_{i\in\text{文本}}\log p_\theta(y_i\mid y_{<i},\ \text{图像})}_{\text{下一个 token 预测}}
\;+\;\lambda\,\underbrace{\mathbb{E}_{t,\varepsilon}\big\|v_\theta(z_t,t\mid\text{上下文}) - (\varepsilon - z_0)\big\|^2}_{\text{图像 latent 上的 flow 损失（→ 4.2）}}
$$

一个 Transformer、一个序列、两种损失。λ 平衡两个目标的梯度尺度，调不好就会出现"理解变强、生成变差"或者相反。

### Step 2　离散化的重建上限

VQ 把每个 patch 映射到大小为 $K$ 的码本中最近的码字。一张图被压成 $n$ 个 token，最多有 $K^n$ 种编码，即 $n\log_2 K$ 比特。比如 512×512 的图按 16 倍下采样得到 32×32=1024 个 token，若 $K=2^{14}$，上限就是 14,336 比特。若两张图得到同一组码字，解码时无法根据码字恢复它们原有的差别。连续 latent 免去最近码字的量化，保真度仍取决于下采样、通道数、有限精度和编码器训练。

### Step 3　生成速度

逐 token 自回归生成 1024 个视觉 token 要 1024 次串行前向。扩散或 flow 一步处理整张图，通常迭代十几到几十次，少步模型可缩到 1–4 次（→ 4.3）。比较实际延时时还要计入一次处理多少 token，以及每种模型的缓存与并行。Emu3.5 使用统一的下一个 token 预测目标训练，推理时借助离散扩散加速视觉生成。

### Step 4　为什么要解耦编码器

共享编码器时，两项损失可能对同一细节产生冲突。如果两者梯度的内积为负，仅沿一项的梯度下降方向做小步更新，会在一阶近似下抬高另一项损失。

$$
\nabla_{\phi}\mathcal{L} = \nabla_\phi\mathcal{L}_{\text{理解}} + \lambda\nabla_\phi\mathcal{L}_{\text{生成}},\qquad \big\langle\nabla_\phi\mathcal{L}_{\text{理解}},\ \nabla_\phi\mathcal{L}_{\text{生成}}\big\rangle < 0
$$

解耦后各用各的编码器，冲突从参数空间里移走了，但两套表示描述的是同一个世界，它们之间的一致性需要靠共享的 LLM 主干和训练数据来保证。

### Step 5　跨模态的一致性问题

统一模型的一个独特失败模式：同一个问题，用文字回答和用图像回答，给出的内容不一致。2026 年已经有工作专门研究统一模型能否在不同输出模态之间保持语义等价。这类问题在"两个独立模型"的方案里不会出现，因为那里本来就没有"同一个模型"的预期。

## 4. 极简代码锚点（PyTorch）

混合注意力掩码（文本因果、图像块内双向）和联合损失的骨架。掩码函数已跑通。

```python
import torch, torch.nn.functional as F

def mixed_mask(segments):
    """segments: [("txt", 3), ("img", 4), ("txt", 2)]。返回 (L, L) 布尔掩码，True 表示可见。"""
    L = sum(n for _, n in segments)
    M = torch.tril(torch.ones(L, L, dtype=torch.bool))        # 默认因果
    s = 0
    for kind, n in segments:
        if kind == "img":
            M[s:s + n, s:s + n] = True                        # 同一张图内部双向可见
        s += n
    return M

def joint_loss(text_logits, text_labels, text_mask, v_pred, z0, eps, lam=1.0):
    """text_logits: (L_txt, V)；v_pred: 模型在图像 latent 上预测的速度；z0 / eps: 干净 latent 与噪声"""
    lm = (F.cross_entropy(text_logits, text_labels, reduction="none") * text_mask).sum() / text_mask.sum()
    flow = (v_pred - (eps - z0)).pow(2).mean()                # t=0 数据、t=1 噪声的条件速度（→ 4.2）
    return lm + lam * flow                                    # λ 平衡两种梯度的尺度
```

## 5. 实战直觉、避坑与面试深挖

**2026 前沿现状**
- **BAGEL**：开源的统一模型，7B 激活参数（14B 总参数），在来自大规模交错图文、视频和网页数据的数万亿 token 上预训练，随着交错数据规模扩大，出现了复杂多模态推理等涌现能力。
- **Emu3.5**：定位为多模态世界模型，统一地预测视觉和语言的下一个状态，端到端用下一个 token 预测训练，推理时用离散扩散加速；后训练阶段用多模态奖励做大规模强化学习，以提升长程生成。
- **"简单基线"依然有竞争力**：2026 年 3 月的 Wallaroo 用纯粹的下一个 token 预测统一了理解、生成和编辑，在多个基准上与其他统一模型相当甚至更好。一份持续更新到 2026 年 1 月的综述把现有统一模型归为扩散、自回归、混合三大范式，并指出图像怎么 token 化、架构怎么设计都还处在早期。
- **前沿主力模型仍以"理解"为主**：Kimi K3 这样的原生多模态模型输出文本；高质量图像生成仍主要由专门的 flow 模型完成（→ 4.2）。

**与工程 / 应用的连接**
- **编辑类应用最受益**：基于多轮对话的图像编辑、带参考图的生成，都需要模型同时理解上下文和生成像素，统一模型在这里有结构性优势。
- **一致性要专门测**：统一模型可能出现"文字说一套、图里画一套"。如果你的应用同时输出文字说明和图像，评测时要单独检查两者是否一致。

**常见误区 / 反直觉点**
1. **"统一模型一定比两个专用模型好"** ✗：统一带来了共享理解和一致性的可能，但也带来了目标冲突。在单项指标上，专用模型往往仍然领先。
2. **"离散 token 和 LLM 天然契合，所以是最优解"** ✗：离散化有硬性的重建信息上限，逐 token 生成也慢。架构统一不等于效果最优。
3. **"原生多模态模型就能生成图像"** ✗：原生多模态指训练方式（从预训练起就混合模态），很多原生多模态模型（如 Kimi K3）的输出仍然只有文本。

**高频深挖题**
- **Q1：比较统一理解生成的三种范式，各自的核心矛盾是什么？**
  思路：先讲根本矛盾：理解要语义、生成要像素 → 纯自回归：架构最统一，但离散化有重建上限、生成慢（Emu3.5 用离散扩散加速）→ 混合：图像质量好，但一个序列两种损失、两种注意力，λ 难调 → 解耦编码器：消除编码器冲突，但两套表示的一致性要另外保证 → 收尾：2026 年简单的纯 NTP 基线依然有竞争力，说明数据和规模的作用可能比范式选择更大。
- **Q2：为什么有些统一模型要给理解和生成用两套视觉编码器？**
  思路：写出两种损失对共享编码器的梯度，指出方向相反（丢细节 vs 留细节）→ 解耦后各自优化，冲突移出参数空间 → 代价：两套表示的一致性靠共享主干和数据保证，可能出现跨模态不一致 → 对照：BAGEL 的混合 Transformer 是另一种折中，参数分开、注意力共享。
