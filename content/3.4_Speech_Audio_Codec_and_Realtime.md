# 3.4 语音与音频：神经编解码与实时对话

> **一句话核心直觉**：语音不是一串天然存在的词，而是随时间连续变化的波形：梅尔谱把它变成便于识别的时频特征，神经编解码器则用多层残差矢量量化（RVQ）把一帧拆成多个可重建的离散码。CTC 把许多不同的帧级对齐路径加起来得到同一句文字的概率；语音生成既要决定说什么，也要决定如何发声。实时对话的响应时间取决于端点判断、输入处理和生成合成的**关键路径**，而全双工还要处理用户随时插话。
>

## 1. 从波形到可计算的表示

一段标准的 16 kHz 单声道音频波形，每秒包含 16,000 个连续的时间域振幅采样点。由于采样点极其密集且缺乏高层离散语义，工程上无法直接将原始采样点视为语言模型的离散 token。

在传统语音识别（ASR）流水线中，业界普遍采用手工设计的时频声学特征——**梅尔频谱图（Mel-spectrogram）**：首先利用短时傅里叶变换（STFT）将时域小窗内的振幅分解到频域，再通过贴合人耳听觉感知特性的梅尔三角滤波器组对频谱能量进行加权聚类，最后取对数压缩动态范围。在窗长 25 ms、帧移步长 10 ms 的经典配置下，一秒钟的长录音产生约 100 帧声学切片；若采用 80 个梅尔频带，每帧即为一个 80 维的连续声学特征向量。梅尔谱能够稳定保留音素在时频上的共振峰轨迹，非常适于作为 ASR 编码器的连续输入，但它缺乏文字离散性，若要将其逆向还原为自然波形，仍需外接复杂的神经声码器（Vocoder）。

另一条演进路径则是端到端训练的**神经音频编解码器（Neural Audio Codec）**：原始波形经由卷积编码器在时域上大幅下采样，压缩为每秒数十帧的低频连续潜向量序列，再通过残差矢量量化（RVQ）映射为离散码本索引；接收端的神经解码器仅依据这串离散索引即可高保真重建物理波形。与 ASR 编码器“滤除背景以抽提语义”的目标相反，音频编解码器致力于极致保留发音者的音色、呼吸、停顿乃至环境声学细节。EnCodec、SoundStream 以及 Mimi 均属于这一范式。

## 2. RVQ：用后续码本编码前一层的误差

单个矢量量化（VQ）在码本过大时容易发生索引利用率坍塌。残差矢量量化（Residual Vector Quantization, RVQ）采用多层级联的离散码本：对某一帧的连续潜向量 $z$，第 1 层码本检索与其欧式距离最近的码字向量 $e^{(1)}_{i_1}$，得到初始粗粒度量化值 $\hat z_1$；第 2 层码本不再对原始向量 $z$ 建模，而是专攻第 1 层遗留的重建残差向量 $z - \hat z_1$。以此类推，逐级逼近：

$$
r_0=z,\qquad i_\ell=\arg\min_i\|r_{\ell-1}-e^{(\ell)}_i\|^2,\qquad
r_\ell=r_{\ell-1}-e^{(\ell)}_{i_\ell},\qquad
\hat z_L=\sum_{\ell=1}^L e^{(\ell)}_{i_\ell}.
$$

在网络传输或序列建模时，每一帧只需按层输出 $L$ 个离散索引标量 $(i_1, i_2, \dots, i_L)$。解码端依据预置的共享码本查表取出对应向量并求和叠加，恢复出潜向量 $\hat{z}_L$，最后喂入波形生成解码器。

当各层码本均包含零向量时，选择最近邻的残差范数绝不可能劣于保持不动（选零），因此在理论推演与玩具实验中，重构均方误差（MSE）随启用码本层数 $L$ 的增加单调递减；但其代价是传输索引与 token 开销随层数呈线性增加。**在工业真实落地中，这并不等于无条件质量保障**：工业级码本通常不含强制零向量，且端到端训练涵盖对抗判别损失（GAN）与感知损失；单纯压低潜空间 MSE，并不必然等价于人类主观听感（MOS 分）更自然。

### 2.1 为什么每秒语音 token 比文字多

设音频帧率为 $f$，每帧启用 $L$ 层 RVQ 码本，每个码本拥有 $K$ 个码字候选，其定长编码的基础物理账目为：

$$
\text{索引数/秒}=fL,\qquad \text{比特/秒}=fL\lceil\log_2 K\rceil.
$$

以典型的 50 帧/秒、8 层码本、每层 1024 码字为例，一秒语音即产生 $50 \times 8 = 400$ 个离散索引，对应净码率为 $400 \times 10 = 4000$ bit/s（4 kbit/s）。相比未经压缩的 24 kHz / 16 bit 单声道 PCM 裸音频流（$24000 \times 16 = 384$ kbit/s），编解码器实现了近百倍的高倍率无损压缩。

但对比自然语言文本：一段 1 秒钟的正常人类语速，对应的文本分词通常仅消耗 3 到 5 个自然语言 token；同一秒内音频离散索引的数量是文本 token 的近百倍之多。**然而，高 token 数量并不意味着必须付出百倍串行生成的时延代价。** 在自回归生成架构中，模型可以采用并行预测头（同时前向预测一帧的 8 个码本）、时间延迟模式（Delay Pattern，在时间步间错位滑动）或“粗码自回归 + 细码并行扩散”的分级混合生成策略，在保证表达密度的同时打破串行推理时延瓶颈。

## 3. ASR：一段声音如何对齐成一句文字

语音识别系统的核心使命是将连续的声学特征序列映射为离散的自然语言字符序列。经典的“编码器—解码器（Encoder-Decoder）”方案中，文字解码器基于声学编码器的帧特征以及已生成的文本前缀，自回归预测下一个文字 token：

$$
p(y\mid x)=\prod_{j=1}^{|y|}p(y_j\mid y_{<j},\operatorname{Enc}(x)).
$$

该框架通过跨模态交叉注意力（Cross-Attention）隐式建立时间帧与文本字词之间的软对齐，无需昂贵的人工逐帧音素对齐标注。但必须注意：离线系统可以纵览整段音频的双向全局上下文；而流式实时系统必须严格限制编码器的未来感知窗（Chunk-based 或 Causal Masking），方能实现低时延增量输出。

### 3.1 CTC：将对齐视为隐变量

连接主义时间分类（Connectionist Temporal Classification, CTC）为每个输入声学帧输出全量词表字符以及一个特殊的空白占位符 blank（记为 `_`）的概率分布。在**给定声学编码器表征后各帧输出概率条件独立**的假设下，一条完整的帧级输出路径 $\pi = (\pi_1, \pi_2, \dots, \pi_T)$ 的联合概率等于各时间步概率的连乘积。

折叠算子 $\mathcal{B}$ 首先将连续相邻的相同符号合并为一个，随后将所有 blank 符号全部剥离，从而将海量长度为 $T$ 的对齐路径压缩映射回单一标准文本序列 $y$：

$$
p(y\mid x)=\sum_{\pi:\, \mathcal{B}(\pi)=y}\prod_{t=1}^{T}p_t(\pi_t\mid x),\qquad
\mathcal L_{\mathrm{CTC}}=-\log p(y\mid x).
$$

Blank 符号的设计至关重要：例如路径 `aa_` 折叠为单字 `a`，而 `a_a` 则被精准保留折叠为双字 `aa`——blank 充当了阻断相邻相同字符发生错误黏合的物理时空隔离墙。训练中利用动态规划的前向—后向算法（Forward-Backward Algorithm）高效计算所有合法路径概率之和。

在推理阶段，逐帧贪心选取概率最大符号再执行折叠的操作称为“贪心 CTC 解码”；但必须澄清：**最高概率路径折叠后的文本，并不必然等同于所有路径联合概率和最大的全局最优文本序列**。工业流式场景通常借助 Beam Search 束搜索算法合并同前缀路径，并外挂自然语言模型以矫正声学混淆。

## 4. TTS：从要说什么，到怎样发声

语音合成（TTS）要求模型在决定文本字符内容的同时，决定发音者的音色、语调、微观韵律与停顿。前沿架构普遍采用“语义到声学”的两阶段解耦范式：
1. **语义建模阶段（Semantic Stage）**：从输入的文字或音素序列自回归预测出高度抽象、剔除环境噪声但保留发音内容的**语义 token**（如基于 w2v-BERT、HuBERT 提取的高维表征）；
2. **声学建模阶段（Acoustic Stage）**：以语义 token 序列、目标说话人提示音频（Prompt Audio）为先验条件，联合生成细腻刻画音色质感、呼吸细节与基频起伏的低层**声学 token**（如 RVQ 码本序列）；
3. **波形合成阶段**：由神经音频编解码器的解码器或轻量流匹配声码器并行输出物理时域波形。

这一分工的精髓在于关注点分离：语义阶段专注于文本与音素的精准对应（避免漏字、错读与重复发音），声学阶段专注于发声风格与音色还原。

## 5. 实时语音：把计时起点和依赖写清楚

评估实时全双工语音助手时，最容易出现认知的关键误区是**将整个输入语句的时长计入响应时延**。实际上，当用户在开口说话时，客户端音频采集、分块上传、流式声学编码与前缀转写已经在并行推进。

我们建立一个严密且符合物理因果的实时交互延迟依赖模型：以用户最后一个发音振幅样本结束的物理时刻记为 $t = 0$；系统端到端输出首块可听音频的耗时受关键路径控制：

$$
t_{\text{首块}}=\max(E,R)+G+S+N.
$$

各项具有严格物理定义：
- **$E$（端点确认时刻，Endpointing VAD）**：系统静音检测算法确认用户确实已经讲完话而非呼吸短暂停顿的判决完成时刻；
- **$R$（输入尾包处理完成时刻）**：包含用户最后一截音频的上传传输、流式 ASR 或原生音频编码模型消化完毕的时刻；
- **$G$（首个回复单元生成时延）**：语言模型生成出第一个能够派发合成的语义文本词或语音 token 所需的推理时间；
- **$S$（TTS 首块音频合成时延）**：流式语音合成器将首个词块渲染为时域波形的时间；
- **$N$（下行与播放缓冲时延）**：音频首包下行网络传输及终端防断续抖动缓冲（Jitter Buffer）耗时。

由于端点判断 $E$ 与输入处理 $R$ 在时间线上并行重叠，二者取最大值 $\max(E, R)$ 决定了触发下游生成的咽喉关口。若当前 $E = 180$ ms、$R = 120$ ms、$G = 100$ ms、$S = 80$ ms、$N = 60$ ms，端到端首块时延为 $\max(180, 120) + 100 + 80 + 60 = 420$ ms；而若盲目假设输入必须在端点确认后才串行启动，推算出的顺序基线则高达 $180 + 120 + 100 + 80 + 60 = 540$ ms。

### 5.1 流式不等于全双工

能够以流式 chunk 处理输入并边生成边播放，仅仅迈过了“流式交互”的门槛；真正的**全双工（Full-Duplex）**交互提出了三项更严苛的系统工程要求：
1. **声学回声消除（AEC）**：扬声器播放助手声音的同时，麦克风会拾取到自身的强烈回声，必须在物理输入端毫秒级完全抵消消除，避免模型自我打断与自说自话；
2. **打断判别与插话仲裁（Barge-in）**：用户在助手讲话时随时可能开口；系统必须在 150–200 ms 内精准判别出用户是真性打断对话（需瞬间停播、重置生成状态并退回监听），还是仅仅在给出自然倾听反馈（Backchannel，如“嗯”、“对”、“好的”，此时助手应继续流畅发声而非停顿）；
3. **端到端原生对齐建模**：如 Kyutai 提出的 Moshi 模型，在单一大模型架构内部构建跨通道的双流交织序列，同时预测用户信道与助手信道的音频 token，在表征底层打通了实时双向倾听与表达。

## 6. 数值复算

### 数值复算 · RVQ 的逐层残差

第一段逐样本执行最近邻 RVQ，恰好对应上方实验的均匀网格、3 码字和 50 帧/秒；它只用 Python 标准库，可直接在普通 CPU 运行。

```python
xs = [i / 100 for i in range(-100, 101)]
rec = [0.0] * len(xs)
for layer in range(1, 7):
    radius = 0.5 ** (layer - 1)
    codes = (-radius, 0.0, radius)
    for i, x in enumerate(xs):
        residual = x - rec[i]
        rec[i] += min(codes, key=lambda c: abs(residual - c))
    mse = sum((x - y) ** 2 for x, y in zip(xs, rec)) / len(xs)
    print(f"L={layer} MSE={mse:.6f} 符号/秒={50*layer} 比特/秒={100*layer}")
```

**运行结果**

### 数值复算 · CTC 路径与首包延迟

第二段枚举三个时间步的全部 CTC 路径，先合并相邻重复再去 blank，并把折叠到同一结果的概率相加；随后独立计算首包延迟的关键路径。

```python
import itertools
import math

probs = {"a": 0.6, "_": 0.4}
totals = {}
for path in itertools.product(("a", "_"), repeat=3):
    collapsed = []
    prev = None
    for symbol in path:
        if symbol != prev and symbol != "_":
            collapsed.append(symbol)
        prev = symbol
    result = "".join(collapsed) or "∅"
    totals[result] = totals.get(result, 0) + math.prod(probs[c] for c in path)
for result in ["∅", "a", "aa"]:
    print(f"{result}: {totals[result]:.3f}")
E, R, G, S, N = 180, 120, 100, 80, 60
print(f"首包={max(E, R)+G+S+N} ms 顺序基线={E+R+G+S+N} ms")
```

**运行结果**

```text
∅: 0.064
a: 0.792
aa: 0.144
首包=420 ms 顺序基线=540 ms
```

## 7. 练习（附解答）

**练习 1。** 75 帧/秒、8 层、每层 1024 个码字，定长码流每秒多少索引和比特？如果一帧的 8 层都由一个并行头同时预测，有多少时间步？

**解。** $75\times8=600$ 个索引、$600\times10=6000$ bit/s；并行预测时是 75 个时间步。这里的位率未计容器和纠错开销，时间步也不能单独代表真实耗时。

**练习 2。** 某流水线的 $E=220$ ms、$R=300$ ms、$G=80$ ms、$S=70$ ms、$N=50$ ms。把端点检测缩短 100 ms 能节省多少？把 $R$ 从 300 缩到 200 ms 又能节省多少？

**解。** 初始为 $300+80+70+50=500$ ms。只缩短 $E$ 没有效果；单独把 $R$ 改为 200 ms 后由 $E=220$ ms 决定，首包为 420 ms，节省 80 ms。两种修改是分别比较原始流水线。

**练习 3。** CTC 目标是 `book`，至少要多少帧？`b_o_ok` 是否也是合法路径？

**解。** 四个字符中 `oo` 相邻重复，至少需要 $4+1=5$ 帧，例如 `bo_ok`。`b_o_ok` 虽然也合法并折叠为 `book`，它不是最短路径；这两种路径都要参与求和。
