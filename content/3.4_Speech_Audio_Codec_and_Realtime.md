# 3.4 语音与音频：神经编解码与实时对话

> **一句话核心直觉**：语音不是一串天然存在的词，而是随时间连续变化的波形：梅尔谱把它变成便于识别的时频特征，神经编解码器则用多层残差矢量量化（RVQ）把一帧拆成多个可重建的离散码。CTC 把许多不同的帧级对齐路径加起来得到同一句文字的概率；语音生成既要决定说什么，也要决定如何发声。实时对话的响应时间取决于端点判断、输入处理和生成合成的**关键路径**，而全双工还要处理用户随时插话。
>
> **唤醒标签**：波形 → 梅尔谱 / codec · RVQ 残差 · 帧率 × 码本层数 · CTC 路径求和与 blank · 语义 / 声学 token · 首包关键路径 · 端点误切 · 全双工与打断

前置：3.2（模态对齐）、3.3（多模态生成）、4.5（离散表示）。

## 1. 从波形到可计算的表示

16 kHz 单声道波形每秒是 16,000 个连续幅度样本，不能直接把每个采样点当成语言模型的一个词。最常见的识别前端先用短时傅里叶变换（STFT）把短窗内的波形分解到频率上，再按人耳感知设计的梅尔滤波器组汇总能量，最后取对数。窗长 25 ms、步长 10 ms 时，长录音约每秒产生 100 帧；如果有 80 个梅尔频带，一帧就是 80 维连续特征。窗口重叠，开头结尾帧数会随填充规则略变。

梅尔谱保留时间和频率上的语音线索，适合作为 ASR 编码器的输入，但它本身不是文字，也不是自然可读的离散 token；要从它合成波形还需要声码器。另一条路是训练神经编解码器：波形经过编码器下采样，得到每帧一个连续向量，再量化成离散索引，解码器据此重建波形。压缩重建与语音识别关注的信息不同：前者要尽可能保留音色、韵律和背景细节，后者更关心说了什么。EnCodec、SoundStream 是神经音频编解码器的例子。

## 2. RVQ：用后续码本编码前一层的误差

对某一帧的潜向量 $z$，第 1 层码本选最近码字 $e^{(1)}_{i_1}$，重建得到 $\hat z_1$；第 2 层不再量化 $z$ 本身，而是量化没表示好的残差 $z-\hat z_1$。依此类推：

$$
r_0=z,\qquad i_\ell=\arg\min_i\|r_{\ell-1}-e^{(\ell)}_i\|^2,\qquad
r_\ell=r_{\ell-1}-e^{(\ell)}_{i_\ell},\qquad
\hat z_L=\sum_{\ell=1}^L e^{(\ell)}_{i_\ell}.
$$

每层只需传一个码字的索引。编码器和解码器预先共享码本，解码器按索引取出向量并相加，然后把得到的潜序列送入波形解码器。真正的训练还涉及量化的梯度近似、重建损失及改善感知质量的损失；这几个公式描述的是推理时的量化与重建，不能单独推断训练效果。

固定每层码本，且每层都含零向量时，最近邻的残差范数不可能比选零更大。所以本实验的重建均方误差随层数不升，代价是索引随层数线性增多。**这不是所有 codec 的无条件保证**：真实码本未必含零，不同层数的模型还可能分别训练；潜空间 MSE 降低也不等于人听起来一定更自然。

### 2.1 为什么每秒语音 token 比文字多

帧率为 $f$，每帧启用 $L$ 个码本、每个码本 $K$ 个码字，定长编码的基础账目是

$$
\text{索引数/秒}=fL,\qquad \text{比特/秒}=fL\lceil\log_2 K\rceil.
$$

例如假设 50 帧/秒、8 层、每层 1024 个码字，一秒有 400 个离散索引，需要 $400\times10=4000$ bit；它对应 **4 kbit/s 的码本索引**，不含头信息等额外开销。作为比较，24 kHz、16 bit、单声道 PCM 是 $24000\times16=384$ kbit/s。若某段转写平均每秒 4 个文本 token，同一秒有约 100 倍的音频码本索引；这个比例随语言、语速、分词器和 codec 改变，不能当成所有语音的常数。

**索引数也不等于必然的串行步数。** 模型可以把各层索引依次展开，也可以对同一时刻的多个码本并行预测，或先自回归预测粗码再并行补细码。比较计算量时要注明预测方式、时间步数、每步输出头和上下文；仅拿两个模态的“token 数”相除不能得出延迟比。

## 3. ASR：一段声音如何对齐成一句文字

ASR 编码器先把声学特征压成帧序列。编码器—解码器方法让文字解码器基于声音表示和已生成的前缀预测下一个文字 token：

$$
p(y\mid x)=\prod_{j=1}^{|y|}p(y_j\mid y_{<j},\operatorname{Enc}(x)).
$$

这里不要求人工标每个字对应的精确起止帧；交叉注意力可以学习软对齐。离线系统可能看到整段音频，流式系统需要限制未来上下文或按块处理，不能仅凭“编码器—解码器”这个名称推断它能实时输出。

### 3.1 CTC：将对齐视为隐变量

CTC 为每个输入时间步输出字符（或子词）及特殊符号 blank 的分布。假设**给定编码器表示后各帧输出的路径概率可相乘**，一条路径 $\pi$ 的概率是 $\prod_t p_t(\pi_t\mid x)$。折叠函数 $B$ 先合并相邻重复符号，再删除 blank，把不同路径归到同一个文字序列：

$$
p(y\mid x)=\sum_{\pi:\, B(\pi)=y}\prod_{t=1}^{T}p_t(\pi_t\mid x),\qquad
\mathcal L_{\mathrm{CTC}}=-\log p(y\mid x).
$$

例如 `aa_` 折叠为 `a`，而 `a_a` 折叠为 `aa`：blank 使两个相同字符不会被合并。同一个目标可能有大量路径，训练时用动态规划求和，不必枚举。三个时间步每步 $p(a)=0.6$、$p(\_)=0.4$，穷举可得 $P(a)=0.792$、$P(aa)=0.144$、$P(\varnothing)=0.064$，见[下方可运行算例](#worked-example-2)。如果目标包含相邻重复字符，就需要中间 blank，因此可用帧数至少是目标长度加相邻重复对数。

逐帧取最大概率再折叠叫贪心 CTC 解码；它找的是最高概率的**路径**，不一定是路径概率之和最大的**文字序列**。束搜索可以合并同一前缀的路径，也可结合语言模型。CTC 本身并不强制编码器因果：用双向编码器时每帧仍可能依赖未来声音。流式系统要另外限制编码器的未来窗口，并评估部分转写反复改写造成的体验问题。

## 4. TTS：从要说什么，到怎样发声

文字转语音需要同时决定文字内容、声音、音色、节奏与停顿。一类两级系统先从文字或音素预测相对抽象的**语义 token**，再以语义序列、说话人或提示音频为条件生成更细的**声学 token**；最后 codec 解码器或声码器产生波形。前一级更接近内容，后一级为高保真重建补足声音细节。SPEAR-TTS 是文本、语义和声学建模的例子；AudioLM 展示了语义与声学 token 对音频生成的分工。

不是所有 TTS 都遵循这一流水线。VALL-E 以文字、提示音频和神经 codec 码为条件生成语音；其他系统也可能直接预测梅尔谱，或者用连续潜变量及扩散 / flow 合成。语义与声学的划分是架构选择而不是完全隔离：语义 token 仍可能携带说话人信息，声学 token 也携带内容。

工程上需分别听和测：文字是否漏读错读、是否保留指定说话人、长句中的节奏与韵律是否自然，以及生成速度能否维持播放。参考音色的授权、噪声和语种也会改变任务设置。仅以重建 MSE 排序，可能漏掉足以使人听出合成感的失真。

## 5. 实时语音：把计时起点和依赖写清楚

用户刚说完到听见助手第一块语音，中间可能有上行、分块与上下文、ASR 或原生音频理解、说话结束检测、模型回复、TTS 首块、下行和播放缓冲。很多操作在用户讲话时已并行进行，**不能把整个用户话语时长再次加到说完后的响应延迟里**。

考虑一个明确的玩具流水线：从用户最后一个声音样本结束时刻记 $t=0$；$E$ 是端点确认完成时刻，$R$ 是含输入传输与剩余理解处理的完成时刻，二者可以重叠。回复要等两者完成；其后依次需要 $G$ 生成首个可合成单元、$S$ 合成首块、$N$ 完成下行与播放缓冲：

$$
t_{\text{首块}}=\max(E,R)+G+S+N.
$$

若 $E=180$、$R=120$、$G=100$、$S=80$、$N=60$，单位均为 ms，首块是 420 ms。假设输入处理必须等端点之后才启动，则这一对比基线为 $180+120+100+80+60=540$ ms。现实系统还可能让语言模型和 TTS 部分重叠、提前回应或存在排队，这时要重画依赖图；公式不能不加检查地直接套用。

[用 Python 复算首包延迟](#worked-example-2)。这里 $E$ 和 $R$ 是同一个起点下的**完成时刻**，而非总录音时长。先缩短关键路径：在示例中将 $R$ 从 120 降到 70 ms 不改变 420 ms，因为仍需等待 $E=180$ ms。把端点等待砍得过短，又可能把自然停顿当成说完。上线要看端点误切率、漏切率、首个可听音频的 p50/p95、排队时间、生成实时率、音频断续和用户打断成功率，而非只看首个文本 token。

### 5.1 流式不等于全双工

流式可以在输入未结束时增量处理，也可以分块播放输出；**全双工**进一步要求系统在播放时仍能监听输入、处理重叠说话与插话，并及时停止或调整自己的输出。播放音频可能被麦克风重新采到，因此还要考虑回声消除；对“嗯”“继续”等反馈也不能一律当作打断。Moshi 等原生语音对话模型探索了同时建模对话音频流；实际可用性仍由硬件、网络、语音活动检测和产品策略共同决定。

## 6. 数值复算

### 数值复算 · RVQ 的逐层残差

第一段逐样本执行最近邻 RVQ，恰好对应上方实验的均匀网格、3 码字和 50 帧/秒；它只用 Python 标准库，可直接在普通 CPU 运行。

```python
xs = [i / 100 for i in range(-100, 101)]
rec = [0.0] * len(xs)
for layer in range(1, 7):
    radius = 0.5 ** (layer - 1)
    codes = (-radius, 0.0, radius)
    for i, x in enumerate(xs):
        residual = x - rec[i]
        rec[i] += min(codes, key=lambda c: abs(residual - c))
    mse = sum((x - y) ** 2 for x, y in zip(xs, rec)) / len(xs)
    print(f"L={layer} MSE={mse:.6f} 符号/秒={50*layer} 比特/秒={100*layer}")
```

**运行结果**

```text
L=1 MSE=0.082935 符号/秒=50 比特/秒=100
L=2 MSE=0.020746 符号/秒=100 比特/秒=200
L=3 MSE=0.005174 符号/秒=150 比特/秒=300
L=4 MSE=0.001294 符号/秒=200 比特/秒=400
L=5 MSE=0.000323 符号/秒=250 比特/秒=500
L=6 MSE=0.000081 符号/秒=300 比特/秒=600
```

### 数值复算 · CTC 路径与首包延迟

第二段枚举三个时间步的全部 CTC 路径，先合并相邻重复再去 blank，并把折叠到同一结果的概率相加；随后独立计算首包延迟的关键路径。

```python
import itertools
import math

probs = {"a": 0.6, "_": 0.4}
totals = {}
for path in itertools.product(("a", "_"), repeat=3):
    collapsed = []
    prev = None
    for symbol in path:
        if symbol != prev and symbol != "_":
            collapsed.append(symbol)
        prev = symbol
    result = "".join(collapsed) or "∅"
    totals[result] = totals.get(result, 0) + math.prod(probs[c] for c in path)
for result in ["∅", "a", "aa"]:
    print(f"{result}: {totals[result]:.3f}")
E, R, G, S, N = 180, 120, 100, 80, 60
print(f"首包={max(E, R)+G+S+N} ms 顺序基线={E+R+G+S+N} ms")
```

**运行结果**

```text
∅: 0.064
a: 0.792
aa: 0.144
首包=420 ms 顺序基线=540 ms
```

## 7. 练习（附解答）

**练习 1。** 75 帧/秒、8 层、每层 1024 个码字，定长码流每秒多少索引和比特？如果一帧的 8 层都由一个并行头同时预测，有多少时间步？

**解。** $75\times8=600$ 个索引、$600\times10=6000$ bit/s；并行预测时是 75 个时间步。这里的位率未计容器和纠错开销，时间步也不能单独代表真实耗时。

**练习 2。** 某流水线的 $E=220$ ms、$R=300$ ms、$G=80$ ms、$S=70$ ms、$N=50$ ms。把端点检测缩短 100 ms 能节省多少？把 $R$ 从 300 缩到 200 ms 又能节省多少？

**解。** 初始为 $300+80+70+50=500$ ms。只缩短 $E$ 没有效果；单独把 $R$ 改为 200 ms 后由 $E=220$ ms 决定，首包为 420 ms，节省 80 ms。两种修改是分别比较原始流水线。

**练习 3。** CTC 目标是 `book`，至少要多少帧？`b_o_ok` 是否也是合法路径？

**解。** 四个字符中 `oo` 相邻重复，至少需要 $4+1=5$ 帧，例如 `bo_ok`。`b_o_ok` 虽然也合法并折叠为 `book`，它不是最短路径；这两种路径都要参与求和。
