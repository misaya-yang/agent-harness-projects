# 5.3 训练诊断：读懂 Loss 曲线与数值稳定

> **一句话核心直觉**：Loss 曲线是训练的心电图。读它的方法不是"看涨跌"，而是对每一种异常形状（尖刺、平台、发散、loss 降了但下游不涨）都备好一张"前三个嫌疑人 + 各自的验证实验"清单。大模型训练的稳定性问题，几乎都能追到少数几个数值源头：**注意力 logit 失控、输出 logit 漂移、MoE 里的离群激活、学习率与 batch 的配合**。
> **唤醒标签**：loss spike · grad norm · QK-norm / QK-Clip · z-loss · warmup-stable-decay · 离群激活 · 回滚与跳批

前置：5.1（显存与算力）、1.1（残差流与归一化）、1.4（MoE 路由）。

---

## 1. 痛点与钩子：如果没有它，世界会怎样？

一次万卡规模的预训练，第 5 万步 loss 突然跳高。最常见的第一反应是"回滚到上一个 checkpoint、跳过这批数据"。DeepSeek-V4 的技术报告记录了这种做法的局限：**简单回滚能暂时恢复训练状态，却无法阻止尖刺再次出现**；他们进一步发现，尖刺的出现始终与 MoE 层里的离群值相关，路由机制似乎还会加剧这些离群值。

另一个例子来自 Kimi K2：Muon 优化器的 token 效率更高，但规模放大后出现了注意力 logit 爆炸，**这在 Muon 下比在 AdamW 下更频繁**。加上 QK-Clip 之后，K2 在 15.5T token 的预训练中没有出现一次 loss 尖刺。

每一次尖刺都意味着整个集群回滚、重跑几个小时。会诊断，省下的是真金白银；会预防，才是大模型训练团队真正的门槛。

## 2. 第一性原理：看透它的几何 / 物理直觉

### 2.1 异常形状 → 嫌疑人清单

| 曲线形状 | 前三个嫌疑人 | 怎么验证 | 常见干预 |
|---|---|---|---|
| **尖刺**（突然跳高） | ① 坏数据批次 ② 注意力 logit 失控 ③ MoE 离群激活 / 路由抖动 | 在尖刺前的 checkpoint 上重放同一批数据：复现 → 动力学问题，不复现 → 数据问题；看每个头的最大 logit、各层梯度范数、激活最大值 | 回滚 + 跳批、QK-Norm / QK-Clip、z-loss、梯度裁剪、激活截断、降学习率 |
| **早期平台**（loss 不降） | ① 学习率过低或 warmup 过长 ② loss mask / 标签错位 ③ 数据没打乱或重复 | 小规模过拟合一个 batch：降不下去就是实现 bug | 修 bug、调学习率、检查数据管线 |
| **发散**（NaN / inf） | ① 数值溢出（FP8 缩放、FP16 无 loss scaling）② 学习率过大 ③ 初始化 | 定位第一个出现 inf 的层和张量 | 降学习率、检查缩放因子、换精度、修初始化 |
| **缓慢上漂**（长期训练后 loss 抬头） | ① 输出 logit 漂移 ② 权重范数持续增长 ③ 数据分布切换 | 看 log Z 和各层权重范数的趋势 | z-loss、权重衰减、检查数据配比切换点 |
| **loss 降、下游不涨** | ① 过拟合或记忆 ② 数据配比偏了 ③ 评测本身有问题 | 看验证集 loss、分领域 loss、评测协议（→ 5.4） | 调配比、去重、修评测 |

**万能的第一步**：先把"数据问题"和"动力学问题"分开。在尖刺前的 checkpoint 上重放同一批数据，这一个实验就能把排查空间砍掉一半。

### 2.2 注意力 logit 为什么会失控

```
logit = q · k / √d = (W_q x)·(W_k x) / √d
           ↑ 随 ‖W_q‖·‖W_k‖ 增长

logit 变大 → softmax 饱和（几乎 one-hot）→ 梯度要么消失、要么集中在极少数位置
→ 更新更激进 → 权重继续变大 → logit 继续变大 …… 正反馈
```

三种刹车：
- **QK-Norm**：对 q、k 先做归一化再点积，logit 被天然限幅。但它要求 key 在推理时能被显式归一化，**MLA 推理时根本不展开 key**（→ 1.3），所以用不了。
- **logit soft-capping**：用 tanh 把 logit 压进一个范围，代价是扭曲注意力分布。
- **QK-Clip**（Kimi K2）：不改前向，每步更新后检查每个头的最大 logit，超过阈值就把该头的 $W_q$、$W_k$ 按比例缩小（§3 Step 1）。从权重这个源头下手，而且只动出问题的头。

### 2.3 学习率调度：warmup → 平台 → 衰减

```
lr
 │      ┌─────────────────────────────┐
 │     ╱                               ╲
 │    ╱                                 ╲___
 └───┴───────────────────────────────────┴──► step
   warmup        平台（大部分训练）          衰减
```

DeepSeek-V4 的设置就是这种形状：前 2000 步线性 warmup，大部分训练保持常数，最后做余弦衰减；V4-Flash 的峰值学习率是 2.7×10⁻⁴、V4-Pro 是 2.0×10⁻⁴，都衰减到峰值的十分之一。同时 batch 大小逐步增大（Flash 最大 7550 万 token，Pro 最大 9440 万 token），序列长度从 4K 依次扩展到 16K、64K、1M。

**读曲线时的一个陷阱**：进入衰减阶段后 loss 会明显加速下降，这是学习率降低带来的，不代表这段数据"更好"。这类调度的好处是可以从平台期任意一个 checkpoint 分叉出去做衰减，便宜地评估"如果现在结束训练会怎样"。

### 2.4 低精度训练的三个坑

```
① 缩放因子跟不上   FP8 的动态范围很窄，每个张量都要配缩放因子。整个张量只配一个因子时，
                   一个离群值就会把其余数值全部挤进下溢区。
                   → 细粒度缩放：DeepSeek-V3 对激活按 1×128 的小块、对权重按 128×128 的块分别缩放
② 离群激活         巨量激活（→ 1.1 的注意力汇）和 MoE 层里的离群值，是低精度的天敌
                   → 门控注意力、激活截断这类结构改动，同时也是在为低精度训练和推理铺路
③ 累加精度         低精度相乘，累加必须在更高精度里做；主权重和优化器状态保持 FP32（→ 5.1），
                   否则微小的更新会被舍入成 0
```

诊断时的一个信号：同样的配置，BF16 跑得稳、FP8 出现尖刺或缓慢发散，优先怀疑①和②；只有 RL 阶段出问题，还要考虑训推精度不一致（→ 2.7）。

### 2.5 监控面板该有什么

```
基础    train / val loss、学习率、tokens/s、MFU
梯度    全局梯度范数、逐层梯度范数、被裁剪的步数比例
更新    更新量 / 权重范数（逐层）
数值    每个头的最大注意力 logit、输出层 log Z、激活最大值 / 峰度
MoE     各专家负载、router 熵、被丢弃的 token 比例
```

## 3. 承重墙推导：重新捡起核心数学

### Step 1　QK-Clip

每个头在本 batch 内的最大 logit：

$$
S^h_{\max} = \frac{1}{\sqrt d}\max_{X\in\mathcal{B}}\max_{i,j} Q^h_i K^{h\top}_j
$$

超过阈值 τ 时，令 $\gamma = \min(1, \tau/S^h_{\max})$，在优化器更新之后缩放：

$$
W_q^h \leftarrow \gamma^{\alpha} W_q^h,\qquad W_k^h \leftarrow \gamma^{1-\alpha} W_k^h,\qquad \alpha = 0.5
$$

- 下一步的 logit 恰好被缩放 γ 倍（本篇代码实测：τ=100、$S_{\max}$=400 时 logit 缩放为 0.25）。
- **设计巧妙之处**：它不改变当前步的前向和反向，只把最大 logit 当作引导信号；实践中只有少数几个头会爆炸，所以按头处理，不影响其他头。
- 在 MLA 上要区分：共享的 RoPE key 被所有头共用，不能按单个头去缩放，只能缩放每个头独有的部分。

### Step 2　z-loss：免费的输出层稳定器

$$
\mathcal{L}_z = \lambda\,\Big(\log\sum_j e^{z_j}\Big)^2,\qquad \lambda \approx 10^{-4}
$$

softmax 对 logits 的整体平移不变，所以把 $\log Z$ 往 0 拉**不改变任何预测**，却能把输出 logits 保持在数值安全的范围内，防止它在长训练中缓慢漂移、最终溢出。

### Step 3　梯度裁剪与它的报警含义

$$
g \leftarrow g\cdot\min\Big(1,\ \frac{c}{\|g\|}\Big)
$$

裁剪本身是保险丝。如果**大部分步都在被裁剪**，说明学习率或数值本身有问题，裁剪只是在掩盖症状。监控"被裁剪的步数比例"比看梯度范数本身更有诊断价值。

### Step 4　尖刺检测与自动应对

用指数滑动平均跟踪 loss 的均值 m 和方差 v，当 $\ell_t > m + k\sqrt v$ 时判定为尖刺（异常点不更新统计量，避免把尖刺吸收进基线）。检测到之后：

- **回滚 + 跳批**：针对数据问题。
- **切换到稳定模式**：DeepSeek-V4 的 Anticipatory Routing 就是一个例子。第 t 步的特征计算用当前参数 $\theta_t$，路由索引却用历史参数 $\theta_{t-\Delta t}$ 计算，从而把主干更新和路由更新解耦；数据提前在 t−Δt 步取好，路由索引预先算好缓存，避免加载两次参数，额外开销控制在约 20%。它只在检测到尖刺时由自动检测器开启，并配合一次短回滚，过一段时间再切回标准模式。
- **从结构上压住离群值**：V4 在两个模型的整个训练过程中都使用 SwiGLU 截断：线性分量截断在 [−10, 10]，门控分量的上界限制为 10。作者称这能有效消除离群值，且不损害性能。

### Step 5　更新量 / 权重比

$$
r = \frac{\|\Delta\theta\|}{\|\theta\|}\quad(\text{逐层})
$$

经验上每步 $10^{-3}$ 量级比较健康。某一层的 r 突然变大，往往先于 loss 尖刺出现，是比 loss 更早的预警信号；r 长期过小，说明这一层几乎没在学（学习率或初始化不合适）。

## 4. 极简代码锚点（PyTorch）

一组训练监控与稳定化工具：尖刺检测器、按头 QK-Clip、z-loss、逐层更新比。已跑通：在一条带噪声的下降曲线上注入两步尖刺，检测器准确标出了这两步。

```python
import math, torch

class SpikeDetector:
    """EMA 跟踪 loss 均值与方差；异常点不更新统计量，避免把尖刺吸收进基线。"""
    def __init__(self, beta=0.9, k=6.0, warm=20):
        self.m, self.v, self.n, self.beta, self.k, self.warm = None, 0.0, 0, beta, k, warm
    def step(self, loss):
        self.n += 1
        if self.m is None: self.m = loss; return False
        if self.n > self.warm and loss > self.m + self.k * math.sqrt(self.v):
            return True                                         # → 回滚 / 跳批 / 切稳定模式
        d = loss - self.m
        self.m += (1 - self.beta) * d
        self.v = self.beta * (self.v + (1 - self.beta) * d * d)
        return False

@torch.no_grad()
def max_logit_per_head(q, k):                                   # q, k: (B, H, L, d)
    s = (q @ k.transpose(-1, -2)) / q.shape[-1] ** 0.5          # (B, H, L, L)
    return s.amax(dim=(0, 2, 3))                                # (H,)

@torch.no_grad()
def qk_clip_(Wq, Wk, s_max, tau=100.0, alpha=0.5):
    """Wq, Wk: (H, d_h, D)；s_max: (H,)。在优化器 step 之后原地缩放超阈值的头。"""
    g = (tau / s_max).clamp(max=1.0)                            # 没超阈值的头 g = 1，不受影响
    Wq.mul_(g.pow(alpha)[:, None, None]); Wk.mul_(g.pow(1 - alpha)[:, None, None])

def z_loss(logits, coef=1e-4):                                  # logits: (B, T, V)
    return coef * (torch.logsumexp(logits, -1) ** 2).mean()     # 拉 log Z → 0，不改变预测

@torch.no_grad()
def update_ratios(model, before):                               # before: {name: 更新前的参数副本}
    return {n: ((p - before[n]).norm() / (before[n].norm() + 1e-12)).item()
            for n, p in model.named_parameters() if n in before}
```

## 5. 实战直觉、避坑与面试深挖

**2026 前沿现状**
- **稳定性手段越来越"结构化"**：从早期的"出了尖刺就回滚"，到 QK-Clip 从权重源头限幅、SwiGLU 截断从激活源头限幅、Anticipatory Routing 从路由动态上解耦。DeepSeek-V4 也坦率地承认，Anticipatory Routing 和 SwiGLU 截断确实缓解了训练不稳定，但其机制"仍未被充分理解"。
- **优化器换代带来新的不稳定**：Muon 已经成为前沿开源模型的主流优化器（→ 5.1），而 K2 的经验表明，Muon 下注意力 logit 爆炸比 AdamW 下更频繁。换优化器不是一个孤立的决定，它会改变整个系统的数值行为。
- **残差结构也在为稳定性让路**：DeepSeek-V4 的 mHC 把残差映射约束在双随机矩阵上，谱范数不超过 1，作者称这提高了数值稳定性；朴素的 Hyper-Connections 在堆叠时频繁出现数值不稳定。

**与工程 / 应用的连接**
- **排查方法论是同一套**：先把问题二分（数据还是动力学，对应应用侧的"输入问题还是系统问题"），再找最早出现异常的那个指标，而不是盯着最终症状。这和看 Agent trace 找第一个出错的步骤是一回事。
- **微调时同样适用**：自己做 SFT 或 RL 时，loss 平台期最常见的原因是 loss mask 或聊天模板错位（→ 2.1）；先用一个 batch 过拟合测试排除实现 bug，再谈调参。

**常见误区 / 反直觉点**
1. **"尖刺 = 坏数据，跳过就好"** ✗：V4 的经验是回滚能暂时恢复、但尖刺会反复出现，根源在 MoE 层的离群值。先用"同一批数据重放"判断是数据还是动力学。
2. **"梯度裁剪能解决不稳定"** ✗：裁剪是保险丝，不是治疗。大部分步都在裁剪，说明真正的问题在学习率、数值或结构上。
3. **"衰减阶段 loss 降得快，说明后期数据质量高"** ✗：那是学习率下降本身带来的效果。比较数据配比要在同样的调度阶段比较，或者从同一个 checkpoint 分叉出去做衰减。

**高频深挖题**
- **Q1：大规模预训练中出现 loss 尖刺，你的排查流程是什么？**
  思路：先二分：在尖刺前的 checkpoint 上重放同一批数据 → 复现说明是动力学问题：按顺序看每头最大注意力 logit、逐层梯度范数和更新比、激活最大值、MoE 的专家负载与 router 熵，找最早异常的层 → 对应干预：QK-Clip / QK-Norm、z-loss、激活截断、降学习率、路由稳定化 → 不复现说明是数据问题：定位样本、清洗、跳批 → 最后补一句：预防比应对更重要，监控面板要在 loss 出事之前报警。
- **Q2：为什么 MLA 不能用 QK-Norm？Kimi K2 怎么解决注意力 logit 爆炸？**
  思路：QK-Norm 要求对 key 显式归一化，而 MLA 推理时把 $W_{UK}$ 吸收进 query、根本不展开 key（→ 1.3），归一化无处可加 → QK-Clip：每步更新后计算每头最大 logit，超过 τ 就按 $\gamma^{\alpha}$、$\gamma^{1-\alpha}$ 缩放 $W_q$、$W_k$，不改当前前向，只动出问题的头；共享的 RoPE key 不能按头缩放 → 效果：K2 在 15.5T token 上零尖刺。
