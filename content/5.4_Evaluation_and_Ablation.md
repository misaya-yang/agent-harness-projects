# 5.4 评测与消融：先量噪声，再谈提升

> **一句话核心直觉**：一个评测分数只是"真实能力 + 抽题噪声 + 生成采样噪声 + 评测系统噪声"的一次抽样。说"A 比 B 好"之前，先回答两个问题：噪声底有多高？差值的误差条有多宽？消融实验要做的，是把你想证明的那个变量从所有其他变量里隔离出来。
> **唤醒标签**：标准误与置信区间 · 配对差 · 聚类标准误 · 功效分析 · pass@k 无偏估计 · 数据污染 · LLM-as-judge 偏置 · harness 方差

本篇紧跟 M2 读：RL 实验最容易被噪声骗（2.5 的长度偏置、2.7 的失配都会伪装成"效果提升"）。

## 1. 痛点与钩子：如果没有它，世界会怎样？

本篇代码先给两个模型生成潜在的正误结果，A 的正确率为 70%，B 为 72%。在 500 道题上，观测正误有 15% 的概率因为采样随机性而翻转。**单次评测把 A 排在 B 前面或排成平手的概率，在 10 套模拟题上的结果介于 17% 和 36% 之间。** 用同一套题重跑，也可能看到不同排名。

Agent 评测更糟：
- 在 SWE-Bench-Verified 上独立跑十次，单次 pass@1 会因为选了哪一次而相差 2.2–6.0 个百分点，即使 temperature=0，标准差也超过 1.5 个百分点。
- Anthropic 发现，只改基础设施的资源配置，Terminal-Bench 2.0 上资源最多和最少的两种设置就相差 6 个百分点（p < 0.01）。[Anthropic 的基础设施对照实验](https://www.anthropic.com/research/infrastructure-noise)
- 固定模型、只换 harness，Terminal-Bench 2 的 pass@1 能从 69.7% 涨到 77.0%。

很多论文和发布会宣称的提升就是 2–3 个百分点，而这正落在评测过程本身的自然波动之内。

## 2. 第一性原理：看透它的几何 / 物理直觉

### 2.1 一个分数的三种噪声

| 噪声 | 哪项改变会让同一模型得分波动 |
| --- | --- |
| 抽题噪声 | 从同一目标分布另抽一套题，难度组合发生变化 |
| 预测噪声 | 同一道题重新采样输出，答对情况可能变化 |
| 系统噪声 | 基础设施、harness、裁判模型或推理引擎出现波动 |

不同的方法对付不同的噪声：配对比较消掉"题目难度"带来的方差；对同一道题多采样几次再平均，压低预测噪声；固定并公开 harness 与基础设施，控制系统噪声。2025 年底的一项研究系统地测量了这些噪声成分：在 MATH500 上，不同最终模型之间，抽题噪声的标准误通常不到预测噪声的一半。

### 2.2 三个统计工具的直觉

- **配对差**。让两个模型做同一套题。两者同对或同错时，差值为零。单独汇总仅一个模型答对的题，可以保留有助于区分两者的信息。
- **聚类标准误**：题目常常是成组出现的（同一篇阅读材料的多道题、同一个仓库的多个 issue），组内高度相关，有效样本量远小于题目数。不按组聚类，误差条会被严重低估。
- **功效分析**：在跑实验**之前**算清楚：要检测 2 个百分点的差异，需要多少道题、多少次采样？如果答案是 4000 道而你只有 500 道，这个实验从设计上就证明不了你想证明的东西。

把准确率固定在 70% 和 72%，只改变两模型一对一错的比率。保持分数差相同，配对后的区间仍然可能变宽或变窄。

固定题数，让两个模型一对一错的题目占比逐步升高。平均分仍相差两个百分点，区间却会变宽。试着从两模型同做对、同做错的题目入手，解释为什么这些题没有贡献分差。

```academy-lab
5.4
```

在两模型不同判定很少时，少数样本就决定了差值。可以同时报告那两格实际计数，只 A 对和只 B 对。若任务还按仓库或文档成组，标准误或重采样也要尊重分组。

### 2.3 消融实验的五项对照

1. **改动范围**。单项消融中固定其他变量。想识别两个改动的交互效应，比较四种组合。
2. **算力**。预先选定 token 数、步数或 FLOP 总量作为预算，再控制预算一致。
3. **调参**。基线和新方法使用相同的调参预算。
4. **随机种子**。用多个独立种子，发表均值、区间和每次运行结果。
5. **机制指标**。若假设改动能缓解熵坍塌，同时比较熵曲线和按概率分桶的 `clip_frac`。

### 2.4 评测本身会骗人的三种方式

| 问题 | 表现 | 对策 |
|---|---|---|
| **数据污染** | 题目或答案进了训练集，分数虚高 | n-gram 重叠检测、困惑度探针、只用模型知识截止之后的新题、canary 字符串 |
| **LLM-as-judge 偏置** | 偏好靠前的答案、更长的答案、和自己风格相近的答案 | 交换顺序取平均、长度控制、rubric 逐条判、多裁判、用人工标注校准 |
| **harness 与基础设施** | 同一个模型，换脚手架或资源配置分数大变 | 公开并固定 harness、多次运行、单独报告基础设施错误率 |

### 同一批解答怎样估计 pass@k？

保留同一道题的 20 个候选，其中 5 个正确。等概率抽取 $k$ 个不同候选，全部失败意味着每次都抽中剩余的错误答案，概率为 $\binom{15}{k}/\binom{20}{k}$。这个比例也等于所有大小为 $k$ 的子集里完全不含正确解的占比，可用穷举做独立核对。

不能把该值直接替换成 $(15/20)^k$，后者对应有放回的抽取。无放回地连抽几个错误后，下一抽的错误概率已经下降。在重复独立采样的假设下，对随机生成的整池候选再取期望，就得到常用 pass@k 估计器的含义。它衡量“至少有一个正确候选”，并未提供把该候选从池中选出的办法。

```academy-lab
5.4-pass-k
```

**迁移练习。** 若线上系统没有可靠的选择器，把 pass@5 写成一次回答的线上准确率是否成立？即使 5 个候选中存在正确答案，系统仍可能返回其中一个错解。

## 3. 承重墙推导：重新捡起核心数学

### Step 1　单个分数的误差条

正确率是伯努利变量的均值，由中心极限定理：

$$
\mathrm{SE} = \sqrt{\frac{\bar s(1-\bar s)}{n}},\qquad 95\%\ \text{CI} = \bar s \pm 1.96\,\mathrm{SE}
$$

在独立抽样的 500 道题上，正确率 70% 的标准误约为 2.05 个百分点，95% 置信区间半宽约为 4 个百分点。这个区间对应单个模型。比较两个模型的差值需要单独估计方差。样本很少或结果稀有时，优先检查近似区间的覆盖率，可以使用二项式精确区间或与抽样设计相符的重采样。

### Step 2　配对差为什么更灵敏

$$
\mathrm{Var}(\bar A - \bar B) = \frac{\sigma_A^2 + \sigma_B^2 - 2\,\mathrm{Cov}(A,B)}{n},\qquad
\mathrm{SE}_{\text{paired}} = \frac{\mathrm{sd}(d_i)}{\sqrt n},\quad d_i = A_i - B_i
$$

两个模型在同一道题上的表现正相关（难题都错、易题都对），协方差项把方差减下来。不配对的比较等于白白扔掉了这个信息。

### Step 3　聚类标准误

题目分成若干组 c，组内相关：

$$
\mathrm{SE}_{\text{clustered}} = \frac{1}{n}\sqrt{\sum_c\Big(\sum_{i\in c}(s_i - \bar s)\Big)^2}
$$

经验上的"设计效应"约为 $1 + (m-1)\rho$（m 为组大小，ρ 为组内相关）。本篇代码里 50 组、每组 10 题、组内完全相关时，聚类标准误是朴素标准误的 3.2 倍；Anthropic 报告的 DROP 基准上，这个比值是 3.05。

### Step 4　降低预测噪声：多采样与用概率

对每道题采样 K 次取平均，题内采样方差降为 1/K；能拿到 token 概率时，直接用正确答案的概率代替"采样一次看对不对"，方差更小。Miller 的建议清单里，这一条与"用 CLT 算标准误""按组聚类""对配对差做推断"并列。

### Step 5　pass@k 的无偏估计

对每道题生成 n ≥ k 个样本，其中 c 个正确。从中不放回地抽 k 个、至少一个正确的概率：

$$
\widehat{\text{pass@}k} = 1 - \frac{\binom{n-c}{k}}{\binom{n}{k}}
$$

- 它对模型真实的 pass@k 是无偏的。直接用 $1-(1-c/n)^k$ 是有偏的。
- 例：n=10、c=3 时 pass@1 = 0.30，pass@5 ≈ 0.917。高 k 的 pass@k 对"能力边界"敏感，正是 2.5 那场"磨尖还是扩边"争论用的指标。

### Step 6　功效分析：需要多少题

要以显著性 α=0.05、功效 80% 检测差异 δ（配对差的标准差为 $\sigma_d$）：

$$
n \;\ge\; \Big(\frac{(z_{0.975} + z_{0.8})\,\sigma_d}{\delta}\Big)^2 \approx \Big(\frac{2.8\,\sigma_d}{\delta}\Big)^2
$$

检测 2 个百分点：$\sigma_d=0.3$ 时需要约 1764 道题，$\sigma_d=0.45$ 时需要约 3969 道。大多数基准只有几百道题，这就是为什么单个基准上的小幅提升几乎总是无法下结论。

## 4. 极简代码锚点（Python / PyTorch）

一套评测统计工具：标准误、配对、聚类、pass@k、功效。已跑通，§1 和 §3 的数字都来自它。

```python
import math, torch

def se_bernoulli(s):                                    # s: (n,) 每题 0/1
    p = s.float().mean().item(); return math.sqrt(p * (1 - p) / len(s))

def paired_diff(a, b):                                  # 同一套题上的两个模型
    d = (a - b).float(); return d.mean().item(), (d.std() / math.sqrt(len(d))).item()

def clustered_se(s, cluster):                           # cluster: (n,) 每题所属的组
    s = s.float(); mu = s.mean(); tot = 0.0
    for c in cluster.unique():
        tot += ((s[cluster == c] - mu).sum().item()) ** 2  # 组内残差先求和，再平方
    return math.sqrt(tot) / len(s)

def pass_at_k(n, c, k):                                 # 无偏估计：每题生成 n 个、其中 c 个对
    if n - c < k: return 1.0
    return 1.0 - math.prod((n - c - i) / (n - i) for i in range(k))

def n_needed(sigma_d, delta, z=1.96 + 0.84):            # α=0.05、功效 80%
    return math.ceil((z * sigma_d / delta) ** 2)

# 模拟：真实 70% vs 72%、500 题、15% 采样翻转 → 单次评测排错的概率
N, wrong = 500, 0
diff = torch.rand(N); pA, pB = (diff < 0.70).float(), (diff < 0.72).float()
for _ in range(2000):
    a = torch.where(torch.rand(N) < 0.15, 1 - pA, pA)
    b = torch.where(torch.rand(N) < 0.15, 1 - pB, pB)
    wrong += int(a.mean() >= b.mean())
print(wrong / 2000)                                     # 约 0.17–0.36，取决于抽到的题目
```

### 数值复算 · 同一批解答怎样估计 pass@k？

在同一个 Python 会话中先运行本节上方的实现，再运行以下算例。

```python
import math
for k in [1, 5, 16]:
    exact = pass_at_k(20, 5, k)
    reference = 1 - math.comb(15,k)/math.comb(20,k) if k <= 15 else 1.
    assert abs(exact-reference) < 1e-12
    print(f"k={k:2d}  不放回={exact:.3f}  有放回={1-0.75**k:.3f}")
```

**运行结果**

```text
k= 5  不放回=0.806  有放回=0.763
k=16  不放回=1.000  有放回=0.990
```

## 5. 实战直觉、避坑与面试深挖

**2026 前沿现状**
- **Agent 评测的方差被系统量化**：ICLR 2026 的《On Randomness in Agentic Evals》在 SWE-Bench-Verified 上收集了 6 万条轨迹，覆盖三个模型和两种脚手架，结论是 2–3 个百分点的提升可能只是评测噪声。基准方也在跟进：Terminal-Bench 2.1 的排行榜要求每个任务至少公开 5 次试验结果。
- **基础设施是混杂变量**：Anthropic 在校准环境时发现，多达 6% 的任务因为与模型无关的 pod 错误而失败；Agent 评测本质上是端到端的系统测试，任何组件都可能成为混杂因素。
- **harness 必须披露**：2026 年 5 月的一篇立场文章指出，每个基准分数都是模型和 harness 共同产出的，harness 引起的方差可能远大于模型引起的方差，甚至出现模型排名反转，因此提出了披露标准和方差分解协议。

**与工程 / 应用的连接**
- **Agent 评测和模型评测共用这套统计底座**：从生产 trace 自建评测集时，同一个会话或同一个仓库的多个任务要按组算聚类标准误；改 prompt、换 harness 做 A/B 时，用同一批任务算配对差；声称"成功率提升"之前，先用功效分析算一下手头的任务数够不够。
- **评测预算的分配**：同样的预算，"更多题目各跑一次"和"更少题目各跑多次"压的是不同的噪声。抽题噪声大就加题，预测噪声大就加采样次数，先测清楚哪个是主要成分再决定。

**常见误区 / 反直觉点**
1. **"跑几次，报最好的那次"** ✗：这是选择偏差，等于在噪声上做了一次 best-of-n。要报均值和区间。
2. **"temperature 设成 0 就没有方差了"** ✗：推理引擎的非确定性和环境的随机性依然存在。上面的研究在 temperature=0 下仍测到超过 1.5 个百分点的标准差。
3. **"基准分数是模型的属性"** ✗：它是模型 × harness × 基础设施 × 评测协议的联合产物。只比模型、不固定其他因素，结论可能整个反过来。

**高频深挖题**
- **Q1：你的改动让某个基准从 70% 涨到 72%，怎么证明这不是噪声？**
  思路：先报误差条：500 题时单个分数的 95% 区间约 ±4 个百分点 → 用配对差而不是两个独立分数做检验；题目成组时用聚类标准误 → 多种子、多采样，报均值和区间 → 用功效分析说明需要多少题才能检测 2 个百分点 → 最后排除混杂：污染检查、等算力对比、harness 和基础设施是否一致。
- **Q2：设计一个消融，证明你的 RL 改进（比如 clip-higher）真的有效，而不是"多训了几步"或"调参运气好"。**
  思路：等步数、等 token 数对比；基线和新方法给同样的调参预算；至少 3 个种子，画完整的训练曲线而不是单点；评测用配对检验并报置信区间；最关键的一条：**机制指标要和你声称的机制一致**，比如 clip-higher 应该表现为低概率 token 的 clip_frac 下降、熵下降变慢，否则就算分数涨了，也不能说是因为你以为的那个原因。
