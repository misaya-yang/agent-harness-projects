# 5.5 应用岗到算法岗：用一条失败轨迹讲清机制与证据

> **一句话核心直觉**：把应用问题变成算法问题，不是把项目名词换成 PPO 或 Transformer，而是沿着“可观察的失败 → 可形式化的对象 → 有对照的干预 → 可能推翻自己的结果”向下追问。
>
> **唤醒标签**：证据命中 · 条件概率与选择偏差 · 策略和环境 · 配对差 · 面试追问 · 能力边界

应用工程中定位一次工具调用失败、比较两版检索器、分析失败轨迹的经验，可以成为算法面试的入口。本篇使用**虚构、可复算的演练数据**。准备真实面试时，用你亲自做过的决策、可展示的记录和明确的职责替换它；没有训练过模型，就说清自己做的是评测或系统干预。

## 1. 痛点与钩子：检索改好了，Agent 为什么没有明显变好？

假设一个代码助手要修复真实仓库里的 issue：检索相关文件，模型生成修改，在隔离环境运行测试，成功标准是隐藏测试通过。公开的 [SWE-bench](https://arxiv.org/abs/2310.06770) 把真实 GitHub issue 与仓库测试组织成类似任务；SWE-bench 提供了一个具体的任务背景。

两套配置各评同一批 100 题。标注员对每次生成前的上下文判断：其中是否包含足以支持正确修复的证据。两种配置可以命中不同的题。下面的“成功”由各自输出的隐藏测试决定。

| 配置 | 充分证据命中 | 命中后成功 | 未命中后成功 | 总成功 |
|---|---:|---:|---:|---:|
| A | 60/100 | 45/60 | 4/40 | 49/100 |
| B | 80/100 | 48/80 | 2/20 | 50/100 |

面试官问：“你改检索器后，证据命中从 60% 到 80%，为什么端到端只增加 1 个百分点？换大模型、加 context 还是做 RL？”

一个合格的第一反应不是拍一个技术名词，而是先复述单位和条件：命中集合变了，命中后成功率从 75% 到 60%，两个分数都只是**观察到的条件比例**。需要检查新增命中是否更难、证据是否真的可用、上下文是否稀释或排挤其他信息、生成或测试环节是否失败。100 道题上的 1 个百分点也不足以说明真实提升。

## 2. 从一条应用链，映射到可研究的算法对象

### 2.1 先算清楚：更高召回怎样传到最终结果

记 $E=1$ 为当前上下文含充分证据，$Y=1$ 为最终任务成功，定义 $R=P(E=1)$、$H=P(Y=1\mid E=1)$、$M=P(Y=1\mid E=0)$。以 $E$ 把全部任务分成两组，由全概率公式得到

$$
P(Y=1)=P(E=1)P(Y=1\mid E=1)+P(E=0)P(Y=1\mid E=0)
=RH+(1-R)M.
$$

A 的 $0.60\times0.75+0.40\times0.10=0.49$；B 的 $0.80\times0.60+0.20\times0.10=0.50$。若**假设**两项条件成功率保持 A 的数值，只把 R 提到 80%，会预测 62%，而非观测的 50%。预测与观测相差 12 个百分点，说明“条件成功率不变”在这个例子里没有成立，**不说明检索改动本身使生成能力下降了 15 个百分点**：B 额外命中的很可能是另一批难题。

先只把召回调到 80%，记录总体成功率。保持召回不动，再把命中后的成功率从 75% 调到 60%。把两次读数分别和起点比较，就能看出只改善一个环节和同时改变两个环节的区别。


如果要估计提高召回本身的因果效果，随机分配检索配置，固定模型、提示模板、工具、token 预算与判分环境；对**同一道题**保留两份检索结果与输出，再做配对比较。进一步让同一道题在受控上下文中只替换目标证据，可以测试证据可用性；但插入证据可能改变长度、位置和其他文本，必须报告这些变化。分数按任务组或仓库分层，还要核对标注员之间的证据判断是否一致。**条件化于检索后的命中状态会改变题目构成，不能把组间比较当随机干预。**

映射不等于声称因果等价。例如，上下文压缩会改变模型看到的历史，与长上下文训练存在共同问题；它并不自动是 KV 架构优化。工具调用日志也不天然是高质量 RL 数据：奖励、动作边界、权限和真实采样概率是否可得都需要核验。

### 2.3 从 harness 到 RL：动作概率算在什么地方

给定历史 $h_t$，策略按 $\pi_\theta(a_t\mid h_t)$ 采样动作 $a_t$；工具返回 $o_{t+1}$ 并由环境分布 $P(o_{t+1}\mid h_t,a_t)$ 产生。对于固定环境，轨迹概率可写成

$$
p_\theta(\tau)=p(h_0)\prod_{t=0}^{T-1}\pi_\theta(a_t\mid h_t)P(o_{t+1}\mid h_t,a_t).
$$

如果满足求导与期望可交换的条件，且环境没有直接依赖 $\theta$，则 score-function 恒等式给出

$$
\nabla_\theta\mathbb E[R(\tau)]
=\mathbb E\left[R(\tau)\sum_t\nabla_\theta\log\pi_\theta(a_t\mid h_t)\right].
$$

工具输出是下一步策略的**条件**，不是策略采样的动作，因此不会作为动作位置加入 $\log\pi_\theta$；模型自己写出的工具名、参数和最终回答才是动作。实践中还需为 token 做 mask，控制优势估计、off-policy 与奖励投机，见 [2.3 策略梯度](/lessons/2-3.html)和 [2.6 多轮轨迹](/lessons/2-6.html)。如果工具响应是由另一个可训练策略生成，上面的“固定环境”前提就不再成立。

这能把熟悉的 trace 排查引到算法题：问候选人如何分离动作与观察、如何从终局测试分配信用、如何让 rollout 和训练看到一致的 token，以及 verifier 不完备时如何防止刷分。能解释这一链条，不代表已经训练过 RL 模型。

## 3. 追问的三层结构：现象、机制、反证

还是用代码助手。面试时可以按下面的节奏组织答案，每一层都留下一个可追问接口：

1. **现象和边界（是什么）**：任务单位是仓库 issue，成功定义是隐藏测试通过；报 R、H、M 和总成功率，披露样本、harness、抽样方式。区分本例构造数据与真实项目记录。
2. **机制和计算（为什么）**：写出全概率式，解释 B 的命中集合可能变难。若追问“上下文更长为何更慢”，用 [5.1](/lessons/5-1.html) 的 KV 和带宽公式估算；若追问“如何用轨迹训练”，用上面的策略、环境与 mask 说明最小训练对象。
3. **对照和证伪（如何知道）**：同题比较、固定模型与工具版本、记录证据位置和长度。先预注册主要指标，再看配对差与不确定性；新增命中如果主要是高难题，分难度控制后 H 的变化可能消失，这会推翻“模型利用证据变差”的直觉。

主动把追问引向自己有证据的部分，例如：“我能把这个假设变成同题检索替换实验；若需要训练策略，我会先补动作 mask 与 verifier 的验证。”这句话提出了具体下一步，也把已做和拟做的工作分开。

### 3.1 配对分歧数决定一次提升的精度

换另一道**独立构造**的诊断题：在 200 个同题比较中，80 题两者都成功、60 题两者都失败、24 题只有 A 成功、36 题只有 B 成功。A 是 104/200=52%，B 是 116/200=58%，差 6 个百分点。

设每题 $d_i=Y_{B,i}-Y_{A,i}\in\{-1,0,1\}$，仅 A 成功的数量 $a$ 对应 $-1$，仅 B 成功的数量 $b$ 对应 $+1$。配对均值和无偏样本方差为

$$
\bar d=\frac{b-a}{n},\qquad
s_d^2=\frac{(a+b)-n\bar d^2}{n-1},\qquad
\mathrm{SE}(\bar d)=\frac{s_d}{\sqrt n}
=\sqrt{\frac{(a+b)/n-\bar d^2}{n-1}}.
$$

对这道题，近似 95% 区间为 $6.00\pm1.96\times3.86$，即 **[−1.56, 13.56] 个百分点**。区间跨零，因此数据与较小负差及正差都相容，不能只凭这 200 题确认 B 更好。这里用正态近似并假设题目独立同分布；同仓库 issue 相关时应按仓库聚类或按仓库 bootstrap。配对后的题目抽样误差不自动涵盖生成随机性或训练 seed。

```academy-lab
5.5-diagnosis
```

固定差值为 6 个百分点，把双方各自独占成功的数量从 6 和 18 同时增加到 24 和 36，区间从 [1.26, 10.74] 拓宽到 [−1.56, 13.56]。因为分歧题决定了 $d_i$ 的波动；两个独立的总分无法重建每题的配对关系。不要把“区间跨零”反过来说成“已经证明两种方法没有差异”。[用 Python 复算这三种配对情况](#section-4-2)

## 4. 极简代码锚点：两组可独立复算

下面均只用 Python 标准库；复制任一代码块即可独立执行。数字是上文构造数据，不依赖 GPU 或任何远程服务。

### 数值复算 · 从条件成功率回到总成功率

```python
def diagnose(hit, correct_hit, miss, correct_miss):
    n = hit + miss
    recall = hit / n
    h = correct_hit / hit
    m = correct_miss / miss
    return recall, h, m, recall * h + (1 - recall) * m

for name, counts in [("A", (60, 45, 40, 4)), ("B", (80, 48, 20, 2))]:
    recall, h, m, total = diagnose(*counts)
    print(f"{name}: R={recall:.0%}, H={h:.0%}, M={m:.0%}, 总成功率={total:.0%}")
print(f"固定 H=75% 的 B 预测: {0.8 * 0.75 + 0.2 * 0.1:.0%}")
```

**运行结果**

```text
A: R=60%, H=75%, M=10%, 总成功率=49%
B: R=80%, H=60%, M=10%, 总成功率=50%
固定 H=75% 的 B 预测: 62%
```

该函数要求命中和未命中两组都非空；如果某组没有样本，条件成功率不可估，不能用零代替。有限样本的比例还有统计误差，此处只检查算术。

### 4.2 同一差值的三种配对不确定性

```python
from math import sqrt

n = 200
for k in (0, 18, 80):
    a_only, b_only = 6 + k, 18 + k
    d = (b_only - a_only) / n
    se = sqrt(((a_only + b_only) / n - d * d) / (n - 1))
    print(f"k={k:2d}: 仅A={a_only:2d}, 仅B={b_only:2d}, 差={100*d:.2f}pp, "
          f"95%区间=[{100*(d-1.96*se):.2f}, {100*(d+1.96*se):.2f}]pp")
```

**运行结果**

```text
k= 0: 仅A= 6, 仅B=18, 差=6.00pp, 95%区间=[1.26, 10.74]pp
k=18: 仅A=24, 仅B=36, 差=6.00pp, 95%区间=[-1.56, 13.56]pp
k=80: 仅A=86, 仅B=98, 差=6.00pp, 95%区间=[-7.30, 19.30]pp
```

这里 `pp` 是百分**点**，不是相对百分比。极少分歧、数据高度分组或结果很稀有时，不要机械依赖正态区间；应检查适合抽样设计的精确方法或按独立组重采样。

## 5. 实战直觉：一段能经得住追问的回答

### 5.1 90 秒诊断示范

> “我会先把 20 个百分点的证据命中提升和最终成功提升分开。按全概率公式，A 是 49%，B 是 50%；若 B 仍有 A 的命中后成功率，本来预测 62%，所以恒定条件成功率的假设失败了。B 新命中的题可能更难，我不能据此断言模型更差。下一步用同一批 issue 对比两份检索轨迹，标注证据充分性及其位置，固定模型、token 预算和测试环境；同时报告仅 A 对和仅 B 对的配对计数，并按仓库聚类。若同题、等预算插入证据后成功率提高，优先修检索；若证据明确存在但依然失败，检查生成、工具和验证器，再决定是否收集训练数据。”

回答时具体区分“我实现了什么、观察了什么、团队其他人做了什么、哪些只是我的下一步”。

### 5.2 当前实践：harness 和评测本身也是变量

[On Randomness in Agentic Evals](https://arxiv.org/abs/2602.07150) 研究了 Agent 评测中的随机性；[Anthropic 的基础设施对照](https://www.anthropic.com/research/infrastructure-noise)显示基础设施配置能改变编码 Agent 的评测结果。因此即使模型权重固定，也要披露工具接口、超时、硬件资源、网络与失败重试。不要把某一论文的具体数字迁移为所有项目的误差条：在自己任务上重复运行才知道噪声大小。

评测与训练紧密相连，但 verifier 的可计算分数不一定等于用户真正要的结果。隐藏测试覆盖不全时，模型可能学到钻测试漏洞；需要保留独立测试、审计异常高分轨迹，并人工核对任务语义。参考 [HumanEval 的 pass@k 估计](https://arxiv.org/abs/2107.03374)：多次采样至少一个正确与系统能实际选出正确结果是两件事。

### 5.3 两道迁移练习（含答案）

**练习一：** 新检索器在 100 题上召回率 90%，命中后成功率 50%，未命中成功率 10%。预计总成功率是多少？它优于 A 的 49% 吗，是否证明检索器导致提升？

**答案：** $0.9\times0.5+0.1\times0.1=0.46$，低于 A 的 49%。这是给定组比例的算术；未提供同题配对、抽样误差或受控干预，不能由此断定因果，更不能断定不存在改进空间。先看新增命中是否充分、题目难度和上下文预算。

**练习二：** 200 道同题评测中仅 A 成功 24、仅 B 成功 36，两者的提升是多少？能否只根据这两个数确定 B 的准确率？

**答案：** 差值 $(36-24)/200=6$ 个百分点；但缺少两者都成功的数量，无法知道各自准确率。上述正态近似区间为 [−1.56, 13.56] 个百分点；若题目按仓库相关，区间还应按仓库估计。

## 6. 3 分钟记忆唤醒自测

1. 写出 $P(Y=1)=RH+(1-R)M$。为什么更高的 R 仍可能对应更低的总成功率？
2. 一条工具结果在策略梯度中是动作还是条件？什么前提改变后答案也会改变？
3. 比较两版 Agent 时，为什么应记录两列仅一方成功的题数、harness 和仓库分组？

答案：条件成功率和题目构成也可改变；固定环境的工具响应是后续动作的条件、模型采样输出是动作，若响应由可训练策略生成则要重建概率分解；互斥计数决定配对差的方差，harness 与分组分别影响系统噪声和独立抽样假设。
