# 6.2 预训练数据工程：把网页变成可训练、可审计的数据

> **一句话核心直觉**：预训练并非把网页 token 越多越好。重复文档使同一段文字被反复计权，质量过滤会改变语言和领域的分布，测试题泄漏又会让评测不再独立。精确去重、近重检索、质量筛选、配比和污染审计各自回答不同的问题；要同时记住留了多少、删了什么，以及模型在未污染的目标分布上有没有真正变好。
> **唤醒标签**：网页 → 规范化 → 精确去重 → MinHash/LSH 近重 → 质量分 → 领域混合 → 污染审计 · $J=|A\cap B|/|A\cup B|$ · $P(\text{LSH 候选})=1-(1-s^r)^b$ · 覆盖率和误报 · 固定 token 预算对照
>
> 前置：6.1（固定算力和 token 预算）、5.4（评测与消融）；合成数据如何自举见 2.9。

## 1. 问题：同样训 1T token，为什么数据会让结果不同？

一个真实坐标是 [RefinedWeb](https://arxiv.org/abs/2306.01116)：研究者从 Common Crawl 的原始网页提取文本，用文档/行级规则过滤，再结合 MinHash 近重与精确子串去重，得到约 5T token 的英文语料，并公开其中 600B token。论文在所测试的条件下发现，仅靠经过处理的网页也能训练出有竞争力的模型；这不是说网页天生高质量，也不是多语言覆盖的证据。

现在沿用“网页变成训练语料”的场景，假设我们要做一个回答技术问题、读多语言文档的基座模型。网页抓取回来后，重复镜像的“重置密码”教程占了许多份；部分代码页只有导航和广告；西班牙语教程被一个偏向英文的分类器打了低分；一份公开问答又恰好包含我们准备用来评估的题目及答案。

如果直接抽样训练，有三种不同失败：

1. **重复权重**：十份镜像被当成十个独立的证据。固定预算下，其他知识被挤掉；反复出现的文字也更容易被记忆。Lee 等人的去重研究观察到重复训练文本与记忆和评估重叠有关，效果随语料和模型而变，不能把所有重复都视为无价值。
2. **选择偏差**：过滤器以英文书写、常见网页格式为优质代理，可能删掉有价值的少数语言、代码或专业材料。平均分上升，不代表目标能力或各语言覆盖都上升。
3. **评测污染**：测试题及答案以原题、镜像或改写形式进入训练；分数既包含泛化，也可能包含见过题目的收益。删掉训练集内部的重复文档，并不能自动保护一个外部测试集。

6.1 的 $D$ 是训练看过的 token 数，**不等于独立信息量，也不说明这些 token 的任务价值**。数据工程要把每一步的选择变成可测量的实验。

## 2. 先动手：九篇网页经过一条漏斗

下面的语料是合成的小例子，不是对真实网页的测量：A1 是英文教程，A2 只改大小写和标点，A3 改了末词；B1/B2 是相近代码说明；C 是西班牙语食谱；D 是重复广告；E 含评测问答；F 是问答模板。长度用空格词近似 token，质量分是人为预设，不是分类器的实测表现。先规范大小写与标点，**精确去重 → 候选检索及精确 3-gram Jaccard 贪心核验 → 质量阈值**，每一步都真的对这九篇执行；候选既可穷举，也可用固定种子的 MinHash/LSH 索引查找。

```academy-lab
6.2
```

默认穷举、近重阈值 0.70、质量分阈值 0.50：91 → 81 → 71 → **61** 个空格 token，最后保留 A1、B1、B2、C、E、F。A1/A3 的 3-gram 相似度是 $7/9=0.778$，B1/B2 是 $6/10=0.6$。默认阈值下，穷举做 22 次精确比较，固定种子的 LSH 找到 1 对候选并做 1 次精确比较，两个漏斗结果相同。

把近重阈值降到 0.60：穷举会去掉 B2，最后留 51 token；切换 LSH，B1/B2 恰好没有命中任何 band，B2 被漏召并保留，最后仍是 61 token。两种算法都对找到的候选应用同一精确阈值，差别发生在**候选是否找到**。反过来把阈值升到 0.80：A1/A3 仍被 LSH 检索为候选，但精确相似度 0.778 不够高，因此两篇都保留。这些计数来自各自按固定顺序贪心去重的过程，且不含哈希和建索引开销，不能据此推断真实语料的耗时或加速比。把质量分阈值升到 0.65，C 和 F 同时被过滤。**减少重复、删掉广告、丢失语言覆盖与排查评测污染是不同的判断**：E 在默认漏斗中仍被保留。

## 3. 精确去重与近重：从一个集合的交并开始

### 3.1 精确去重：相同要先定义清楚

先解码、去 HTML 模板、确定 Unicode 规范化、大小写和空白处理，再为**规范化后的文档**算稳定哈希。哈希相同可进一步比对原文，以免把罕见哈希碰撞当作相同。保留代表时记录原 URL、抓取时间、许可证和重复簇：同一文本可能来自不同的来源和时间。仅按 URL 去重会漏掉镜像，仅按原始字节去重会漏掉空格或标点改变。

RefinedWeb 的大规模管线依次采用近重和精确子串处理；下面的小例子为了隔离操作，使用先文档级精确、再近重的顺序，两者不能把删除量直接对比。

精确去重还要选粒度：文档级能处理全篇镜像，段落级可以去掉被大量网页复制的页脚；过度去段落可能破坏代码、上下文或短文。去重前后统计**文档数和 token 数**，长文被删一篇与短文被删一篇并不等价。实际的 token 应用目标模型的分词器重算，而不是拿本课空格词数直接推训练账。

### 3.2 近似重复：shingle 和 Jaccard

把文档切成连续的 $n$ 词片段（shingle）并视作集合。例如 A1 的最后一个 3-gram 是 `email verification safely`，A3 对应 `email verification securely`。两篇各 8 个不重复 3-gram，共有 7 个，交集为 7，并集为 $8+8-7=9$：

$$
J(A,B)=\frac{|S_A\cap S_B|}{|S_A\cup S_B|}=\frac79\approx 0.778.
$$

这是对称的集合相似度，忽略同一 shingle 在文档内重复多少次。相似不代表内容相同，阈值过低会把仅共享模板或相似代码的有用文档合并；阈值过高又漏掉改写。长度差异很大时，短文几乎包含在长文里，但 Jaccard 仍可能偏低；这时还可检查定向包含率 $|S_{\rm short}\cap S_{\rm long}|/|S_{\rm short}|$。短文本的 shingle 也可能太少，需要专门处理。

### 3.3 MinHash 省什么，LSH 又漏什么

对每个 shingle 施加一个**均匀随机排列**，取集合中排列最小的元素，称为一个 MinHash 值。两个集合的最小值相同，当且仅当并集的最小元素属于交集。因此

$$
\Pr[h_{\min}(A)=h_{\min}(B)]
=\frac{|S_A\cap S_B|}{|S_A\cup S_B|}=J(A,B).
$$

用 $k$ 个独立排列得到签名，签名相等的比例 $\hat J=k^{-1}\sum_i \mathbf 1[h_i(A)=h_i(B)]$ 估计 $J$。理想独立条件下，标准差是 $\sqrt{J(1-J)/k}$；$J=7/9,k=128$ 时约 0.0367。实际哈希族和计算实现可能偏离理想排列，需要在抽样文档对上测误差。

有了签名，若对十亿篇文档仍两两比较，代价依然接近平方级。**LSH 是找候选的索引，不是最终相似度证明**：把签名分成 $b$ 个 band，每组 $r$ 行；同一 band 的 $r$ 行全相同就作为候选。假设各行独立、真实相似度为 $s$，一组命中概率为 $s^r$，至少一组命中概率为

$$
P_{\rm candidate}(s)=1-(1-s^r)^b.
$$

取 $b=20,r=5$：$s=0.60$ 时约 80.2%，$s=7/9$ 时约 99.88%。它是平滑的概率曲线，不是一道确定的阈值；**未成为候选的真近重无法靠后续精确比较补回来**。候选生成后再计算精确相似度、结合长度和来源，抽样人工标注测召回与误合并。

本课实验将九篇文本的 3-gram 排序编号，用固定种子 3 生成 100 个仿射哈希，分成 20 组、每组 5 行，组内全部相同才检索出候选。§7.2 可复算：A1/A3 命中 7 组，B1/B2 命中 0 组，尽管后者的精确 Jaccard 恰为 0.60。仿射哈希不是完全独立的随机排列，理论候选概率只是理想对照；换种子和哈希族可能改变具体命中。阈值只决定**已检出的候选**是否合并，不能提高 LSH 本身的召回率。

### 3.4 代表文档、顺序与跨切分

简单贪心法按输入顺序保留第一篇；若后来的文档质量更高，仍可能被丢掉。生产系统可以按质量、许可证、时间等选择代表，记录每个成员和删除原因；连通分量聚类能合并间接相连的重复，但 A≈B、B≈C 并不保证 A≈C，长链会误合并。对同一重复簇先切分后去重也可能让兄弟页面分别进入训练与验证：应先建簇，再以簇为单位切分；对固定外部基准，还需要单独的跨集合审计（§6）。

## 4. 质量筛选是一个有代价的分类决策

常见处理先去明显垃圾：空文档、异常重复、损坏编码、过多模板、低信息量等；再用分类器、参考语料相似度或困惑度给文档打分。规则可解释但容易误杀特殊格式；分类器会继承标注集和训练数据的偏差；困惑度偏爱参考模型熟悉的文风，**低困惑度不自动等于真实、有用、安全或合法**。不同语言、代码和数学应分层抽样审阅，不能仅用全局平均保留率。

设 $G$ 为有用文档、$+$ 为过滤通过。通过后的有用比例由贝叶斯公式决定：

$$
P(G\mid +)=\frac{P(+\mid G)P(G)}{P(+\mid G)P(G)+P(+\mid \neg G)P(\neg G)}.
$$

例如 100 篇里 30 篇有用；过滤器保留其中 80%，也误保留 70 篇无用文档的 20%。于是保留 $24+14=38$ 篇，精度 $24/38=63.2\%$，有用文档召回率是 $24/30=80\%$。提高阈值也许提高精度，但会损失更多召回与 token；是否值得，要用下游模型验证。这里的“有用”依赖人工标注和目标任务，并非网页自带的真值。

RefinedWeb 特别选择避免使用机器学习内容质量分类器（语言识别除外），以减少额外引入的偏差；另一类实证是 [DataComp-LM](https://arxiv.org/abs/2406.11794) 在统一训练与评测框架中比较过滤、去重和混合策略。两者提供待验证的设计选择，并未证明某一种过滤器适用于每个目标语料。

工程上每一版都要留：过滤器版本、规则命中、按领域/语言的输入与保留 token、人工复核样本、每个训练分片的来源与许可证。尤其要检测少数语言、表格、代码和专业领域是否被系统性低估。质量过滤不能代替隐私处理、授权判断或恶意内容处理；这几项各需独立规则和审计。

## 5. 领域配比与合成改写：留下的还不等于实际训练的

假设去重过滤后，有 100B 通用 token、20B 科学 token。若希望训练预算 60B 中两类各占 50%，就各抽 30B：通用池看 0.3 轮，科学池看 **1.5 轮**。科学池只有 $20/(100+20)=16.7\%$ 的库存，却要提供 50% 训练 token；需要上采样或重复。简单写作

$$
D_i=q_iD,\qquad \text{等效经过轮数}_i=\frac{q_iD}{U_i},\qquad \sum_i q_i=1,
$$

其中 $U_i$ 是领域 $i$ 的可用 token，$q_i$ 是**训练 token**配比。若实现按文档均匀抽样，还要处理文档长度不同，否则文档配比并不等于 token 配比。重复不会凭空创造独立材料；随着重复增加收益通常下降（→ 6.1），要在固定计算量和目标能力上比较增量。记录各池的实际抽样次数、去重策略和来源，防止同一份材料在不同领域标签下又被多次计数。

合成改写可以补充格式、语言或任务表达，也可能引入事实错误、教师模型的风格偏置及变相复制。保存源文和生成链，检查事实、许可、近重和领域覆盖，分开标记天然/合成；用同预算的真实数据和无改写对照检验增益。具体的验证和自训练偏差见 2.9。

## 6. 数据污染：内部去重和跨训练—评测审计不是一回事

训练集合里的文档彼此不重复，测试题仍可能恰好出现在某个训练文档里。反过来，训练数据有大量镜像，也不必然包含某张测试卷。污染审计至少要说明：**哪个数据快照、哪版评测、比较题干还是答案、归一化与匹配规则是什么**。

下方扫描同一份九篇玩具训练集：对每道题的每个不重复 $n$-gram，计算其在**单篇**训练文档中的覆盖率，再取最大值。单篇约束避免跨文档拼出一题。四题分别是原题、相同事实的改写、共享套话但问题不同、潮汐新题。

```academy-lab
6.2-audit
```

默认 3-gram、60% 标记阈值：原题覆盖 100%，改写 **0%**，不同题目的模板却覆盖 **63.6%**，因此 2/4 被标记。原题应追踪来源及时间；模板命中要人工复核；词面改写没有命中不代表未见过。甚至共享一个常识事实也不等同于泄漏某道测试题：仅凭这四题不能推断真实污染率。改变 $n$ 与阈值可看到这个代理的敏感度。

比较一次评测是否可信的最小流程：

1. 固化训练快照、评测版本和可审计的规范化规则；题干、选项、答案分别比对，记录匹配文档而非只存一个比例。
2. 词面匹配后做人工分层复核；对翻译、改写、代码语义近重等再用适合的检索器召回，并单独测漏检。公共模板、简单事实与真正的题目泄漏要区分。
3. 额外准备有来源时间和保密边界的新题，按主题、难度、语言与原题匹配，报告原题和清洁子集的逐题分数、覆盖、置信区间。**清洁子集大小及选择偏差必须报告**，分差不是精确的“记忆造成的分数”，因为难度也可能变了。
4. 在相同初始化、token 数、训练步数和配比下比较有/无疑似泄漏簇的训练，核对重复种子；有条件再审计模型对疑似文本的逐字续写。即便无词面命中，也不能证明不存在语义近重或其他泄漏路径。

## 7. 从零实现：复算漏斗和索引概率

### 数值复算 · 从九篇网页到 61 个 token

纯标准库即可运行。先记录每一步的文档数、token 数及保留 ID；3-gram 以集合计算，按固定输入顺序贪心保留。第二段复用这里的 `docs` 和 `grams`。

```python
import re

docs = [
    ("A1", "how to reset an account password using email verification safely", .90),
    ("A2", "How to reset an account password using email verification safely!", .90),
    ("A3", "how to reset an account password using email verification securely", .86),
    ("B1", "python read csv file handle missing values and write report", .88),
    ("B2", "python read csv file handle missing values and export report", .82),
    ("C", "recetas de arroz para la familia con verduras y especias", .62),
    ("D", "click now win prize click now win prize click now", .10),
    ("E", "which planet is known as the red planet mars", .75),
    ("F", "read the passage and answer this question what is three plus seven", .55),
]
def words(text):
    return re.findall(r"[a-z0-9]+", text.lower())
def grams(text, n=3):
    w = words(text)
    return {tuple(w[i:i+n]) for i in range(len(w)-n+1)}
def jaccard(a, b):
    x, y = grams(a), grams(b)
    return len(x & y) / len(x | y)
def summary(name, rows):
    count = sum(len(words(text)) for _, text, _ in rows)
    print(f"{name}: {len(rows)} 篇, {count} token, " + ",".join(row[0] for row in rows))

seen, exact = set(), []
for row in docs:
    key = tuple(words(row[1]))
    if key not in seen:
        seen.add(key)
        exact.append(row)
near = []
for row in exact:
    if all(jaccard(row[1], prev[1]) < .70 for prev in near):
        near.append(row)
filtered = [row for row in near if row[2] >= .50]
print(f"A1/A3={jaccard(docs[0][1], docs[2][1]):.3f}, B1/B2={jaccard(docs[3][1], docs[4][1]):.3f}")
for name, rows in [("原始", docs), ("精确", exact), ("近重", near), ("质量", filtered)]:
    summary(name, rows)
```

**运行结果**

```text
A1/A3=0.778, B1/B2=0.600
原始: 9 篇, 91 token, A1,A2,A3,B1,B2,C,D,E,F
精确: 8 篇, 81 token, A1,A3,B1,B2,C,D,E,F
近重: 7 篇, 71 token, A1,B1,B2,C,D,E,F
质量: 6 篇, 61 token, A1,B1,B2,C,E,F
```

### 7.1 复算 LSH 候选率与污染审计

与上段放在同一 Python 会话中运行；近重候选概率是独立随机哈希下的解析值。审计计算的是题目 shingle 在某一篇训练文档里的最大覆盖率，并保留具体命中对象。

```python
from math import sqrt

for s in (.60, 7/9):
    chance = 1 - (1 - s**5)**20
    print(f"J={s:.3f}: 20×5 候选率={chance:.4f}")
print(f"J=7/9, k=128 的估计标准差={sqrt((7/9)*(2/9)/128):.4f}")
queries = [
    ("原题", "which planet is known as the red planet"),
    ("同事实改写", "name the rust colored world"),
    ("共同模板", "read the passage and answer this question what is ten divided by two"),
    ("潮汐新题", "which force causes earth ocean tides"),
]
for name, query in queries:
    q = grams(query, 3)
    matches = [(len(q & grams(text, 3)) / len(q), doc_id) for doc_id, text, _ in docs]
    score = max(value for value, _ in matches)
    ids = ",".join(doc_id for value, doc_id in matches if value == score) if score else "无"
    print(f"{name}: 覆盖率={score:.1%}, 复核={'是' if score >= .6 else '否'}, 命中={ids}")
```

### 7.2 固定种子的 MinHash/LSH 与穷举对照

接着 §7 的代码运行；语料中的所有 3-gram 排序后从 1 开始编号。使用种子 3 的线性同余序列产生每一行的 $a,b$，令 $h(x)=(ax+b)\bmod 65521$，对每篇文档的 shingle 取最小值形成签名。候选由 band 哈希桶检索，再计算精确 Jaccard；每篇只和此前保留的代表比，遇到第一篇达到阈值的代表即停止。`候选` 是桶里命中的文档对数，`精比` 是实际执行的精确比较数。

```python
# docs、exact、grams 和 jaccard 来自上方第 7 节。
vocab = sorted(set().union(*(grams(text) for _, text, _ in docs)))
shingle_id = {shingle: i+1 for i, shingle in enumerate(vocab)}

def signature(text):
    ids = [shingle_id[g] for g in grams(text)]
    state, out = 3, []
    for _ in range(100):
        state = (1664525*state + 1013904223) % 2**32
        a = 1 + state % 65520
        state = (1664525*state + 1013904223) % 2**32
        b = state % 65521
        out.append(min((a*x+b) % 65521 for x in ids))
    return out

sigs = {doc_id: signature(text) for doc_id, text, _ in exact}
def band_keys(sig):
    return [(i, tuple(sig[i*5:(i+1)*5])) for i in range(20)]
for left, right in [("A1", "A3"), ("B1", "B2")]:
    a, b = sigs[left], sigs[right]
    same = sum(x == y for x, y in zip(a, b))
    hits = sum(x == y for x, y in zip(band_keys(a), band_keys(b)))
    texts = {doc_id: text for doc_id, text, _ in docs}
    similarity = jaccard(texts[left], texts[right])
    print(f"{left}/{right}: J={similarity:.3f}, 签名相同={same}/100, 命中组={hits}/20, "
          f"候选={'是' if hits else '否'}, J≥0.60={'是' if similarity >= .60 else '否'}")

def greedy(threshold, use_lsh):
    kept, buckets = [], {}
    candidates = comparisons = 0
    for row in exact:
        keys = band_keys(sigs[row[0]])
        if use_lsh:
            indices = set().union(*(buckets.get(key, set()) for key in keys))
            pool = [kept[i] for i in sorted(indices)]
        else:
            pool = kept
        candidates += len(pool)
        duplicate = False
        for prior in pool:
            comparisons += 1
            if jaccard(row[1], prior[1]) >= threshold:
                duplicate = True
                break
        if not duplicate:
            index = len(kept)
            kept.append(row)
            if use_lsh:
                for key in keys:
                    buckets.setdefault(key, set()).add(index)
    return candidates, comparisons, ",".join(row[0] for row in kept)

for threshold in (.70, .60, .80):
    for label, use_lsh in [("穷举", False), ("LSH", True)]:
        candidates, comparisons, kept = greedy(threshold, use_lsh)
        print(f"阈值={threshold:.2f} {label}: 候选={candidates}, 精比={comparisons}, 留存={kept}")
```

## 8. 最小对照与常见误区

要判断一条数据规则有没有帮助，先冻结模型、分词器、训练 token、算力、学习率、评估时间和其余配比，只改变一个规则，例如“有/无近重”。从同一上游语料构建两版，报告去重率、剩余各域 token、实际重复轮数、训练 loss、干净评测的各领域结果和多种子波动。若去重后 token 不够而混入其他数据，比较就同时改变了数据来源；应额外设计控制以拆分这两个效应。

- **“去重越狠越好”**：相似教程、语言变体和代码小差别可能有用，过低阈值会合并它们；先测误合并和目标任务变化。
- **“分类器分高就一定质量高”**：它只代表模型对训练标签的预测，语言和领域偏差需要分层审计。
- **“MinHash 判定相似，就一定删除”**：LSH 只生成候选；候选可能漏报或误报，最终决策取决于精确验证、保留代表和业务规则。
- **“训练集去重后评测无污染”**：内部去重与训练—测试交叉比对是两条工作流；无词面命中也无法证明没有改写泄漏。
- **“数据量增大等于覆盖扩大”**：增加重复样本只改变权重，覆盖要看语言、领域、事实和任务的独立来源。

## 9. 练习（附解答）

**练习 1**　两个 3-gram 集合各有 20 项，其中 15 项相同。Jaccard 是多少？$b=20,r=5$ 时的候选概率约多少？

> **解答**：并集 $20+20-15=25$，所以 $J=15/25=0.6$；$1-(1-0.6^5)^{20}\approx 0.802$。约 19.8% 的这类对在理想独立假设下仍可能不成为候选。

**练习 2**　过滤后代码池 10B、通用池 90B，希望以 30% 代码比例训练 100B token。代码池需要重复多少轮？30% 是池内占比还是实际训练 token 占比？

> **解答**：训练中代码 $30$B token，代码池经过 $30/10=3$ 轮；30% 是抽样后的训练 token 占比，库存中代码只占 10%。近重、同源重复和按文档而非 token 抽样都会影响实际情况。

**练习 3**　一组 50 道题有 8 道与训练数据共享题干模板，另外两道语义改写漏检。能说污染率是 16% 吗？

> **解答**：不能。共享模板可能只是正常格式，语义改写可能漏掉；需要逐例核对完整题干、答案、来源和时间，再报告审计方法的误报与漏报。即使题目文本重合，也需进一步判断模型是否训练过相应快照及对评测的影响。

**练习 4**　一个质量过滤器保留了 90/100 篇，看上去数据量损失很小。如何判断它有没有误伤某一种语言？

> **解答**：按语言分别统计输入和保留 token，分层人工标注保留与丢弃样本，并在固定预算下比较各语言的清洁评测；90% 的全局保留率不能排除某种少数语言被全部删掉。
