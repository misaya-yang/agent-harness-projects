# 6.5 中期训练与长上下文扩展

> **一句话核心直觉**：大规模预训练之后、后训练之前，可以用继续训练调整数据配方并逐级延长上下文：保留通用与短文本，同时增加高质量、代码、数学或长文数据。长窗口的每 token 注意力成本随长度增加，因而 token 占比不能直接当作算力占比。把多个短文档拼进一个大窗口，也不等于得到了文内的长程依赖：需处理跨文档注意力、位置和标签边界。最终要按任务、位置、长度和阈值测**有效长度**，而不是只看模型配置中的最大长度。
> **唤醒标签**：数据配比 $p_k$ · 稳态到退火 · 长度课程 · $6N+6n_{\rm layer}dL$ · RoPE 缩放 · token 占比 ≠ FLOPs 占比 · 文档边界 · 长程任务与有效长度

前置：6.1 的算力账，6.2 的数据与去重，1.2 的 RoPE 频谱，5.4 的评测和消融。

---

## 1. 工程问题：基座要能处理长文，最后一段训练怎么安排？

假设你已有一个在 4K 窗口训练的基座，产品要处理几十页的文档，还希望它能分析代码和执行多步推理。配置里的窗口从 4K 改成 128K，让程序能接收长输入，并不保证模型能找到远处信息、综合多处证据或保持短文本能力。

可以把问题拆成三笔账：**内容账**，训练后段拿什么数据教模型；**长度账**，不同窗口吃掉多少 token 和算力；**能力账**，检验它是否真正利用了远处的内容。所谓“中期训练”通常指大规模通用预训练后、面向指令或偏好对齐的后训练前的继续训练；不同团队的命名和阶段边界不同，不必假设所有模型都严格分成三段。

---

## 2. 数据配方：给后训练准备什么基础？

预训练的基本目标仍是预测下一个 token。假设 $P_k$ 是第 $k$ 类中按有效 token 加权的输入与上下文分布，按**被计入损失的 token 数**设权重 $p_k$，且 $\sum_k p_k=1$，混合目标可写成

$$
\mathcal L(\theta)=\sum_k p_k\,\mathbb E_{x\sim P_k}[\ell(\theta;x)].
$$

这里 $\ell$ 是单个 token 的负对数似然；$p_k$ 改变，就改变了各类梯度在训练中的权重。后段可以提高经过筛选的数学、代码、推理说明、技术文档和自然长文的比例，同时保留通用、多语言及短文本作为回放。具体比例是模型、数据和任务的实验选择，**不是“高质量越多越好”的固定定律**：过度重复或过滤可能导致覆盖变窄、遗忘、代码或考试题污染评测集。

两条曲线要分开：切换配方后，训练 loss 统计的是**新分布**，即使读数瞬间改变，也不能直接归因于能力改变。应保留固定的通用、代码、数学和长文验证集，检查各自 loss 与任务分数；同样 token 预算下对照旧配方与新配方，报告多次运行或不确定性（→ 5.4）。如果增加合成数据，还要独立检查答案正确性、多样性和与评测集的重合。

“把能力预埋给后训练”是一个工程假设：基座先从文档、示例与代码中学到语言、事实和可调用的规律，SFT/RL 再教它在指令下更可靠地使用。基座 loss、任务准确率和后训练效果要分别量；不能只因最终模型会推理，就断言某一类中期数据产生了该能力。要做因果判断，就固定起点与后训练流程，对继续训练的数据作消融。

还有一个易漏口径：**抽样样本占比不等于 token 占比**。每个样本恰好填满窗口时，如果 10% 样本是 128K，90% 是 4K，长样本贡献 $0.1\times128/(0.1\times128+0.9\times4)\approx78.0\%$ 的 token。长度差异大时应先确定按样本还是按 token 配比，并记录实际 padding、截断和有效损失 token。

## 3. 分阶段长度课程：token 少不一定便宜

可以在保留短文本回放的同时，逐步引入 32K 和 128K 样本。下面用 **100B token 的假想预算**演示怎么记账。该留多少回放数据，需要固定训练预算、改变配比，再分别测短文与长文能力。

| 阶段 | 阶段总 token | 4K token | 32K token | 128K token | 主要目的 |
|---|---:|---:|---:|---:|---|
| S0 | 60B | 60B | 0 | 0 | 通用短文本基础 |
| S1 | 20B | 15B | 5B | 0 | 适应中等长度，保留短文本 |
| S2 | 20B | 15B | 0 | 5B | 引入目标长度，继续回放 |
| 合计 | 100B | 90B | 5B | 5B | 长 token 占 10% |

### Step 1　算每 token 的注意力成本

设 $N$ 为参与稠密计算的参数量，$h$ 为层数，$d$ 为注意力总宽度，$L$ 为完整序列长度，$D$ 为 token 数。沿用 5.1，在理想稠密因果注意力下，$QK^\top$ 和 $PV$ 的前向配对数约 $L^2/2$，反向粗略为前向的两倍，得到

$$
F(L)\;\approx\;6N+6hdL\quad\text{FLOPs/token},\qquad
C\;\approx\;\sum_L D_L F(L).
$$

第一项是线性层的前向与反向；第二项是注意力的额外配对。对严格的有限长度因果三角形，$L$ 可细化为 $L+1$，本课与 5.1 一样取大 $L$ 近似。公式假设无 padding、没有稀疏注意力、序列都填满对应窗口（仍使用因果掩码），且不含激活重算、通信及其他开销；实际 wall time 还要看内核、显存和并行策略。FlashAttention 主要节省显存和访存，并不消除稠密注意力的平方配对（→ 1.5）。

### Step 2　按 token 而非样本汇总

取 $N=8\text{B}$、$h=32$、$d=4096$。本表三阶段的 100B token 合计约 $5.734\times10^{21}$ FLOPs，其中 10B 长窗口 token 却消耗约 **19.6%** 的 FLOPs；这些是两种长度各 5B 混合的结果。[数值复算见后文](#worked-example)。

如果这 10B token 全部改成 128K，其余 90B 仍是 4K，长样本计算份额升至 24.7%，总算力约为全 4K 训练的 1.195 倍。拖动下面的比例和长度，就能看到两条不同的占比曲线。

```academy-lab
6.5
```

窗口增长还会改变每张卡的激活显存、并行切分、通信量及有效 batch。为装下目标长度，可能需要上下文并行、重计算或减小 microbatch（→ 5.2）。如果只看 FLOPs 而忽略利用率，无法承诺实际耗时的倍数。

**迁移练习 1。** 如果每个样本都恰好填满，10% 的样本用 128K，90% 用 4K，它们各提供多少 token？用任意 100 个样本计，长样本贡献 $10\times128=1280$K，短样本贡献 $90\times4=360$K，长 token 比例是 $1280/1640\approx78.0\%$。这是 token 占比，还不是 FLOPs 占比。

## 4. 从 4K 到 128K：位置、内容、边界缺一不可

### Step 1　先让位置表示覆盖目标范围

RoPE 的一对维度以角频率 $\theta_i$ 旋转，位置 $p$ 的角度是 $p\theta_i$（→ 1.2）。把目标长度放大 $s=128\text{K}/4\text{K}=32$ 倍，位置插值（PI）用 $p'=p/s$，因此频率等效变为 $\theta_i/s$；目标范围的相位大致压回旧训练范围。但它也压缩了相邻位置的角差，可能损伤局部分辨率。YaRN 等方法按频率分区处理并配合幅度或温度调整，具体实现应跟随模型配置；继续训练和长短任务评测仍不可省略。

位置尺度只是一个旋钮：它缓解未见过的位置范围，不会凭空制造正确的长程数据或保证跨文档的检索能力。[Llama 3 技术报告](https://arxiv.org/abs/2407.21783)描述了逐步扩展上下文的继续预训练与针对性评估；它是一个可研究的具体方案，不能据此认定所有架构必须采用同一长度课程。

### Step 2　拼接能填满窗口，却不一定有长程依赖

把两个互不相关、各 $m=64$ token 的文档 A、B 连成 128 token。全局因果掩码只阻止看未来，B 中每个 query 仍能看到 A 的所有 64 个 key，共 $64^2=4096$ 个跨文档位置对。128 长度的全部因果位置对有 $128\times129/2=8256$ 个，因此跨文档位置占 **49.6%**。这里“跨文档”指 B 对 A 的可见性；若目标任务允许连续数据流，跨边界上下文可以是有意设计。若希望样本独立，它就是需要排查的上下文泄漏风险。

在每个文档内部限制注意力、重置相应 position ID，并按实现处理首 token 的预测/损失边界，才能使拼接后等价于独立样本；仅插入 EOS/EOD 标记不会自动屏蔽注意力，**只重置位置也不等于屏蔽**。可以通过块对角因果 mask 或保证序列隔离的变长注意力实现；还需确认数据打包、标签 shift、padding 和缓存的边界一致。跨文档可见性与**训练集和评测集重复导致的数据污染**是两个不同问题，后者还需去重和隔离。

隔离后，每篇文档最远只有 63 token 的文内距离，因此不存在距离至少 64 的合法文内位置对。长度 128 的天然长文却有 2080 个这样的**候选**位置对：它们也许只是无关段落，并不自动是有效依赖。改变文档长短与距离阈值，观察可见性和合法候选的差别：

长度一样的窗口，一边放互不相关的短文，一边放一篇天然长文。只数距离超过阈值、又属于同一文档的位置对。有资格相互注意，还要结合文本内容才能判断两处是否真的相关。

```academy-lab
6.5-packing
```

**迁移练习 2。** 把四篇互不相关的 32-token 文档拼成 128 token，并在文档间使用块对角因果 mask。最长的合法文内距离是多少？是 31，而非 127。位置 ID 重置和标签边界也要处理；要训练更远的真实依赖，仍需合适的长文档或有依据地构造跨段任务。

### Step 3　内容要真的跨过长距离

天然长文可以来自书籍、代码仓库、论文、长对话等，但长度本身不是质量标签。数据管线要核对许可与来源、解析和去重，检查截断位置、文档是否完整，以及相关信息是否跨段出现。合成长上下文例子可以控制距离和证据位置，但若模板、答案或检索线索太固定，模型可能学会任务格式而不是综合内容。抽样检查、源文档级切分以及对抗干扰项都很重要。

## 5. 配置长度、有效长度和任务能力

设配置允许的最大输入长度是 $L_{\max}$。对指定任务分布 $\mathcal T$、指标 $S$ 和阈值 $\tau$，可把**有效长度**操作性地定义为：在测试过的离散长度中，所有不超过该长度的测试点都达到阈值的最大长度。它依赖任务、证据位置、干扰量、模型和阈值，也受采样误差影响，不是模型的唯一固有常数。

例如测得 8K、32K、64K 的分数分别为 94%、88%、66%，若阈值是 80%，则该测试网格上通过到 32K；这不表示 33K 必然失败，也不能推断 128K 的结果。报告每个长度的样本数、置信区间和位置分层，关注上下文开头、中部、结尾以及容易出现的“中段遗忘”。固定生成 token、截断策略和提示格式，否则模型可能根本没看到需要的信息。

长上下文评估至少拆开：

1. **单点检索**：不同位置的一条事实能否找到。它容易控制，但单条“大海捞针”不代表理解全文。
2. **多证据任务**：两处或多处信息需要关联、排序、消歧或多跳推理；加入相似干扰项，答案必须依赖这些远处证据。
3. **真实任务与保持能力**：长文问答、代码仓库定位、长对话总结，同时比较短上下文、通用和代码基准，检查长训或 RoPE 调整后的退化。

RULER 和 LongBench 提供不同类型的长上下文测试；[Lost in the Middle](https://arxiv.org/abs/2307.03172)显示信息位置会影响使用效果。跑基准前检查文档级去重、答案泄漏、训练与评测来源重叠，并核对推理服务是否真的使用了对应上下文长度。即使合成检索全对，也应再用目标业务的长文、多证据任务验证。

## 6. 从头复算两组结果

### 数值复算 · 长度课程的计算量与文档配对

第一组把短窗口固定为 4K，分别试 10% 的 token 处于 32K、64K、128K；最后算第 3 节的三阶段混合。$1\,\mathrm{ZFLOPs}=10^{21}$ FLOPs。

```python
N, layers, width, tokens = 8e9, 32, 4096, 100e9

def per_token(length):
    return 6 * N + 6 * layers * width * length

short = per_token(4096)
for length in (32768, 65536, 131072):
    p = 0.10
    long = per_token(length)
    avg = (1 - p) * short + p * long
    long_share = p * long / avg
    print(f"{length//1024:3d}K  总 FLOPs={tokens*avg/1e21:.3f}Z  长样本占比={long_share:.1%}  相对全 4K={avg/short:.3f}×")
stage0 = 60e9 * short
stage1 = 15e9 * short + 5e9 * per_token(32768)
stage2 = 15e9 * short + 5e9 * per_token(131072)
stage_total = stage0 + stage1 + stage2
print(f"三阶段总 FLOPs={stage_total/1e21:.3f}Z  长样本占比={(5e9*per_token(32768)+5e9*per_token(131072))/stage_total:.1%}")
```

**运行结果**

```text
 32K  总 FLOPs=5.348Z  长样本占比=13.8%  相对全 4K=1.044×
 64K  总 FLOPs=5.605Z  长样本占比=17.8%  相对全 4K=1.094×
128K  总 FLOPs=6.121Z  长样本占比=24.7%  相对全 4K=1.195×
三阶段总 FLOPs=5.734Z  长样本占比=19.6%
```

第二组显式枚举因果距离，比较隔离的短文档与一篇同样总长度的天然长文。分母统一为 128 个位置的全部因果配对，包含自身位置。

```python
m = 64
total = (2*m) * (2*m + 1) // 2
cross = m*m
print(f"总因果配对={total}  跨文档={cross} ({cross/total:.1%})")
for k in (32, 64):
    packed = 2 * sum(m - d for d in range(k, m))
    natural = sum(2*m - d for d in range(k, 2*m))
    print(f"距离≥{k:2d}  隔离拼接={packed:4d} ({packed/total:.1%})  天然长文={natural:4d} ({natural/total:.1%})")
```

**运行结果**

```text
总因果配对=8256  跨文档=4096 (49.6%)
距离≥32  隔离拼接=1056 (12.8%)  天然长文=4656 (56.4%)
距离≥64  隔离拼接=   0 (0.0%)  天然长文=2080 (25.2%)
```

## 7. 决策与误判

- **先定义任务再定长度**：目标文档实际有多长、证据有多远、需要单点检索还是多处综合？用任务与位置分层的有效长度选择训练和服务目标。
- **把配方写成 token × 长度的账**：各阶段同时记录数据类别、长度、有效 loss token 和计算量；切换配方后用固定验证集，而不是比较不同训练分布的 loss 均值。
- **别把标称长度当能力**：位置插值和长窗口解决“能输入”的一部分，是否用到远处信息还要通过检索、多证据任务与真实工作负载证明。
- **检查打包边界**：EOS 是内容标记；样本独立性要由注意力、位置、目标标签和数据切分共同保证。长文中的大量位置对也不等于有意义的远程监督。
- **留住短任务**：扩大窗口和改变 RoPE 后，跟踪短文本、通用、代码等固定集；出现退化时重新评估混合比例、位置方案与训练预算。
