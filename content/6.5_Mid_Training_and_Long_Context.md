# 6.5 中期训练与长上下文扩展

> **一句话核心直觉**：在大规模通用预训练完工之后、面向指令微调（SFT）与强化学习（RL）的后训练之前，工业界普遍插入一段承上启下的“中期训练”（Mid-Training / Continued Pre-training）：在维持通用基础能力回放防遗忘的前提下，大幅拉升教科书代码、高阶数学推理与自然长文本的混合权重，并梯次分级拓展上下文窗口（从 4K 逐步跨越至 32K、128K）。长序列注意力的计算复杂度随长度呈二次方膨胀，导致长上下文的单 token 算力成本随长度线性暴增，长文本 token 占比绝不能等同于算力占比（10% 的 128K token 将吞噬近 25% 的总算力）。单纯把多篇短文档拼满长窗口并不能赋予模型长程理解力：仅插 `<eos>` 或重置 `position_id` 绝不能阻止注意力跨文档泄漏；且拼接短文本在数学上根本不存在跨文档的远距监督信号。最终，系统研发必须以特定任务、信息位置分层与检索阈值严格度量**有效工作长度**，切忌将模型配置项里的最大上下文长度直接当作真实能力。
> **唤醒标签**：中期训练 / 继续预训练 · 数据动态配比 $p_k$ · 梯次长度课程 · 单 token 注意力算力 $6N+6hdL$ · token 占比 ≠ FLOPs 占比 · RoPE 插值与 YaRN · 样本打包跨文档泄漏 · 块对角因果掩码 · 有效长度 vs 标称配置长度 · Lost in the Middle
>
> 前置知识：6.1（预训练算力账本与 Scaling Law）、6.2（数据工程与清洗去重）、1.2（RoPE 旋转位置编码与频谱特性）、5.4（控制变量评测协议）。

## 1. 工程问题：基座要能处理长文，最后一段训练怎么安排？

假设团队刚刚在数万张卡上完成了一个 8B 参数、在 4K 上下文窗口上吞吐了 10T token 的高性能通用基座模型。然而产品落地的实际业务需求极为苛刻：
- 法律与金融业务要求模型一次性阅读 80 页上市公司财报并做跨章节财务审计；
- 软件工程助手要求模型能够完整吃进包含数十个源文件的代码仓库，准确定位跨模块调用的隐蔽 Bug；
- 复杂推理任务要求模型在生成长思维链（Chain-of-Thought, CoT）时不发生遗忘与发散。

在模型的配置文件 `config.json` 中，将 `max_position_embeddings` 字段从 4096 改写为 131072（128K），在程序接口上确实能够让模型直接接收长输入而不报错；但这丝毫不能赋予模型真正的长文本理解能力。若直接在 128K 长度下推理，模型不仅在寻找远处线索时形同盲人，甚至连原本在 4K 长度下表现优异的短文本常识问答和代码补全能力都会发生严重的表征退化。

为了打通从通用短文本基座通向生产级长上下文助手的“最后一公里”，现代工业界在通用预训练与对齐后训练之间，普遍确立了**中期训练（Mid-Training）**阶段。

推进中期训练必须算清三笔严密的工程账：
1. **内容账（Data Mixture）**：训练后段究竟引入什么性质的数据？如何平衡高质量推理合成语料、代码与通用短文本的回放比例，实现新能力的激发与旧知识防遗忘的双赢？
2. **长度账（Compute & Length Budget）**：长上下文窗口下，自注意力机制的平方复杂度如何让每 token 算力急剧膨胀？不同长度阶段吃掉了集群多少真实的 FLOPs 与通信开销？
3. **能力账（Effective Utilization）**：模型是否真的具备跨越数万 token 关联远处证据的能力？如何穿透大海捞针的表面繁荣，准确测出模型的有效上下文工作边界？

## 2. 数据配方：给后训练准备什么基础？

预训练的底层数学目标依然是因果自回归下的下一个 token 预测（Next Token Prediction）。
设语料库由 $K$ 个不同的数据域（如通用网页、GitHub 代码、arXiv 学术论文、数学竞赛题库、长篇电子书、前沿合成推理数据等）构成。$P_k$ 为第 $k$ 类数据域的文本分布，$p_k$ 为该领域**被计入反向传播损失的有效 token 数权重**（$\sum_k p_k = 1$），则联合优化目标形式化为：

$$
\mathcal{L}(\theta) = \sum_{k=1}^K p_k\,\mathbb{E}_{x \sim P_k}\big[\ell(\theta; x)\big]
$$

其中 $\ell(\theta; x)$ 为单个 token 的负对数似然损失。配比权重 $p_k$ 的变动，在代数上直接决定了来自该领域的梯度在总参数更新方向中所占的边际比重。

**中期训练配比的关键工程规律**：
- **能力预埋与后训练承接**：中期训练的核心假设是“把高阶认知底座预先烧录进基座模型的权重隐空间中”。通过在前向训练流中将高质量代码、数学推导、合成多步推理链以及高质量长文的配比大幅提升至 40%–60%，基座模型能够提前掌握复杂符号变换规律与跨段落逻辑推演；随后的 SFT（指令微调）与 RL（强化学习，如 RLVR/PPO）仅需扮演“激活器与意图对齐器”的角色，教模型以对话规范调用已掌握的推理能力；
- **回放机制是守住泛化底色的生命线**：绝不能为了突击代码和长文，而在中期训练流中完全移除通用通识文本！必须保持 20%–30% 以上的精选通用多语言与短文本常识回放，否则模型将在数十亿 token 内发生灾难性遗忘；
- **严格区分‘样本占比’与‘token 占比’的统计口径陷阱**：
  若数据读取管道按文档条数（Document Count）进行均匀抽样，一旦样本长度差异悬殊，实际进入模型的 token 权重将被彻底扭曲。假设样本都填满上下文，其中 10% 的文档是 128K 完整长文，90% 是 4K 短文：
  
  $$
  \text{长文本实际 token 占比} = \frac{0.10 \times 128\text{K}}{0.10 \times 128\text{K} + 0.90 \times 4\text{K}} = \frac{12.8}{12.8 + 3.6} \approx \mathbf{78.0\%}
  $$
  
  原本以为只采样了 10% 的长样本，底层实际吞吐的 token 中竟然有高达 78% 均为长文本！这种口径错位会瞬间撑爆计算预算。**在设计数据加载器（DataLoader）时，必须统一按物理有效损失 token（Valid Loss Tokens）进行配比归一化**。

## 3. 分阶段长度课程：token 少不一定便宜

在硬件显存与算力约束下，若在进入中期训练的第一步就直接全量加载 128K 样本，模型将遭受剧烈的收敛震荡。工业级最佳实践通常采用**渐进式梯次长度课程（Staged Length Curriculum）**。

下表给出一个典型的 100B token 中期训练阶段规划参考方案：

| 训练阶段 | 阶段总预算 | 4K 短窗口 token | 32K 中窗口 token | 128K 目标窗口 token | 核心工程目标与调度重点 |
|---|---:|---:|---:|---:|---|
| **S0 通用固化** | 60B | 60B | 0 | 0 | 调整高质量配方，固化通用短文本基底 |
| **S1 中程拓展** | 20B | 15B | 5B | 0 | 调整 RoPE 基频，平稳适应 32K 语境并保持回放 |
| **S2 极限冲刺** | 20B | 15B | 0 | 5B | 引入 128K 超长上下文，配合退火完成能力封顶 |
| **全阶段合计** | **100B** | **90B** | **5B** | **5B** | **长文本（$\ge 32\text{K}$）token 仅占 10%** |

### Step 1　推导自注意力算力的长度爆炸公式

设模型参与稠密计算的参数量为 $N$，隐藏层层数为 $h$，隐藏层总宽度为 $d$（即 $d = n_{\text{heads}} \times d_{\text{head}}$），当前处理的单条连贯序列长度为 $L$。

在 Transformer 前向传播中，因果自注意力包含两次大规模矩阵乘法：
1. $QK^\top$ 计算注意力打分：$(L \times d) \times (d \times L)$，对于因果下三角掩码，涉及有效元素对约 $L^2 / 2$ 个，单头计算量为 $2 \times d_{\text{head}} \times (L^2/2) = d_{\text{head}} L^2$。汇总全网络 $h$ 层、每层所有注意力头，前向乘累加 FLOPs 为 $2 \times h \times d \times (L^2/2) = hdL^2$；
2. $P \cdot V$ 注意力值加权汇总：同样为下三角矩阵乘法，前向计算量同样为 $hdL^2$ FLOPs。

前向自注意力总计算量约为 $2hdL^2$ FLOPs。反向传播由于需要同时对激活求导与对投影求导，计算量严格为前向的 2 倍（$4hdL^2$）。
因此，单条长度为 $L$ 的序列在注意力机制上消耗的总浮点计算量为 $6hdL^2$ FLOPs。
**平摊到每一个输入 token 上，注意力机制消耗的单 token 算力为**：

$$
\text{单 token 注意力 FLOPs} = \frac{6hdL^2}{L} = 6hdL
$$

将线性层前向（$2N$）与反向（$4N$）合计的 $6N$ 算力合并，得到单 token 的全生命周期计算量解析式：

$$
\boxed{F(L) \approx 6N + 6hdL \quad\text{FLOPs/token}}
$$

处理包含各长度分布的语料总算力即为 $C \approx \sum_L D_L F(L)$。

**一个震撼的量化对比**：
以标准 8B 模型为例（参数量 $N = 8 \times 10^9$，层数 $h = 32$，隐藏维度 $d = 4096$）：
- 线性层恒定开销为 $6N = 6 \times 8 \times 10^9 = 4.8 \times 10^{10}\text{ FLOPs/token}$；
- 注意力项系数为 $6hd = 6 \times 32 \times 4096 \approx 7.864 \times 10^5$；
- 当序列长度 $L = 4096$（4K）时：
  注意力开销为 $7.864 \times 10^5 \times 4096 \approx 3.22 \times 10^9\text{ FLOPs/token}$，仅占线性层的 **6.7%**，宏观上可以忽略；
- **当序列长度跃升至 $L = 131072$（128K）时**：
  注意力开销直接飙升至 $7.864 \times 10^5 \times 131072 \approx \mathbf{1.031 \times 10^{11}\text{ FLOPs/token}}$！
  **此时，光是计算注意力配对的算力消耗，就已经达到了全模型所有线性层计算总和的 2.15 倍**！单 token 总算力从 4K 时的 $5.12 \times 10^{10}$ 暴增至 128K 时的 $1.511 \times 10^{11}$，单步开销整整翻了近 3 倍！

>    - 切换为 64K：对应算力占比爬升至 17.8%；
>    - 当把【长窗口 token 占比】拉升至 25% 时：在 128K 窗口下，长文本将霸占全集群近 **47.6%** 的算力！
>
> **工程核心定论**：长序列的 FLOPs 膨胀极其迅猛。在规划算力预算与机器排期时，**绝对不能把 10B 长度为 128K 的数据简单等同于 10B 短文本**，必须严谨套用 $F(L)$ 算力核算公式。此外，真实物理耗时还会由于激活显存剧增被迫引发的上下文并行（Context Parallelism）、通信 All-to-All 以及重计算（Activation Checkpointing）而进一步成倍放大。

## 4. 从 4K 到 128K：位置、内容、边界缺一不可

### Step 1　位置编码的跨尺度适配：从 PI 到 YaRN

在旋转位置编码（RoPE，→ 1.2）中，第 $i$ 对应二维子空间的旋转角频率为 $\theta_i = b^{-2i/d}$（默认基频 $b = 10000$），位于序列绝对位置 $p$ 处的 token，其赋予的旋转相位为 $p\,\theta_i$。

当预训练模型从 4K 拓展到 128K 时，位置索引 $p$ 扩张了 $s = \frac{128\text{K}}{4\text{K}} = 32$ 倍。未经微调的模型在此前从未见过 $p > 4096$ 的极端相位，直接外推会导致注意力权重严重失真。

主流的频率域调整技术：
- **位置线性插值（Position Interpolation, PI）**：将位置索引直接缩小 $s$ 倍：$p' = p / s$。此时等效角频率变为 $\theta'_i = \theta_i / s$。PI 巧妙地将 128K 范围内产生的所有旋转相位强行压缩回了原本模型见过的 $[0, 4K]$ 相位区间内。然而其致命代价是：**它将相邻 token 之间的相对角位移差缩小了 $s$ 倍，极度模糊了近距离局部语法和短语结构的绝对位置分辨率**；
- **YaRN（Yet another RoPE extensioN）的频谱解耦思想**：YaRN 认识到不同维度通道的物理语义截然不同：
  - 高频维度通道（周期极短）：负责捕捉相邻 1–2 个 token 之间的严密语法依赖，这些通道**绝对不做插值**（保持原频率不变，捍卫高频分辨率）；
  - 低频维度通道（周期跨越数千 token）：主要编码全局长距离语义轮廓，这些通道**执行全额位置插值**；
  - 中频过度带：通过光滑的 S 型斜坡函数在非插值与全插值之间平稳过渡；
  - 配合注意力熵的全局温度增益缩放，YaRN 使得模型在极少微调步数下即可平稳无损地适应超长上下文。

### Step 2　样本拼接（Context Packing）与边界污染的残酷现实

在训练长上下文时，为了彻底消除数据填充（Padding）带来的显存与算力浪费，工程流水线普遍采用**样本打包拼接（Packing）**：将多篇短文档拼接在同一个长度为 128K 的大批次序列中。

然而，若简单地依赖默认的因果自注意力掩码，系统将面临灾难性的**注意力越界泄漏**。
考察一个极简微型场景：将两篇互不相关、长度各自仅为 $m = 64$ token 的文档 A 与 B，强行拼接为一个 128 token 的序列窗口：
- 在默认的全下三角因果掩码下，文档 B 中的每一个 token（从第 65 到 128 个位置），都能无障碍地向文档 A 中的全部 64 个 token 投射注意力；
- 这在整个 128 长度窗口的 $128 \times 129 / 2 = 8256$ 个合法因果下三角位置配对中，凭空制造了 $64 \times 64 = 4096$ 个**跨文档虚假可见配对**，其在总注意力配对中竟然霸占了 **49.6%** 的容量！

> **交互实验引导 · 细看隔离拼接与天然长文的本质鸿沟**：
> 在拼接与天然长文实验室中，观察三类位置配对在 128 长度因果空间中的百分比分布：
> 1. **默认状态基准观测（短文档 $m=64$，远距阈值 $1.00m$，即 $k \ge 64$）**：
>    - 第一根条形图【不隔离：跨文档配对】：清晰显示未经隔离的短文拼接中，跨越边界的虚假注意力对高达 **49.6%**（4096 个对）。如果下游任务要求样本相互独立，这构成了极其严重的上下文交叉污染；
>    - 第二根条形图【隔离拼接：文内距离 $\ge k$】：一旦我们引入严格的块对角掩码阻断跨文档注意力，你会看到极为残酷的一幕——**文内远距离配对占比直接归零（0.0%）**！因为在单篇 $m=64$ 的短文档内部，两点间的最远距离物理极限仅为 $64 - 1 = 63$，**在数学上根本不存在任何距离大于等于 64 的合法文内配对**！
>    - 第三根条形图【天然长文：文内距离 $\ge k$】：而对于一篇连贯且一气呵成的 128 token 天然长文档，两点间距离大于等于 64 的合法候选配对足足有 **2080 个**，霸占了全部下三角因果空间的 **25.2%**！
> 2. **调节远距阈值**：
>    将【远距阈值】下调至 $0.50m$（即距离 $\ge 32$）：隔离拼接的文内配对出现 12.8%（1056 个对），而天然长文则拥有 56.4%（4656 个对）。
>
> **工程极其深刻的底线结论**：
> 1. **仅插 `<eos>` 或重置 `position_id` 绝对无法阻止注意力泄漏**：自注意力机制并不理解特殊符号的语义边界，只要注意力掩码处于开启状态，前向传播依然会跨越边界融合上下文。**必须采用严格的块对角因果掩码（Block-diagonal Causal Mask）或在底层调用变长无填充算子（如 FlashAttention varlen API）**；
> 2. **拼接短文本永远无法凭空教会模型长程依赖**：将 32 篇 4K 短文本拼接装满 128K 窗口并执行隔离，虽然成功压榨了 GPU 的并行吞吐，但模型在注意力头内见到的最大文内跨度永远被锁死在 4K 以内！**要想训练出真正能跨越 64K、128K 进行复杂信息推理的模型，语料库中必须真实注入高质量、篇幅连贯且跨段落富含深层逻辑依赖的天然长文档**。

## 5. 配置长度、有效长度和任务能力

在开源社区与技术宣传中，经常看到某模型标榜“支持 128K 乃至 1M 上下文”。然而系统工程师必须保持清醒认知：**配置文件里的标称长度（Configured Length $L_{\max}$），仅仅代表网络结构在物理上不发生越界报错的吞吐极限**。

真正的基座能力，必须通过**操作性有效长度（Effective Context Length）**进行严格定义与度量：

> **有效长度操作性定义**：在给定的长程评测任务分布 $\mathcal{T}$、量化指标 $S$ 与基准及格阈值 $\tau$（如检索准确率 $\ge 80\%$）约束下，在评测覆盖的所有离散测试长度网格中，**所有不超过该长度的测试点均能达标的最大序列长度**。

例如对一个宣称 128K 的模型在特定代码长程调用基准上进行网格评测：
- 8K 长度下准确率为 94%（及格）；
- 32K 长度下准确率为 88%（及格）；
- 64K 长度下准确率骤跌至 66%（不及格）；
- 128K 长度下准确率跌破 30%。
在 80% 阈值下，该模型在该任务上的**真实有效长度仅为 32K**！盲目将其投产到 64K 业务流中必然引发业务崩溃。

在长上下文评测体系中，必须分层解耦三大核心能力：
1. **单点检索与大海捞针（Needle in a Haystack, NIAH）**：将一句无关的秘密事实（“针”）插入到数万字互不相关的背景填充文本（“干草堆”）中，测试模型能否在末尾精准找回。单点检索具有极高的自动化调试价值，但必须认清：**NIAH 全绿（100% 召回）仅仅是长上下文能力的最低及格线，它绝不证明模型理解了长文本的内在逻辑结构**；
2. **多跳证据聚合与冲突仲裁（Multi-hop Reasoning & Aggregation）**：在数万字的上下文中，埋藏位于前段、中段、后段的 3–5 处互相关联的线索，要求模型在排除大量混淆干扰项的前提下，完成逻辑串联推导；
3. **空间位置偏置与“迷失在中段”（Lost in the Middle）**：大量的实证研究表明，大模型在长文本处理中普遍呈现出两头强、中间弱的 U 型注意力偏置曲线（首尾信息召回率极高，而位于文本 30%–70% 深度处的信息极易被注意力头直接忽视）。在评测中必须对线索深度（Context Depth）做分层网格切片（从 0% 到 100% 均匀采样埋入深度），彻底排查中段遗忘盲区。

## 6. 从头复算两组结果

### 数值复算 · 长度课程的计算量与文档配对

第一组把短窗口固定为 4K，分别试 10% 的 token 处于 32K、64K、128K；最后算第 3 节的三阶段混合。$1\,\mathrm{ZFLOPs}=10^{21}$ FLOPs。

```python
N, layers, width, tokens = 8e9, 32, 4096, 100e9

def per_token(length):
    return 6 * N + 6 * layers * width * length

short = per_token(4096)
for length in (32768, 65536, 131072):
    p = 0.10
    long = per_token(length)
    avg = (1 - p) * short + p * long
    long_share = p * long / avg
    print(f"{length//1024:3d}K  总 FLOPs={tokens*avg/1e21:.3f}Z  长样本占比={long_share:.1%}  相对全 4K={avg/short:.3f}×")
stage0 = 60e9 * short
stage1 = 15e9 * short + 5e9 * per_token(32768)
stage2 = 15e9 * short + 5e9 * per_token(131072)
stage_total = stage0 + stage1 + stage2
print(f"三阶段总 FLOPs={stage_total/1e21:.3f}Z  长样本占比={(5e9*per_token(32768)+5e9*per_token(131072))/stage_total:.1%}")
```

**运行结果**

```text
 32K  总 FLOPs=5.348Z  长样本占比=13.8%  相对全 4K=1.044×
 64K  总 FLOPs=5.605Z  长样本占比=17.8%  相对全 4K=1.094×
128K  总 FLOPs=6.121Z  长样本占比=24.7%  相对全 4K=1.195×
三阶段总 FLOPs=5.734Z  长样本占比=19.6%
```

第二组显式枚举因果距离，比较隔离的短文档与一篇同样总长度的天然长文。分母统一为 128 个位置的全部因果配对，包含自身位置。

```python
m = 64
total = (2*m) * (2*m + 1) // 2
cross = m*m
print(f"总因果配对={total}  跨文档={cross} ({cross/total:.1%})")
for k in (32, 64):
    packed = 2 * sum(m - d for d in range(k, m))
    natural = sum(2*m - d for d in range(k, 2*m))
    print(f"距离≥{k:2d}  隔离拼接={packed:4d} ({packed/total:.1%})  天然长文={natural:4d} ({natural/total:.1%})")
```

**运行结果**

```text
总因果配对=8256  跨文档=4096 (49.6%)
距离≥32  隔离拼接=1056 (12.8%)  天然长文=4656 (56.4%)
距离≥64  隔离拼接=   0 (0.0%)  天然长文=2080 (25.2%)
```

## 7. 决策与误判

**工业级长上下文研发的黄金决策准则**：
- **以业务真实的跨度需求定义长度阶梯**：不要为了追逐技术噱头盲目追求 1M 上下文。先核算实际业务场景中多证据检索的核心跨度，以通过特定及格线的有效长度作为交付验收标准；
- **将配比账本细化至 Token 数量与 FLOPs 双维矩阵**：在设计中期训练流水线时，严密记录每一个阶段各领域的数据类别、序列长度、有效损失 token 吞吐与折合计算量；切换配方时，必须在固定的通用基准与长文本集上同步评估，严禁只比较训练 loss 的单点读数；
- **严密审查样本打包的隔离屏障**：在底层算子层面，彻底抛弃单纯依靠特殊符号隔离的幻想，全量部署块对角因果掩码与变长 FlashAttention；确保文档间的自注意力计算物理隔断，同时保证长程依赖由真实的连贯天然长文提供训练支撑；
- **捍卫基础能力的无损基线**：在调整 RoPE 频率与延长上下文的整个周期内，时刻跟踪模型在短文本常识、经典代码单题补全与通用推理基准上的得分；一旦出现超过 1.5% 的性能坍塌，果断增加通用短文本的回放权重并微调插值温度参数。
