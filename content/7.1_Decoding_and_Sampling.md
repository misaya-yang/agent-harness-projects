# 7.1 解码与采样

> **一句话核心直觉**：模型每一步只给出一个分布，取哪个 token 由解码算法决定。追求"最可能的序列"（贪心、beam search）会掉进两个坑：长度越短概率越高，所以最可能的输出常常是空的或很短；重复一旦出现就会自我强化，形成循环。直接按分布采样又会掉进另一个坑：12.8 万个 token 的长尾每个都很小，加起来却不小，500 个 token 里几乎必然采到一个离谱的词。温度只改变锐度（$dH/dT = \mathrm{Var}_p(z)/T^3 \ge 0$），不删除任何 token，升温时尾部的质量还会急剧上涨；截断（top-k、top-p、min-p）才真正把尾部切掉，三者的区别在于阈值是否随分布形状变化。约束解码用语法掩码保证输出合法，代价是扭曲分布：逐步掩码采样的并不是"合法输出上的条件分布"，模型可能被推向它本来不想给的答案。
> **唤醒标签**：贪心 ≠ 最可能序列 · 一半以上的最优翻译是空串 · n-gram 贪心必然循环 · 自我强化 · $p^{1/T}$ = 熵正则的最优解 · $dH/dT = \mathrm{Var}(z)/T^3$ · 长尾质量 · top-p 在高温下留下上万个 token · min-p = 相对阈值 · 先除温度再截断 · Gumbel-max · CTRL 惩罚对正负 logit 不对称 · 温度 0 也不确定：batch invariance · 掩码 ≠ 条件分布 · 先推理后答案

## 1. 问题：模型给的是分布，答案从哪来？

语言模型的最后一层输出一个 logit 向量 $z \in \mathbb{R}^{|V|}$，softmax 之后是下一个 token 的分布。Llama 3 的词表有 128,256 个 token，所以每一步都是一个 12.8 万维的分布。**模型本身到此为止**，接下来选哪个 token、选完怎么继续，是解码算法的事。同一个模型、同一个 prompt，换一种解码方式，可以得到复读机、平庸的套话、离题的胡言乱语，或者一段好文本。

解码算法分三类：

- **搜索**：找概率最高的序列。贪心每一步取 argmax，beam search 同时保留 $k$ 条候选。
- **采样**：按分布随机抽。温度调节分布的锐度，截断规则（top-k、top-p、min-p）删掉不可靠的长尾。
- **约束**：不管怎么选，只允许走到合法的输出（JSON、正则、语法）。

这一课回答两个常被问到的问题："为什么同一个 prompt 每次答案都不一样？"（采样，以及一个更隐蔽的原因：温度为 0 时也不一定一样，§5.3）和"JSON 模式怎么保证输出合法？"（§6）。

## 2. 找"最可能的序列"：贪心与 beam search

### 2.1 贪心不是最可能的序列

一个序列的概率是每步条件概率的乘积：$P(y) = \prod_t p(y_t \mid y_{<t})$。贪心每步取局部最大，但局部最优不保证全局最优。§9.1 的小例子：第一步 "The" 的概率 0.45，比 "A" 的 0.40 高，贪心选了 "The"；可 "The" 之后的三个词各只有 0.30–0.35，而 "A" 之后 "cat" 有 0.90。

| 序列 | 概率 | |
|---|---|---|
| A cat sat | 0.216 | beam = 2 找到的 |
| （空，直接结束） | 0.150 | |
| A cat | 0.144 | |
| The cat sat | 0.0945 | 贪心找到的 |

beam search 每步保留概率最高的 $k$ 个前缀。$k = 2$ 时，"A" 作为第二名活了下来，最终找到了 0.216 的序列。beam 越宽越接近真正的最大值（MAP），代价是 $k$ 倍的计算和 KV 缓存。

### 2.2 最可能的序列往往不是好文本

**第一个坑：越短越可能。** 每多一个 token，概率就乘上一个小于 1 的数。上表里排第二的就是空序列：它只需要第一步输出结束符（0.15），比任何以 "The" 开头的句子都可能。真实模型里这个效应很严重。Stahlberg & Byrne 用精确搜索找到了一个 Transformer 翻译模型在 WMT15 英德测试集上每句的全局最优译文：**超过一半的句子，模型给分最高的是空译文**。beam search 之所以能用，恰恰因为它搜不到真正的最优；作者的结论是这个模型需要"恰到好处的搜索误差"。机器翻译里 beam 越宽、BLEU 反而越低的现象（Koehn & Knowles）也是这个原因。常见的补救是用长度归一化的得分（$\log P(y)$ 除以长度的某个幂次）代替 $\log P(y)$。

**第二个坑：重复会自我强化。** 对 $n$-gram 模型可以严格证明贪心必然循环：下一个 token 是最近 $n-1$ 个 token 的确定函数，状态只有有限个，走得足够久必然回到见过的状态，之后就永远重复（§9.2 的二元模型几步之后就陷入 "the dog sat on the dog sat on…"）。Transformer 能看到整个上下文，没有这种必然性，但 Xu et al. 发现了一个类似的机制：人类语料里连续重复的句子极少（Wikitext-103 中只有 0.02%），而模型**重复一句话的次数越多，再重复它的概率越高**，起始概率越高的句子自我强化越强。贪心会选中这个越来越大的概率，于是陷入循环。

这不是老模型的问题。Qwen3 的模型卡对思考模式明确要求不要用贪心解码，因为"会导致性能下降和无尽的重复"；DeepSeek-R1 的模型卡建议温度设在 0.5–0.7，理由也是防止无尽重复或语无伦次。

### 2.3 根源：MLE 训练出来的分布是"抹开"的

为什么最大化概率得到的是坏文本？Holtzman et al. 发现，人类写的文本并不集中在模型的高概率区域，每个 token 的概率起伏很大，时常出现低概率的词；而 beam search 的文本每一步都是高概率词，平淡、重复。

从训练目标看这很自然。MLE 最小化的是 $\mathrm{KL}(p_{\text{data}} \,\|\, p_\theta)$（→ 0.5）：只要数据在某处有质量，模型就必须在那里放质量，否则 KL 爆炸。所以模型宁可把分布抹得宽一点，也不能漏掉任何可能。Hewitt et al. 把这总结为：**模型分布是真实分布的平滑版本**，大约是 $p_\theta \approx (1-\lambda)\,p_{\text{true}} + \lambda\cdot(\text{平滑项})$。平滑带来两个后果：

- 搜索（取众数）时，抹开的分布让短序列、重复序列占了便宜；
- 采样时，平滑项分散在十几万个 token 上，每个很小、合起来不小，它们就是"离谱的词"的来源（§3.3）。

现代解码的主流因此是**采样 + 截断**：采样避免众数的退化，截断去掉平滑出来的长尾。

## 3. 温度：同一个排序，不同的锐度

### 3.1 定义

$$
p_T(i) = \frac{e^{z_i/T}}{\sum_j e^{z_j/T}}
$$

$T \to 0$ 时质量集中到最大的 logit，退化为贪心；$T = 1$ 是模型原本的分布；$T \to \infty$ 时趋于均匀分布。温度不改变 token 的排序，也**不会把任何 token 的概率变成 0**。

### 3.2 推导一：升温一定让熵变大

记 $\beta = 1/T$，$p_i = e^{\beta z_i}/Z$，$Z = \sum_j e^{\beta z_j}$。因为 $\log p_i = \beta z_i - \log Z$，

$$
H = -\sum_i p_i \log p_i = \log Z - \beta\,\mathbb{E}_p[z]
$$

需要两个导数。配分函数的导数给出均值：$\frac{d}{d\beta}\log Z = \frac{1}{Z}\sum_j z_j e^{\beta z_j} = \mathbb{E}_p[z]$。均值的导数给出方差：

$$
\frac{d}{d\beta}\mathbb{E}_p[z] = \sum_i z_i \frac{dp_i}{d\beta} = \sum_i z_i\, p_i\,(z_i - \mathbb{E}_p[z]) = \mathrm{Var}_p(z)
$$

代回去：

$$
\frac{dH}{d\beta} = \mathbb{E}_p[z] - \mathbb{E}_p[z] - \beta\,\mathrm{Var}_p(z) = -\beta\,\mathrm{Var}_p(z)
$$

再用 $d\beta/dT = -1/T^2$：

$$
\boxed{\ \frac{dH}{dT} = \frac{\mathrm{Var}_{p_T}(z)}{T^3} \ \ge 0\ }
$$

熵随温度单调上升，上升的速度由当前分布下 logit 的方差决定。§9.3 用数值差分验证：确定的分布上两者都是 0.9708，开放的分布上都是 1.1323。

### 3.3 推导二：温度就是熵奖励的系数

为什么偏偏是 $p^{1/T}$ 这种形式？考虑在"贴近模型"和"保持多样"之间权衡：

$$
\max_q\ \ \mathbb{E}_{q}[\log p] + T\cdot H(q) \quad \text{s.t.}\ \sum_i q_i = 1
$$

拉格朗日函数对 $q_i$ 求导：$\log p_i - T(\log q_i + 1) - \mu = 0$，所以 $\log q_i = \frac{1}{T}\log p_i + \text{常数}$，即

$$
q^* \propto p^{1/T} = e^{z/T}
$$

温度 $T$ 就是熵奖励的权重：$T < 1$ 时更看重贴近模型的高概率区，$T > 1$ 时更看重多样性。这和 2.0 里 KL 正则化强化学习的最优策略 $\pi^* \propto \pi_{\text{ref}}\,e^{r/\beta}$ 是同一个数学结构。

### 3.4 推导三：升温时尾部质量会暴涨

真实模型的 logit 大致是这样的：少数合理的候选 logit 很高，其余十几万个 token 的 logit 挤成一团，近似正态分布 $\mathcal{N}(\mu, \sigma^2)$。设头部最高的 logit 比这一团的中心高 $\Delta$，算一下这一团（"尾部"）的总权重。对正态变量，$\mathbb{E}[e^{z/T}] = e^{\mu/T + \sigma^2/(2T^2)}$，所以

$$
\log(\text{尾部总权重}) \approx \log|V| + \frac{\mu}{T} + \frac{\sigma^2}{2T^2}, \qquad \log(\text{头部权重}) \approx \frac{\mu + \Delta}{T}
$$

二者之差：

$$
\log\frac{\text{尾部}}{\text{头部}} \approx \underbrace{\log|V|}_{\text{与 } T \text{ 无关}} + \frac{\sigma^2}{2T^2} - \frac{\Delta}{T}
$$

$\log|V| = \log 128256 = 11.76$ 是一个不随温度变化的常数，它代表"人多势众"。头部的优势 $\Delta/T$ 却随温度线性缩水。所以**温度每升一点，尾部都会成倍地追上来**。

§9.3 构造了这样一个分布（尾部 logit 取 $\mathcal{N}(0, 2.5^2)$，头部是"确定"和"开放"两种语境），算出尾部的总质量和 500 个 token 里至少采到一次尾部 token 的概率：

| $T$ | 确定语境的尾部质量 | 500 token 内踩中 | 开放语境的尾部质量 | 500 token 内踩中 |
|---|---|---|---|---|
| 0.7 | $2\times 10^{-6}$ | 0.1% | $1.7\times 10^{-4}$ | 8.2% |
| 1.0 | $8\times 10^{-4}$ | 33% | $7.5\times 10^{-3}$ | 98% |
| 1.3 | $3.2\times 10^{-2}$ | ≈100% | $8.5\times 10^{-2}$ | ≈100% |
| 1.6 | 0.27 | ≈100% | 0.35 | ≈100% |

这是一个构造的分布，具体数字因模型而异，但算术是普遍的：**单个 token 的概率小，不代表采到它们的概率小**。$T = 1$ 时开放语境的尾部只占 0.75%，一段 500 token 的回答却几乎必然踩中一次；而一个离谱的词一旦进入上下文，后面的生成都要以它为条件，错误会传下去。温度只能整体调节锐度，没法单独去掉尾部，所以需要截断。

## 4. 截断：只在可靠的 token 里采样

### 4.1 四种规则

把分布从大到小排好：$p_{(1)} \ge p_{(2)} \ge \cdots$。截断规则选出一个保留集合 $A$，在 $A$ 里重新归一化后采样。

| 规则 | 保留集合 $A$ | 阈值是否随分布变化 |
|---|---|---|
| top-k | 前 $k$ 个 | 不变：永远 $k$ 个 |
| top-p（nucleus） | 累计概率达到 $p$ 的最短前缀 | 随分布的整体形状变化 |
| min-p | $p_i \ge p_{\min}\cdot p_{(1)}$ | 随最大概率（模型的把握）变化 |
| $\epsilon$ / $\eta$ 采样 | $p_i \ge \epsilon$（$\eta$ 采样的阈值还随熵调整） | $\epsilon$ 不变，$\eta$ 随熵变化 |

### 4.2 每种规则在哪里失效

§9.4 用同一个分布比较三种规则（$k = 40$，$p = 0.9$，$p_{\min} = 0.1$）。"尾部"指不属于合理候选的 token：

| 情形 | top-k 40 | top-p 0.9 | min-p 0.1 |
|---|---|---|---|
| $T=1$，确定 | 留 40 个，其中 35 个是尾部 | 留 1 个 | 留 1 个 |
| $T=1$，开放 | 留 40 个，其中 10 个是尾部 | 留 23 个 | 留 27 个 |
| $T=1.6$，确定 | 尾部占 1.2% | **留 14,120 个，尾部占 19%** | 留 2 个，尾部 0% |
| $T=1.6$，开放 | 尾部占 0.8% | **留 20,044 个，尾部占 27%** | 留 30 个，尾部 0% |

```academy-lab
7.1
```

- **top-k 的问题是 $k$ 固定。** 模型很确定时，第 2 到第 40 名都是垃圾，也被留下了（$T = 1$ 时它们的质量还很小，升温后就占到了 1%）；模型面对很多合理选择时（比如创意写作的开头），40 个又可能太少。
- **top-p 在高温下崩溃。** top-p 看的是累计质量。升温之后头部的质量被尾部稀释，要凑够 90% 只能一路吃进尾部：$T = 1.6$ 时保留了一两万个 token，采样有五分之一到四分之一的概率落在尾部。所以 top-p 只适合配合温和的温度（0.6–1.0）。
- **min-p 的阈值跟着模型的把握走。** 阈值是最大概率的 10%：模型确定时 $p_{(1)}$ 大、阈值高，只留几个；模型不确定时阈值低，留得多。尾部 token 的概率远低于最大概率的 10%，无论温度多高都进不来。这就是 min-p 论文主张可以"放心升温"的机制。

但要分清**机制和效果**。Schaeffer et al. 重新检查了 min-p 论文的证据，发现原论文的人类评测漏了数据、统计检验做错了，在控制超参数数量之后，min-p 在质量、多样性或二者权衡上都没有超过基线。上表只说明 min-p 在高温下切得更干净，不说明它生成的文本更好。实践中的默认值多数仍是 $T = 0.6$–1.0 配 top-p 0.9–0.95，模型卡通常会给推荐值（比如 Qwen3 思考模式：$T = 0.6$、top-p 0.95、top-k 20）。

### 4.3 顺序很重要

温度和截断谁先谁后，结果不同。HF transformers 的顺序是先除温度，再依次做 top-k、top-p、min-p，所以上表里截断看到的是升温之后的分布。如果**先截断、再升温**，保留集合在 $T = 1$ 时就定了，升温只是在保留下来的合理候选之间重新分配，尾部永远进不来。想要多样性又不想要垃圾时，这个顺序更安全。读一个推理框架的采样参数，先查它的顺序。

## 5. 采样的实现细节

### 5.1 Gumbel-max：不用累加也能采样

最直接的采样是算累积分布、抽一个均匀数、二分查找。另一种方法是给每个 logit 加一个独立的 Gumbel 噪声，再取 argmax：

$$
\arg\max_i\ (z_i + G_i) \ \sim\ \mathrm{softmax}(z), \qquad G_i = -\log(-\log U_i),\ U_i \sim \mathrm{U}(0,1)
$$

**证明。** Gumbel 分布的 CDF 是 $F(g) = e^{-e^{-g}}$，密度 $f(g) = e^{-g}e^{-e^{-g}}$。$k$ 胜出的条件是对所有 $i \ne k$，$z_i + G_i < z_k + G_k$。给定 $G_k = g$：

$$
P(k \text{ 胜出}) = \int f(g)\prod_{i\ne k} F(z_k + g - z_i)\,dg = \int e^{-g}\exp\!\Big(-e^{-g}\sum_i e^{z_i - z_k}\Big)dg
$$

（$i = k$ 那一项来自 $f(g)$ 里的 $e^{-e^{-g}}$。）令 $S = \sum_i e^{z_i - z_k}$，换元 $u = e^{-g}$，积分变成 $\int_0^\infty e^{-uS}du = 1/S = e^{z_k}/\sum_i e^{z_i}$。证毕。

它有三个用处：

- **并行**：只需要逐元素加噪声和一次 argmax，没有前缀和。
- **可复现**：噪声由随机种子决定，种子固定时采样就是 logit 的确定函数。
- **不放回抽样**：取 $z + G$ 的前 $k$ 大，恰好是从分布中不放回地抽 $k$ 个（Gumbel-top-k）。Kool et al. 把它推广到序列上，得到随机 beam search：beam 里的 $k$ 条序列是真正的不放回样本，而不是 $k$ 个众数。

§9.5 抽 20 万次，频率与 softmax 的最大偏差是 0.0017；"先 0 后 1"的频率 0.3491，理论值 $p_0 p_1/(1-p_0) = 0.3499$。

工程上还有一个细节：top-p 需要排序，对 12.8 万维的向量排序在 GPU 上不便宜。FlashInfer 用拒绝采样绕开了排序：先忽略阈值采一个 token，用它的概率更新阈值，在剩下的 token 里重复，直到采到的 token 满足 top-p 条件。

### 5.2 重复惩罚：一个容易写错的公式

CTRL 提出的重复惩罚对已经出现过的 token 做：logit 为正就除以 $\theta$，为负就乘以 $\theta$（$\theta > 1$）。为什么要分正负？因为直接除以 $\theta$ 会把负 logit 往 0 推，**反而提高了它的概率**。§9.5 的例子：logit $[2, -2, 0]$，前两个出现过，$\theta = 1.3$。CTRL 规则下第二个 token 的概率从 0.016 降到 0.013；直接除的话升到 0.037，惩罚变成了奖励。

这个规则还有一个副作用：softmax 对所有 logit 加同一个常数不变，CTRL 惩罚却会变，因为加常数可能改变 logit 的正负号。减法形式的惩罚没有这个问题，常见的 frequency / presence penalty 就是

$$
z_i \leftarrow z_i - \alpha_{\text{freq}}\cdot c_i - \alpha_{\text{pres}}\cdot \mathbb{1}[c_i > 0]
$$

$c_i$ 是 token $i$ 已出现的次数。两种惩罚都作用在 prompt 和已生成的所有 token 上，包括标点、代码缩进、JSON 的引号，所以设大了会伤害格式。Qwen3 的模型卡建议 presence penalty 设在 0–2 之间，并提醒设得高可能导致语言混杂和轻微的性能下降。

### 5.3 温度为 0，结果也会不同

把温度设为 0（贪心），同一个请求发 1000 次，结果应该完全一样？Thinking Machines 用 Qwen3-235B-A22B 做了这个实验：温度 0，同一个 prompt 生成 1000 次、每次 1000 个 token，得到了 **80 种不同的输出**，最常见的那种只出现了 78 次。

常见的解释是"GPU 并行累加的顺序不固定"，但他们指出这不是主因：同一个矩阵乘法单独跑多次，结果是逐位相同的。真正的原因是**缺少批不变性（batch invariance）**：推理服务把你的请求和别人的请求拼成一个 batch，batch 大小随负载变化，而矩阵乘法、注意力、归一化的内核会根据 batch 大小选择不同的切分和归约顺序。浮点加法不满足结合律，归约顺序一变，logit 的低位就变；两个候选 logit 很接近时，argmax 就翻转了，之后的生成全部分叉。他们实现了批不变的内核后，1000 次输出完全一致。这对 RL 也很重要：训练端和推理端算出的 log 概率不一致，本身就是一种 off-policy（→ 2.7）。

## 6. 约束解码：保证 JSON 合法

### 6.1 机制：每一步掩掉不合法的 token

要求输出满足 JSON schema、正则表达式或一个语法时，在每一步：

1. 根据已生成的前缀，算出哪些 token 接上去之后仍然**可能**走到合法输出；
2. 把其余 token 的 logit 设为 $-\infty$；
3. 在剩下的 token 里照常采样。

难点在于**语法是定义在字符上的，token 却是多个字符的块**。一个 token 可能是 `":`、`{"` 或 ` true`，跨越语法里的好几个符号。判断它是否合法，要把它的每个字符依次喂给语法的自动机。

- **正则 → 有限状态机**：Outlines 的做法是离线预计算一张表，对 FSM 的每个状态记下哪些 token 可以接受，运行时查表即可。
- **上下文无关语法 → 下推自动机**：JSON 可以任意嵌套，需要一个栈来记住还有几层括号没闭合，合法 token 集合取决于栈的内容，无法完全预计算。XGrammar 把词表分成两类：**上下文无关的 token**（是否合法只取决于当前位置，不取决于栈，占绝大多数）可以预先检查；**上下文相关的 token** 运行时用一个持久化的栈来检查。再把掩码计算和 GPU 前向重叠起来，开销接近零，比之前的方案快最多 100 倍。

### 6.2 掩码会扭曲分布

逐步掩码保证了输出合法，但它采样的分布是什么？设合法输出的集合为 $\mathcal{L}$，我们想要的是模型在合法输出上的条件分布：

$$
p(y \mid y \in \mathcal{L}) = \frac{P(y)}{P(\mathcal{L})} = \frac{\prod_t p(y_t \mid y_{<t})}{P(\mathcal{L})}
$$

逐步掩码实际采样的是：

$$
q(y) = \prod_t \frac{p(y_t \mid y_{<t})}{Z_t(y_{<t})}, \qquad Z_t(y_{<t}) = \sum_{w \text{ 合法}} p(w \mid y_{<t})
$$

两者之比 $q(y)/p(y\mid\mathcal{L}) = P(\mathcal{L})/\prod_t Z_t(y_{<t})$ 依赖于路径 $y$。**如果某条路径途中的合法质量 $Z_t$ 很小，掩码就会把这条路径放大很多倍**。

§9.6 的例子。问"这家公司的总部在哪个城市"，schema 规定答案只能是 "New York" 或 "Boston"。模型第一步给 "New" 0.60（它想说的其实是 "New Jersey"："New" 之后接 "Jersey" 的概率 0.98，接 "York" 只有 0.02）、"Boston" 0.30、"Chicago" 0.10：

| 答案 | 模型原始概率 | 合法输出上的条件概率 | 逐步掩码 |
|---|---|---|---|
| Boston | 0.300 | **0.962** | 0.333 |
| New York | 0.012 | 0.038 | **0.667** |

在合法答案里，模型其实 96% 相信是 Boston。掩码在第一步只删掉 "Chicago"，"New" 拿到了 0.6/0.9 = 0.667 的概率；走进 "New" 之后，"Jersey" 被禁止，只能接 "York"。模型本来不想去的答案被放大了 17 倍，KL 散度 1.55 nat。

```academy-lab

```

正确的做法是在每一步按**未来能否合法**加权：$q(w \mid y_{<t}) \propto p(w \mid y_{<t})\cdot P(\mathcal{L} \mid y_{<t}w)$。这里 $P(\mathcal{L} \mid \text{New}) = 0.02$，"New" 的权重变成 $0.6\times 0.02 = 0.012$，恰好恢复精确的条件分布。可惜这个"未来合法概率"一般算不出来，Grammar-Aligned Decoding 的 ASAp 算法用已有的样本逐步逼近它，保证在样本足够多时收敛到正确的分布。

### 6.3 实践中的后果

- **格式限制会伤害推理。** Tam et al. 比较了同一个任务让模型自由回答和强制 JSON / XML 格式回答，强制格式下推理能力显著下降，约束越严下降越多。
- **schema 里把推理放在答案前面。** 自回归模型的答案只能依赖它前面的 token。`{"answer": ..., "reasoning": ...}` 让模型先给答案再编理由；`{"reasoning": ..., "answer": ...}` 才能让推理影响答案。
- **让合法的写法也是自然的写法。** 掩码之所以扭曲分布，是因为模型想走的路被堵死了。枚举值用模型习惯的拼写和大小写，在 prompt 里先给出格式示例，让模型本来就想按格式写，掩码就几乎不用干预。
- **约束也会改变分词。** 语法逐字符检查，可能允许模型用一种不常见的切法拼出合法字符串（比如把一个常见词拆成几个罕见 token），这些 token 序列在训练中很少出现，后续生成的质量会下降。

## 7. 采样参数与 RL rollout

强化学习（→ 2.3、2.5）里的采样参数不只影响输出的风格，还影响梯度是否正确。策略梯度要求样本来自 $\pi_\theta$，并且用 $\log\pi_\theta$ 计算更新。如果 rollout 用 $T = 0.7$ 加 top-p 0.95 采样，实际的采样分布是另一个分布 $\pi'$，用 $\pi_\theta$ 的 log 概率去算梯度就是在用错的分布做估计。

§9.7 在开放语境上算了一下：$\pi'$ 只保留 24 个 token，$\pi$ 在其余 token 上还有 7.3% 的质量，这部分**永远采不到**，策略梯度看不见它们，也就无法调整它们；已采到的 token 上，$\pi/\pi'$ 在 0.68 到 1.41 之间，KL$(\pi'\|\pi) = 0.096$ nat。所以多数 RL 训练用 $T = 1$、不截断地采样；如果用了别的温度，计算 log 概率时也要除以同一个温度，让训练的策略就是采样的策略。

温度在这里还控制探索。rollout 的熵太低，同一个 prompt 的一组回答都一样，组内优势全为 0，GRPO 没有学习信号；熵太高，回答里充满尾部 token。RL 训练中策略的熵会持续下降（熵塌缩），很多工作会监控它（→ 2.7）。评测时同样要注意采样设置：DeepSeek-R1 的评测用 $T = 0.6$、top-p 0.95，每题采 64 次来估计 pass@1，而不是用贪心解码只跑一次。

## 8. 与 0.5、0.7、2.0 的联系

- **0.5 熵与 KL**：MLE 最小化前向 KL，模型分布覆盖所有模式，因此是"抹开"的（§2.3）；温度是熵正则的系数（§3.3）。
- **0.7 采样**：Gumbel-max 是逆变换采样之外的另一种精确采样；约束解码的扭曲是"局部归一化 ≠ 全局条件化"，与重要性采样、序列蒙特卡洛的思路相通。
- **2.0 强化学习基础**：$p^{1/T}$ 与 KL 正则化 RL 的最优策略 $\pi_{\text{ref}}e^{r/\beta}$ 同构；rollout 的采样分布必须与计算梯度的策略一致（§7）。
- **7.2 投机解码**：它要在不改变目标模型采样分布的前提下加速，所以本课定义的"采样分布"就是 7.2 要保持的东西，截断和温度都要先作用在目标分布上。

## 9. 从零实现

### 9.1 贪心、beam search 与最可能的序列

```python
import numpy as np
from collections import Counter, defaultdict

LM = {                                  # 一个手写的小语言模型：前缀 → 下一个词的分布
    (): {"The": 0.45, "A": 0.40, "<eos>": 0.15},
    ("The",): {"cat": 0.35, "dog": 0.35, "bird": 0.30},
    ("A",): {"cat": 0.90, "dog": 0.10},
}
def dist(prefix):
    if prefix in LM: return LM[prefix]
    return {"sat": 0.6, "<eos>": 0.4} if len(prefix) == 2 else {"<eos>": 1.0}

def all_seqs(prefix=(), p=1.0):         # 穷举所有序列及其概率
    for w, q in dist(prefix).items():
        if w == "<eos>": yield prefix, p * q
        else: yield from all_seqs(prefix + (w,), p * q)

def greedy():
    pre, p = (), 1.0
    while True:
        w, q = max(dist(pre).items(), key=lambda kv: kv[1]); p *= q
        if w == "<eos>": return pre, p
        pre += (w,)

def beam(k):
    beams, done = [((), 1.0)], []
    while beams:
        cand = []
        for pre, p in beams:
            for w, q in dist(pre).items():
                if w == "<eos>": done.append((pre, p * q))
                else: cand.append((pre + (w,), p * q))
        beams = sorted(cand, key=lambda x: -x[1])[:k]
        done = sorted(done, key=lambda x: -x[1])[:k]
        if done and (not beams or done[0][1] >= beams[0][1]): break   # 已完成的比所有活着的都好
    return done[0]

for s, p in sorted(all_seqs(), key=lambda x: -x[1])[:4]:
    print(f"{' '.join(s) or '(空)':12s} {p:.4f}")
g = greedy(); print("贪心", " ".join(g[0]), round(g[1], 4))
for k in (2, 4): b = beam(k); print(f"beam={k}", " ".join(b[0]), round(b[1], 4))
# A cat sat 0.2160 / (空) 0.1500 / A cat 0.1440 / The cat sat 0.0945
# 贪心 The cat sat 0.0945 · beam=2 A cat sat 0.216 · beam=4 A cat sat 0.216
```

```python
V = 128256                                       # Llama 3 的词表

def H(p): q = p[p > 0]; return -(q * np.log(q)).sum()
```

### 9.4 三种截断规则

```python
def top_k(p, k=40):
    keep = np.zeros_like(p, bool); keep[np.argsort(-p)[:k]] = True; return keep
def top_p(p, P=0.9):
    order = np.argsort(-p); n = np.searchsorted(np.cumsum(p[order]), P) + 1   # 累计质量 ≥ P 的最短前缀
    keep = np.zeros_like(p, bool); keep[order[:n]] = True; return keep
def min_p(p, m=0.1):
    return p >= m * p.max()

for T in (1.0, 1.6):
    for name, z in [("确定", confident), ("开放", open_)]:
        p, h = softmax(z, T), heads[name]
        for rule, f in [("top-k 40", top_k), ("top-p 0.9", top_p), ("min-p 0.1", min_p)]:
            keep = f(p); kept = p * keep
            print(f"T={T} {name} {rule:9s} 留 {keep.sum():6d} 个（尾部 {keep[h:].sum():5d} 个），"
                  f"尾部占 {kept[h:].sum() / kept.sum():5.1%}")
# T=1.0 确定: top-k 留 40（尾部 35，占 0.0%） · top-p 留 1 · min-p 留 1
```

```python
rng = np.random.default_rng(0)
z = np.array([2.0, 1.0, 0.5, -1.0]); p = np.exp(z) / np.exp(z).sum()
G = -np.log(-np.log(rng.random((200_000, 4))))
freq = np.bincount(np.argmax(z + G, axis=1), minlength=4) / 200_000
print("softmax", p.round(4), " Gumbel", freq.round(4), f" 最大偏差 {np.abs(freq - p).max():.4f}")

print(f"先 0 后 1: {np.mean((top2[:, 0] == 0) & (top2[:, 1] == 1)):.4f}  理论 {p[0] * p[1] / (1 - p[0]):.4f}")

def ctrl_penalty(z, seen, theta=1.3):
    z = z.copy()
    for i in seen: z[i] = z[i] / theta if z[i] > 0 else z[i] * theta
    return z
def naive_penalty(z, seen, theta=1.3):
    z = z.copy(); z[seen] /= theta; return z
z = np.array([2.0, -2.0, 0.0]); sm = lambda v: np.exp(v) / np.exp(v).sum()
print("原始", sm(z).round(3), " CTRL", sm(ctrl_penalty(z, [0, 1])).round(3), " 直接除", sm(naive_penalty(z, [0, 1])).round(3))
# softmax [0.6095 0.2242 0.136 0.0303]  Gumbel [0.6079 0.2244 0.1377 0.0301]  最大偏差 0.0017
# 先 0 后 1: 0.3491  理论 0.3499
# 原始 [0.867 0.016 0.117]  CTRL [0.813 0.013 0.174]  直接除 [0.793 0.037 0.17]   ← 直接除反而奖励了 token 1
```

### 9.6 约束解码的扭曲与前瞻修正

```python
lm = {(): {"New": 0.60, "Boston": 0.30, "Chicago": 0.10},
      ("New",): {"Jersey": 0.98, "York": 0.02}}
allowed = {("New", "York"), ("Boston",)}                  # schema 的 enum
nxt = lambda pre: lm.get(pre, {"<eos>": 1.0})
def walk(pre=(), p=1.0, out=None):                        # 不加约束的序列分布
    out = {} if out is None else out
    for w, q in nxt(pre).items():
        if w == "<eos>": out[pre] = out.get(pre, 0) + p * q
        else: walk(pre + (w,), p * q, out)
    return out
P = walk()
exact = {s: P[s] / sum(P[a] for a in allowed) for s in allowed}
ok = lambda pre: any(s[:len(pre)] == pre for s in allowed)
future = lambda pre: sum(P[a] for a in allowed if a[:len(pre)] == pre) / sum(v for s, v in P.items() if s[:len(pre)] == pre)

def constrained(lookahead, pre=(), p=1.0, out=None):
    out = {} if out is None else out
    cand = {w: q for w, q in nxt(pre).items()
            if (w == "<eos>" and pre in allowed) or (w != "<eos>" and ok(pre + (w,)))}
    if lookahead:                                          # 按“未来能否合法”加权
        cand = {w: q * (1.0 if w == "<eos>" else future(pre + (w,))) for w, q in cand.items()}
    s = sum(cand.values())
    for w, q in cand.items():
        if w == "<eos>": out[pre] = p * q / s
        else: constrained(lookahead, pre + (w,), p * q / s, out)
    return out
M, F = constrained(False), constrained(True)
for s in sorted(allowed):
    print(f"{' '.join(s):9s} 原始 {P[s]:.3f}  精确条件 {exact[s]:.3f}  逐步掩码 {M[s]:.3f}  前瞻加权 {F[s]:.3f}")
print(f"KL(掩码 || 精确) = {sum(M[s] * np.log(M[s] / exact[s]) for s in allowed):.2f} nat")
# Boston    原始 0.300  精确条件 0.962  逐步掩码 0.333  前瞻加权 0.962
# New York  原始 0.012  精确条件 0.038  逐步掩码 0.667  前瞻加权 0.038
# KL(掩码 || 精确) = 1.55 nat
```

## 10. 实战直觉、避坑与面试深挖

**与工程 / 应用的连接**
- **按任务选解码**：代码、工具调用、抽取类任务要确定性，用低温度（0–0.3）或贪心；对话 $T \approx 0.7$ 配 top-p 0.9–0.95；推理模型按模型卡（多为 $T = 0.6$、top-p 0.95），不要贪心。创意写作想要更高的温度，就先截断再升温，或用 min-p。
- **需要可复现时**：固定种子只能保证"同样的 logit → 同样的采样"。在线服务里 batch 大小随负载变化，logit 本身就可能变；需要逐位一致时要用批不变的内核，或者离线固定 batch。
- **结构化输出**：用 XGrammar / Outlines 这类引擎保证语法，同时把 schema 设计成模型自然会写的样子：推理字段放在答案字段前面，枚举值用常见拼写，prompt 里先给示例。
- **RL 训练**：rollout 默认 $T = 1$、不截断；任何温度或截断都要在计算 log 概率时同样施加，并监控 rollout 的熵。

**常见误区 / 反直觉点**
1. **"贪心就是在找最可能的回答"** ✗：贪心只找每一步的局部最大值；真正的最可能序列往往是很短的甚至空的，而且重复。
2. **"温度调低就不会说胡话了"** ✗：温度只改变锐度，不删除任何 token；$T = 1$ 时 0.75% 的尾部质量在 500 个 token 里几乎必然被采到。去掉尾部要靠截断。
3. **"top-p 0.9 就是去掉了 10% 的垃圾"** ✗：top-p 保留多少 token 取决于分布的形状；高温下它可能保留两万个 token，其中大部分是尾部。
4. **"重复惩罚就是把出现过的 logit 除以 θ"** ✗：负 logit 除以 θ 会变大，惩罚变成奖励；CTRL 的规则对正负 logit 分别处理。
5. **"温度为 0 输出就是确定的"** ✗：服务端的 batch 大小会改变内核的归约顺序，logit 的低位随之变化，接近平局时 argmax 会翻转。
6. **"约束解码只是过滤，不影响模型想说什么"** ✗：逐步掩码采样的不是合法输出上的条件分布，模型可能被推向一个它本来认为不太可能的答案（§6.2 的例子放大了 17 倍）。

**高频深挖题**
- **Q1：为什么 beam search 在开放式生成里效果不好，在翻译里却还能用？**
  思路：beam 逼近众数 → 众数短、平淡、重复（MLE 的分布被抹开）→ 翻译有源句约束，输出空间窄，且靠长度归一化和适度的搜索误差 → 加分项：Stahlberg & Byrne 发现一半以上句子的精确最优是空译文。
- **Q2：推导温度对熵的影响。**
  思路：$H = \log Z - \beta\mathbb{E}[z]$ → $d\log Z/d\beta = \mathbb{E}[z]$，$d\mathbb{E}[z]/d\beta = \mathrm{Var}(z)$ → $dH/dT = \mathrm{Var}(z)/T^3$ → 加分项：$p^{1/T}$ 是 $\max_q \mathbb{E}_q\log p + T\,H(q)$ 的解。
- **Q3：比较 top-k、top-p、min-p。各自在什么情况下失效？**
  思路：top-k 阈值固定，确定时留垃圾、开放时切掉好词 → top-p 按累计质量，高温时尾部稀释头部，要吃进上万个 token → min-p 相对最大概率，阈值随把握收放 → 加分项：温度和截断的先后顺序；min-p 的效果证据有争议。
- **Q4：JSON 模式是怎么实现的？它有什么副作用？**
  思路：语法 → FSM / 下推自动机 → 每步算合法 token 集合并掩码 → token 跨多个字符，需要模拟自动机；XGrammar 预检上下文无关的 token → 副作用：逐步掩码 ≠ 条件分布，格式限制降低推理表现 → 加分项：推理字段放答案前面。
- **Q5：同一个请求温度为 0，为什么两次结果不同？**
  思路：不是"并行累加随机"→ 是 batch 大小变化导致内核选择不同的归约策略 → 浮点加法不结合 → logit 低位变化，近似平局时 argmax 翻转 → 加分项：批不变内核；RL 中训推 log 概率不一致。

## 11. 练习（附解答）

**练习 1**　一个分布有 1 个 token 概率 0.5，另外 1000 个 token 各 0.0005。分别用 top-k = 40、top-p = 0.9、min-p = 0.1 截断，各保留多少 token？

> **解答**：top-k 保留 40 个（0.5 那个加 39 个小的）。top-p：0.5 之后还需要 0.4，每个小 token 贡献 0.0005，要 800 个，所以保留 801 个。min-p：阈值 $0.1\times 0.5 = 0.05$，小 token 都低于阈值，只保留 1 个。同一个分布，三种规则保留 40、801 和 1 个 token：在"一个明显的答案 + 一大片均匀的尾部"这种形状上，top-p 最宽松。

**练习 2**　logit 只有两个：$z_1 = 2$，$z_2 = 0$。求 $T = 1$ 时的熵和 $dH/dT$，再用 $T = 1.01$ 的熵做差分验证。

> **解答**：$p_1 = e^2/(e^2 + 1) = 0.8808$，$p_2 = 0.1192$。$H = -(0.8808\ln 0.8808 + 0.1192\ln 0.1192) = 0.1118 + 0.2535 = 0.3653$ nat。$\mathrm{Var}(z) = 4p_1 - (2p_1)^2 = 4p_1 p_2 = 0.4200$，所以 $dH/dT = 0.4200$。$T = 1.01$ 时 $p_1 = 1/(1 + e^{-2/1.01}) = 0.8787$，$H = 0.1136 + 0.2559 = 0.3695$，差分 $(0.3695 - 0.3653)/0.01 = 0.417$，与 0.420 吻合（剩下的差别来自差分步长带来的二阶项）。

**练习 3**　某个回答需要 300 个 token。若每一步有 0.2% 的质量落在尾部，整段回答完全不碰尾部的概率是多少？要让这个概率达到 95%，每步的尾部质量要压到多少？

> **解答**：$(1 - 0.002)^{300} = e^{300\ln 0.998} \approx e^{-0.6006} = 0.549$，近一半的回答会踩中至少一次尾部。要 $(1-m)^{300} \ge 0.95$，需 $m \le 1 - 0.95^{1/300} \approx 1.71\times 10^{-4}$。每步的尾部质量必须压到万分之二以下，靠降温很难做到又不损失多样性，截断可以直接把它变成 0。

**练习 4**　§6.2 的例子里，"New" 之后接 "York" 的概率 $b$ 是多少时，逐步掩码给 "New York" 的概率才等于精确的条件概率？解释原因。

> **解答**：掩码给 "New York" 的概率是 $0.6/(0.6 + 0.3) = 2/3$，与 $b$ 无关；精确的条件概率是 $0.6b/(0.6b + 0.3)$。令二者相等得 $0.6b/(0.6b + 0.3) = 2/3$，解得 $b = 1$。只有当 "New" 之后不存在被禁止的路（$Z_t = 1$），掩码才不扭曲分布。一般地，掩码无偏的条件是每条合法路径上 $\prod_t Z_t$ 都相同。

**练习 5**　用 Gumbel-max 采样时，把所有 logit 除以 $T$ 再加 Gumbel 噪声，和先加噪声再除以 $T$，结果一样吗？

> **解答**：不一样。$\arg\max(z/T + G)$ 服从 $\mathrm{softmax}(z/T)$，这是正确的温度采样。$\arg\max((z + G)/T) = \arg\max(z + G)$，除以正数不改变 argmax，相当于 $T = 1$。温度必须作用在 logit 上，再加噪声。
