# 7.2 投机解码

> **一句话核心直觉**：单条请求的 decode 每生成一个 token 都要把全部权重从显存读一遍，算力只用了千分之几；同样读一遍权重，验证 5 个 token 和生成 1 个 token 花的时间几乎一样。投机解码让一个便宜的草稿先猜 $\gamma$ 个 token，目标模型一次前向并行验证：每个草稿 token 以 $\min(1, p/q)$ 的概率接受，拒绝时从残差 $\max(0, p-q)$ 里重采样。这个改良的拒绝采样保证输出分布与目标模型**完全相同**，接受率 $\alpha = \sum\min(p,q) = 1 - \mathrm{TV}(p,q)$。每轮期望产出 $(1-\alpha^{\gamma+1})/(1-\alpha)$ 个 token，加速比还要除以草稿成本 $1 + \gamma c$，所以 $\gamma$ 有最优值。它只在显存带宽受限时有效：batch 大到算力受限时，被拒绝的草稿就是纯浪费，加速比跌到 $E/(\gamma+1) < 1$；但长上下文的 KV 读取让 decode 一直受带宽限制，投机解码在大 batch 下依然有效。
> **唤醒标签**：权重读一遍 = 验证一批 · 接受 $\min(1, p/q)$ · 残差 $\max(0, p-q)$ · 输出分布 = $p$ · $\alpha = 1 - \mathrm{TV}$ · $E = (1-\alpha^{\gamma+1})/(1-\alpha)$ · $S = E/(1 + \gamma c)$ · 最优 $\gamma$ · 算力受限时 $E/(\gamma+1)$ · 长上下文 KV 受限 · 草稿：小模型 / 抄上下文 / Medusa / EAGLE / MTP · DeepSeek-V3 接受率 85–90%、1.8× · 先做温度和截断再验证

## 1. 问题：decode 时 GPU 在等什么？

按 5.1 的屋脊线算一笔账。Llama-3-8B 有 80.3 亿参数，bf16 权重 16.06 GB。单条请求 decode 时，每生成一个 token 要把所有权重从 HBM 读一遍：

$$
t_{\text{token}} \approx \frac{16.06\ \text{GB}}{3.35\ \text{TB/s}} = 4.8\ \text{ms} \ \Rightarrow\ \approx 208\ \text{token/s}
$$

同时做的计算是每个参数一次乘加，$2\times 8.03\times 10^9 = 1.6\times 10^{10}$ FLOPs，摊到 4.8 ms 上是 3.3 TFLOP/s，**只用了 H100 峰值（989 TFLOP/s）的 0.34%**。算术强度约为 1 FLOP/字节，而 H100 的屋脊点在 $989/3.35 \approx 295$ FLOP/字节，差了两个数量级。

关键的观察是：如果一次前向处理 5 个 token 而不是 1 个，权重还是只读一遍，计算量变成 5 倍也还远在屋脊点之下，**耗时几乎不变**。prefill 就是这样并行处理整段 prompt 的。decode 之所以只能一个一个来，是因为第 $t+1$ 个 token 要等第 $t$ 个生成出来才知道输入是什么。

所以，只要能**猜**出接下来的几个 token，目标模型就能一次前向把它们全部检查一遍。猜对的直接收下，猜错的从那里重来。这个想法最早出现在 Stern et al. 的分块并行解码（2018，只适用于贪心），Leviathan et al. 和 Chen et al. 在 2022–2023 年独立提出了支持采样、并且**不改变输出分布**的版本：前者在 T5-XXL 上加速 2–3 倍，后者在 Chinchilla 70B 上加速 2–2.5 倍。

## 2. 算法

记目标模型的分布为 $p(\cdot \mid \text{前缀})$，草稿的分布为 $q(\cdot \mid \text{前缀})$。每一轮：

1. **起草**：草稿自回归地生成 $\gamma$ 个 token $x_1, \dots, x_\gamma$，记下每一步的分布 $q_1, \dots, q_\gamma$。
2. **验证**：目标模型对"前缀 + $x_1 \dots x_\gamma$"做**一次**前向，得到 $\gamma + 1$ 个位置的分布 $p_1, \dots, p_{\gamma+1}$（$p_i$ 以 $x_1 \dots x_{i-1}$ 为条件）。
3. **逐个接受**：对 $i = 1, 2, \dots$，以概率 $\min\big(1, p_i(x_i)/q_i(x_i)\big)$ 接受 $x_i$。第一次被拒绝时，从残差分布 $\mathrm{norm}\big(\max(0, p_i - q_i)\big)$ 中采一个 token 替代它，丢掉后面所有草稿，本轮结束。
4. **奖励 token**：如果 $\gamma$ 个全部接受，再从 $p_{\gamma+1}$ 中采一个 token。这个分布在验证时已经算好了，是白送的。

所以每轮至少产出 1 个 token（最坏情况和普通 decode 一样），最多 $\gamma + 1$ 个。被拒绝位置之后的草稿必须丢掉，即使它们看起来是对的：它们和目标模型在那些位置算出的分布，都以被拒绝的那个 token 为条件。KV 缓存里这些位置的条目也要回滚（把序列长度截回去即可，分页 KV 下是 $O(1)$ 的操作，→ 7.4）。

## 3. 为什么输出分布不变

### 3.1 单个位置的证明

只看一个位置，省略下标。草稿提议 $x \sim q$，以 $\min(1, p(x)/q(x))$ 接受。输出 token 为 $x$ 有两条路：

- **草稿提议了 $x$ 并被接受**：$q(x)\cdot\min\big(1, \tfrac{p(x)}{q(x)}\big) = \min\big(q(x), p(x)\big)$。
- **草稿被拒绝，然后从残差里采到 $x$**：总的接受概率是 $\beta = \sum_y \min(p(y), q(y))$，拒绝概率 $1 - \beta$。残差分布是 $r(x) = \dfrac{\max(0, p(x) - q(x))}{\sum_y \max(0, p(y) - q(y))}$。注意分母 $\sum_y \max(0, p - q) = \sum_y \big(p - \min(p,q)\big) = 1 - \beta$，所以这条路的概率是 $(1-\beta)\cdot r(x) = \max(0, p(x) - q(x))$。

相加：

$$
P(\text{输出 } x) = \min(p(x), q(x)) + \max(0, p(x) - q(x)) = p(x)
$$

**输出恰好服从 $p$，与 $q$ 无关。** 草稿只影响速度，不影响结果。直觉上，接受这一步把 $q$ 里"多出来"的质量（$q > p$ 的部分）按比例削掉，残差这一步把 $q$ "不够"的质量（$p > q$ 的部分）补上。

多个位置用归纳法：第 1 个位置的输出服从 $p_1$；接受 $x_1$ 之后，第 2 个位置面对的是以 $x_1$ 为条件的同样情形，输出服从 $p_2$；依此类推。一旦拒绝，后面的草稿全部作废，下一轮从新的前缀重新开始，所以每个输出 token 都服从目标模型在其真实前缀下的条件分布。

§9.1 抽了 100 万次：输出频率与 $p$ 的 TV 距离是 0.0012（抽样噪声的水平），而直接用草稿的 TV 距离是 0.2091。

### 3.2 接受率就是 1 减 TV 距离

$$
\alpha = \sum_x \min(p(x), q(x)) = \sum_x \frac{p(x) + q(x) - |p(x) - q(x)|}{2} = 1 - \frac{1}{2}\sum_x |p(x) - q(x)| = 1 - \mathrm{TV}(p, q)
$$

接受率直接衡量两个分布有多像。§9.1 实测 0.7904，公式 0.7909。

两个特例：

- **贪心解码**（$T \to 0$）：$p$ 和 $q$ 都是 one-hot。草稿的 argmax 等于目标的 argmax 就接受，否则残差就是目标的 one-hot，等于直接采用目标的 argmax。
- **温度与截断**：目标分布指的是**做完温度和截断之后**的分布（→ 7.1）。验证前要对 $p$ 和 $q$ 施加同样的处理，否则保持的是一个错误的分布。

### 3.3 "无损"的边界

在精确算术下，投机解码的输出分布与目标模型完全相同。Chen et al. 的措辞更准确："在硬件数值精度内"保持目标分布。验证时一次前向处理 $\gamma + 1$ 个 token，用的内核和归约顺序与单 token decode 不同，logit 的低位会有差别（→ 7.1 §5.3）。所以开启投机解码后，同一个随机种子下的输出可能与关闭时逐位不同，但分布是一样的。

## 4. 能快多少

### 4.1 每轮期望产出

假设每个草稿 token 被接受的概率都是 $\alpha$，并且相互独立。记 $K$ 为本轮被接受的草稿数，前 $i$ 个都被接受的概率是 $\alpha^i$，所以 $P(K \ge i) = \alpha^i$（$i \le \gamma$）。本轮产出 $K + 1$ 个 token（被接受的草稿，加上一个重采样的或奖励的 token）：

$$
\mathbb{E}[K + 1] = 1 + \sum_{i=1}^{\gamma} P(K \ge i) = \sum_{i=0}^{\gamma}\alpha^i = \frac{1 - \alpha^{\gamma+1}}{1 - \alpha}
$$

$\gamma \to \infty$ 时上限是 $1/(1-\alpha)$：$\alpha = 0.8$ 时每轮最多期望 5 个 token，不论草稿多长。

### 4.2 加速比与最优草稿长度

每轮的代价是 $\gamma$ 次草稿前向加 1 次目标前向。记草稿一次前向的耗时是目标的 $c$ 倍，在带宽受限的区域，目标验证 $\gamma + 1$ 个 token 与生成 1 个耗时相当：

$$
S(\gamma) = \frac{1 - \alpha^{\gamma+1}}{(1 - \alpha)(1 + \gamma c)}
$$

分子随 $\gamma$ 增长但增速 $\alpha^{\gamma+1}$ 指数衰减，分母线性增长，所以**存在最优的 $\gamma$**。多加一个草稿 token 值得的条件是：它带来的期望产出 $\alpha^{\gamma+1}$ 相对当前产出 $E$ 的比例，超过它带来的成本 $c$ 相对当前成本 $1 + \gamma c$ 的比例。§9.3 的结果：

| | $c = 0.02$ | $c = 0.1$ | $c = 0.3$ |
|---|---|---|---|
| $\alpha = 0.6$ | $\gamma^* = 6$，2.17× | $\gamma^* = 3$，1.67× | $\gamma^* = 1$，1.23× |
| $\alpha = 0.8$ | $\gamma^* = 11$，3.82× | $\gamma^* = 6$，2.47× | $\gamma^* = 3$，1.55× |
| $\alpha = 0.9$ | $\gamma^* = 19$，6.37× | $\gamma^* = 10$，3.43× | $\gamma^* = 5$，1.87× |

$\alpha = 0.8$、$c = 0.1$ 时，$\gamma$ 从 1 到 16 的加速比是 1.64、2.03、2.27、2.40（$\gamma = 4$）、2.47（$\gamma = 6$）、2.40、2.15、1.88：过了最优点之后，草稿越长越慢。**接受率比草稿长度重要得多**：$\alpha$ 从 0.8 提到 0.9，最优加速从 2.47 倍升到 3.43 倍。

### 4.3 独立性假设与实测

真实文本的接受率因位置而异：变量名、闭合括号、固定搭配几乎必中，句子开头、关键的数字几乎猜不中。§9.2 实现了完整的投机解码：目标是一个二阶马尔可夫链，草稿是它的最佳一阶近似，再混入不同比例的噪声来调节质量：

| 草稿 | 实测接受率 $\alpha$ | 每次目标前向产出（实测） | 公式 $(1-\alpha^5)/(1-\alpha)$ |
|---|---|---|---|
| 最佳一阶近似 | 0.907 | 4.15 | 4.16 |
| 混入 30% 噪声 | 0.750 | 3.05 | 3.05 |
| 混入 60% 噪声 | 0.569 | 2.20 | 2.18 |

用平均接受率代入公式，与实测相当吻合。§9.2 还检查了输出分布：最差的草稿下，投机解码的第 6 个 token 与精确分布的 TV 距离是 0.0139，直接从目标采样是 0.0155，二者都在抽样噪声的水平；只用草稿则是 0.1669。

接受率随语境变化，这也是改进的方向：EAGLE-2 发现草稿模型的置信度能很好地预测接受率，于是根据置信度动态决定在哪里多猜、在哪里少猜（§6.4）。

## 5. 批大小与上下文长度：什么时候反而变慢

### 5.1 两种区域

上面的分析假设验证 $\gamma + 1$ 个 token 和生成 1 个一样快，这只在带宽受限时成立。推理服务会把很多请求拼成一个 batch（→ 7.4），batch 大了，计算量就会追上来。一次前向的耗时近似为

$$
t = \max\Big(\frac{\text{读取的字节}}{\text{带宽}},\ \frac{\text{FLOPs}}{\text{峰值算力}}\Big)
$$

- **带宽受限**：耗时由读取权重和 KV 决定，验证多几个 token 几乎免费，加速比 $\approx E/(1 + \gamma c)$。
- **算力受限**：耗时正比于处理的 token 数。验证 $B(\gamma+1)$ 个 token 的耗时是普通 decode 的 $\gamma + 1$ 倍，产出却只有 $E$ 倍：

$$
S \to \frac{E}{\gamma + 1} = \frac{1 - \alpha^{\gamma+1}}{(1-\alpha)(\gamma+1)} < 1
$$

$\alpha = 0.8$、$\gamma = 4$ 时是 0.672：被拒绝的草稿 token 每个都占用了真实的算力，投机解码比不用还慢三分之一。

### 5.2 KV 读取改变了答案

decode 时除了权重，还要读每条序列的 KV 缓存。Llama-3-8B 每个 token 的 KV 是 128 KiB（→ 1.3），一条 8K 上下文的序列就是 1 GiB，64 条就是 64 GiB，远超 16 GB 的权重。KV 读取随 batch 和上下文长度线性增长，而且**同一条序列验证 $\gamma + 1$ 个 token 时只需读一遍它的 KV**。所以上下文越长，decode 越牢牢地停在带宽受限的区域。

§9.4 用理想屋脊线算了 Llama-3-8B 在 H100 上的情况（$\alpha = 0.8$，$\gamma = 4$，草稿 5 亿参数）：

| 上下文 256 | B = 1 | B = 64 | B = 256 | B = 512 | B = 1024 |
|---|---|---|---|---|---|
| 加速比 | 2.69× | 2.76× | 1.12× | 0.76× | 0.64× |

| 上下文 8192 | B = 1 | B = 16 | B = 32 | B = 56（显存满） |
|---|---|---|---|---|
| 加速比 | 2.73× | 3.00× | 3.11× | 3.19× |

短上下文时，batch 超过约 300 后投机解码开始亏损；长上下文时，显存装满之前 decode 一直受带宽限制，加速比反而随 batch 略有上升。MagicDec 系统地论证了这一点：对中等和长序列，投机解码在高吞吐的大 batch 场景下仍然有效，他们在 Llama3.1-8B 上的大 batch 服务中做到了最高 2.51 倍。反过来，EAGLE-3 在单条请求上最高 6.5 倍，到 SGLang 里 batch 64 时吞吐提升只有 1.38 倍，说明短上下文的大 batch 会稀释收益。

实践中，推理框架会根据负载调整草稿长度，负载很高时直接关掉投机解码。

## 6. 草稿从哪来

$\alpha$ 要高，$c$ 要低，这两个要求是矛盾的：草稿越像目标模型，通常也越贵。几类方案在这两者之间做了不同的取舍。

### 6.1 同家族的小模型

最直接的是用同一家族、同一个分词器的小模型，比如用 Llama 3 系列的 1B 模型给 70B 起草。带宽受限时成本大致正比于参数量，$c$ 很小；缺点是要多部署、多维护一个模型，它的 KV 缓存也要占显存，而且小模型和大模型的分布差距决定了 $\alpha$ 的上限。

### 6.2 不用模型：从上下文里抄

很多任务的输出大量复制输入：改代码时大段代码原样保留，RAG 和摘要会引用原文。**Prompt lookup decoding** 在 prompt 里找与最近几个生成 token 匹配的 n-gram，把它后面的内容当草稿，成本几乎为零。**Lookahead decoding** 用 Jacobi 迭代并行地猜多个位置，同时维护一个 n-gram 池，在 MT-bench 上加速最高 1.8 倍，在多卡的代码补全上最高 4 倍。

这就是**代码补全加速最明显**的原因：代码的熵低（变量名重复出现，括号、缩进、关键字可预测），而且常常复制上下文里已有的内容，接受率很高，每轮几乎能吃满 $\gamma + 1$ 个 token。

### 6.3 长在目标模型上的头：Medusa

Medusa 在目标模型最后一层的隐状态上加 $k$ 个额外的解码头，第 $i$ 个头直接预测第 $t + i + 1$ 个位置的 token，用树形注意力一次验证多个候选组合。只训练这些头（Medusa-1）就能加速 2.2 倍以上；把头和主干一起微调（Medusa-2）能到 2.3–3.6 倍，但主干变了，严格来说已经不是原来的模型。Medusa 的头之间相互独立：第 3 个头预测 $t+4$ 时，并不知道 $t+2$、$t+3$ 猜的是什么，越往后越不准。

### 6.4 在特征上自回归：EAGLE 系列

EAGLE 认为在倒数第二层的特征上做自回归比在 token 上容易，但特征序列本身有不确定性（同一个特征之后可能采出不同的 token），于是把**已经采样出的 token** 也作为输入，一个只有一层的小网络就能准确预测下一步的特征。它复用目标模型的嵌入和 LM head，$c$ 很小，在 LLaMA2-Chat 70B 上加速 2.7–3.5 倍。

- **EAGLE-2**：草稿的置信度能很好地预测接受率，于是按置信度动态地展开草稿树，把验证预算花在最可能被接受的分支上，加速 3.05–4.26 倍。
- **EAGLE-3**：发现增加训练数据对 EAGLE 帮助有限，原因是"预测特征"这个目标的约束；改为直接预测 token，融合多层特征，并在训练时就模拟推理时的多步起草（training-time test），让草稿能从更多数据中受益，最高加速 6.5 倍。

### 6.5 预训练时就带上：多 token 预测

Gloeckle et al. 在预训练时用 $n$ 个输出头同时预测后面 $n$ 个 token，既提高了样本效率，4-token 预测的模型在推理时还能用这些头做自投机，最多快 3 倍。DeepSeek-V3 的 MTP 模块是**串行**的：预测第二个 token 时会用到第一个 token 的嵌入，保持了因果链，这和 Medusa 的独立头不同。DeepSeek-V3 报告第二个 token 的接受率在 85%–90% 之间，解码速度（TPS）提升到 1.8 倍。代入公式检验：$\gamma = 1$、$\alpha = 0.875$ 时每次前向产出 $1 + \alpha = 1.875$ 个 token，1.8 倍意味着 MTP 模块的开销只有约 4%。

### 6.6 树形验证

一次只验证一条草稿链，第一个位置猜错就全军覆没。如果在每个位置保留几个候选，组成一棵树，再用树形注意力掩码（每个节点只看到它的祖先）让目标模型一次前向验证整棵树，被接受的就是最长的匹配路径。采样时，SpecInfer 把残差技巧推广到多个候选：依次尝试每个候选，每被拒绝一次就更新一次残差分布，仍然保证输出分布不变。树越大，单轮接受得越多，但每次验证处理的 token 也越多，在算力受限时浪费也越大，又回到了 §5 的权衡。

## 7. 与 5.1、7.1、7.4 的联系

- **5.1 屋脊线**：投机解码是把闲置的算力换成更少的串行步数，前提是 decode 受带宽限制（§1、§5）。
- **7.1 解码与采样**：投机解码保持的是"做完温度和截断之后"的目标分布；Gumbel-max 的思路（固定随机数）也被用来做草稿与目标的耦合。
- **7.4 推理服务**：连续批处理决定 batch 多大，分页 KV 让回滚被拒绝的 token 成本为零，而 batch 大小又决定投机解码是赚是亏（§5）。
- **1.3 KV 缓存**：GQA、MLA 压缩 KV 之后，长上下文 decode 的带宽压力变小，投机解码的收益也随之改变。

## 8. 从零实现

### 8.1 一步投机采样：输出服从 $p$

```python
import numpy as np
rng = np.random.default_rng(0)
V = 8
p = rng.dirichlet(np.full(V, 0.5))                     # 目标模型
q = 0.6 * p + 0.4 * rng.dirichlet(np.ones(V))          # 草稿：像 p，但不完全一样

n = 1_000_000
x = rng.choice(V, size=n, p=q)                         # 草稿提议
accept = rng.random(n) < np.minimum(1, p[x] / q[x])    # 以 min(1, p/q) 接受
resid = np.maximum(p - q, 0); resid /= resid.sum()     # 拒绝后从残差分布重采样
y = np.where(accept, x, rng.choice(V, size=n, p=resid))
freq = np.bincount(y, minlength=V) / n
tv = lambda a, b: 0.5 * np.abs(a - b).sum()
print(f"TV(输出, p) = {tv(freq, p):.4f}   TV(q, p) = {tv(q, p):.4f}")
print(f"接受率 实测 {accept.mean():.4f}   Σmin(p,q) = {np.minimum(p, q).sum():.4f}   1 - TV = {1 - tv(p, q):.4f}")
# TV(输出, p) = 0.0012   TV(q, p) = 0.2091
# 接受率 实测 0.7904   Σmin(p,q) = 0.7909   1 - TV = 0.7909
```

### 8.2 完整的投机解码

```python
V = 32
rng = np.random.default_rng(1)
B1 = rng.dirichlet(np.full(V, 0.1), size=V)            # 主要取决于上一个 token
R = rng.dirichlet(np.full(V, 0.1), size=(V, V))        # 少量取决于再上一个
P2 = 0.85 * B1[None, :, :] + 0.15 * R                  # 目标 p(c | a, b)：二阶马尔可夫链
pi = np.full((V, V), 1 / V**2)                         # 二元组 (a, b) 的平稳分布
for _ in range(500): pi = np.einsum("ab,abc->bc", pi, P2)
Q1 = np.einsum("ab,abc->bc", pi, P2) / pi.sum(0)[:, None]   # 最佳一阶近似 q(c | b)
target = lambda seq: P2[seq[-2], seq[-1]]
def draft_of(mix):                                     # mix 越大，草稿越差
    return lambda seq: (1 - mix) * Q1[seq[-1]] + mix / V

def speculative(draft, ctx, n_new, gamma, rng):
    out, calls = list(ctx), 0
    while len(out) - len(ctx) < n_new:
        xs, qs, cur = [], [], list(out)
        for _ in range(gamma):                         # 1. 草稿逐个起草 γ 个
            qd = draft(cur); x = rng.choice(V, p=qd); xs.append(x); qs.append(qd); cur.append(x)
        ps = [target(out + xs[:i]) for i in range(gamma + 1)]   # 2. 目标一次前向给出 γ+1 个分布
        calls += 1
        for i in range(gamma):                         # 3. 逐个接受
            if rng.random() < min(1, ps[i][xs[i]] / qs[i][xs[i]]):
                out.append(xs[i])
            else:
                r = np.maximum(ps[i] - qs[i], 0); out.append(rng.choice(V, p=r / r.sum())); break
        else:
            out.append(rng.choice(V, p=ps[gamma]))     # 4. 全部接受：奖励 token
    return out[len(ctx):][:n_new], calls

for mix in (0.0, 0.3, 0.6):
    d = draft_of(mix)
    seq, calls = speculative(d, [0, 1], 20000, 4, rng)
    full = [0, 1] + seq
    a = np.mean([np.minimum(target(full[:i]), d(full[:i])).sum() for i in range(2, len(full))])
    print(f"噪声 {mix:.0%}: α = {a:.3f}  每次目标前向 {20000 / calls:.2f} 个 token  公式 {(1 - a**5) / (1 - a):.2f}")

state = np.zeros((V, V)); state[0, 1] = 1              # 第 6 个 token 的精确分布
for _ in range(6): state = np.einsum("ab,abc->bc", state, P2)
exact = state.sum(0)
runs = 20000
spec = np.bincount([speculative(draft_of(0.6), [0, 1], 6, 4, rng)[0][5] for _ in range(runs)], minlength=V) / runs
def plain(n):
    s = [0, 1]
    for _ in range(n): s.append(rng.choice(V, p=target(s)))
    return s[2:]
base = np.bincount([plain(6)[5] for _ in range(runs)], minlength=V) / runs
M = np.stack([draft_of(0.6)([0, b]) for b in range(V)])    # 只用草稿的转移矩阵
s = np.zeros(V); s[1] = 1
for _ in range(6): s = np.einsum("b,bc->c", s, M)
print(f"TV(投机, 精确) = {tv(spec, exact):.4f}  TV(直接采样, 精确) = {tv(base, exact):.4f}  TV(只用草稿, 精确) = {tv(s, exact):.4f}")
```

```
噪声 30%: α = 0.750  每次目标前向 3.05 个 token  公式 3.05
噪声 60%: α = 0.569  每次目标前向 2.20 个 token  公式 2.18
TV(投机, 精确) = 0.0139  TV(直接采样, 精确) = 0.0155  TV(只用草稿, 精确) = 0.1669
```

### 8.3 加速比与最优 $\gamma$

```python
E = lambda a, g: (1 - a ** (g + 1)) / (1 - a)
S = lambda a, g, c: E(a, g) / (g * c + 1)
for a in (0.6, 0.8, 0.9):
    print(f"α={a}: " + "   ".join(
        f"c={c}: γ*={max(range(1, 21), key=lambda g: S(a, g, c)):2d} S={max(S(a, g, c) for g in range(1, 21)):.2f}"
        for c in (0.02, 0.1, 0.3)))
print("α=0.8, c=0.1:", [round(S(0.8, g, 0.1), 2) for g in (1, 2, 3, 4, 6, 8, 12, 16)])
```

### 8.4 批大小与上下文：屋脊线模型

```python
N, Nd = 8.03e9, 0.5e9                    # 目标、草稿的参数量（bf16，每参数 2 字节）
kv_tok, L, d = 131072, 32, 4096          # Llama-3-8B 每 token 的 KV 字节、层数、宽度
BW, peak = 3.35e12, 989e12               # H100：带宽、bf16 峰值
def step(B, tokens, n_param, ctx, kv=True):
    byte = 2 * n_param + (B * ctx * kv_tok if kv else 0)               # 权重读一遍 + 每条序列的 KV 读一遍
    flop = 2 * n_param * tokens + (4 * L * ctx * d * tokens if kv else 0)
    return max(byte / BW, flop / peak)
a, g = 0.8, 4
for ctx, Bs in ((256, (1, 64, 256, 512, 1024)), (8192, (1, 16, 32, 56))):
    out = []
    for B in Bs:
        t_plain = step(B, B, N, ctx)
        t_spec = step(B, B * (g + 1), N, ctx) + g * step(B, B, Nd, ctx, kv=False)
        out.append(f"B={B}: {t_plain * E(a, g) / t_spec:.2f}×")
    print(f"上下文 {ctx}: " + "  ".join(out))
print("算力受限时的极限 E/(γ+1) =", round(E(a, g) / (g + 1), 3))
# 上下文 256: B=1: 2.69×  B=64: 2.76×  B=256: 1.12×  B=512: 0.76×  B=1024: 0.64×
# 上下文 8192: B=1: 2.73×  B=16: 3.00×  B=32: 3.11×  B=56: 3.19×
# 算力受限时的极限 E/(γ+1) = 0.672
```

## 9. 实战直觉、避坑与面试深挖

**与工程 / 应用的连接**
- **先看负载形态再决定开不开**：低并发、对延迟敏感（交互式聊天、代码补全）收益最大；短上下文的高并发离线批处理可能亏损；长上下文的服务在大 batch 下依然受益。
- **草稿的选择看任务**：编辑代码、RAG、改写这类大量复制输入的任务，prompt lookup 几乎零成本；通用对话用 EAGLE-3 或模型自带的 MTP 头；同家族小模型最容易上手。
- **监控接受率**：接受率随领域变化，用聊天数据训练的草稿头遇到代码或其他语言可能大幅下降。线上要按任务统计 $\alpha$，据此调 $\gamma$。
- **采样参数要一致**：温度、top-p 等处理要同时施加在目标和草稿的分布上，验证的是处理之后的分布。

**常见误区 / 反直觉点**
1. **"投机解码会降低一点质量"** ✗：改良的拒绝采样保证输出分布与目标模型相同（在数值精度内）；草稿只影响速度。
2. **"草稿越长越快"** ✗：期望产出的上限是 $1/(1-\alpha)$，草稿成本却线性增长；$\alpha = 0.8$、$c = 0.1$ 时最优 $\gamma$ 是 6，$\gamma = 16$ 时比 $\gamma = 6$ 慢四分之一。
3. **"被拒绝之后，后面的草稿如果对也能留下"** ✗：后面的草稿和目标在那些位置的分布都以被拒绝的 token 为条件，必须全部丢弃。
4. **"投机解码在大 batch 下一定没用"** ✗：短上下文的大 batch 算力受限，确实会亏；长上下文的 KV 读取让 decode 一直受带宽限制，大 batch 下依然有加速。
5. **"接受率就是草稿 top-1 猜中的比例"** ✗：采样时接受率是 $\sum\min(p,q) = 1 - \mathrm{TV}(p,q)$，取决于整个分布的重叠；只有贪心解码时才等于 argmax 一致的比例。

**高频深挖题**
- **Q1：证明投机采样的输出服从目标分布。**
  思路：接受路径给 $\min(p,q)$ → 拒绝概率 $1 - \beta$，残差 $\max(0, p-q)/(1-\beta)$ → 两路相加等于 $p$ → 多位置归纳，拒绝后丢弃后续草稿 → 加分项：接受率 $= 1 - \mathrm{TV}$；温度和截断要先做。
- **Q2：给定接受率 $\alpha$、草稿长度 $\gamma$、草稿成本 $c$，推导加速比。**
  思路：$P(K \ge i) = \alpha^i$ → $E = (1-\alpha^{\gamma+1})/(1-\alpha)$ → 除以 $1 + \gamma c$ → 有最优 $\gamma$ → 加分项：独立性假设；动态草稿长度 / 草稿树。
- **Q3：为什么投机解码在高并发时收益下降，甚至变慢？什么情况下例外？**
  思路：屋脊线 → batch 大了进入算力受限，验证 $\gamma+1$ 个 token 耗时 $\gamma+1$ 倍 → 加速比趋于 $E/(\gamma+1) < 1$ → 例外：长上下文的 KV 读取随 batch 增长，decode 保持带宽受限 → 加分项：MagicDec；按负载调 $\gamma$。
- **Q4：Medusa、EAGLE、MTP 有什么区别？**
  思路：Medusa 是最后一层上的独立头，后面的头不知道前面猜了什么 → EAGLE 在特征上自回归，输入已采样的 token 消除不确定性；EAGLE-2 动态树，EAGLE-3 直接预测 token、多层特征、训练时模拟推理 → MTP 在预训练时就学，DeepSeek-V3 串行 MTP 接受率 85–90% → 加分项：Medusa-2 微调了主干，不再严格无损。
- **Q5：为什么代码补全的加速最明显？**
  思路：代码熵低，标识符、括号、缩进可预测 → 大量复制上下文 → $\alpha$ 高，每轮接近 $\gamma+1$ 个 token → prompt lookup 几乎零成本 → 加分项：领域变化时接受率下降，需要监控。

## 10. 练习（附解答）

**练习 1**　$\alpha = 0.7$，$\gamma = 3$，$c = 0.05$。每轮期望产出多少 token？加速比是多少？

> **解答**：$E = (1 - 0.7^4)/0.3 = (1 - 0.2401)/0.3 = 2.533$。成本 $1 + 3\times 0.05 = 1.15$，加速比 $2.533/1.15 = 2.20$ 倍。

**练习 2**　$p = (0.5, 0.3, 0.2)$，$q = (0.3, 0.3, 0.4)$。求接受率、残差分布，并验证每个 token 的输出概率等于 $p$。

> **解答**：$\alpha = \min(0.5, 0.3) + \min(0.3, 0.3) + \min(0.2, 0.4) = 0.3 + 0.3 + 0.2 = 0.8$，等于 $1 - \frac{1}{2}(0.2 + 0 + 0.2) = 0.8$。残差 $\max(0, p - q) = (0.2, 0, 0)$，归一化后是 $(1, 0, 0)$。输出 token 0：草稿提议 0 并接受，$0.3\times\min(1, 0.5/0.3) = 0.3$，加上拒绝后从残差采到 0，$(1 - 0.8)\times 1 = 0.2$，共 0.5 ✓。token 1：$0.3\times 1 = 0.3$ ✓。token 2：$0.4\times\min(1, 0.2/0.4) = 0.2$ ✓。

**练习 3**　DeepSeek-V3 的 MTP 只额外预测 1 个 token，接受率 85%–90%，解码速度提升 1.8 倍。按本课的公式，MTP 模块的开销 $c$ 大约是多少？

> **解答**：$\gamma = 1$ 时每次前向产出 $E = 1 + \alpha$，即 1.85–1.90 个 token。加速比 $S = E/(1 + c) = 1.8$，所以 $c = E/1.8 - 1$，在 0.028 到 0.056 之间，即 MTP 模块的开销只有一次完整前向的 3%–6%。它只有一层 Transformer，并且复用了主模型的嵌入和输出头。

**练习 4**　证明在算力受限的区域，任何 $\gamma \ge 1$ 都不如不用投机解码（忽略草稿成本）。

> **解答**：算力受限时耗时正比于处理的 token 数，加速比 $S = E/(\gamma+1) = \frac{1}{\gamma+1}\sum_{i=0}^{\gamma}\alpha^i$，是 $1, \alpha, \dots, \alpha^\gamma$ 的平均值。$\alpha < 1$ 时除了第一项都小于 1，所以 $\gamma \ge 1$ 时平均值小于 1。每个被拒绝的草稿 token 都占用了一份真实的算力却没有产出，只有 $\alpha = 1$（草稿完美）时才不亏。

**练习 5**　用一个 1B 的同家族模型给 70B 模型起草。在带宽受限时 $c$ 大约是多少？如果实测 $\alpha = 0.7$，最优 $\gamma$ 和加速比是多少？

> **解答**：带宽受限时耗时正比于读取的权重，$c \approx 1/70 \approx 0.014$（实际还有内核启动等固定开销，会更大）。$S(\gamma) = (1 - 0.7^{\gamma+1})/(0.3(1 + 0.014\gamma))$：$\gamma = 4$ 时 $2.773/1.056 = 2.63$，$\gamma = 6$ 时 $3.059/1.084 = 2.82$，$\gamma = 8$ 时 $3.199/1.112 = 2.88$，$\gamma = 10$ 时 $3.267/1.14 = 2.87$。最优 $\gamma \approx 8$–9，加速约 2.9 倍，已经接近上限 $1/(1-0.7) = 3.33$；再提升只能靠提高接受率。
