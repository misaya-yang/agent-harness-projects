# 8.1 Embedding 与向量检索：从相似度到可控召回

> **一句话核心直觉**：向量检索不是把文本塞进模型变成向量就大功告成了：训练目标决定哪些文本在几何空间中相互靠近，索引结构决定能否在毫秒级时延与内存预算内精准找到它们，而向量维度与量化压缩直接决定了系统的硬件成本。排查检索故障时，必须先把语义表征错误与近似近邻搜索错误彻底剥离，才能有的放矢地优化召回率、延迟与内存占用。

## 1. 痛点与钩子：明明有答案，为什么找不到？

公司退款政策手册中明确记载着“E42 属于支付失败”与“支付失败支持 30 天内申请退款”。当用户提问“E42 的退款期限是多久？”时，检索系统取回的却是已经废弃的旧版本例外条款。表面上都是“没搜出正确答案”，但底层通常源自三种性质完全不同的工程故障：

1. **表征错误（Representation Failure）**：即便通过暴力遍历对库中全体切片计算真实相似度，包含答案的正确切片在向量空间中的距离排名依然靠后。这是 Embedding 模型的语义表征能力不足或训练目标失配，仅靠调整向量数据库索引参数绝不可能修复语义空间本身的问题。
2. **近似搜索错误（ANN Failure）**：在暴力精确遍历下，正确切片稳稳排进前 10 名；但在近似最近邻（ANN）索引中，由于剪枝贪心搜索提前终止，正确切片未能被召回。此时向量本身的分布有效，应当针对同一批向量与相同距离度量，调优索引的建图或搜索宽度。
3. **信息单元切分错误（Chunking Failure）**：退款期限与错误码定义被斩断在两个独立的文本切片（Chunk）中、关键段落未被解析入库，或者该问题本身属于跨切片推理的多跳问题。这属于切块策略与前置数据处理管线的范畴（→ 8.2）。

## 2. 第一性原理：训练一个可以预计算的搜索空间

### 2.1 双塔架构与 InfoNCE 损失

双塔架构分别使用查询塔 $q=f_Q(x)$ 与文档塔 $d=f_D(y)$ 将文本映射至定长稠密向量；两塔可以共享参数，也可以根据模态差异分别训练。双塔的核心工程价值在于**解耦**：文档库中海量切片的向量 $d$ 可以在离线阶段批量前向计算并构建索引；在线线上请求到来时，系统仅需实时推理一次查询塔生成 $q$，即可通过向量内积或余弦在毫秒级内完成海量候选初筛。

然而，这种离线解耦的代价是缺乏交互：双塔在计算相似度之前，查询与文档之间没有任何 Token 级别的全量自注意力交互（Cross-Attention），对复杂否定、细粒度语序与精细数值的敏感度天然弱于重排交叉编码器（Cross-Encoder，→ 8.2）。

在线计算余弦相似度前，先对非零向量进行 $L_2$ 归一化，训练时常用的 InfoNCE 损失函数如下：

$$
s(q,d)=\frac{q^\top d}{\|q\|\|d\|},\qquad
L_i=-\log\frac{\exp(s(q_i,d_i^+)/\tau)}{\exp(s(q_i,d_i^+)/\tau)+\sum_j\exp(s(q_i,d_j^-)/\tau)}.
$$

该式为单向对比学习目标（每个查询配对一个正例与若干负例）；双向对称目标则额外对调查询与文档反向计算一次。在工程训练中，小批次内通常直接利用其他样本配对的文档充当批内负样本（In-batch Negatives），这种方式完全无需额外计算文档向量编码，但若批次内碰巧存在语义相近的问答，极易引入**假负例（False Negatives）**。随机采样的负样本通常距离查询过远，难以提供有效梯度；而使用 BM25 词法检索或旧版本检索器挖掘的高排名非相关文档作为**困难负样本（Hard Negatives）**，虽然紧贴决策边界，但挖掘得越深，越需要前置清洗，严密排查多标注正例、近重复文档与同义表述。

### 2.2 点积、余弦与各向异性

若在推理前对查询向量与文档向量均执行 $L_2$ 归一化，则内积点积 $q^\top d$、余弦相似度 $\cos(q,d)$ 与欧氏距离平方 $\|q-d\|^2$ 满足严格单调对应关系：

$$
\|q-d\|^2 = \|q\|^2 + \|d\|^2 - 2q^\top d = 2 - 2\cos(q,d).
$$

此时采用内积、余弦或欧氏距离进行 Top-$k$ 近邻排序，其返回结果完全一致。但若未对向量进行归一化，点积将同时融合夹角与向量模长（Norm）——模型往往会自发利用模长来编码实体的置信度或流行度先验；若训练时基于点积优化，线上部署时却擅自改成余弦归一化，候选项的相对顺序将被彻底打乱。对于全零向量，工程实现必须单独兜底，严禁直接除以零模长。

在未经对比微调的语言模型表征中，文本向量往往挤压在一个狭窄的高维圆锥空间内：即使是语义毫无关联的两段文本，也能测得偏高的余弦相似度（如普遍处于 0.7～0.9 区间），这种几何塌缩现象被称为**各向异性（Anisotropy）**。因此，相似度绝对分值受模型底座、池化算子与语料分布强烈影响，0.8 绝不天然代表“80% 的置信度或相关概率”。虽然均值中心化或白化能恢复几何各向同性，但也可能误伤模型在下游任务中已学得的细粒度区分度；一切分布变换都必须在保留的验证集上复测业务指标，绝不能把单纯的几何统计指标当成检索质量的代名词。

### 2.3 精确近邻与业务相关性是两把尺

给定完全相同的 Embedding 编码器、向量度量方式与前置元数据过滤条件，精确暴力遍历全体向量得到的 Top-$k$ 集合记为 $E_k(q)$，近似近邻（ANN）索引返回的集合记为 $A_k(q)$：

$$
\operatorname{ANN\ recall@}k=\frac{|A_k(q)\cap E_k(q)|}{k}.
$$

该指标衡量的是索引工程本身的近似保真度（即向量空间里的精确近邻有没有在搜索中被贪心剪枝漏掉），它完全不判断这些向量在业务逻辑上是否真正回答了用户的问题。真实场景中的“标注相关文档召回率（Relevance Recall@k）”与“端到端最终答案正确率”是另一维度的指标。排查故障时，务必先在测试集上抽样跑全量精确暴力搜索（Exact Search）确立理论上限：只有在精确搜索已排进候选、而 ANN 发生漏召时，才优先去调索引参数；若精确搜索下的业务相关召回率本身就很低，核心瓶颈必然在对比学习训练、训练数据质量或文本切块管线之中。

## 3. 承重墙推导：搜索宽度为什么值得花钱？

### Step 1　困难负例怎样进入梯度

设 $p_j$ 为所有候选切片经 Softmax 归一化后的预测概率，固定查询向量与其他样本打分，对未除温度的原始相似度分数求偏导：

$$
\frac{\partial L}{\partial s^+}=\frac{p^+-1}{\tau},\qquad
\frac{\partial L}{\partial s_j^-}=\frac{p_j^-}{\tau}.
$$

当负样本与正样本越相似时，分母中的负样本得分暴增，直接压缩正样本的归一化概率 $p^+$，导致分子项 $|p^+-1|$ 显著变大，从而向正样本编码器施加更大力度的正向拉近梯度；与此同时，该困难负样本也分得高达 $p_j^-/\tau$ 的排斥梯度。梯度反向传播会显著推开二者的空间距离。这不仅从数学上论证了困难负样本挖掘能强力塑造清晰的决策边界，更解释了为什么假负例会产生破坏性毒害：它会强迫编码器把语义本来相符的正确切片强行推开。实际神经网络的参数梯度还需通过各编码器的雅可比矩阵逐层传导。

### Step 2　从精确遍历到图搜索

暴力精确搜索（Exact Search）对每个进入系统的查询都需要遍历 $N$ 个向量，计算代价高达 $O(Nd)$；当向量数据与距离度量确定后，其结果可作为评判近似搜索质量的绝对真值。而在近似检索中，基于图结构的索引让每个向量节点向近邻节点连接有向边：查询从初始入口节点出发，贪心地沿着距离更近的邻居前进，以期用极少的距离计算次数收敛至真实近邻。

单层图索引在面对复杂高维分布时极易陷入局部极值陷阱。**HNSW（分层可导航小世界图）**将跳表（Skip List）的分层思想引入近邻图：顶层为节点极度稀疏的长程快速通道，允许查询以极少的跳步完成全图跨越与粗定位；逐层向下，节点密度指数级递增，直到包含全体数据的底层执行精细的局部近邻搜索，从而将全图搜索复杂度从线性 $O(N)$ 降低至对数级 $O(\log N)$。真实构建过程涉及严格的插入顺序、启发式邻居选择算法与多层连接预算；下方的实验展示了一个便于拆解机理的单层玩具图。

在生产级 HNSW 体系中：
- **$M$ 是建图阶段的核心连接预算**：它决定了每个节点所能保留的最大双向边数。增大 $M$ 会显著增加索引占用的内存体积和离线建图时间，但能极大改善全图的连通性与长程可导航性。
- **$efSearch$ 是在线查询时的动态搜索宽度**：它定义了贪心探索过程中维护的动态候选优先队列容量，通常必须大于等于用户请求的返回数量 $k$。提高 $efSearch$ 能提供更宽的探索视野、降低误入局部极值的概率并有效改善召回率，代价是成倍增加在线距离计算次数与 P99 响应延迟。

需要特别说明，$ef$ 并不等于访问节点数的绝对上限。在真实业务语料上，两项参数都不能保证所有单条查询的指标严格单调，必须在目标数据集上绘制端到端的 Recall-P95/P99 延迟-内存三维权衡曲线。

### Step 3　IVF 缩小搜索范围，PQ 压缩每个向量

在大规模工业级场景中，全内存常驻密集向量与 HNSW 边表往往超出硬件预算。**IVF（倒排文件）**与 **PQ（乘积量化）**分别从“空间剪枝”与“数据压缩”两个正交维度压榨资源：

- **IVF（Inverted File）解决“搜索哪些候选”**：通过 $k$-means 预先在向量空间聚类出若干粗聚类中心（Voronoi 胞元），将库中全体向量挂载到对应的聚类倒排列表上。在线查询时，仅计算查询向量与各聚类中心的距离，仅对最近的 $nprobe$ 个倒排列表进行桶内扫描。增大 $nprobe$ 能有效扩大候选扫描面并提升召回，但也直接线性增加耗时；若真实近邻由于聚类边界误差掉入未探测的桶中，无论桶内计算多精确也无法召回。
- **PQ（Product Quantization）解决“每个向量占多少内存”**：将 $d$ 维连续向量划分为 $m$ 个低维子空间，并在各子空间分别训练聚类码本（例如 256 个质心，仅需 1 字节索引表示）。高维浮点向量被压缩为 $m$ 字节的离散量化编码；在线查询时，系统只需预计算查询向量各子段到码本质心的距离查找表（LUT），便能以快速查表累加替代高开销的浮点内积。

工程中常用的 **IVF-PQ** 进一步对向量脱离聚类中心的残差（Residuals）进行乘积量化，从而同时兼顾剪枝扫描范围与极致内存压缩。但必须牢记：量化压缩不可避免地引入几何失真，可能导致相似度排序在微观上发生错位；通常需要在量化粗排选出较宽候选集后，加载原始未压缩向量进行二次浮点精确重排。仅宣称压缩码大小往往会隐瞒 ID 映射表、码本、倒排表索引结构以及可能保留的原向量存储开销。

以 100 万条 768 维 float32 原始向量为例：纯向量数据需占用约 2.86 GiB 内存；若切分为 96 段、每段 8 bit 码本，压缩后的 PQ 编码仅需 96 MB（约 91.6 MiB），编码体积缩小为原始向量的 $1/32$。但这绝不代表端到端服务索引也能恰好缩小 32 倍。选型时，IVF-PQ 的 $nprobe$、码长及重排深度，必须与 HNSW 的 $M$ 和 $ef$ 在同一份数据分布与相同的业务召回标准下进行配对基准测试。

### Step 4　可截断表征与粗到细两级检索

传统的 Embedding 裁剪往往会彻底摧毁向量的语义拓扑。**Matryoshka Representation Learning（套娃表征学习）**在训练阶段同时约束模型在多个嵌套前缀维度（例如 64、128、256、全维 768）上优化对比损失，强制模型将最重要的核心语义信息汇聚在靠前维度的低维子空间中。

这使得两级检索（Coarse-to-fine Retrieval）在工程上变得极其经济：
1. **粗筛阶段**：仅提取前 64 维超短向量构建轻量级向量索引，在极小内存与算力开销下毫秒级拉取 Top-100 粗选候选；
2. **精排阶段**：仅对这 100 个候选切片读取全量 768 维向量进行高保真相似度重排。

> [!IMPORTANT]
> 针对经过归一化训练的向量模型，在截断出前缀子向量后，**必须对该前缀子向量重新执行 $L_2$ 归一化**，而后方可计算余弦相似度。若遗漏重新归一化，由于各维度能量分布的非均匀性，截断向量的模长差异会严重扭曲相似度排名。此外，未经套娃训练的通用模型严禁盲目切除尾部维度。

## 4. 极简代码锚点与数值复算

### 数值复算 · 对比损失与困难负样本

算例仅使用 Python 标准库，完全在 CPU 环境下自包含复算。

```python
import math

def infonce(hard, tau):
    scores = [0.8, hard, 0.2]
    weights = [math.exp((s - max(scores)) / tau) for s in scores]
    p = [w / sum(weights) for w in weights]
    return p[0], -math.log(p[0]), (p[0] - 1) / tau, p[1] / tau

for hard in (0.2, 0.7):
    pos, loss, grad_pos, grad_hard = infonce(hard, 0.2)
    print(f"负例={hard:.1f} p正={pos:.3f} loss={loss:.3f} 正梯度={grad_pos:.3f} 负梯度={grad_hard:.3f}")
```

**运行结果**

```text
负例=0.7 p正=0.604 loss=0.505 正梯度=-1.981 负梯度=1.831
```

### 数值复算 · 单层图搜索与访问数量

独立构建上述 36 点单层图拓扑并执行启发式搜索，`seen` 集合严格统计真正计算过与查询点欧氏距离的节点数量。此逻辑为纯教学实现，不包含 HNSW 的多层跳跃与工业级启发式选边。

```python
import math, heapq

points = [(x + 0.24 * math.sin(3*x + 7*y), y + 0.21 * math.cos(5*x - 2*y))
          for y in range(6) for x in range(6)]
query = (4.3, 4.5)
distance = math.dist

def graph_search(m, ef):
    graph = [[j for _, j in sorted((distance(p, other), j)
                                    for j, other in enumerate(points) if j != i)[:m]]
             for i, p in enumerate(points)]
    first = (distance(query, points[0]), 0)
    candidates, best, seen = [first], [first], {0}
    while candidates:
        d, i = heapq.heappop(candidates)
        if len(best) >= ef and d > best[-1][0]:
            break
        for j in graph[i]:
            if j in seen:
                continue
            seen.add(j)
            item = (distance(query, points[j]), j)
            if len(best) < ef or item < best[-1]:
                heapq.heappush(candidates, item)
                best = sorted(best + [item])[:ef]
    exact = [i for _, i in sorted((distance(query, p), i) for i, p in enumerate(points))[:3]]
    found = [i for _, i in best[:3]]
    return exact, found, len(set(exact) & set(found)), len(seen)

for m, ef in ((3, 3), (3, 6), (4, 3), (2, 12)):
    exact, found, hits, visits = graph_search(m, ef)
    print(f"M={m} ef={ef:2d} 精确={exact} 返回={found} 召回={hits}/3 距离计算={visits}")
```


## 5. 实战判断、迁移与前沿现状

**标准诊断排查路径**：
固定文档分块与 Embedding 模型版本，在覆盖真实线上问答分布的保留评测集上，先全量运行精确暴力搜索（Exact Top-$k$），随后将生产环境的 ANN 召回结果与该精确基线逐对比较；同时独立评测业务金标准相关证据召回率。
- 若 ANN recall@k 已达 95% 以上，而业务相关召回依然垫底，问题必然出在查询意图改写、Embedding 训练样本质量或假负例污染，调大向量索引参数纯属徒劳；
- 若精确搜索的业务召回表现优异，而 ANN 出现大幅跳水，则应集中调优索引参数（如增加 HNSW 的 $efSearch$ 或 IVF 的 $nprobe$）。
评测时必须严格记录元数据过滤条件、请求批大小、硬件架构、并发度、冷热缓存命中率、P95/P99 延迟与常驻物理内存。对于带租户权限过滤的查询，Exact 与 ANN 必须在同一可见过滤子集内求交，因为前置过滤与后置过滤本身会剧烈改变图搜索的连通性与实际计算量。

**2026 前沿现状**：
工业级生产检索几乎从不依赖单一向量检索，而是普遍将密集向量检索与稀疏词法索引（如 BM25）组合为混合检索通道，再利用重排模型做深度算力打分（→ 8.2）。支持弹性动态维度的 Embedding 模型（如 OpenAI 的 text-embedding-3 系列）与套娃表征学习正在普及，但这绝不意味着任意模型都能随意截断保真。虽然开源库（Faiss、hnswlib 等）提供了丰富的底层算子，但硬件向量指令集（如 AVX-512、NEON）、量化失真与生产数据漂移直接左右实际吞吐，厂商官方跑分绝不能替代自建数据集上的严密压测。

**迁移练习 1**：在某批线上查询中，ANN 与 Exact 暴力搜索的 Top-10 平均交集为 9 个（ANN recall@10 = 90%），但人工评测的业务金标准相关证据召回率依然低迷。此时若将 HNSW 的 $efSearch$ 参数翻倍，能否解决业务召回低的问题？

> **解答**：不能保证。ANN recall@10 为 90% 表明索引已经高度保真地找出了该向量空间内的绝大部分近邻。业务召回低下说明问题出在向量空间本身——即 Embedding 模型未能把正确文档映射到查询附近，或是切块过小切断了上下文。此时翻倍 $efSearch$ 只能在向量距离极小的非相关候选中继续打转，无法修复模型表征与分块缺陷。

**迁移练习 2**：一条 768 维 float32 单精度浮点向量占用 3072 字节；若采用切分成 96 个子空间、每个码本 8 bit（256 个中心）的乘积量化（PQ），压缩后的编码数据有多大？这是否等同于端到端索引的全部开销？

> **解答**：量化后的纯向量编码为 96 字节，纯数据体积确实缩小为原本的 $1/32$（约 3.125%）。但这绝不等于端到端索引的全部物理内存占用：生产级索引还需要额外存储文档全局 ID 映射表、96 个子空间的码本质心表、IVF 粗聚类倒排链表指针、内存对齐填充，以及为了二次重排而可能选择性常驻内存的原始高保真向量。
