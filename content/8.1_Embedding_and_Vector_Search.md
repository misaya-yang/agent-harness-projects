# 8.1 Embedding 与向量检索：从相似度到可控召回

> **一句话核心直觉**：检索不是“把文本变成向量”就结束了：训练目标决定哪些文本靠近，索引决定能否在预算内找到它们，维度和压缩决定成本。先把表征错误与近似搜索错误拆开，再优化召回、延迟和内存。

## 1. 痛点与钩子：明明有答案，为什么找不到？

公司退款手册中有“E42 是支付失败”和“支付失败 30 天内可退款”。用户问“E42 的退款期限是多久？”，系统却取回了旧例外条款。至少有三种不同故障：

1. **表征错**：精确遍历所有向量时，正确块的相似度排名仍低。改索引参数不能修好语义空间。
2. **近似搜索错**：精确搜索排进前 10，ANN 没找回来。比较相同向量、相同距离的 exact 和 ANN，调索引。
3. **信息单元错**：期限和错误码被切开、关键文本没有入库，或用户需要两个块才能回答。它属于切块与数据管线（→ 8.2）。

先做预判：正样本与查询相似度固定为 0.8，简单负样本为 0.2。另一个负样本从 0.2 靠近到 0.7，会影响训练多大？

## 2. 第一性原理：训练一个可以预计算的搜索空间

### 2.1 双塔与 InfoNCE

查询塔给 $q=f_Q(x)$，文档塔给 $d=f_D(y)$；两塔可以共享参数，也可以分别训练。文档向量可提前计算并建索引，在线只编码查询与搜索，适合从海量候选中快速取回。用余弦时先把非零向量归一化：

$$
s(q,d)=\frac{q^\top d}{\|q\|\|d\|},\qquad
L_i=-\log\frac{\exp(s(q_i,d_i^+)/\tau)}{\exp(s(q_i,d_i^+)/\tau)+\sum_j\exp(s(q_i,d_j^-)/\tau)}.
$$

这里是每个 query 一个正例、若干负例的单向目标；双向目标可再对调查询和文档。小批次里常把其他配对的文档当 in-batch 负例，廉价但可能含**假负例**。随机负例通常太容易区分；BM25 或旧模型挖出的高排名真负例更接近决策边界，但越难越要排查同义答案、多正例与重复文档。

### 2.2 点积、余弦与各向异性

若两边都做 $L_2$ 归一化，$q^\top d=\cos(q,d)$，$\|q-d\|^2=2-2\cos(q,d)$，三种排名相同。未归一化的点积还含范数，模型可能用长度编码置信度或流行度；训练采用点积却在服务时强行改余弦，会改变排名。零向量需单独处理，不能直接除范数。

文本向量可能聚在共同方向附近：不相关文本也得到较高的余弦，这叫**各向异性**。绝对相似度阈值因模型、语料和查询分布而变，0.8 并不自动表示“80% 相关概率”。对比训练、池化或中心化可能改变分布，但中心化与白化也可能损伤目标任务，应在留出的查询上验证，不能把某个几何统计直接当业务质量。

### 2.3 精确邻居与语义相关性是两把尺

给定同一编码器、同一度量与过滤条件，精确遍历的 top-$k$ 记为 $E_k(q)$，ANN 返回为 $A_k(q)$：

$$
\operatorname{ANN\ recall@}k=\frac{|A_k(q)\cap E_k(q)|}{k}.
$$

这度量索引有没有找回**向量空间里的**精确邻居，不判断它们是否真正回答问题。人工标注的相关文档召回、最终答案正确率是另外的指标。先抽样跑 exact 建基线：ANN recall 低才优先改索引；exact 的业务相关性也低，则看训练、数据和切块。

## 3. 承重墙推导：搜索宽度为什么值得花钱？

### Step 1　困难负例怎样进入梯度

设 $p_j$ 为所有候选切片经 Softmax 归一化后的预测概率，固定查询向量与其他样本打分，对未除温度的原始相似度分数求偏导：

$$
\frac{\partial L}{\partial s^+}=\frac{p^+-1}{\tau},\qquad
\frac{\partial L}{\partial s_j^-}=\frac{p_j^-}{\tau}.
$$

负例越接近正例，通常获得越多概率与排斥梯度。梯度下降提高正例分数、降低负例分数。它解释了困难负例的价值，也解释了错标为何有害；实际参数梯度还要通过编码器的雅可比传播。

### Step 2　从精确遍历到图搜索

exact 对每个 query 计算 $N$ 次距离，代价约 $O(Nd)$；向量与距离度量不变时结果可当搜索真值。图索引让每个向量连接一些邻居：从入口出发，先扩展靠近 query 的候选，希望少算距离就到达邻域。**HNSW** 将图做成多层：稀疏上层导航到附近，底层再作更宽的近邻搜索。构建时有插入顺序、邻居选择和建图搜索宽度；它并非下面的单层玩具图。

先猜：下图的单层有向图中，每点向距离最近的 $M$ 点连边；从 0 出发，用查询距离排序候选，并最多保存 $ef$ 个当前最佳点。$M=3$、$ef=3$ 会卡在哪里？增大哪个预算可抵达金圈？

固定每个点的出边数，只扩大候选池。先用精确 top-3 核对找回了几个邻居，再数多算了几次距离。两个读数放在一起，才能判断这次召回提升花了多少搜索成本。

真实 HNSW 中，**M 是建图时的连接预算**，实现往往还区分不同层的最大出边，受邻居选择、插入顺序等影响；提高它通常增加索引边、建图成本，并可能改善可导航性。**efSearch 是查询时保留候选的宽度**，一般需至少不小于返回数 $k$；提高它通常增加距离计算、延迟并改善召回。$ef$ 不等于访问数量的硬上限。两者都不能保证每个单独查询的结果或延迟严格单调，必须画目标语料上 recall–p95/p99 延迟–内存曲线。玩具图在某些设置下甚至不连通；真实 HNSW 的多层图、启发式连边和工程实现不同，不能用 10/22 次距离预测线上耗时。

### Step 3　IVF 缩小搜索范围，PQ 压缩每个向量

**IVF（倒排文件）**先训练粗聚类中心，把向量分配到倒排列表；查询时只搜索最近的 $nprobe$ 个列表。增大 $nprobe$ 一般多访问向量、提高召回和延迟；若正解落在未访问的桶中，桶内再精确也找不回。聚类、列表不均衡、过滤和数据漂移都会改变代价。

**PQ（乘积量化）**把 $d$ 维向量切成 $m$ 段，每段用一个码本的中心编号近似；查询可预先算各子空间到码字的距离表，累加近似距离。IVF-PQ 可对粗中心的残差做 PQ，从而同时省扫描范围和每向量字节。压缩后距离会失真，近邻可能换序；保留原向量对较多候选做精排可缓解，但会增加读取和存储。只报压缩码大小会漏掉 ID、码本、倒排表、索引结构与可能保留的原向量。

例：100 万条、768 维 float32 原向量需要约 2.86 GiB；分 96 段、每段 8 bit 的 PQ 码需要 96 MB，约 91.6 MiB，码本和其他结构另算。压缩码为原向量的 $1/32$，不代表端到端索引也恰好缩小 32 倍。IVF-PQ 的 $nprobe$、码长、候选重排数要与 HNSW 的 $M$、$ef$ 在相同数据和同一 recall 定义下比较，不能仅凭算法名选型。

### Step 4　可截断表征与粗到细

Matryoshka 训练在多个前缀维度同时优化目标，让前几维本身也携带有用表征。可以用短前缀做廉价粗召回，再用全维向量对候选重排；归一化模型应在截断**之后重新归一化**以计算该前缀的余弦。粗召回漏掉的候选，后续精排找不回来。普通 embedding 未必经过这种训练，随意裁掉尾维不保证质量；即使是可截断模型，也要实测目标维度的质量、内存、索引重建和延迟。

## 4. 极简代码锚点与数值复算

### 数值复算 · 对比损失与困难负样本

两组算例均只用 Python 标准库，可在 CPU 上运行。

```python
import math

def infonce(hard, tau):
    scores = [0.8, hard, 0.2]
    weights = [math.exp((s - max(scores)) / tau) for s in scores]
    p = [w / sum(weights) for w in weights]
    return p[0], -math.log(p[0]), (p[0] - 1) / tau, p[1] / tau

for hard in (0.2, 0.7):
    pos, loss, grad_pos, grad_hard = infonce(hard, 0.2)
    print(f"负例={hard:.1f} p正={pos:.3f} loss={loss:.3f} 正梯度={grad_pos:.3f} 负梯度={grad_hard:.3f}")
```

**运行结果**

```text
负例=0.7 p正=0.604 loss=0.505 正梯度=-1.981 负梯度=1.831
```

### 数值复算 · 单层图搜索与访问数量

独立构建上面的 36 点单层图并搜索，`seen` 统计真正计算过的 query 距离。它不是 HNSW 库，也不衡量毫秒延迟。

```python
import math, heapq

points = [(x + 0.24 * math.sin(3*x + 7*y), y + 0.21 * math.cos(5*x - 2*y))
          for y in range(6) for x in range(6)]
query = (4.3, 4.5)
distance = math.dist

def graph_search(m, ef):
    graph = [[j for _, j in sorted((distance(p, other), j)
                                    for j, other in enumerate(points) if j != i)[:m]]
             for i, p in enumerate(points)]
    first = (distance(query, points[0]), 0)
    candidates, best, seen = [first], [first], {0}
    while candidates:
        d, i = heapq.heappop(candidates)
        if len(best) >= ef and d > best[-1][0]:
            break
        for j in graph[i]:
            if j in seen:
                continue
            seen.add(j)
            item = (distance(query, points[j]), j)
            if len(best) < ef or item < best[-1]:
                heapq.heappush(candidates, item)
                best = sorted(best + [item])[:ef]
    exact = [i for _, i in sorted((distance(query, p), i) for i, p in enumerate(points))[:3]]
    found = [i for _, i in best[:3]]
    return exact, found, len(set(exact) & set(found)), len(seen)

for m, ef in ((3, 3), (3, 6), (4, 3), (2, 12)):
    exact, found, hits, visits = graph_search(m, ef)
    print(f"M={m} ef={ef:2d} 精确={exact} 返回={found} 召回={hits}/3 距离计算={visits}")
```

**运行结果**

```text
M=3 ef= 3 精确=[28, 34, 35] 返回=[25, 19, 13] 召回=0/3 距离计算=10
M=3 ef= 6 精确=[28, 34, 35] 返回=[28, 34, 35] 召回=3/3 距离计算=22
M=4 ef= 3 精确=[28, 34, 35] 返回=[28, 34, 35] 召回=3/3 距离计算=20
M=2 ef=12 精确=[28, 34, 35] 返回=[21, 20, 15] 召回=0/3 距离计算=11
```

## 5. 实战判断、迁移与前沿现状

**诊断顺序**：固定切块和 embedding 版本，在覆盖真实问题分布的留出集上先跑 exact，再把 ANN 与它配对比较；同时量业务相关证据召回。若 ANN recall 已高而业务召回低，查 query 改写、训练对与假负例；若 exact 好而 ANN 低，调 $ef$ 或 $nprobe$。记录过滤条件、批大小、硬件、并发、索引构建参数、冷暖缓存、p50/p95/p99 与常驻内存。对访问控制等过滤，exact 和 ANN 必须使用同一可见集合；过滤方式本身也会改变访问量。

**2026 前沿现状**：检索服务常把稠密向量与词法检索结合，并在候选上做更贵的交叉编码或模型重排（→ 8.2）。支持可变输出维度的 embedding（例如 OpenAI 的 text-embedding-3 系列支持 `dimensions`）和 Matryoshka 训练使同一表示能用于不同预算；这不等于所有模型裁剪后都保质。Faiss 和 hnswlib 分别提供 IVF/PQ 与 HNSW 实现和参数说明，但库、硬件、过滤条件与数据分布决定实际权衡，发布报告和模型卡不能替代自己测。

**迁移练习 1**：某批查询 ANN 与 exact 的 top-10 平均交集为 9 个，但人工相关证据召回仍低。把 $ef$ 加倍是否能保证修复？

> **解答**：ANN recall@10 为 90%，但它只比较向量邻居。先看 exact 的人工相关召回及分块：若 exact 已漏相关文档，$ef$ 无法修复表征或入库问题；若 exact 包含它而 ANN 丢失，可以在延迟与内存预算内调 $ef$、比较配对结果。

**迁移练习 2**：一条 768 维 float32 向量 3072 字节，96 段、每段 8 bit 的 PQ 码多大？两者都算上了吗？

> **解答**：每条码 96 字节，向量数据层面为 32 倍；实际索引还需 ID、码本、倒排表与可能保存的原向量。压缩造成的排名误差必须测；用精排只能恢复进入候选的近邻。
