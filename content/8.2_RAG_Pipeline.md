# 8.2 RAG 全链路：找到证据，放对位置，再回答

> **一句话核心直觉**：RAG 的答案由数据、切块、检索、重排、上下文和生成共同决定。对同一道题保留各阶段的证据与输出，才能区分“没有找到”“找到后丢了”“放进来却没用好”。
> **唤醒标签**：切块 · BM25 + 稠密 · RRF · cross-encoder · 证据覆盖 · 重排 · 位置与干扰 · 忠实度 ≠ 正确率 · 反事实诊断

前置：双塔、ANN 与 exact 邻居（→ 8.1）；本课是 Agent 系统管理外部知识的入口（→ 8.4）。

## 1. 痛点与钩子：手册里有答案，机器人为什么答错？

用户问“E42 退款期限是多少”。手册的一段说 E42 是支付失败，下一段说支付失败可在 30 天内退款；过期的例外条款和别的退款规则也含有 `E42`、`refund` 等词。线上答案可能错在四处：

| 阶段 | 保留的可观察对象 | 典型失败 |
|---|---|---|
| 数据与切块 | 原文版本、块边界、元数据、访问权限 | 条款过期；条件和结论断在两块；漏索引 |
| 召回 | query、过滤条件、候选 ID 与分数 | 相关块没进候选；稀疏或稠密各有盲区 |
| 重排与上下文 | 每个候选的排名、截断后位置及 token | 找到正确块，但被重排、预算或去重丢掉 |
| 生成与引用 | 输入上下文、答案、引用与评测 | 已提供证据仍忽略条件、被干扰或引用错 |

对同一个模型和固定问题，先猜：把两个相邻段落合成大块，会更容易一次取回全部事实吗？大块又付出什么？

## 2. 第一性原理：检索的是信息单元，而不是整篇真相

### 2.1 切块决定候选及上下文的颗粒度

小块更聚焦，便宜地排进候选，但条件、指代或表格的标题可能在别的块；大块能保住邻接关系，却稀释相似度、耗费重排与上下文预算。常用做法按标题、段落、表格等语义边界切分，保留文档 ID、标题、版本、位置和权限；必要时对命中块展开父段或相邻块。重叠可以减轻跨边界丢失，却会产生相近重复项；它不是免费召回。

下表是实验的完整语料，向量是人为指定的二维教学数据，查询向量为 $(1,0)$。事实 A、B 必须同时覆盖；B1 说例外已被废止，B2 是另一条无关规则。大块只将同一文档的两段合并，向量取两段之和后计算余弦；它不模拟真实模型对合并文本的重新编码。

| 块 | 文本（按空格分词） | 教学向量 | 金标准事实 |
|---|---|---|---|
| A1 | `e42 means card payment failed` | (0.8, 0.6) | A：错误码含义 |
| A2 | `failed card payment refund deadline thirty days` | (1.0, 0.1) | B：30 日期限 |
| B1 | `e42 refund exception was superseded` | (0.2, 0.98) | — |
| B2 | `refund deadline seven days` | (0.3, 0.95) | — |
| C1 | `e24 card shipment failed` | (0.5, 0.8) | — |
| C2 | `shipment tracking delivery` | (0.0, 1.0) | — |

### 2.2 稀疏、稠密及混合检索

BM25 用词频、文档频率和长度归一化匹配，适合错误码、型号和罕见专名；同义改写可能漏掉。稠密检索把查询和文本嵌入向量空间，能连接训练中学到的语义关系，但准确的型号、数字和否定词也可能被模糊。两种召回的候选取并集，再融合或交给重排，常能互补；是否互补必须用实际数据测。

实验中每个查询词 $t$ 的 BM25 分量是：

$$
\operatorname{idf}(t)=\log\!\left(1+\frac{N-\operatorname{df}(t)+0.5}{\operatorname{df}(t)+0.5}\right),\quad
\operatorname{BM25}(d,q)=\sum_{t\in q}\operatorname{idf}(t)\frac{f(t,d)(k_1+1)}{f(t,d)+k_1(1-b+b|d|/\overline{|d|})}.
$$

这里 $k_1=1.2,b=0.75$，$N$ 是当前块数。不同实现的 IDF、分词和去重可能不同。稠密分数取二维向量余弦。两者量纲不同，实验先各自排序，使用加权 reciprocal rank fusion，名次从 1 开始：

$$
\operatorname{RRF}(d)=\frac{1-\alpha}{60+r_{\mathrm{BM25}}(d)}+\frac{\alpha}{60+r_{\mathrm{dense}}(d)}.
$$

60 是此实验的平滑常数。RRF 利用名次、不要求原始分数同尺度，但丢弃了分数间隔信息；实验对全部块评分，实际系统可能只提供每路的 top-$n$，未出现的候选通常不贡献对应项。权重、候选深度和过滤需要验证；不能把两路 top-1 的融合当成完整语料上的融合。

## 3. 承重墙推导：从候选到答案，每一步丢了什么？

### Step 1　重排花更贵的计算，换查询与文档的交互

双塔分别编码 query 与文档，因此文档向量可离线存储；**交叉编码器**把 query 和每个候选一起输入，经过 token 级交互后逐对打分。它可以更细致地比较否定、时间、实体和条件，但通常要对每个候选单独算一次，代价随候选数和长度增长；它只重排收到的候选，无法凭空找回漏召的文档。生产上还要核对截断位置：如果模型只看到块的开头，末尾证据等于没被重排器看到。

下面用六条合成轨迹定位问题。每题有唯一标注证据 R，A–E 为干扰；R 的检索排名依次为 1、2、3、4、5、6。重排分数是预先给定的数字，**不是运行了交叉编码器**。例如 Q1 的 R 分数为 0.6、A 为 0.9；Q2 的 R 为 0.9、A 为 0.3；Q3 的 R 为 0.5、A 为 0.9、B 为 0.8。完整分数与答案在复算代码中。重排只对选入的候选排序。

候选 top-3、重排后留 top-2 时：Q4–Q6 在候选阶段漏召；Q3 的 R 在候选里却排第 3，被上下文截断；Q1 和 Q2 都带有 R，但只读第一块会在 Q1 抄到 A 的错误数字。六题得到 **3/6 候选含证据 → 2/6 上下文含证据 → 1/6 答对**。将阅读器切到匹配题号后，同一上下文答对 2/6。把候选扩大到 6、继续保留两个块且匹配题号，得到 6/6 → 5/6 → 5/6；Q3 仍因重排排第 3 被截断。[用 Python 复算](#worked-example-2)

这个阅读器是可执行的规则，不是对真实 LLM 的性能预测。它假设 R 是唯一能答对的证据、干扰块数字都错，并且阅读器没有参数知识。**只有在这类封闭假设下**，正确回答才必须先有标注证据；现实中模型可能早已知道答案，也可能找到另一条有效证据，而标签可能不完整，因此标注证据召回不是答案正确率的统一上界。

### Step 2　上下文长度不等于有效利用

上下文窗口能装下更多文字，却不能保证模型从每个位置等效地提取信息。位置、近似但错误的文档、过期版本及相互矛盾的证据都可能干扰。Lost in the Middle 的实验展示了所测试模型和任务上的位置效应，并不构成所有模型、所有问题的一条固定曲线。长上下文也不能自动替代数据更新、权限过滤、检索及引用；不同任务可以实测“整篇输入”与 RAG 在质量、token 成本和时延上的差别。

做位置对照时，固定问题、证据文本、生成器和 token 预算，只改变证据在开头 / 中间 / 末尾的位置；再固定位置改变干扰块数量与内容。保持同一批题并复跑，避免把不同问题难度或生成随机性误认成位置效应（→ 5.4）。同时检查上下文是否保留标题、条件与来源链接：单独拿到“30 天”可能丢失适用对象或版本。

### Step 3　指标分开、单位对齐

设每题有人工标注相关集合 $G_q$，检索集合为 $C_q$：

$$
\operatorname{relevance\ recall@}k(q)=\frac{|G_q\cap C_q|}{|G_q|},\quad
\operatorname{precision@}k(q)=\frac{|G_q\cap C_q|}{|C_q|}.
$$

这两式假设 $G_q$ 非空、实际返回集合 $C_q$ 非空。多题可按题平均，也可按标注事实数微平均，要说清分母。多跳问题还应测**完整证据覆盖**：回答所需的所有标注事实是否都被选入；只命中一条的 hit@k 并不能代表完整覆盖。若答案可以由多种证据组合支持，按可接受的证据集合逐项判断，避免把另一条正确来源算成漏召。MRR 衡量首个相关项的位置，nDCG 可使用分级相关性，它们补充而非替代覆盖率。

**忠实度**问回答中的主张能否由给定上下文支持；**正确率**问它是否符合外部真值。引用需要指向真正支持该主张的位置，不能只检查链接能打开。遵照过期文档可能忠实但错误；依靠参数知识答对而上下文没依据可能正确却不忠实。人工或经人工校准的评审应检查时间版本、引用蕴含和遗漏条件，避免把自动裁判视为真值。

这里的相关证据召回与 → 8.1 的 ANN recall 不同：前者对照人工相关标签，后者对照同一向量空间的 exact 邻居；高 ANN recall 不能保证业务证据相关。

### Step 4　做三种反事实来定位瓶颈

1. **查召回**：固定数据与 query，比较候选和标注证据；再用 exact 与 ANN 比较，分清向量排序问题和索引近似问题。核查入库、权限与过滤。
2. **查重排**：固定同一候选集，比较重排前后证据位置、上下文覆盖；可用人工标注形成排序 oracle 做受标签与上下文预算约束的参照。重排只能选到候选里的内容。
3. **查利用**：固定或人工插入经过核验的证据，比较不同位置、干扰与生成设置下的忠实度和正确率。若 oracle 上下文仍答错，继续查生成、任务定义和标注；若人工提供证据能答对，再回到前面的阶段。

这些测试不是把所有正确答案都归因于同一条标注证据，而是通过固定变量比较**这条证据**是否到达、是否被使用。

## 4. 极简代码锚点与数值复算

### 数值复算 · 切块和混合排名

两段分别从原始数据计算，不依赖外部服务或模型，普通 CPU 的 Python 标准库即可执行。第一段对 BM25、稠密余弦排序后做加权 RRF；第二段给重排器固定分数，规则阅读器明确处理题号和数字。

```python
import math

paragraphs = [
    ("A1", "e42 means card payment failed", (0.8, 0.6), "A"),
    ("A2", "failed card payment refund deadline thirty days", (1.0, 0.1), "B"),
    ("B1", "e42 refund exception was superseded", (0.2, 0.98), ""),
    ("B2", "refund deadline seven days", (0.3, 0.95), ""),
    ("C1", "e24 card shipment failed", (0.5, 0.8), ""),
    ("C2", "shipment tracking delivery", (0.0, 1.0), ""),
]

def hybrid(size, alpha, k):
    chunks = []
    for i in range(0, len(paragraphs), size):
        parts = paragraphs[i:i+size]
        name = parts[0][0] if size == 1 else parts[0][0][0]
        words = sum((p[1].split() for p in parts), [])
        vec = tuple(sum(p[2][j] for p in parts) for j in range(2))
        facts = "".join(p[3] for p in parts)
        chunks.append(dict(name=name, words=words, vec=vec, facts=facts))
    n = len(chunks)
    avglen = sum(len(c["words"]) for c in chunks) / n
    for c in chunks:
        score = 0.0
        for term in ("e42", "refund", "deadline"):
            df = sum(term in d["words"] for d in chunks)
            tf = c["words"].count(term)
            idf = math.log(1 + (n - df + 0.5) / (df + 0.5))
            score += idf * tf * 2.2 / (tf + 1.2 * (0.25 + 0.75*len(c["words"])/avglen))
        c["bm25"] = score
        c["dense"] = c["vec"][0] / math.hypot(*c["vec"])
    def ranks(key):
        order = sorted(range(n), key=lambda i: (-chunks[i][key], i))
        return {i: rank + 1 for rank, i in enumerate(order)}
    sparse, dense = ranks("bm25"), ranks("dense")
    score = lambda i: (1-alpha)/(60+sparse[i]) + alpha/(60+dense[i])
    order = sorted(range(n), key=lambda i: (-score(i), i))[:k]
    return [chunks[i]["name"] for i in order], set("".join(chunks[i]["facts"] for i in order))

for size, alpha, k in ((1, 0, 2), (1, 0.5, 2), (1, 1, 2), (2, 0.5, 1)):
    names, facts = hybrid(size, alpha, k)
    print(f"每块{size}段 α={alpha:.1f} top-{k}={','.join(names)} 事实覆盖={len(facts)}/2")
```

每块1段 α=0.5 top-2=A2,B2 事实覆盖=1/2
每块1段 α=1.0 top-2=A2,A1 事实覆盖=2/2

### 数值复算 · 六条逐阶段诊断轨迹

```python
# 按检索顺序排列：R 是唯一标注证据，A–E 为干扰块。
traces = [
    ("Q1", 30, "RABCDE", dict(R=.6, A=.9, B=.3, C=.2, D=.1, E=.05)),
    ("Q2", 60, "ARBCDE", dict(R=.9, A=.3, B=.2, C=.1, D=.08, E=.05)),
    ("Q3", 90, "ABRCDE", dict(R=.5, A=.9, B=.8, C=.2, D=.1, E=.05)),
    ("Q4", 15, "ABCRDE", dict(R=.9, A=.5, B=.4, C=.3, D=.2, E=.1)),
    ("Q5", 45, "ABCDRE", dict(R=.8, A=.9, B=.5, C=.4, D=.3, E=.1)),
    ("Q6", 21, "ABCDER", dict(R=.8, A=.9, B=.5, C=.4, D=.3, E=.1)),
]
wrong_values = dict(A=7, B=9, C=11, D=13, E=17)

def diagnose(candidate_k, context_k, reader):
    summary = [0, 0, 0]
    for qid, gold, retrieval, scores in traces:
        candidates = list(retrieval[:candidate_k])
        ranked = sorted(candidates, key=lambda name: -scores[name])
        context = ranked[:context_k]
        passages = [(qid, gold) if name == "R" else ("other", wrong_values[name])
                    for name in context]
        answer = passages[0] if reader == "first" else next((p for p in passages if p[0] == qid), None)
        evidence_candidate = "R" in candidates
        evidence_context = "R" in context
        correct = answer is not None and answer[1] == gold
        summary = [a + int(b) for a, b in zip(summary, (evidence_candidate, evidence_context, correct))]
        print(f"{qid} 候选={''.join(candidates)} 上下文={''.join(context)} 答案={answer[1] if answer else '无'} 正确={int(correct)}")
    print(f"{reader}: 候选证据={summary[0]}/6 上下文证据={summary[1]}/6 答对={summary[2]}/6")

for reader in ("first", "matched"):
    diagnose(3, 2, reader)
```

## 5. 实战判断、迁移与前沿现状

**面向 Agent 的落地顺序**：从真实问题分层抽样，给证据记录稳定文档 ID、版本和必要上下文；上线 trace 保留 query 改写、各路候选与分数、重排结果、最终 prompt 中的顺序，以及生成答案与引用。先量故障占比，再定改动：入库或切块有问题先修数据；漏召高先改召回；候选已到、上下文未到就改重排及预算；证据已到却用错才针对生成器、提示和干扰做对照。

**2026 前沿现状**：原始 RAG 把外部检索作为生成的条件；现有实践常组合 BM25 与稠密候选、cross-encoder 重排，以及带引用的生成。评估工具如 Ragas 把上下文相关、答案忠实和正确性拆为不同维度；这些指标的定义、裁判和领域适配需要人工校验。长上下文模型带来新的“全文输入 vs 检索”的成本与质量选择，并没有消除对新鲜数据、权限、版本和证据归因的需求。

**迁移练习 1**：100 题中，70 题的已标注证据出现在候选，55 题进入上下文，模型却答对 75 题。是否必然算错了？

> **解答**：不必然。模型可以通过已有知识答对，检索到的其他有效证据也可能未标注，且“答对”与“证据被取回”是不同事件；需要题级交叉表及人工核查。若要求答案必须由给定证据支持，应另报有依据且正确的题数，不能把 75 直接当作有依据的答案数。

**迁移练习 2**：某题候选包含正确条款，但 top-3 上下文没有它。应该先调生成温度吗？

> **解答**：先固定候选，检查重排分数、模型截断、重复过滤与上下文 token 预算；把核验后的条款插入上下文做对照。若插入后答对，优先修候选到上下文的环节；若仍答错，再检查条件、冲突、位置与生成器利用情况。

## 6. 3 分钟记忆唤醒自测

1. 为什么小块可以提高局部匹配，却让多跳问题更难获得完整证据？重叠有什么代价？
2. BM25、双塔与交叉编码器分别在哪里计算 query–文档交互？为什么需要候选和重排两个预算？
