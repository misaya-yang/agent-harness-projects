# 8.4 上下文工程与长期记忆

> **一句话核心直觉**：上下文是模型每次决策时能看到的有限工作区；摘要是有损编码，外部记忆把部分历史留在窗口之外、需要时再找回来。有效记忆取决于**写入、召回、真实性与时效、利用**的整条链；增加召回并不保证更准，过期记忆也可能比没有记忆更糟。
> **唤醒标签**：有限工作区 · 信息瓶颈与充分统计 · 任务相关摘要 · 位置与干扰 · 写入 / 召回 / 新鲜度 / 利用 · 过期的负价值 · 时间与作用域 · KV 缓存 ≠ 语义记忆 · 长程一致性与反事实评测

## 1. 问题：长会话里，用户更正过的偏好去了哪里？

延续 → 8.3 的**离线行程助手**：用户先说「我喜欢靠窗」，十轮之后更正「以后一般选靠过道」；又过了一段对话，用户要求 11 月 23 日从 A 到 B，避开会议，并尽量按当前偏好选座。班次、日历和对话都是本课虚构的离线数据，助手只输出拟定方案。

一次失败的答案写了「按你的偏好选靠窗」。可能是：摘要漏掉了更正；记忆根本没写入；写入了却没有召回；召回了但把旧事实排在新事实前面；证据完整但模型忽略了。**相同的最终错误，需要不同干预**。先看每轮模型的输入有哪些部分：

$$
\text{总预算 }B=B_{\rm instructions}+B_{\rm current}+B_{\rm history}+B_{\rm retrieved}+B_{\rm output}.
$$

这是 token 账本，输出预算预留多少取决于调用约定；历史、工具返回与召回记忆要争夺可用输入空间。窗口足够长不代表每条信息都会被同等利用：Lost in the Middle（arXiv 2307.03172）在其检索与问答实验中观察到位置影响，尤其是部分模型对中间位置的利用较弱。这不是「所有模型和所有任务都必然中间最差」的定律；要固定证据内容、长度和干扰项，改变位置后实测。

## 2. 摘要：先决定要保留什么，再决定压多少

### 2.1 一条罕见偏好，为什么比重复的闲聊更值钱

设窗口外的历史有 10 条等长事实，恰好一条是当前问题需要的座位偏好。摘要只能保留 $k=3$ 条。若从 10 条中均匀无放回地选 3 条，保住目标的概率是

$$
P_{\rm random}=\frac{\binom{9}{2}}{\binom{10}{3}}=\frac{3}{10}=0.30.
$$

如果摘要器以概率 $q=0.75$ 识别出这条关键事实并为其预留位置；识别失败时退回均匀随机保留，则由全概率公式

$$
P_{\rm selective}=q+(1-q)\frac{k}{10}=0.75+0.25\times0.30=0.825.
$$

**相同预算下是 30.0% 对 82.5%**。[数值复算](#worked-example)枚举 120 种等概率摘要。这个例子假设了问题已知、一条关键事实、等长事实和指定的回退规则；保住事实不代表它一定正确、最新或会被模型利用。真实摘要可能知道用户长期目标，但不知道下次具体问什么；重要性估计本身也会犯错。

### 2.2 信息论边界：丢掉的区别无法凭摘要恢复

令 $H$ 是原始历史，$Q$ 是问题，$Y$ 是要回答的真实偏好，$S=g(H,Q)$ 是只利用历史和问题产生的摘要。给定 $Q$，有马尔可夫关系 $Y\to H\to S$，由数据处理不等式（→ 0.5）

$$
I(Y;S\mid Q)\le I(Y;H\mid Q).
$$

这里摘要器没有额外接入与 $Y$ 相关的独立证据；外部检索引入新证据时不能简单套成这一条链。不等式说摘要不能创造关于 $Y$ 的历史信息，**不等于摘要一定让实际模型更差**：较短的相关内容可能减少干扰、使有限能力的解码器更容易利用证据。

极端地说，两段历史在更正之前相同，一段最终改为「靠过道」、另一段改为「靠窗」，摘要却都写成「有座位偏好」。如果两种情况事先等可能，且只给摘要、不提供其他证据，任何回答者对二选一的最好正确率也只有 50%。丢掉的正是区分两段历史所需的信息。

对固定任务分布，理想摘要要尽量保留回答所需的**充分信息**：若 $P(Y\mid H,Q)=P(Y\mid S,Q)$，摘要对该问题保留了历史中关于 $Y$ 的全部预测信息。但「充分」依赖问题分布；只针对座位问题压缩的摘要未必还保留预算、日期和同行人的约束。

## 3. 长期记忆：写、找、确认、用

### 3.1 记忆不是把所有聊天永久塞进提示

把近期消息作为工作区，把可复用的事实放在外部记忆；每次按问题检索候选，再在预算内插入上下文。一个概念性的记录可以是：

| 字段 | 本例的两个事件 |
|---|---|
| 对象与字段 | 同一虚构用户 · 通用座位偏好 |
| 值与时间 | 第 1 轮「靠窗」；第 10 轮「以后一般靠过道」 |
| 作用域 | 长期默认偏好；本次明确要求若不同，可覆盖默认 |
| 来源 | 用户原话与轮次，保留更正关系 |
| 状态 | 后一条取代同作用域的前一条；旧值仅作为历史，不作为当前偏好 |

「当前偏好」不是简单地选数据库里全局最新的一条：某次旅行的临时要求与「以后一般」作用域不同，系统记录、用户纠正和工具猜测的来源权重也不同。时间戳、来源和作用域让冲突可判别；删除记忆时也要明确是否连同派生摘要一起删除，避免旧摘要继续携带已删除的事实。真正应该写什么由用户的授权、未来效用和保留成本共同决定；本例不需任何真实用户数据。

### 3.2 写入与遗忘是预算决策

对一条候选记忆 $m$，可以用概念上的**期望净价值**理解写入：

$$
V(m)=\mathbb{E}_{Q,\,Y}[L(\hat Y_{\rm without},Y)-L(\hat Y_{\rm with\ }m,Y)]-\lambda\,\mathrm{tokens}(m)-C_{\rm stale}(m)-C_{\rm retention}(m).
$$

$L$ 是决策损失，期望按未来问题与真实状态的分布取；$C_{\rm stale}$ 是错误或过期使用的代价，$C_{\rm retention}$ 表示存储、维护等成本。这个式子是**决策框架**，不是可直接从一条文本精确算出的分数。默认座位偏好可能跨多次请求受益；一次性的班次空位容易变，应该带时间并重新查询。高频提及不等于高价值：一条罕见但会改变决定的约束可能值得保留。

检索时可综合相似度、任务相关性、时间与来源；阈值和条数提高召回的同时也可能增加无关或旧内容。遗忘既可以是用户更正或删除后的显式失效，也可以是过期检查、合并和预算淘汰；单靠「按时间删除最旧记录」可能先丢掉很少变化但很重要的约束。MemGPT（arXiv 2310.08560）把有限上下文和外部存储的管理放在同一系统里讨论；MemoryBank（arXiv 2305.10250）探索了长期记忆与遗忘策略。

## 4. 一条条件概率链：为什么检索更多也可能更差

对每个偏好问题，设 $w$ 是相关事实曾被写入的概率，$r$ 是**已写入时**检索返回一个候选的概率，$f$ 是返回的候选既正确又对当前问题有效的条件概率。这个玩具模型假设没写入时不返回候选；返回多个候选的冲突先简化成一个最终候选。再设：

- 候选正确有效时，模型答对的条件概率 $u=0.95$；
- 候选错误或已过期时，仍答对的条件概率 $s=0.10$；
- 没候选时，答对的条件概率 $b=0.50$。

比较「全部不检索」时，还假定关闭候选后的无候选正确率在各组均为 $b$；若组间不同，应分别估计。可以随机展示或关闭候选来检验反事实效果。

三个互斥分支「正确候选并答对」「无效候选仍答对」「无候选仍答对」相加，得到

$$
P(\text{答对})=wr\,[fu+(1-f)s]+(1-wr)b.
$$

在 $w=0.9,r=0.8,f=0.75$ 时，候选到达率 $wr=0.72$。三项正确答案分别贡献 **51.3%、1.8%、14.0%**，总正确率 **67.1%**；把所有候选禁用的基线为 50.0%。这个结果是例子中的概率，不是记忆系统的实测水平。

保持 $w,f,u,s,b$ 不变，增加 $r$ 的收益斜率是

$$
\frac{\partial P(\text{答对})}{\partial r}=w\,[fu+(1-f)s-b].
$$

只有 $f>(b-s)/(u-s)=0.4/0.85\approx0.471$ 时，增加同等质量的召回才有正收益（这里 $u>s$、$w>0$）。如果 $f=0.4$，同样的 $w,r$ 下总正确率变为 **45.68%**，反而低于 50% 的无候选基线。按这个设定，找回更多旧偏好会让答案更差。

```academy-lab
8.4-retrieval
```

这条因果判断需要额外前提：例如随机控制是否展示候选，且各分支的正确率在干预后保持不变；对照群体可比。真实系统中降低检索阈值会同时改变 $r$ 和 $f$，不同难度题的基线 $b$ 也可能不同。仅看到相关性不能断言「提高召回导致退化」；应在相同任务上随机开启 / 关闭或替换候选，再观察正确性与冲突。

## 5. 位置、长期检索与模型内部状态

### 5.1 长上下文和检索回答不同问题

直接放完整历史的好处是原文、上下文和更正关系可见；限制是 token 成本、位置偏差及无关内容干扰。外部记忆能把远期事实以较少 token 带回来，但多出写入、索引、检索与版本错误。二者可以结合：保留近期原文，加上针对当前问题召回的有来源记忆；当两者冲突时检查来源、时间和作用域。

RAG（arXiv 2005.11401）把检索作为生成时获取外部证据的方法；长期记忆在此基础上还要处理**用户历史随时间改变**。不要把一次检索命中率当成最终回答正确率：命中旧偏好也算命中某条相关文本，但可能不是有效证据。

### 5.2 KV 缓存不是可直接查询的用户偏好表

普通推理 KV cache 是给注意力层保存前文的键和值，避免每个新 token 重算前缀（→ 1.3、→ 7.4）；它依赖具体前缀和模型状态，并不天然具有可编辑的「用户 → 座位偏好」语义或跨会话持久检索能力。把窗口外的文本留在数据库是**外部记忆**，不是让普通 KV 缓存自动变成长期记忆。

另一条路线是在模型架构中显式传递状态：Transformer-XL（arXiv 1901.02860）把上一段隐藏状态复用于下一段的注意力，训练时对缓存状态截断梯度；Compressive Transformer（arXiv 1911.05507）进一步研究压缩旧状态；Recurrent Memory Transformer（arXiv 2207.06881）用可训练的记忆 token 跨段传递信息。这些内部状态的保存、训练和可解释性各不相同，不等同于外部记录的可搜索、可更正事实。固定大小状态压缩也有信息损失，和 → 1.6 的线性 / 递归状态存在相同的容量问题。

## 6. 怎样定位与评测长期一致性

同一组虚构用户会话，标注用户、事实、时间、作用域、来源和正确的最终回答，再隔多轮插入更新、干扰与无答案问题。LongMemEval（arXiv 2410.10813）把长程对话记忆拆成信息提取、多会话推理、时间推理、知识更新与弃答等能力；应分别报告，而不只给一个总分。

| 可观察症状 | 下一步受控实验 | 要比较的量 |
|---|---|---|
| 正确偏好没有进入记忆 | 对同一会话标注应写事实，对照实际记录 | 写入覆盖率、误写率 |
| 已写入却没有返回 | 固定已写入的索引，比较问题与候选 | 当前有效证据的 recall@k、无关候选率 |
| 返回了旧值 | 给同一问题分别提供新值、旧值、两者及来源 | 识别冲突 / 更新后的正确率 |
| 正确证据在上下文仍答错 | 给所有方法相同正确候选，只改变位置或干扰 | 条件利用率、位置敏感度 |
| 没证据却自信回答 | 设置真实不可知的问题，检查是否承认未知 | 弃答准确性及误答率 |

与「不使用长期记忆」「只用最近窗口」「摘要」「检索历史」「人工提供有效证据」做配对对照，报告任务正确率、新旧偏好冲突率、证据新鲜度、延迟和 token 成本。人工提供正确证据能帮助判断**利用能力**，但不是无条件的系统上限：额外证据同样可能改变提示长度和干扰。评测时用同一批会话比较；多个问题来自同一用户时，置信区间按用户或会话分组重采样（→ 5.4），避免把相关样本当独立样本。

## 7. 数值与离线代码

下列三个例子只依赖 Python 标准库；每段可单独运行。数据均为虚构，概率是教学设定。

### 数值复算 · 摘要保留、过期风险与偏好更正

**1. 枚举随机摘要，再计算选择性保留。**

```python
from itertools import combinations

n, k, q = 10, 3, 0.75
subsets = list(combinations(range(n), k))
random_recall = sum(0 in chosen for chosen in subsets) / len(subsets)
selective_recall = q + (1 - q) * random_recall
print(f"均匀子集数: {len(subsets)}")
print(f"随机保留关键事实: {random_recall:.3f}")
print(f"选择性保留关键事实: {selective_recall:.3f}")
```

**运行结果**

```text
均匀子集数: 120
随机保留关键事实: 0.300
选择性保留关键事实: 0.825
```

**2. 区分正确、过期和缺失三个分支。**

```python
w, r, f = 0.90, 0.80, 0.75
u, stale, baseline = 0.95, 0.10, 0.50

def outcome(freshness):
    found = w * r
    current_correct = found * freshness * u
    stale_correct = found * (1 - freshness) * stale
    no_candidate_correct = (1 - found) * baseline
    return current_correct, stale_correct, no_candidate_correct

parts = outcome(f)
print("三种来源的正确率贡献:", ", ".join(f"{x:.3f}" for x in parts))
print(f"总正确率: {sum(parts):.3f}；无候选基线: {baseline:.3f}")
print(f"有效率 0.40 时的总正确率: {sum(outcome(0.40)):.4f}")
print(f"有效率收益阈值: {(baseline-stale)/(u-stale):.4f}")
```

**运行结果**

```text
三种来源的正确率贡献: 0.513, 0.018, 0.140
总正确率: 0.671；无候选基线: 0.500
有效率 0.40 时的总正确率: 0.4568
有效率收益阈值: 0.4706
```

**3. 在同一用户、同一作用域内按明确更正排序。**

```python
records = [
    {"user": "虚构用户", "scope": "长期座位偏好", "turn": 1, "value": "靠窗"},
    {"user": "虚构用户", "scope": "长期座位偏好", "turn": 10, "value": "靠过道"},
    {"user": "虚构用户", "scope": "本次行程", "turn": 11, "value": "靠窗"},
]
matching = [r for r in records if r["user"] == "虚构用户" and r["scope"] == "长期座位偏好"]
current = max(matching, key=lambda r: r["turn"])
print(f"长期默认: {current['value']}（第 {current['turn']} 轮更正）")
print("本次行程的临时偏好: 靠窗")
```

**运行结果**

```text
长期默认: 靠过道（第 10 轮更正）
本次行程的临时偏好: 靠窗
```

这个示例预先知道哪些记录是同一用户、同一作用域的明确表述；真实数据需先解决身份、来源、否定和时间语义，不能对任意文本机械取最新。

## 8. 实战直觉、避坑与面试深挖

**与工程 / 应用的连接**

- **按任务价值分配预算**：目标、当前用户要求、有效约束和可追溯证据要与历史摘要、检索候选一起竞争空间；对将来的未知问题评估，而不是只优化当前摘要看起来有多短。
- **记录来源、时间和作用域**：相同字段的更正需要可比较的依据；把临时请求与长期偏好分开，过期的动态事实需要更新或再次查询。
- **按环节定位**：先测写入和有效证据召回，再固定正确证据测利用；控制历史长度、位置和干扰，才能判断增加窗口或更换检索是否有效。

**常见误区 / 反直觉点**

1. **「窗口越长，记住的就越多」**：可放入更多 token 不等于模型均匀利用所有 token；位置与干扰必须按任务测。
2. **「摘要越短越好」**：摘要节省预算，同时可能丢掉对后续决策至关重要的低频事实。
3. **「召回越多越准」**：更多错误或过期候选可能降低准确率；本课公式明确给出净收益所需条件。
4. **「KV cache 就是用户长期记忆」**：前者缓存模型计算状态，后者需要按用户和问题存取、更新与解释事实。

**高频深挖题**

- 为什么信息论说压缩不会增加信息，短摘要却可能提高实际准确率？答题路径：条件数据处理不等式 → 信息损失与解码器有限能力是两个问题 → 相关摘要减少干扰。
- 检索命中为什么仍可能答错？答题路径：当前有效证据是否写入 → 候选是否召回 → 时间、来源与作用域 → 利用率和输出。
- 怎样判定提高召回造成了退化？答题路径：同一任务做随机展示或候选替换 → 单独测有效率与条件利用 → 控制 token、位置与题目难度。

## 9. 迁移练习（附解答）

**练习 1**　离线学习助手有 20 条等长历史，恰有一条是下次问题所需的「考试日期」。摘要保留 4 条；随机策略均匀抽取，选择性策略以 0.6 的概率识别关键事实，否则退回随机。两种策略的保留率分别是多少？

> **解答**：随机保留率是 $4/20=0.20$；选择性保留率是 $0.6+(1-0.6)\times0.20=0.68$。这只衡量日期被保留，不表示日期一定未更新或最终回答一定正确。

**练习 2**　离线食谱助手每次有 0.8 的概率检索到一条用户偏好候选；其中一半正确有效。正确候选下答对率为 0.9，无效候选下为 0.2，无候选为 0.6。计算总体正确率，并判断在其他条件不变时继续增加召回是否有利。

> **解答**：$0.8[0.5\times0.9+0.5\times0.2]+0.2\times0.6=0.56$，低于始终无候选的 0.6。候选组条件正确率 $0.55<0.6$，因此在本模型中继续扩大**同质量**召回会降低正确率。若提高召回同时改变候选有效率或问题难度，还须重新测量。
