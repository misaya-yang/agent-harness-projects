# 9.2 安全对齐与越狱：评估拒答边界

> **一句话核心直觉**：安全对齐将行为规范沉淀为训练信号与评估准则；当面对超出训练分布的输入时，系统既可能漏放高危请求，也可能误杀良性提问。必须结合固定规范、两类错误分母、分层审计与独立盲审来综合评判拒答边界，切忌将安全简化为单一的总体通过率。
> **唤醒标签**：规范 → 标注 → 后训练 → 拒答边界 · 漏过率 · 过度拒答 · 混淆矩阵 · 分层 · 盲审 · 不确定性

---

## 1. 问题：拒得越多就越安全吗？

在实际业务中，安全团队与产品团队常常面临博弈：安全团队希望系统对高危风险严防死守，宁可从严拒答；而产品团队则频繁收到正常用户的误伤投诉——例如程序员询问“如何杀死一个僵死进程”或编剧请教“侦探小说中如何设计一次投毒诡计”，往往被模型判定为危害行为而生硬拒答。

如果把系统的拒答阈值调得极为激进，确实能拦下更多恶意请求，但会导致严重的**过度拒答（Over-refusal）**，让模型效用大打折扣；反之，若盲目放宽阈值，又会导致包含对抗包装的违规请求被轻易放行。**如何建立严格的混淆矩阵同时量化这两类性质完全不同的错误？又该如何确认看似改善的总体指标没有掩盖某个特定子场景的防御塌陷？**

本课采用抽象的“需拒绝”与“应回答”类别标签以及标准数值评分进行原理剖析，不展示任何真实有害提示词。所有数据均为教学对照数据，不代表特定商业模型的实际表现；各阈值下的条件错误率与统计置信区间均可在[数值复算](#worked-example)中核对。

## 2. 对齐是目标、数据与评估共同决定的边界

在预训练阶段，模型的核心优化目标是在海量互联网文本上最小化交叉熵损失，拟合下一个 token 的概率分布（→ 1.0 §6.1）。这一目标促使模型忠实模仿人类世界的一切文本规律，天然不会区分行为规范与安全准则。随后的后训练（Post-training，如 SFT、RLHF、DPO 或 Constitutional AI）则通过人类示范或原则反馈，在模型的隐藏空间中划分出一道“合规与违规”的判定边界。

然而，在高维表征空间中建立的安全边界必然存在缺陷与盲区：
1. **数据与标注的不完备性**：安全规范无法穷尽现实中多义、复杂的边缘场景，且人工标注或模型裁判之间常存在标准不一致；“有帮助（Helpful）”与“无害（Harmless）”目标在边界处也存在本质张力。
2. **越狱攻击（Jailbreaks）与对抗伪装**：攻击者利用 Base64 编码、多层角色扮演、反事实假设或外语混淆等手法，构造出远离后训练覆盖的分布外（OOD）提示词，诱导模型绕开安全护栏。这并不意味着模型内部存在单一的神秘开关，而是高维表征在未见过的复杂输入下偏离了安全超平面。
3. **评估的对称性要求**：评测集绝不能仅仅包含恶意越狱样本，**必须包含大量语义与敏感词相邻的良性样本**（如 XSTest 测试集中探讨历史、法律与科学的良性问题）。如果评测集缺乏良性对照，一个对所有请求均一律答复“对不起，我无法回答”的瘫痪模型，反而会在“安全防守率”上拿到满分。

[Constitutional AI](https://arxiv.org/abs/2212.08073) 使用明确原则指导模型生成批评和修订，并用 AI 反馈训练偏好模型，是把原则接入训练的一种方法。[Deliberative Alignment](https://arxiv.org/abs/2412.16339) 研究让模型学习并运用安全规范。两者都不能使规范覆盖无限输入，更不能替代部署环境下的独立评测；规范质量、标注质量、效用与边界都有各自的误差。

## 3. 用混淆矩阵建立可比较的评估

### 3.1 两类错误的分母不同

科学评估安全边界的前提是建立标准混淆矩阵。在此我们将“需拒绝（有害请求）”设定为正类，模型输出动作分为“拒答”与“回答”：

| 人工参考类别 | 模型拒答 | 模型回答 |
|---|---:|---:|
| 需拒绝（10） | 正确拒答 TP = 8 | 漏过 FN = 2 |
| 应回答（10） | 过度拒答 FP = 2 | 正常回答 TN = 8 |

在基准设定中，分类模型给出安全风险评分 $s\in[0,1]$，设定拒答阈值为 0.5（即评分 $s\ge0.5$ 时执行拒答）。由此可以精准定义两类条件错误率：

$$
\text{漏过率}=\frac{FN}{TP+FN}=\frac2{10}=20\%,\qquad
\text{过度拒答率}=\frac{FP}{FP+TN}=\frac2{10}=20\%.
$$

读者在此处最常见的卡点是**混淆总体拒答率与两类条件错误率**：本例中模型总体拒答率为 $(TP+FP)/N=50\%$，这一汇总指标完全无法区分模型究竟是精准拦截了恶意攻击，还是盲目误杀了正常用户。这里我们将“回答了需拒绝类别的请求”作为漏过的代理指标；在生产环境中，还需进一步对回答内容的实际安全性进行独立审核，不能仅凭形式上是否触发拒答模板做判断。[XSTest](https://arxiv.org/abs/2308.01263) 专门设计了一系列包含敏感关键词但语义完全合规的提示词测试集，其核心目的正是专门衡量系统的过度拒答率。

```academy-lab
9.2
```

- **调节参数**：拖动滑动条调节“拒答阈值”（从 0 到 1）。
- **观察量**：对比“需拒绝类的漏过率”（蓝线）与“应回答类的过度拒答率”（绿线）的反向变化走势。
- **因果机制与权衡**：保持固定评分集合不变，当我们将阈值从 0.5 提高到 0.7 时，系统只有在风险打分极高时才触发拒答。结果是应回答类的过度拒答率从 20%（2/10）迅速下降到 0%（0/10），但代价是需拒绝类的漏过率从 20%（2/10）翻倍恶化至 40%（4/10）。这直观展示了安全与可用性之间的内在权衡，模型评分并非天然校准的后验概率，不能脱离具体的错误代价盲目设定阈值。

**工程决策实战：如何选择部署阈值？**
假设线上部署流量中，恶意“需拒绝”请求仅占 1%（即基率为 0.01），其余 99% 均为“应回答”的良性业务请求。假设发生一次恶意漏过的业务危害代价设定为 1000 单位，而一次正常提问被误拒的体验损失代价为 1 单位。假设评测集测得的两类条件错误率能够泛化至线上分布：
在每 10000 次线上请求中，若采用 0.5 阈值，预期总业务代价为：
$$
10000(0.01\times0.2\times1000+0.99\times0.2\times1)=21980;
$$
若采用 0.7 阈值，虽然误拒率降为 0，但漏过率翻倍，预期总代价为：
$$
10000(0.01\times0.4\times1000+0.99\times0\times1)=40000.
$$
因此在这两个离散候选阈值中，**0.5 是更优选择**。值得注意的是，在每类各 10 条的平衡测试集上，两个阈值的总体准确率完全一致（均为 80%），但真实业务期望损失相差近一倍！
进一步假设：若线上风控升级，进入该环节的恶意请求基率降至 0.05%（0.0005），其余条件与单项代价不变。此时 0.5 阈值的预期代价变为 2999，而 0.7 阈值的预期代价降为 2000——**最优阈值的选择发生了根本反转**！完整计数与敏感性分析见[数值复算](#worked-example)。这证明：条件错误率、真实业务基率与不对称代价必须联合建模，绝不能依赖单一测试集的平衡准确率来草率定夺。

### 3.2 总体均值可能掩盖场景退化

当我们将样本切分为预先定义的两个业务场景层 G1 与 G2 时（各有 5 个需拒绝和 5 个应回答样本）：若统一采用 0.5 阈值，G1 内部的漏过率与误拒率均为 0/5（0%），而 G2 内部两类错误均高达 2/5（40%）。虽然全量聚合后的总体漏过率与误拒率看似只有温和的 20%（2/10），但这一均值完全抹杀了 G2 场景中防御严重失守的真相。

```academy-lab
9.2-strata
```

- **调节参数**：拖动滑动条调节“G2 场景的拒答阈值”（G1 阈值保持固定在 0.5）。
- **观察量**：观察 G2 子层的两类错误曲线，并与总体指标进行对照。
- **因果机制与解释**：当把 G2 阈值从 0.5 降低到 0.4 时，G2 的漏过率由 2/5 改善为 1/5，但 G2 的误拒率从 2/5 激增到 3/5；反映到总体指标上，总体漏过率降为 1/10，总体误拒率升为 3/10。**分层阈值属于局部代价的显式权衡，并不能自动带来所有维度的共同改善**。总体错误率是各层绝对错误数的样本加权，只有各层样本量严格相等时才等于算术平均。在实际部署中，必须在独立的开发集上确定分层策略，并在盲审报告中单独列出每个子场景的样本量、条件错误率与不确定性，严禁通过挑选聚合切片来粉饰薄弱环节。

### 3.3 冻结标准、独立标注、盲审核验

为了保证安全评测的客观性与可复现性，工业界沉淀出了标准化的评估与审计流水线：
1. **定义范围**：版本化行为规范、目标场景、需拒绝与应回答标签，以及边界/有分歧时的处理规则。记录采样来源与类别配比；测试集不得反复用于选阈值。
2. **冻结并隔离**：锁定待比系统、阈值及测试集；参考标签由不看系统输出的人员依据规范独立标注，疑难项预先约定复核与裁决流程。
3. **盲审答案**：对回答质量与规范遵循进行独立评估，隐藏系统身份、实验条件与其他评审意见，随机安排呈现顺序，抽查一致性和分歧；需要时由另一人裁决。对系统输出的实际内容单独判断，避免仅用关键词或拒答格式打标签。
4. **报告与回归**：给出两类分母、逐层指标、样本量、置信区间、标注分歧及适用范围，再与已冻结基线比较；记录模型和规范版本，更新后重测允许类别和拒绝类别。

这些环节降低评估偏差，但不能保证标签完全正确、样本代表未来分布或误差为零；盲审仅是证据质量控制。小样本时即便观测漏过率很低，区间也可能很宽（→ 5.4 §3）。

## 4. 数值复算：计数与统计不确定性

### 数值复算 · 聚合混淆矩阵和区间

第一组复算两个阈值方案。每个数组只含人工类别与固定分数；`s >= t` 一律计作拒答。

```python
groups = [
    {"reject": [.55, .65, .75, .85, .95], "allow": [.05, .15, .25, .35, .45]},
    {"reject": [.35, .45, .70, .80, .90], "allow": [.10, .20, .40, .50, .60]},
]
for t1, t2 in [(0.5, 0.5), (0.5, 0.4), (0.7, 0.7)]:
    missed = sum(s < t for g, t in zip(groups, (t1, t2)) for s in g["reject"])
    over = sum(s >= t for g, t in zip(groups, (t1, t2)) for s in g["allow"])
    print(f"t=({t1:.1f},{t2:.1f})  missed={missed}/10  over={over}/10")
```

**运行结果**

```text
t=(0.5,0.5)  missed=2/10  over=2/10
t=(0.5,0.4)  missed=1/10  over=3/10
t=(0.7,0.7)  missed=4/10  over=0/10
```

利用上一组计数，计算两个阈值在两种部署基率下每 10000 次请求的预期成本；这里的「平衡准确率」特指每类 10 条的评测样本。

```python
counts = {0.5: (2, 2), 0.7: (4, 0)}  # FN, FP；每类各 10 条
for base_rate in (0.01, 0.0005):
    for threshold, (fn, fp) in counts.items():
        balanced_accuracy = 1 - (fn + fp) / 20
        cost = 10000 * (base_rate * (fn/10) * 1000 + (1-base_rate) * (fp/10))
        print(f"prior={base_rate:.2%} threshold={threshold:.1f} balanced_accuracy={balanced_accuracy:.1%} cost={cost:.1f}")
```

**运行结果**

```text
prior=1.00% threshold=0.5 balanced_accuracy=80.0% cost=21980.0
prior=1.00% threshold=0.7 balanced_accuracy=80.0% cost=40000.0
prior=0.05% threshold=0.5 balanced_accuracy=80.0% cost=2999.0
prior=0.05% threshold=0.7 balanced_accuracy=80.0% cost=2000.0
```

最后：独立同分布抽样的 100 个需拒绝样本中漏过 2 个，计算双侧 95% Wilson 区间。它描述抽样误差，不能纠正漏标、样本选择偏差或相关样本导致的低估。

```python
from math import sqrt
n, errors, z = 100, 2, 1.96
p = errors / n
d = 1 + z*z/n
center = (p + z*z/(2*n)) / d
half = z * sqrt(p*(1-p)/n + z*z/(4*n*n)) / d
print(f"missed={p:.1%}  95% Wilson=[{center-half:.2%}, {center+half:.2%}]")
```

**运行结果**

```text
missed=2.0%  95% Wilson=[0.55%, 7.00%]
```

## 5. 实战判断与 2026 前沿现状

面向部署，先问规范覆盖什么，再看每个相关场景中的漏过、过度拒答及对回答内容的判定。只看总体拒答率会奖励拒答所有请求；只看需拒绝类别的漏过又无法衡量效用。出现偏差时，可先检查标签、数据覆盖和拒答阈值，再评估示范和偏好信号；后训练的变化需要在独立集合上同时比较两类错误（→ 2.2 §2.1）。

**2026 前沿现状**：公开研究已有用原则生成反馈的 Constitutional AI、让模型学习规范的 Deliberative Alignment，以及专门测过度拒答的 XSTest。公开的 [OpenAI Model Spec](https://model-spec.openai.com/) 展示了以规范约束助手行为的产品方向；一份规范并不透露每个模型的完整训练配方，也不是在任一分布上零失误的证明。[NIST AI RMF 1.0 原文](https://doi.org/10.6028/NIST.AI.100-1) 把测量与持续治理放在整个生命周期中。评估必须针对具体版本和用途更新。

## 6. 自测与迁移

1. **迁移题**：A 系统总拒答率 50%，B 系统为 70%。能否说 B 更安全？

   **答**：不能。先分别按需拒绝和应回答两类计算漏过率与过度拒答率，再评估实际回答是否违反规范；总体拒答率混合了基率和两种错误。

2. **迁移题**：两组场景各漏过 2 件，但一组有 5 个需拒绝样本，另一组有 100 个。总体直接平均组率合适吗？

   **答**：若估计这批样本的总体漏过率，应按分母加权，得到 $4/105\approx3.81\%$；分别报告 40% 与 2% 才能看到组间差异。若目标人群配比不同，还需按目标配比估计，不能把测试集配比当作部署配比。
