# 9.3 幻觉与校准：什么时候应该相信答案？

> **一句话核心直觉**：答案事实正确、置信度校准良好与选择性回答的风险—覆盖率权衡，是评估大语言模型可靠性的三个独立维度。校准度量模型“声称 80% 把握时是否确实有 80% 答对”，覆盖率决定系统敢于回答多少，选择性风险决定回答了的内容错了多少；三者必须在相同任务定义与留出数据上联合评估。
> **唤醒标签**：流畅 ≠ 真实 · 答案正确性 · ECE · Brier · 语义熵 · 自洽性 · 风险—覆盖率 · 弃答

---

## 1. 问题：模型说自己有 90% 把握，能直接信吗？

在事实问答或专业咨询场景中，大语言模型常常能以极其流畅、言之凿凿的口吻给出回答，但仔细核查却发现其中包含伪造事实、编造引用或逻辑漏洞。更令工程师困扰的是，模型不仅能生成错误内容，有时还伴随着极高的置信度——自称拥有“90% 的把握”。

为什么模型会表现得过度自信？在自监督预训练中，模型在海量文本上最小化交叉熵损失 $\mathcal{L}=-\sum \log P(x_t \mid x_{<t})$，拟合下一个 token 的条件概率。在这一目标驱动下，未归一化 logits 的相对差值被持续拉大以逼近真实标签的概率极值，导致输出概率普遍过度极化；同时语言表面上的高频共现与物理世界的客观事实并不等价。在随后的对齐（如 RLHF）中，奖励模型往往青睐那些坚定、详尽、看似有用的回复，若训练设置不当，容易对“我不确定”或“我不知道”等诚实弃答施加负惩罚，从而在一定程度上刺激了模型在知识盲区自信胡编的倾向。

评估模型的可信度，必须把问题严密拆解为三问：**答案客观上到底是对是错？模型自称有 90% 置信度的那些问题，实际正确率是否真的接近 90%？在设置置信度门槛允许系统弃答后，系统保留了多少业务覆盖率、又在保留的回答中犯了多少错误？** 两个互动实验与[数值复算](#worked-example)将基于严格固定的答案与真值，演示这三者的差异。若是开放式生成，必须预先严格定义判定标准与多种等价表达的归并规则。

## 2. 事实正确、证据支持和不确定性不是同一件事

在系统评测中，必须将三个经常被混为一谈的概念严格解耦：
1. **事实正确性（Factuality）**：生成的陈述是否符合客观世界的真实事实。模型可能完全不依赖上下文，仅靠预训练记忆撞大运答对，也可能在记忆遗忘时胡编乱造。
2. **证据支持度 / 忠实度（Faithfulness / Grounding）**：生成的陈述能否被给定的参考资料或检索文档直接推导支持。一个回答可能完美复述了一篇陈旧的过时资料（高忠实度），但在现实世界中却是错误的（低事实正确性）；反之亦然。在 RAG 检索问答系统中，必须将检索召回率、文档忠实度与端到端事实性严格分步度量（→ 8.2 §3）。评测时须界定明确的实体与时间范围，“未能验证”不可随意等同于“已证伪”。
3. **模型的不确定性（Uncertainty）**：模型自身对其输出掌握程度的概率估计。模型输出下一个 token 的 Softmax 概率仅代表其在当前上下文前缀下的预测分布，极大受到表面措辞、提示词模板、句子长度以及分词（Tokenization）切分方式的干扰，绝不能直接等同于答案事实正确的概率。整段生成的联合 logprob 也会随序列长度线性衰减。

即便所有答案在文字表达上充满自信，系统在客观上的准确率仍然可能很低。**全量准确率** $\frac1N\sum_i y_i$ 仅统计答案的对错 $y_i\in\{0,1\}$，完全不反映系统输出的概率质量 $p_i$ 是否与真实能力对齐。

## 3. 从校准到选择性回答

### 3.1 校准：按置信度分组比实际正确率

**理想校准（Perfect Calibration）** 的数学定义是条件概率的一致性：$P(Y=1\mid P=p)=p$。它的物理含义是：在模型自评置信度为 0.8 的所有预测中，长期统计下应当恰有 80% 的问题是回答正确的。校准衡量的是概率预测的可靠性，它既不等于“每个单道题目具有 80% 的正确率”，也不等于“模型的整体准确率是 80%”。

在有限评测样本中，标准做法是将预测置信度区间 $[0,1]$ 划分为 $B$ 个区间桶（箱）$I_b$，分别计算每个非空箱内的平均置信度 $\mathrm{conf}(b)$ 与实际样本正确率 $\mathrm{acc}(b)$（空箱不计入）：

$$
\mathrm{ECE}=\sum_{b=1}^{B}\frac{|I_b|}{N}\left|\mathrm{acc}(b)-\mathrm{conf}(b)\right|,\qquad
\mathrm{Brier}=\frac1N\sum_{i=1}^N(p_i-y_i)^2.
$$

- **期望校准误差（Expected Calibration Error, ECE）**：按样本数量加权计算各箱中平均置信度与实际准确率之间的绝对偏差。
- **Brier 分数（Brier Score）**：预测概率与真实标签（0 或 1）之间的均方误差。
- **读者的关键卡点**：本课中的 $p_i$ 指的是系统对“当前固定候选答案正确”这一命题给出的概率（低于 0.5 依然具有合法物理意义），并非分类任务中强制大于 0.5 的 top-1 最大类概率。ECE 极度依赖分箱数量与边界设定，且箱内正负偏差可能相互抵消；而 Brier 分数在衡量校准的同时，还能度量模型将对错样本拉开差距的分辨能力（Sharpness / Resolution）。二者必须配合可靠性图、各箱样本量与置信区间共同解读。[Guo et al.](https://arxiv.org/abs/1706.04599) 详细讨论了深度网络的校准失调与温度缩放（Temperature Scaling）校准技术。

- **调节参数**：拖动滑动条调节“置信度伸缩 $k$”（从 1 降到 0）。
- **观察量**：观察编号圆点在可靠性图中的聚合过程，同时对比 ECE 与 Brier 分数的数值变化。
- **因果机制与陷阱揭示**：我们固定 30 个回答样本（原置信度分别为 0.2、0.6、0.9 的三组各 10 题，正确数分别为 2、6、7，全量准确率为 50%）。使用 5 个等宽箱，在原始置信度下（$k=1$），ECE 为 0.067，Brier 分数为 0.217。
- 当我们将 $k$ 拖动到 0 时，变换公式 $p'=0.5+k(p-0.5)$ 将所有预测概率全部强行压缩至常数 0.5。此时所有 30 个样本全部落入中心箱，箱内平均置信度为 0.5，而数据集整体实际正确率恰好也是 50%（15/30）——**ECE 戏剧性地归零（0.000）**！
- 然而，Brier 分数却从 0.217 恶化到了 0.250！因为这种暴力压平完全剥夺了模型对简单题与难题的区分能力。这清晰证明：**单凭一个趋于零的 ECE 绝不代表系统可靠，必须结合 Brier 分数与可靠性图综合诊断**。实验中的伸缩映射仅用于揭示分箱原理，绝不是推荐的校准算法。

### 3.2 不确定性信号怎么取

为评估大语言模型的不确定性，学术界与工业界探索了多种提取信号：

| 信号 | 怎样读 | 限制 |
|---|---|---|
| token / 序列 logprob | 模型对生成序列的偏好 | 不直接等于事实正确概率，跨长度和措辞比较有偏 |
| 自评置信度 | 让系统报告答案正确性的概率 | 需独立校准，表达出来不代表可靠 |
| 语义熵 | 多次抽样后将等义答案归并，计算意义分布的熵 | 依赖采样、语义归并与问题范围，低熵也可能共同答错 |
| 自洽性 | 比较多次答案是否归为同一意义或取多数 | 样本共享偏差、错误可高度相关，一致不是正确 |

以问答“法国首都是哪座城市？”为例：在相同采样策略下生成 10 次回答，结果为“巴黎”4 次、“法国巴黎”4 次、“伦敦”2 次。
- 若直接按原始字面字符串统计类别频率，**经验答案字符串熵**为 $H_{\rm str}=-[0.4\ln0.4+0.4\ln0.4+0.2\ln0.2]=1.055$ nats；
- 但显然“巴黎”与“法国巴黎”表达的是同一个客观事实实体。将二者合并为同一语义簇后，语义簇的出现概率变为“巴黎”占 0.8、“伦敦”占 0.2，此时计算出的**经验语义组熵**为 $H_{\rm sem}=-[0.8\ln0.8+0.2\ln0.2]=0.500$ nats。
- 上述计算统计的是完整答案层面的经验频率，而非逐 token 的局部熵；分组与计算见[数值复算](#worked-example)。在这个已知真值的例子中，8/10 次采样给出了正确答案，但 0.500 nats 仅仅代表离散语义分布的香农熵，绝不等于 80% 的正确概率；哪怕 10 次采样毫无分歧（语义熵为 0），如果模型训练数据中存在共同系统性偏见，输出仍然可能一致答错。[Farquhar et al.](https://www.nature.com/articles/s41586-024-07421-0) 深入研究了语义熵作为事实生成中不确定性信号的原理；具体效果必须在自身业务分布与延迟成本约束下实测，不能从低熵直接轻率推出事实正确。

### 3.3 弃答：正确率、校准和覆盖率各管什么

在医疗、金融等高风险场景中，模型“知之为知之，不知为不知”的能力至关重要。我们可以引入**选择性分类（Selective Classification，亦称弃答机制）**：令判别变量 $a_i=\mathbf1[p_i\ge\tau]$，只有当置信度达到或超过门槛 $\tau$ 时才输出答案，否则转交人工或弃答。由此定义：

$$
\text{覆盖率}=\frac{\sum_i a_i}{N},\qquad
\text{选择性风险}=\frac{\sum_i a_i(1-y_i)}{\sum_i a_i}.
$$

如果所有样本均未达到门槛（分母 $\sum_i a_i=0$），选择性风险在数学上未定义，绝不可虚假记为 0。在工程中，我们的目标通常是在可容忍的选择性风险上限内，尽可能最大化业务回答覆盖率。然而在有限样本下，提高门槛并不保证观测风险处处单调下降；若置信度排序存在失调，风险甚至会反常升高。必须绘制完整的风险—覆盖率曲线（[Selective Classification](https://arxiv.org/abs/1705.08500)），而不是单单挑选最漂亮的某一个点汇报。

- **调节参数**：拖动滑动条调节“最低置信度”（从 0.50 到 0.95）。
- **观察量**：观察回答覆盖率（蓝线）与已回答部分的错误率（绿线，即选择性风险）随门槛的消长曲线。
- **因果机制与权衡**：在 10 个固定答案中（全量准确率为 60%）：
  - 当门槛设定为 0.75 时，系统筛选出 5 个高置信度回答输出，其中仅错 1 题：此时覆盖率为 50%，已回答部分错误率降至 20%；
  - 当门槛进一步提升至 0.90 时，系统仅回答把握最高的 2 题且全部正确：覆盖率降至 20%，观测选择性风险为 0%。
  - **核心认知警示**：在 2 道题上取得的 0% 错误率，绝不意味着系统在开放分布上的真实风险真的为零！有限样本下的经验曲线并不保证单调性；如果模型的置信度排序存在失调，提高门槛甚至可能错误地剔除对题而保留错题。在实践中，必须严格区分门槛调优集与独立测试集，全面绘制风险—覆盖率曲线，并统筹考虑人工复核成本与业务弃答的机会成本。

## 4. 数值复算：校准与风险—覆盖率

### 数值复算 · 固定答案上的两种比较

第一组计算 5 个等宽箱的 ECE 与 Brier；三组正确数和置信度都固定，变换只改置信度读数。

```python
groups = [(0.2, 10, 2), (0.6, 10, 6), (0.9, 10, 7)]
for scale in (1.0, 0.0):
    bins = [[0, 0, 0.0] for _ in range(5)]  # n, correct, sum of probabilities
    brier = 0.0
    for original_p, n, correct in groups:
        p = 0.5 + scale * (original_p - 0.5)
        b = bins[min(4, int(p * 5))]
        b[0] += n
        b[1] += correct
        b[2] += n * p
        brier += correct * (1-p)**2 + (n-correct) * p**2
    ece = sum(abs(correct - sum_p) / 30 for n, correct, sum_p in bins if n)
    print(f"scale={scale:.1f}  accuracy={15/30:.3f}  ECE={ece:.3f}  Brier={brier/30:.3f}")
```

**运行结果**

```text
scale=1.0  accuracy=0.500  ECE=0.067  Brier=0.217
scale=0.0  accuracy=0.500  ECE=0.000  Brier=0.250
```

第二组计算完整字符串与语义组的经验熵，使用自然对数、单位 nats。

```python
from collections import Counter
from math import log
answers = ["巴黎"] * 4 + ["法国巴黎"] * 4 + ["伦敦"] * 2
meaning = {"巴黎": "巴黎", "法国巴黎": "巴黎", "伦敦": "伦敦"}
for name, counts in [("strings", Counter(answers)),
                     ("meanings", Counter(meaning[x] for x in answers))]:
    entropy = -sum((count/len(answers)) * log(count/len(answers))
                   for count in counts.values())
    print(f"{name}: {entropy:.3f} nats")
```

**运行结果**

```text
strings: 1.055 nats
meanings: 0.500 nats
```

第三组计算门槛改变后的回答覆盖率与条件错误率；比较使用同一组固定答案。

```python
answers = [(.95, 1), (.90, 1), (.85, 0), (.80, 1), (.75, 1),
           (.70, 0), (.65, 1), (.60, 0), (.55, 1), (.50, 0)]
for threshold in (0.50, 0.75, 0.90):
    answered = [correct for p, correct in answers if p >= threshold]
    coverage = len(answered) / len(answers)
    risk = sum(1-correct for correct in answered) / len(answered)
    print(f"threshold={threshold:.2f}  coverage={coverage:.1%}  risk={risk:.1%}")
```

**运行结果**

```text
threshold=0.50  coverage=100.0%  risk=40.0%
threshold=0.75  coverage=50.0%  risk=20.0%
threshold=0.90  coverage=20.0%  risk=0.0%
```

## 5. 实战判断与 2026 前沿现状

部署时先定义答案正确与证据支持的标注，再测总体准确率；把答案固定，用留出数据校准其正确性概率，报告可靠性图、箱数和 Brier；最后在**另一份**评测数据上报告完整风险—覆盖率曲线及分层样本量。校准可以改变概率读数而不改变答案；只改变门槛可以改变回答子集，但不能声称提高了原始全部答案的准确率。模型重训、提示、工具、问题难度或用户群变化都可能使原校准失效，应重新评测。

**2026 前沿现状**：公开研究已把多次采样和语义归并用于检测部分事实性错误，工具调用或检索也能提供外部证据；它们都依赖验证器、来源与任务。OpenAI 的 [Why language models hallucinate](https://openai.com/index/why-language-models-hallucinate/) 讨论了评测中猜测比承认不确定更易得分的激励。相关方法提供改进方向，不保证模型自评、检索结果或一致答案必然正确；用独立事实依据和实际分布检验。

## 6. 自测与迁移

1. **迁移题**：两个模型答对率都为 70%；A 的 0.9 置信箱实际正确率 90%，B 的同箱正确率 60%。能说 A 全面优于 B 吗？

   **答**：不能。只知 A 在这个箱中更接近校准；还需看其他箱、样本数与置信区间、整体正确率的任务构成、Brier，以及选择性风险和覆盖率。单箱结果不能推出全面排序。

2. **迁移题**：新校准器让 ECE 从 0.07 降到 0，却把所有置信度设为数据集总体正确率。应立即上线吗？

   **答**：不能只根据 ECE。常数预测能在总体上校准却丢失题目间区分能力；应在独立数据比较 Brier、可靠性图及风险—覆盖率，并检查分层和数据漂移。是否上线还取决于业务对错误和弃答的代价。
