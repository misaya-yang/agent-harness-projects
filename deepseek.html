CHAPTER 01 · CORDIS COMPOSITION

先看插件树：运行时不是一个不可替换的“大循环”。

DeepSeek Harness 把模型适配器、Prompt、Tools、Session、持久化和 Agent Loop 都挂到 Cordis Context。扩展行为优先新增或替换插件，而不是修改 Loop。

SOURCE ROUTE · DEEPSEEK HARNESS b150a55

先读四个入口，再操作下面的插件责任探针。

四处源码分别回答“配置怎样变成树、谁驱动任务、历史写在哪里、工具怎样执行”。

  1. packages/boot/app-boot/src/profile.tscomposeEntries 按层应用 Bundle 与 Patch，得到有效插件列表。
  2. packages/core/agent-loop/src/agent.tsReactLoopAgent.turn / step 打开 Turn、执行 Step 并决定是否继续。
  3. packages/core/session/src/index.tsSession.append / deriveMessages 保存事实并投影模型历史。
  4. packages/core/tools/src/index.tsToolRuntime.execute 进入 pre、guard、execute、post 与最终结果管线。

学完本章你能：看到一个症状后，先问“哪个插件、哪类事件、哪个服务拥有它”，而不是直接改 Agent Loop。

CHAPTER 02 · TURN / STEP LOOP

一个 Step 是一次模型请求和它触发的工具；一个 Turn 可以有多个 Step。

输入进入持久 Inbox，Loop 先记录 Turn，再组装 Prompt、读取日志、发起流式请求、执行工具并回注结果；只有没有欠下的工作时 Turn 才结束。

Turn / Step 事件步进机idle
  1. turn/start
  2. claim inbox
  3. step/start
  4. user/message
  5. request/header
  6. assistant/chunk*
  7. assistant/message
  8. tool/call → result
  9. step/end → turn/end

逐步观察“活的控制”怎样留下“持久事实”。

CHAPTER 03 · SESSION EVENT LOG

Session Log 记录事实；模型历史和 UI 都是它的投影。

assistant/chunk 保留流式与回放证据，却不直接进入模型历史；user/message、非空 assistant/message 与 tool/result 才成为可见节点。

CHAPTER 04 · PROMPT & REQUEST

每个 Step 都重新组装 Prompt，但请求必须能从日志重建。

SystemPrompt.assemble() 收集 sections、contexts、tool schemas 与 variables；buildRequest() 绑定精确 Provider generation，记录 header/context，再从 deriveMessages() 构造 frozen request。

CHAPTER 05 · TOOL PIPELINE

模型只提出调用；工具结果要穿过有序策略后才成为权威事实。

调用先记录 tool/call，再经过 pre-execute、审批与 monotonic guard、execute、工具 body、post-execute、内容收口，最后同步通知并记录唯一 model-facing result。

CHAPTER 07 · SANDBOX & APPROVAL

Sandbox 限制文件效果；Approval 决定能否获得一次人工决定。

文件模式只有 read-only、workspace-write、danger-full-access。无可用本地 runner 时 confined mode 失败关闭，不降级为未隔离；审批没有 answerer 时也返回 unavailable。

CHAPTER 08 · PROFILE / BUNDLE / PRESET

Profile 组合进程；Preset 组合一个 Agent 的能力面。

Profile 把 Bundle、用户 Patch 与启动 Patch 叠成全局插件树；Preset 在 Agent scope 下挂载 per-session 组合。已有输出的 Agent 不能随意 recompose，否则日志中的旧工具可能失去解释。

CHAPTER 09 · CONTEXT & COMPACTION

Compaction 是带锁、校验和 Surface Replacement 的事务。

系统先在稳定日志上选区与生成摘要，再验证选区未被异步工作改变，最后用有 provenance 的 replacement 落地；原始事件仍留在日志中。

  1. 触发：pre-step 压力或 canonical context overflow。
  2. 锁定：append compaction/start，阻止同范围重入。
  3. 选区：保留近期 tail，不切断 tool call / result 配对。
  4. 摘要：复用 request system/tools，生成 text-only checkpoint。
  5. 验证：whole-surface 或 selected-span 必须仍稳定。
  6. 替换：追加 summary 与 replacement，再 compaction/end。
DO NOT SAY “DELETE CHAT”

Tool-result pruning 同样通过 shadow price 与 Surface replacement 降低模型成本；它没有从 append-only log 中抹掉原始结果。

CHAPTER 10 · EXTENSION RUNTIME

Skills、Web、Subagent、Workflow 与 Hooks 都是独立能力，不是 Loop 特例。

每个扩展通过自己的 Service 或事件加入组合；Dynamic Cordis 还能在 opt-in 运行时定义和切换临时 Package，但它的 VM 不是恶意代码安全边界。

LEARNSkills

Provider-neutral catalog 与 loader tool，把流程知识带入当前 Agent。

ACCESSWeb

Search / fetch Provider 可替换，tool-web 只消费 ctx.web。

DELEGATESubagent

one-shot 或 continuable child；Provider 决定进程与产品边界。

ORCHESTRATEWorkflow

worker thread 隔离事件循环，不构成安全隔离。

INTERCEPTHooks

把外部 hook 协议桥接到 pre-step、tools 与 turn-stopping。

SELF-MODIFYDynamic Cordis

临时 Package 仅存当前进程；VM 受限但明确不是恶意代码安全边界。

POC / OPT-IN包存在，不等于当前 Profile 已挂载。E2B 是 provider-composition POC；Dynamic Cordis 是 deliberate opt-in。任何部署结论都应先读取有效插件树。

CHAPTER 12 · PRACTICE & INTERVIEW

用“组合、事件、能力、证据”解释一个 Agent Harness。

真正掌握 DeepSeek Harness，不是背 package 列表，而是能从有效树找到拥有者、从日志重建状态、从能力缝解释 Provider 替换，并清楚指出 POC 与安全限制。

五步诊断法

先 dump 有效 Profile；再确认 Agent 的 Preset 与 scope；沿 turn/step/session events 找最后一个持久事实；把失败归到 Prompt、LLM、Tool、Provider 或 Policy；最后用一个能推翻假设的最小实验验证。

90-SECOND ANSWER

“DeepSeek Harness 为什么说 everything is a plugin？”

展开答题骨架
它用 Cordis Profile 把插件行组合成 Context：Agent Loop、Session、Prompt、Tools、LLM 和持久化都由服务与事件连接。一次 Turn 由多个 Step 构成，模型输入从 Session Log 投影，工具经过可插拔策略管线后把唯一结果写回日志。Definition / Provider / Consumer 让本地、沙箱或远程执行世界可替换，Web、Headless、ACP 与 SDK 只是不同入口。因此新能力优先新增插件或 Provider，而不是修改 Loop。
Plugin Tree
Profile、Bundle 与 Patch 组合出的有效 Cordis entry 树。
Turn / Step
Turn 是完整用户工作；Step 是一次模型请求及其工具批次。
Session Event
append-only、可持久化和可投影的运行事实。
Surface
从事件序列维护的当前可见消息节点集合。
Capability Seam
Service Definition、Provider 与 Consumer 的完整可替换能力。
Preset
挂在 Agent scope 下的 per-session 插件组合。
Waterfall
监听器必须调用 next 才继续的可拦截事件链。
Compaction
对稳定日志区间生成摘要并以 replacement 更新 Surface。
