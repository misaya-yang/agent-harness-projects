CHAPTER 01 · RUST ARCHITECTURE

先找到拥有问题的 crate，再谈 Agent 能力。

Grok Build 不是单体 CLI。组合根把 TUI、Shell、Agent、Tools 与 Workspace 接成一条可替换的运行管线；共享协议和事件 crate 则把边界稳定下来。

五个责任层

Pager 负责全屏终端与交互；Shell 承载 Session、采样和持久化；Agent 组装模型、工具与系统提示；Tools 管注册、schema、通知和实现；Workspace 拥有文件系统、VCS、进程、权限与检查点。

ROOT-CAUSE LENS

显示错位查 Pager；回合卡住查 Shell；工具不存在查 Agent/Registry；命令状态错查 Workspace。分层的价值，是让故障有唯一首要归属。

  1. xai-grok-pager：scrollback、prompt、modal 与渲染。
  2. xai-grok-shell：Session host、sampling、compaction、events。
  3. xai-grok-agent/tools：提示词、工具能力与调用桥。
  4. xai-grok-workspace：真实世界副作用与恢复点。

CHAPTER 02 · TURN RUNTIME

一次回合，是 Actor、采样与工具执行反复咬合。

每个 Session 运行在独立线程的 Tokio LocalSet 上：SessionActor 负责编排，ChatStateActor 持有 conversation、token 与 prompt index，Persistence actor 异步落盘。模型若返回 tool call，循环执行并回注，直到 stop reason 收敛。

循环中的控制点

每次采样前，系统可能注入项目规则、Skills、Memory 与系统提醒；采样过程中发出消息 chunk、thinking 与 tool call；工具完成后结果进入下一次采样。取消、steer、compact 都在安全间隙改变循环，而不是任意撕开状态。

  1. 接收 prompt，写入 Session history。
  2. 构造 Agent 能力与采样请求。
  3. 流式接收消息、思考与工具调用。
  4. 执行工具并回注，判断继续或结束。
Grok 回合步进机idle
  1. prompt 入会话
  2. 装配 Agent
  3. 构造 sampling request
  4. 流式模型事件
  5. 解析 tool call
  6. 权限与执行
  7. 结果回注

CHAPTER 03 · ACP & EVENTS

ACP 是客户端边界，SessionUpdate 是可观察事实。

编辑器通过 Agent Client Protocol 启动或加载 Session、发送 Prompt、接收 AgentMessageChunk 与 ToolCallUpdate；Grok 自己的扩展通知再承载 rewind、compaction、pending interaction 等专有状态。

CHAPTER 04 · TOOL REGISTRY

工具不是函数集合，而是动态裁剪后的能力视图。

AgentBuilder 选择工具，ToolRegistry 保存定义与实现，ToolBridge 把模型调用转换为受控执行；schema 校验、名称映射、通知、重试与输出归一化分属不同责任。

从定义到结果

模型看见的是 schema 和模型侧名称；运行时保留 canonical identity。调用先验证参数和可见性，再经过 ToolCallContext、权限与实现，流式输出被归一化为可持久化、可展示、可回注的结果。

FAILURE ORDER

未发现 → 查 allowlist/denylist；参数错 → 查 schema；执行错 → 查实现与 Workspace；UI 不更新 → 查 ToolNotification；模型误判 → 查归一化后的结果。

  1. Registry：工具身份、定义、实现与索引。
  2. Bridge：把采样返回的调用接入运行时。
  3. Context：call ID、session、取消与执行元数据。
  4. Output：流式片段、错误类型与截断策略。

CHAPTER 05 · WORKSPACE

Workspace 才是副作用的拥有者。

Shell 不直接假装自己执行了命令。Workspace 封装文件、终端、VCS、MCP、工作树、权限和会话上下文，使本地与远程执行共享工具契约。

Handle / Hub

工具调用必须带已绑定的 Session，才进入该会话的 FinalizedToolset。

Filesystem / VCS

读取、编辑、状态、diff、worktree 与文件快照。

Process Manager

前台命令、长任务、日志、BackgroundHandle 与取消。

Checkpoint

按 prompt index 记录 FS 与可选 hunk/git 状态；rewind 按顺序恢复。

CHAPTER 06 · PERMISSIONS & SANDBOX

审批决定信任，沙箱限制能力。

Grok 的 permission manager 处理 allow once、记住特定动作、全局允许与拒绝；sandbox 再从操作系统层约束命令。配置按 managed → user → GROK_CONFIG overlay → requirements/MDM 合并，最上层可以钳制更低层，overlay 只允许软设置且不能越权。

CHAPTER 07 · SESSION STATE

Session 是可持久化、可派生、可回退的工作记录。

会话不仅保存聊天文本，也包含工具调用、文件编辑、任务状态与扩展通知。resume 从 updates.jsonl 复放历史；fork 可按 prompt index 复制并截断 chat、updates、summary 与压缩点；rewind 支持只回对话、只回文件或两者同时。

CHAPTER 08 · CONTEXT & COMPACTION

压缩不是删聊天，而是 full-replace 一份可继续工作的状态。

Grok 估算上下文占用，当前默认配置在 85% 附近触发自动 compact；专用 sampler 生成摘要，系统写入 segment 与 checkpoint，再整体替换 conversation。恢复时同时复放 ACP 和 Grok 扩展事件；两阶段预压缩是可选特性。

CHAPTER 09 · EXTENSION SYSTEM

Rules 定方向，Skills 教流程，MCP 给能力，Plugins 打包分发，Hooks 做确定性拦截。

五者都能改变 Agent，但作用层不同。Skills 按 local cwd → repo → user → configured → server → bundled 覆盖；Plugins 默认禁用且项目来源受 folder trust；Hook 只有显式 deny 才阻断，执行失败默认 fail-open。

CHAPTER 10 · AGENT BUILDER & SUBAGENTS

Agent 是可移植的能力包，子代理是派生 Session。

AgentBuilder 发现 Skills、裁剪工具、注入 Memory/Plan/Task 能力并渲染 prompt。`task` 默认后台运行，状态由单写者 coordinator 管理；当前默认最大嵌套深度为 1，隔离可选 shared workspace 或 worktree。

定义的四个旋钮

promptMode 决定扩展基础模板还是完全接管；tools/disallowedTools 决定能力面；permissionMode 决定授权交互；completionRequirement 让编排 worker 必须显式提交完成。

DISCOVERY

项目 `.grok/agents/` 可覆盖 built-in，用户或 bundled 同名定义不能覆盖 built-in；最终可见集合还受 `[subagents.toggle]` 过滤。规则发现兼容 AGENTS.md、CLAUDE.md 等多种文件名。

  1. 解析 frontmatter 与系统提示正文。
  2. 组装基础模板、项目规则与 Skills。
  3. 裁剪工具、模型和 permission mode。
  4. 派生隔离 Session，返回结果给父代理。

CHAPTER 11 · EXECUTION SURFACES

同一运行时，服务五种不同控制面。

全屏 TUI 面向人类协作；headless 输出 plain、JSON 或 NDJSON；`agent stdio` 通过 ACP 嵌入编辑器；serve 提供本地 WebSocket；leader 模式复用常驻进程。入口不同，但内核边界应保持一致。

CHAPTER 12 · PRACTICE & INTERVIEW

用“边界、事件、证据”回答系统设计题。

真正掌握 Grok Build，不是记住 crate 名，而是能从症状定位拥有层、从事件重建状态、从安全边界解释为什么某次行动被允许或拒绝。

五步诊断法

先复现并标记 Session/turn 边界；再判断是入口、Shell、Agent、Tool 还是 Workspace；沿 ACP/XAI update 与 ToolNotification 找最后一个可靠事实；核对权限、沙箱与取消状态；最后用最小测试锁住 owning layer。

SOURCE BOUNDARY · 2026-08-23

本课基于本地 `grok-build` 开源快照及其随仓用户指南。协议、模型目录、默认配置和实验性模块会变化；具体部署应以当前 `SOURCE_REV`、源码与官方文档为准。

  1. 谁拥有状态？Session 还是 UI？
  2. 谁拥有副作用？Tool 还是 Workspace？
  3. 哪个事件证明动作已经发生？
  4. 恢复靠 replay、checkpoint 还是重新推理？
  5. 安全由 permission、sandbox 还是 org policy 控制？
