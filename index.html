CHAPTER 01 · TURN LOOP

先看循环，而不是“智能”。

Agent 的能力不是一团魔法，而是一个可观察、可中断、可审计的回合循环。掌握它，你才知道错误发生在哪一层。

心智模型

一次回合不是一次模型调用。它从用户输入入队开始，经过上下文组装、流式响应、工具判定、受控执行与结果回注，直到模型不再请求工具才收敛。

ROOT-CAUSE LENS

把故障归到拥有它的层：模型选错工具、策略拒绝权限、执行环境失败、还是结果没有正确回注。不要把所有失败都叫作“模型不行”。

  1. 提交：输入变成可追踪的操作。
  2. 推理：模型读取上下文并选择下一步。
  3. 行动：工具在权限与沙箱边界内执行。
  4. 回注：结果进入历史，驱动下一次判断。

CHAPTER 02 · EVENT PROTOCOL

把 UI 与内核之间的对话，读成一条事件河流。

Submission 向内核提交意图，Event 向外报告事实。区分命令与事实，是流式界面、恢复机制和审计能力的共同起点。

双向协议

向内的是请求，向外的是证据。界面不应该猜模型是否正在执行工具；它只消费内核发出的开始、增量、审批、执行结果与完成事件。

这套边界让 CLI、桌面端和服务端可以共享同一个内核，而各自拥有不同的呈现与持久化策略。

  1. Submission：用户输入、审批决定、中断与配置更新。
  2. Event：阶段变化、内容增量、工具生命周期与计量。
  3. 可恢复性：状态从事实重建，而不是从界面猜测。

CHAPTER 03 · TOOL LIFECYCLE

工具不是插件列表，而是一条受控执行管线。

模型只提出结构化调用；系统负责发现、校验、授权、执行、截断输出与回注。每个环节都有自己的失败模式。

六个检查点

先确认工具是否对当前回合可见，再校验参数；之后权限策略与沙箱共同决定能否执行。执行结果需要保留退出码、标准输出与标准错误，最后包装成模型能继续推理的结果。

DEBUG ORDER

工具未出现 → 查注册与能力；调用参数错 → 查 schema；执行被拒 → 查审批与沙箱；命令成功但回答错 → 查输出截断和结果回注。

  1. 发现：当前身份与作用域可见哪些工具。
  2. 校验：参数是否符合结构化契约。
  3. 授权：能力与策略是否允许。
  4. 执行：在限定环境中启动并采集结果。
  5. 归一化：保留诊断，控制体积。
  6. 回注：让模型基于事实继续。

CHAPTER 04 · SAFETY BOUNDARIES

沙箱回答“能不能”，审批回答“要不要问”。

把两者混在一起，就会出现既难解释又难测试的权限逻辑。先判定操作落在哪个边界，再决定是否允许用户升级授权。

    CHAPTER 05 · CONTEXT ENGINEERING

    上下文不是“聊天记录”，而是一份有预算的工作集。

    系统指令、项目规则、用户输入、工具输出与摘要争夺同一个窗口。真正的工程问题是：留下什么、压缩什么、何时让缓存前缀保持稳定。

    预算与信息密度

    窗口越大，不等于每个 token 都同样有用。长日志、重复工具输出和过期分支会稀释关键约束。压缩的目标也不是“变短”，而是保留下一步决策所需的状态、证据与未完成工作。

    1. 长期规则、当前目标、关键决定、验证证据。
    2. 已完成步骤、重复输出、可从文件重读的细节。
    3. 无关分支、过期假设、没有影响后续的噪声。

    CHAPTER 06 · PLATFORM RUNTIME

    生产平台不重写内核，它包住内核。

    HTTP 生命周期、能力、审批、工具、事件存储与签名租约形成控制面；Codex 回合循环仍是模型平面。清晰的所有权边界决定系统能否演进。

    CHAPTER 07 · PRACTICE & INTERVIEW

    把架构知识变成诊断顺序。

    真正有用的掌握，不是能背组件名，而是面对失败时知道先看哪一条证据、归属哪一层、做哪一个最小实验。

    三轮练习

    1. 观察：用事件流描述“发生了什么”，不先解释原因。
    2. 归因：把现象映射到模型、工具、策略、环境、状态或平台层。
    3. 验证：设计一个能推翻当前假设的最小检查。
    60-SECOND ANSWER

    如何解释一个生产级 Agent 的核心循环？

    展开参考答案
    它是一个事件驱动、可中断的控制循环：组装受约束上下文，流式调用模型，解析结构化工具请求，经能力/审批/沙箱执行，把规范化结果回注，直到模型收敛。外围平台负责身份、生命周期、持久化与租约，内核负责单轮推理与行动。

    速查术语

    Submission
    进入内核的操作：输入、审批、中断或配置更新。
    Event
    内核向外报告的事实：增量、工具状态、完成与计量。
    SandboxPolicy
    操作系统边界：进程实际能读、写或联网到哪里。
    ApprovalPolicy
    交互策略：遇到边界时何时询问、拒绝或直接放行。
    Compaction
    把旧历史折叠成保留关键状态的摘要，释放上下文预算。
    Lease
    短期、可验证、绑定作用域的能力凭据。
