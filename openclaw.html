ONE GATEWAY · THREE LOOPS · DURABLE EVIDENCE

让 Agent 活过很多天，也不靠死循环烧钱。

OpenClaw 不是“一条永不结束的 while”。它让常驻 Gateway 保存连接与状态，让三层循环各管一段生命，再用缓存、压缩、异步投递和预算闸门控制成本与风险。十二章都从一次具体事故出发：先听懂，再判断，最后动手验证。

  • 用一条短 trace 判断故障属于 turn、logical prompt 还是 attempt
  • 解释 cache、compaction、replay、memory 四者为什么不能混用
  • 设计可恢复的子代理异步完成通知，而不把 accepted 当结果
  • 用预算、事件和副作用证据决定重试、换路或立即停下

COURSE MAP · ONE SYSTEM, FOUR QUESTIONS

读完不是“知道很多名词”，而是会回答四个运行问题。

活在哪里常驻 Gateway

连接、会话、审批与事件投影由一个长活控制进程承接；模型与工具只是被它调度的工作面。

为什么继续三层循环

内层处理模型与工具，中层决定逻辑任务是否续跑，外层为失败 attempt 选择重试、轮换或终止。

怎么不失忆事件树与检索记忆

原始转录追加保存；压缩只生成快照边界；长期事实按需检索，不把全部历史硬塞进每次请求。

怎么不失控预算与证据

时间、尝试、深度、宽度、字符量各有主人；存在副作用且结果不确定时，默认不盲目重放。

开课检查：如果你能在一句话里区分 Gateway、session、turn、attempt，就可以进入第一章；如果不能，先记住它们分别是“总管、会话、一步、一次尝试”。

CHAPTER 01 · THREE OWNERS OF CONTINUE

事故：模型已经停了，任务却又跑了一轮。到底谁按了“继续”？

答案不是一个大循环。OpenClaw 把继续权拆给三个层次，每一层只回答一个问题。

LEARNING ROUTE · SAY IT WITHOUT CODE

白话模型：做一步、接着做、换一种方式做。

  1. turn 循环：模型要不要调用工具，工具结果要不要再交给模型。
  2. logical prompt 循环：这条用户请求是否因排队输入、恢复或压缩继续。
  3. attempt 循环：provider、凭证或模型失败后，是否换一个候选再试。
attempt → logical prompt → turn → tool results → turn end → settle / continue

判断法：看到 tool call 就先想内层；看到压缩或排队输入就想中层；看到换凭证、换模型和重试预算就想外层。

本章过关：任选一次“多跑了一轮”的故障，给每层各写一个可能原因，并指出真正拥有终止权的是哪一层。

逐步观察一条消息怎样穿过三层循环再回到等待。

DON'T FLATTEN THE STACK“没有 maxTurns”不等于“没有边界”。内层靠语义停止，中层靠收束裁决，外层靠预算与断路器。边界分散是为了让每次停止都能说明原因。
CHAPTER 02 · INTERRUPT WITHOUT BREAKING HISTORY

事故：用户中途改主意，旧工具没启动，却让下一轮请求因“缺少结果”报废。

插话不是粗暴杀进程。它必须在未启动动作前生效，同时保住每个 tool call 都有对应结果。

先用白话分清三种消息

steering 是“现在改方向”，在下一个安全检查点消费；follow-up 是“做完当前事再做”，在自然停点消费；next turn 随下一条普通用户轮进入。

queue → checkpoint → 已启动的收尾 → 未启动的生成 skipped 结果 → next turn

关键不变量：插话可以改变未来，不能假装过去没发生。已经启动的副作用要收结果；被跳过的调用也要有可审计的合成结果。

SETTLE CHECK

内核发出结束事件，只说明本轮模型与工具停了。会话层仍要判断移交、中止、恢复、压缩和排队消息。全部否定才真正 settled。

收束裁决机idle
  1. 是否移交
  2. 是否中止
  3. 错误能否恢复
  4. 恢复是否耗尽
  5. 是否需要压缩
  6. 是否还有排队消息

选择场景，观察短路顺序如何决定 settled、continue 或 handoff。

本章过关：画出“用户在并行工具批中段插话”的六步 trace，并明确哪些调用继续、哪些调用 skipped、为什么不能直接删掉 call。

CHAPTER 03 · THE PROCESS DIED, THE TASK DIDN'T

事故：Gateway 重启后，内存计数全没了。助理凭什么知道做到哪一步？

恢复的依据不是“进程记得”，而是可重放的持久事件、明确边界和对未知结果的诚实标记。

  1. 转录是事件树：消息、状态变化和分支按追加顺序保存，当前 leaf 决定活跃路径。
  2. 压缩不抹历史：它追加新的投影边界，原始事件仍可审计与回滚。
  3. 重启先辨类型：计划内重启有 sentinel；意外中断靠 recovery claim 与持久状态恢复。
  4. 缺结果就是未知：被中断工具不能自动算成功，也不能假设安全重跑。
persisted event → restart claim → rebuild active branch → mark interrupted outcome unknown → decide resume

CHAPTER 04 · FOUR THINGS CALLED MEMORY

事故：团队把 cache、compaction、replay 和 memory 当成一回事，结果越优化越贵。

它们分别解决重复计费、窗口太满、进程恢复、跨会话找事实。混淆问题，就会选错机制。

机制它真正保存或改变什么判断问题
Cache复用字节相同的稳定请求前缀；动态运行时状态在边界之后。前缀变了吗？
Compaction用摘要边界替代旧历史的模型视图，同时保留最近尾巴和原始事件。窗口要满了吗？
Replay从持久状态重建请求；前缀相关状态必须失效或刷新。能安全重建吗？
Memory长期事实进入检索语料，按需 search/get；耐久内容再经来源与预算门晋升。需要哪条旧事实？
stable prefix | CACHE BOUNDARY | dynamic context → budget → retrieve / compact → provider

缓存边界是一条性能 API：工具目录、规则与稳定工作区上下文尽量保持字节一致；日期、审批状态、通道能力和子任务事件放到易变区。运行时载体还会被移到请求尾部，让变化发生在本来就要追加的地方。长期记忆则用混合检索与多重门槛控制晋升，避免一次偶然提及永久污染未来会话。

CHAPTER 05 · SLEEP IS THE DEFAULT

事故：助理今天没主动工作。它是坏了，还是根本没有收到唤醒事件？

长期存活不是持续烧 token，而是让状态睡在账本里，在消息、自动化或心跳到来时短暂启动有界 run。

AUTOMATION精确时机

CHAPTER 06 · RETRY IS A SAFETY DECISION

事故：一次 429 被多层重试放大；更糟的是，消息已经发出却又被重复发送。

先分类，再检查副作用，最后只消耗属于当前层的预算。重试不是“再来一次”，而是安全判决。

  1. 先分流：provider/传输失败走 failover；工具失败通常变成模型可见的错误结果。
  2. 预算分账：单请求、run 内 attempt、跨 run 探测、凭证冷却各有独立主人。
  3. 墙钟优先：瞬时错误受次数和时间窗共同限制；服务端等待建议是下界。
  4. 副作用封闸：已发消息、已建计划、已 spawn 孩子或结果可能已被消费时，不能证明安全就停止 replay。

CHAPTER 07 · COMPACT WITHOUT LYING

事故：摘要说压缩成功，窗口却没释放；下一轮又压一次，成本进入死循环。

安全压缩不是删聊天，而是在事件树上追加可回滚快照，并用确定性旁路保护摘要易漏事实。

TRIGGER三种入口

回合后超过阈值、overflow 后压缩再试、请求前预检。每条路径都有防环条件。

CUT原子切点

切点不能落在 tool result；工具调用与对应结果必须一起保留或摘要。

SUMMARY分块再合并

大历史先规划原子块，分别摘要，再合并成固定结构的交接文本。

SIDECAR机械事实旁路

文件操作与未决请求由程序提取，不把全部正确性押给 LLM。

choose cut → group atomic tool batches → summarize chunks → merge → append boundary → sanitize replay state
SNAPSHOT, NOT DELETION原始转录仍在，模型视图变小。新视图由边界摘要、最近尾巴与新消息构成；旧前缀绑定状态必须刷新或保全。

本章过关：给出一个 tool call 后跟两个 tool results 的序列，画出两个非法切点和一个合法切点。

CHAPTER 08 · COMMIT WHEN EXECUTION REALLY STARTS

事故：五个工具并行提交，第三个被拒绝，后两个却已产生副作用。

并行安全靠“检查 → 提交 → 进入实现体”紧邻发生；否决只砍尚未启动的尾部。

工具派发的四条硬规则

  1. 默认可并行，任何串行声明可让 batch 降级。
  2. 每个调用真正启动时才 commit。
  3. 同一真实目标的写操作串行，不同目标仍并行。
  4. 工具抛异常，循环统一塑形成错误结果。
for call in batch: guard(call) → commit(call) → execute(call) → outcome hook
LARGE TOOL SET

工具太多时可用搜索、目录或受限代码发现，按名字需要时再水化。目录指纹稳定还能避免无意义破坏缓存前缀。

RESULTS HAVE A BUDGET工具结果也是上下文成本。单条、同批聚合和历史回收应分别限量；截断要保留诊断尾部，不能静默丢字。

本章过关：为“同一文件两次写、另一文件一次读”的 batch 排出并行与串行次序，并标出 steering 能阻止哪些动作。

CHAPTER 10 · FOUR INDEPENDENT DEFENSES

事故：命令通过 allowlist，却借解释器内联代码做了完全不同的事。

安全不是一个允许/拒绝按钮，而是容器、路径、审批、出站网络四道各自成立的防线。

SANDBOX容器与配置守卫

危险挂载、host 网络和弱化隔离配置应在创建前拒绝。

PATH词法 + realpath

目标先规范化，再沿已存在祖先解析真实路径，抵御符号链接逃逸。

APPROVAL决策流

命令语义、allowlist、询问策略和一次性授权共同决定 host 执行。

NETWORKDNS pinning

先校验解析 IP，再用同一 IP 建连；跨域跳转剥离敏感 header。

危险 shell 的闸门链闸门 0/6 · idle
  1. 消息进 Gateway
  2. agent 提案工具调用
  3. 审批策略裁决
  4. 审批转发进通道
  5. 用户给出决议
  6. 执行或拒绝并回填

逐闸门推进，观察危险命令由谁裁决、结果如何回到循环。

TRUST BOUNDARY

拒绝也必须成为模型可见的错误结果，明确未执行、不要原样重试。错误对象和网络错误文本本身也不可信：可信凭证应由宿主对象身份证明，错误内容要截断、脱敏并隔离。

本章过关：解释为什么“命令第一词在 allowlist”不足以放行解释器，并为审批超时、明确拒绝、通道断线分别写终局。

CHAPTER 11 · ACCEPTED IS NOT THE RESULT

事故：父代理收到 accepted 就宣布完成；孩子稍后失败，结果再也没人接。

子代理是持久会话。spawn 只创建任务，真正结果由异步 announce 状态机送回。

announce 的最短 trace

spawn accepted → durable child → terminal lifecycle → claim → bounded capture → announce / outbox → parent wake

父回合活跃时，完成事件可作为 steering 注入；父已让渡或空闲时，系统聚合同一波完成并唤醒新回合。投递使用幂等身份、租约、退避和持久 outbox；送达不确定时进入可重试状态，不伪造成功。

CAPABILITY FLOWS DOWN

默认只允许一代子代理、每父会话限制活跃孩子；异步准备前先预留名额。深度、角色与工具天花板写入持久状态，提示词不能扩权。

PLUGIN提供能力

通道、模型、工具、harness 等扩展先读 manifest 再惰性加载代码。

SKILL教授方法

以提示词资产描述工作流与依赖，不等同于插件权限。

HARNESS替换运行时

外部运行时显式声明支持范围、宿主能力与回退。

SOUL塑造声音

人格影响表达，不改变持久化准入、控制域或工具权限。

COST BOUNDARY并发上限不等于 token 预算。浅深度、孩子数、lane 宽度和超时给出乘法上界，但核心链路没有统一 token/成本熔断；提高递归深度时必须另做治理。

本章过关：设计父代理并发委派三项检查的流程，必须包含 accepted、yield、终态证据、批量唤醒与去重策略。

CAPSTONE · FIVE-PASS TRIAGE

一张表完成第一次故障分诊

展开诊断模板

1. 定层：连接/Gateway、attempt、logical prompt、turn/tool、投递或持久状态？

2. 找事件：最后确认事件是什么，缺口发生前还是发生后？

3. 对预算：哪个 owner 在计费，次数、墙钟、并发还是字符预算触顶？

4. 查副作用：消息、计划、spawn、文件写是否已提交或结果不明？

5. 验证恢复：用最小操作证明是继续、换路、显形报错还是安全停止。

比较稳定前缀是否变化；再看运行时载体是否位于边界后和请求尾部；检查工具目录指纹；最后区分缓存失效、消息预算不足，还是确实需要 compaction。

一次模型响应及其工具结果；只知道当前请求与工具批。
logical prompt
围绕一条请求的续跑区间，可因恢复、压缩或排队消息包含多个 turn。
attempt
外层针对 provider、凭证与模型组合的一次运行尝试。
cache
复用未变化的请求前缀；不等于保存全部对话。
compaction
追加摘要边界，缩小模型视图，不覆写原始转录。
replay safety
重建或重试前确认副作用是否已提交、是否可能重复。
announce
子代理结束后向父会话推送状态与有界证据的异步流程。
Gateway
负责连接、控制、会话与事件的常驻进程；不是模型。
