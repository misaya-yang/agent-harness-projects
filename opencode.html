学完本章你能：把任意一次“卡住 / 停不下来 / 提前收摊”的异常，翻译成终止三条件与循环事件流上的一次可验证检查。

  4. 同 session 串行：靠 ensureRunning + RunnerBusy（run-state.ts:88-107），忙则 BusyError——单飞是设计而非 bug。

EXIT TEST

“provider 报了 finish=stop”不足以退出循环：只要 assistant 消息上还挂着未处理的 tool part，循环继续。这就是 hasToolCalls 存在的理由——终止判定防御的是模型侧的谎报与截断。

CHAPTER 02 · ONE SERVER, EVERY SURFACE

TUI 与内核之间隔着一次“假装的 HTTP”——in-worker fetch 让本地模式与远程模式共享同一条协议。

opencode serve 起真 HTTP；默认 TUI 模式把同一个 app 塞进 Bun Worker，用 RPC 转发 fetch 和 global.event，不占 TCP 端口。SDK 由 OpenAPI 代码生成（hey-api），保证客户端与契约同源。

  1. 入口端点：POST /session/:id/message 之外还有 /prompt_async、/abort、/fork、/revert、/command、/shell（groups/session.ts:78-105）。
  2. 事件一律 SSE：WebSocket 只用于 PTY 终端流（groups/pty.ts:116-168）；GET /event 以 text/event-stream + 10s heartbeat 广播（handlers/event.ts:24-78）。
  3. 远程接入：--attach 直连远端 server；OPENCODE_SERVER_PASSWORD 缺省时无鉴权并有裸奔警告（cli/cmd/serve.ts:7-20）。

CHAPTER 04 · TOOLS AS FILTERED VIEWS

模型看到的工具清单，是注册表被“模型家族、agent 白名单、权限”三把刀各削一刀之后的残影。

17 个内建工具 + MCP + 自定义 JS/TS 文件 + 插件注册，汇入 registry.tools()。最惊人的细节：GPT 系新模型只给 apply_patch、隐藏 edit/write——工具视图按模型行为特性定制。

  1. 工具即 Schema：Effect Schema decoder + execute + 编译期 import 的 .txt 描述（tool/tool.ts:99-169）。
  2. 模型过滤：usePatch = modelID.includes("gpt-") && !oss && !gpt-4（registry.ts:297-300）。
  3. MCP 命名与闸门：工具命名 sanitize(server)_sanitize(tool)，调用前强制 ctx.ask（mcp/catalog.ts:117-119 + tools.ts:408）。
  4. 输出截断：2000 行 / 50KB，超限全文落盘并回 outputPath（tool/truncate.ts:12-15,78-81）。
  5. 参数错误不抛异常：解码失败回一个模型可读的“请重写输入”错误（tool.ts:24-34 InvalidArgumentsError）。

CHAPTER 07 · COMPACT THEN CONTINUE

OpenCode 把“上下文满了”实现成循环里的一种任务类型，而不是一个异常。

三处检测（每步 usage 后、ContextOverflowError、prompt 前预检）都归结为 needsCompaction；压缩生成一条 mode:"compaction" 的 assistant 摘要消息，保留最近 tail turns，然后自动注入“Continue…”合成消息续跑。

  1. 阈值公式：isOverflow 先被 compaction.auto === false 与 context === 0 短路；计数取 tokens.total || input+output+cache.read+cache.write，≥ usable 才压缩（usable = input 上限 − reserved，缺省 min(20k, maxOutput)；无 input 上限时兜底 context − maxOutput）（overflow.ts:8-34）。
  2. tail 预算：preserve_recent_tokens ?? clamp(2k,15k,usable*0.25)，按 user 轮次从后往前累计（compaction.ts:115-120,223-269）。
  3. 摘要五段：Objective / Important Details / Work State / Next Move / Relevant Files，增量更新 <prior-summary>（core/session/compaction.ts:16-55）。
  4. PRUNE：更老工具输出清空为“[Old tool result content cleared]”，skill 工具受保护（compaction.ts:28-31,273-317）。
SEE IT RUN

压缩续跑已并入第 01 章主循环步进机的第 9 步：摘要消息落库后注入合成 “Continue if you have next steps…”，回到历史重建，而不是抛错终止回合。

CHAPTER 09 · TWO RUNTIMES ONE STREAM

CHAPTER 11 · STEPS, RETRIES, DOOM LOOPS

防失控是三件套：步数上限翻译成一条“禁工具”提示注入、连续三次同调用触发 doom_loop 审批、重试尊重服务端 retry-after。

OpenCode 不用超时器管住循环，而是把预算与审批织进循环本身——每一步都要花掉预算或过一次闸门。

  1. 步数预算：agent.steps 用尽时 isLastStep 在 messages 尾部注入 MAX_STEPS_PROMPT 假消息——禁工具、要求文本总结（prompt.ts:1178-1179,1281 + core/session/runner/max-steps.ts）。
  2. doom loop 检测：最近 3 个 part 同工具同参数 → permission.ask({permission:"doom_loop"})，把“鬼打墙”升级成一次人工裁决（processor.ts:29,356-380）。
  3. 输出封顶：OUTPUT_TOKEN_MAX=32_000（可 env 覆盖），取 min(model.limit.output, cap)（transform.ts:18,1418）。
NO WALL-CLOCK KILL循环没有全局超时。防失控靠 steps 上限、doom_loop 审批、abort 端点三件套——面试中“OpenCode 如何防死循环”不要答成有超时器。[合理推断]（grep 未命中 loop 级 timeout + 三机制均有源码）

PROBLEM SET 01 · 架构设计题

“把 opencode 的 agent 内核嵌入自研平台，但要求会话历史、计费统计归平台所有，怎么做？”

展开答题骨架与解耦推演

【场景定义】 复用 runLoop / 工具 / 权限引擎，替换存储与事件消费方；TUI 弃用，平台自研前端。

【归属层/机制】 内核与持久化的解耦点恰是“事件投影”（Chapter 03: Events Project to SQL）：内核只 publish（session.ts:629-643 updateMessage→Event），落库是 projector 的订阅副作用（core/session/projector.ts:260-318）。计费字段 assistant 消息自带 cost/tokens.cache。

【关键证据链】 EventV2 Interface（core/src/event.ts:126-149 publish/subscribe/durable/replay）；event-v2-bridge.ts 的双向桥示范了“换总线”的既有先例；share-next.ts 用同一订阅面做增量同步——平台计费可完全复刻此模式。

【方案与防线】 写自己的 projector 替换默认投影（或禁用默认层注入平台 DB）；防线：durable 事件的 seq/aggregateID 必须保留否则回放断链；Instance/directory 上下文注入别丢（bridge 的 Location.Info），否则多租户路由错乱。

PROBLEM SET 02 · 故障排查题

“CI 里 opencode run 跑一半静默退出，无任何工具输出，先查什么？”

展开答题骨架与证据链

【场景定义】 headless 模式、非交互 TTY，进程以退出码结束但 assistant 消息只有半截。

【归属层/机制】 两个高发：(a) 审批纤——CI 无应答者，非 auto 模式收到 permission.asked 直接自动 reject（run.ts:801-816）；(b) provider 侧 finish=stop 谎报——循环靠 hasToolCalls 防御，但 content-filter 收尾会主动 break（prompt.ts:1295-1307）。

【关键证据链】 退出前最后事件是 permission.asked（无 replied）→ 审批；handle.message.finish === "content-filter" → 过滤；retry.ts 5 次耗尽后 Cause.done 静默收场。查 OPENCODE=1 进程日志 loop exit with orphaned interrupted tool 告警。

【方案与防线】 给 CI 配 --yolo/permission allow 规则，并把 reject 转义成显式失败（CorrectedError message 进日志）；防线：CI 前端设外层 job timeout，补上内核缺失的 wall-clock 治理。

PROBLEM SET 03 · 安全扩展题

“用插件体系给公司写一道‘生产库禁连 + 密钥不落盘’护栏，钩子挂在哪？”

展开答题骨架与三把锁

【场景定义】 agent 可自由跑 bash，需拦截 psql prod 类命令，并防止 .env 被 read。

【归属层/机制】 三把锁正交：permission 规则（evaluate findLast，后写 deny 压过先写 allow）、内置 .env 读取默认 ask（agent.ts:119-136 全局 defaults）、外部路径 external_directory（external-directory.ts:15-45）。插件钩子 tool.execute.before（tools.ts:106-112）在 execute 前可抛错硬拦；permission.ask 钩子存在但服务端无触发点（预留，别依赖）。

【关键证据链】 bash pattern 由 tree-sitter 命令节点还原（shell.ts:378-411），rm -rf 拆管道/子命令逐一评估——规则要写通配前缀（arity 字典决定 always 粒度）；deny 返回的 DeniedError 文本会回注模型，可引导其改用安全路径。

【方案与防线】 plugin 里 tool.execute.before 对 bash/edit 类工具做 AST 级二次审查 + 写自定义审计事件；防线：allow 规则不要写 bash:"*"——MCP 工具每次调用才 ask（tools.ts:409-410），把 server 名纳入 pattern 管理。

part
消息的原子内容块（12 种），流式更新的粒度单位，逐 part 落库广播。

主 while(true) 与其一次迭代 = 一次完整模型请求-工具执行周期；step 计数喂给 agent.steps 预算。

内核只 publish 事件，SQLite 行由 projector 订阅写入——状态是事件流的物化视图。
doom loop
连续 3 次同工具同参数被 processor 识别后升级为一次 doom_loop 权限审批。
compaction
溢出前把老历史摘要成一条 mode:"compaction" assistant 消息、保留 tail 并自动续跑的循环内任务。
PRUNE
压缩的姊妹操作：倒序跳过最近 2 轮，把更老非保护工具输出清空为占位文本。
