CHAPTER 01 · LAYER MAP

先分清 Pi AI、Agent Core、Coding Agent 与 TUI。

Pi 不是一个单体 CLI：统一模型 API 负责 Provider，Agent Core 负责状态与工具循环，Coding Agent 负责 Session、资源与入口，TUI 只负责终端呈现。

SOURCE ROUTE · PI a470b121b

先读四个入口，再用责任探针定位问题。

它们分别回答“谁拥有活状态、谁驱动一次 run、谁组合产品能力、谁保存可分支历史”。

  1. packages/agent/src/agent.tsAgent 拥有 transcript、streaming state、queues、listeners 与 abort controller。
  2. packages/agent/src/agent-loop.tsagentLoop / runLoop 产生 turn、message 与 tool lifecycle events。
  3. packages/coding-agent/src/core/agent-session.tsAgentSession 组合模型、工具、SessionManager、资源和 Extensions。
  4. packages/coding-agent/src/core/session-manager.tsSessionManager 把 entry 写入 append-only JSONL tree，并投影当前 branch。

学完本章你能：先找拥有状态的层，再决定读 Provider event、Agent event、Session entry 还是 UI snapshot。

CHAPTER 02 · AGENT STATE

一次 run 使用启动时的 context snapshot；完成事件再把消息写回 public state。agent_end 发出后，等待型 listener 仍属于 settlement。

CHAPTER 03 · EVENT LOOP

一次 prompt run 可以包含多个 Turn；这里的 Turn 是一次模型调用加工具批次。

Provider stream 先形成 committed assistant message；如果其中有 tool calls，执行结果成为 toolResult messages，再开启下一个 Turn。

Prompt 事件步进机idle
  1. agent_start
  2. turn_start
  3. user message
  4. transform → convert
  5. provider stream
  6. assistant message_end
  7. tool execution
  8. toolResult messages
  9. next turn / stop
  10. agent_end

观察 Provider event 怎样被提升为 Agent lifecycle。

CHAPTER 04 · STEER / FOLLOW-UP / ABORT

Steer 早于 Follow-up，但不会撕开正在运行的工具批次。

Steer 在当前 assistant turn 的工具完成后注入；只有没有 tool call 和 steering 时才检查 Follow-up。Abort 只触发 signal，Provider 与 Tool 必须主动尊重它。

CHAPTER 07 · JSONL SESSION TREE

Session 文件是 append-only Entry Tree，不是线性聊天日志。

Header 之外每个 entry 都有 id / parentId；Branch 只移动当前 leaf，旧路径仍在同一个文件。UI 与 LLM context 读取的是当前 branch 投影。

CHAPTER 08 · COMPACTION & BRANCH SUMMARY

Compaction 改变 Context Projection，不擦除旧 Entry。

当前 coding-agent 源码用 firstKeptEntryId 指向保留边界；cut point 不落在 toolResult 上，超大单 Turn 会拆出 prefix summary。Branch summary 则把离开的路径带到新分支。

  1. 判断压力：contextTokens 超过 window - reserveTokens。
  2. 选择边界：从后向前保留近期内容，不切断 tool result。
  3. 序列化：Tool result 在摘要请求中截断，原 JSONL 不变。
  4. 生成摘要：独立 routing/session id，禁用 tools 与 cache retention。
  5. 追加 Entry：summary、firstKeptEntryId、tokensBefore 与 file details。
SOURCE WINS不要把另一套 Harness 格式混进来。仓内部分文档提到 retainedTail，但当前 coding-agent CompactionEntry 与 buildContextEntries() 以 firstKeptEntryId 为实现事实。
CHAPTER 09 · EXTENSIONS & RESOURCES

Extensions 能改工具、事件和 UI；Skills 与 Prompts 主要改变模型输入。

扩展是当前进程内的 TypeScript module，可注册 Tool、Command、Provider 与 lifecycle hook；Skills、Prompt Templates、Themes 和 Packages 由 ResourceLoader 发现并热加载。

CHAPTER 10 · TUI & CLI MODES

TUI 是差分渲染器，不是 Agent 状态机。

Regular 模式使用主屏与 terminal scrollback；实验性 Fullscreen 使用 alternate screen 与自有 viewport。两者都比较前后行，只重画变化区域并用 synchronized output 降低闪烁。

Process control

EVIDENCE

终端截图只能证明呈现状态。自动化应读取 message_end、Session context 或 RPC state，而不是把“屏幕看起来完成”当成运行完成。

CHAPTER 11 · RPC / PROTOCOL / CLIENT

Pi 有两类不同协议：Coding Agent RPC 与实验性 Server Protocol。

RPC 是 stdin/stdout JSONL 命令事件流；独立 Protocol 使用 4-byte length + CBOR，Server Snapshot 是权威状态，Progress 只是临时提示，认证由 Transport Listener 负责。

CHAPTER 12 · SECURITY & PRACTICE

Pi 默认拥有启动用户的全部权限；Project Trust 不是 Sandbox。

内建 Read、Write、Edit、Bash 和 Extensions 都运行在 Pi 进程权限内。处理不可信仓库或无人值守任务时，真正边界必须来自 Container、VM、Micro-VM 或 Policy-controlled Sandbox。

机制实际控制什么不保证什么
Project Trust项目级设置、Packages、Extensions 与资源是否加载不限制已加载工具
--tools allowlist模型看见哪些 Built-in Tools不是进程权限
Gondolin Extension把 Built-in Tools 与 ! commands 路由到 Micro-VM其他 Extensions 仍可能在 Host
Docker / OpenShell隔离整个 Pi 进程及其工具Bind mount 仍可改 Host

五步诊断法

先确定入口模式和当前 Session；再沿 agent/turn/message/tool events 找最后一个事实；区分 Agent conversion 与 Provider adaptation；核对 active tools 与 Extensions；最后确认需要的是 Project Trust、工具配置还是外部隔离。

90-SECOND ANSWER

“Pi Agent 的核心设计是什么？”

展开答题骨架
Pi 把 Provider 统一放在 pi-ai，把 transcript、队列、Abort 和 lifecycle events 放在 Agent Core；每个 Turn 是一次模型请求加工具批次。Coding Agent 再叠加 JSONL Session Tree、Compaction、Extensions、Resources 与 TUI/RPC 入口。并行工具可以按完成顺序发事件，但 ToolResult transcript 仍按模型顺序。Pi 默认没有内建权限系统，Project Trust 只是资源加载 Gate，真正隔离必须来自外部执行边界。
AgentMessage
Agent 内部可扩展消息；通过 convertToLlm 才进入 Provider context。
Turn
Pi Agent 中的一次模型调用及其工具批次。
Steer
当前工具批次结束后、下一次模型调用前注入的消息。
Follow-up
没有工具和 Steering 后才处理的后续消息。
Session Entry
JSONL tree 中带 id / parentId 的 append-only 节点。
Project Trust
控制项目资源加载的 Gate，不是 Sandbox。
